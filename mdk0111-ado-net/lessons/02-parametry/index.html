1Ввод пользователя в тексте запроса

Секретарь печатает приказы по шаблону: «Выдать пропуск сотруднику ___». Фамилию он берёт из заявки и впечатывает в пустое место. Пока в заявке написана фамилия, приказ получается правильным.

Программа поиска товаров получает текст для поиска от пользователя. Текст можно вставить в строку запроса интерполяцией C#. Интерполяция подставляет значение переменной на место выражения в фигурных скобках: $"…'%{text}%'…".

В коде ниже Console.ReadLine() читает строку, которую пользователь ввёл в терминале. Если ввод закрыт, метод возвращает null, и оператор ?? "" подставляет вместо него пустую строку.

Оператор ILIKE сравнивает строку с шаблоном без учёта регистра. Знак % в шаблоне означает «любые символы, в том числе ни одного». Для ввода мыш получается шаблон '%мыш%': ему подходят названия, в которых «мыш» стоит в любом месте.

2SQL-инъекция

      
Секретарь из прошлого раздела впечатывает в приказ всё, что написано в заявке. Если в графе фамилии написать «Иванову. Также выдать ключи от склада», в приказе дословно окажется второе распоряжение.

      
SQL-инъекция — атака, при которой пользователь вводит текст, меняющий смысл SQL-запроса. Она возможна, когда программа собирает текст запроса из ввода: склеивает строки через +, использует интерполяцию $"…" или string.Format.

      

        
Пример такого ввода — ' OR 1=1 --. Первый апостроф закрывает строку шаблона. OR 1=1 добавляет условие, которое верно для каждой строки таблицы. Два дефиса начинают комментарий SQL: сервер пропускает всё, что стоит после них до конца строки, в том числе остаток шаблона и ORDER BY.

      

      
Выберите ввод. Красным выделены символы ввода, которые сервер разобрал как код SQL. Результаты для готовых вариантов получены на стенде.

Ввод с UPDATE меняет данные в таблице. Точка с запятой завершает первый запрос, после неё идёт второй — UPDATE, который ставит всем товарам цену 1.00. Npgsql отправляет на сервер оба запроса, и сервер выполняет оба. Программа печатает список из восьми товаров со старыми ценами, по её выводу изменение не заметно. На стенде цены возвращаются командами docker compose down и docker compose up -d: база создаётся заново из init.sql.

      
Защита от инъекции — передавать значение так, чтобы сервер не мог разобрать его как код.

    


    
    

      
3Параметры запроса

      
В анкете у каждого поля своя клетка. Что бы ни написали в клетке «Фамилия», это остаётся фамилией: графы анкеты от этого не меняются.

      
Параметр запроса — именованное место в тексте SQL, значение для которого передаётся отдельно от текста. В Npgsql место обозначают именем с @, например @pattern. Значение добавляют в коллекцию command.Parameters методом AddWithValue(имя, значение).

      
Program.cs · поиск с параметром

      

        
Знаки % добавлены к значению в C#: шаблон целиком — значение параметра, в тексте запроса остаётся только @pattern. Npgsql заменяет @pattern на $1 — так места параметров обозначаются в протоколе PostgreSQL. Затем он отправляет текст запроса и значения отдельными сообщениями. Сервер сначала разбирает текст, потом подставляет значение в разобранный запрос как данные. Поэтому апострофы и дефисы в значении остаются символами строки.

    При склейке сервер получил запрос с условием OR 1=1 и выполнил его. С параметром сервер получил текст с $1 и значение отдельно. Апостроф в значении журнал показывает удвоенным: так журнал записывает апостроф внутри строки, в самом значении он один.     Значение параметра имеет тип, и от типа зависит, как сервер сравнит его со столбцом.
    
    
    

    
    
    
      
    4Тип значения, NULL и забытый параметр
    
      
    В графу «Сумма» банковского бланка пишут число. Если написать «три тысячи» словами, бланк не примут, хотя смысл тот же. Пустая графа тоже не означает сумму ноль.
    
      
    
        
    Тип параметра Npgsql определяет по типу значения в C#: int передаётся как integer, string — как text, decimal — как numeric. Сервер сравнивает значения совместимых типов. Если тип значения не подходит к столбцу, запрос заканчивается ошибкой.
    
      
    
      
    Выберите случай: справа появятся код и результат на стенде.
    
      
    
        
    Случаи с параметрами
    
        
    
          
    
          
    
        
    
      
    
      
    Отдельно о NULL. В SQL сравнение с NULL через знак = не даёт истину, даже если в столбце тоже NULL. Поэтому условие name = @n со значением DBNull.Value не находит ни одной строки. Пустые значения ищут условием IS NULL.
    
      
    Параметром передают значения. Имя столбца и направление сортировки параметр не задаёт.
    
    
    

    
    
    
      
    5Сортировка по выбору пользователя
    
      
    В анкете можно заполнить клетку, но нельзя переставить графы. Порядок граф задаёт тот, кто составил бланк, и посетитель выбирает только из того, что в бланке предусмотрено.
    
      
    
        
    Параметр заменяет только значение: число, строку, дату. Имена таблиц и столбцов, ключевые слова ASC и DESC — часть текста запроса, сервер разбирает их до подстановки значений. Если написать ORDER BY @col и передать "price", ошибки не будет. Сервер отсортирует строки по значению 'price', одинаковому для всех строк, и порядок не изменится. На стенде такой запрос вернул товары в том же порядке, что и без сортировки: Клавиатура, Мышь, Монитор 24".
    
      
    
      
    Белый список — заранее заданный набор допустимых вариантов. Программа ищет выбор пользователя среди ключей набора и вставляет в запрос только фрагмент, записанный в наборе. Введённый текст в запрос не попадает.
