1Строка результата и объект C#

В регистратуре данные пациента из журнала переписывают в карточку с подписанными графами. Дальше врач работает с карточкой и не ищет нужную строку в журнале.

В занятиях 1 и 2 значения строки читались в отдельные переменные и сразу печатались. В программе, где данные передаются дальше — в другой метод, в отчёт, на страницу сайта, — строку переносят в объект. Объект хранит все значения строки вместе, а читатель и соединение можно закрыть сразу после чтения.

record — тип C#, который объявляют одной строкой: record OrderRow(int Id, string Status, decimal Total);. Компилятор создаёт для него конструктор и свойства Id, Status, Total. Значения свойств задаются при создании объекта и потом не меняются.
Маппер — метод, который переносит одну строку читателя в объект. Он собирает все вызовы Get-методов в одном месте: если в запросе меняется столбец, правка нужна только в маппере.

2Чтение столбца по имени

      
В анкете нужную графу ищут по названию. Если графы в новом бланке переставили, «Фамилия» найдётся по подписи, а графа «третья сверху» окажется другой.

      

        
Номер столбца зависит от порядка в SELECT. Если кто-то поменяет порядок столбцов в запросе, маппер с номерами начнёт читать не те значения. Метод GetOrdinal("status") возвращает номер столбца по его имени, и маппер работает при любом порядке. Регистр в имени не учитывается: GetOrdinal("Status") тоже находит столбец.

        
Имя столбца в результате задаёт SELECT. Для выражения или столбца из другой таблицы его задают словом AS: c.full_name AS customer. После этого столбец ищется только по новому имени. Вызов GetOrdinal("full_name") на стенде закончился ошибкой Field not found in row: full_name.

3NULL в результате

      
В карточке покупателя есть графа «Дата последнего возврата». У покупателя, который ничего не возвращал, она пустая. Написать туда «0» или «01.01.0001» неверно: такая дата выглядит как настоящая.

      

        
NULL в столбце означает отсутствие значения. Он часто появляется после LEFT JOIN: строка из левой таблицы остаётся в результате, даже если в правой для неё ничего не нашлось. Запрос ниже выбирает для каждого клиента дату последнего отменённого заказа. Отменённые заказы есть только у двух клиентов, у остальных в столбце last_cancelled NULL.

Для столбца, где может быть NULL, свойство объекта объявляют с типом, допускающим пустое значение: DateOnly?, int?, string?. Короче всего его читает GetFieldValue<DateOnly?>. Проверка IsDBNull нужна, если вместо пустого значения подставляется своё. До сих пор программа только читала данные. Следующие команды их меняют.

    


    
    

      
4Команды, которые меняют данные

      
Когда в бухгалтерии проводят платёж, в ответ приходит отметка «проведено записей: 1». Если такого счёта нет, придёт «проведено записей: 0».

      

        
Для INSERT, UPDATE и DELETE строк результата нет, поэтому читатель не нужен. Метод ExecuteNonQueryAsync выполняет команду и возвращает число затронутых строк. Ноль означает, что условию WHERE не подошла ни одна строка. Исключения в этом случае нет. Метод ExecuteScalarAsync возвращает одно значение — первый столбец первой строки. Его используют для count(*) и для INSERT … RETURNING id, который возвращает номер новой строки.

      

      
Выберите команду: справа появятся метод и результат на стенде.

Тип значения ExecuteScalarAsync зависит от типа столбца: count(*) в PostgreSQL имеет тип bigint, поэтому приходит long, а id — int. Метод возвращает object?, и значение приводят к нужному типу: (long)(await command.ExecuteScalarAsync())!. Команда на изменение может нарушить правила таблицы, и тогда сервер её отклоняет.

    


    
    

      
5Ошибки ограничений

      
Регистратура не запишет пациента дважды к одному врачу на одно время. Она не запишет к врачу, которого нет в штате, и на приём длиной ноль минут. Каждое правило проверяется при записи, и на каждое есть свой ответ.

      
Ограничение — правило в описании таблицы, которое PostgreSQL проверяет при каждом изменении. Виды ограничений: первичный ключ (PRIMARY KEY), внешний ключ (REFERENCES), проверка значения (CHECK), запрет пустого значения (NOT NULL). Если команда нарушает ограничение, сервер отменяет её целиком и присылает код ошибки SQLSTATE.

      

        
Npgsql превращает ответ сервера в исключение PostgresException. В нём есть код SqlState, имя нарушенного ограничения ConstraintName и текст MessageText. Свойство Detail со значениями ключа по умолчанию скрыто, потому что в нём могут быть данные. Его включают настройкой Include Error Detail=true в строке подключения, на стенде для разработки.

Исключения, которые фильтры не выбрали, проходят дальше, и программа завершается с ошибкой. Это нужно для сбоев, на которые у программы нет ответа: если база недоступна, сообщение «товар уже есть в заказе» было бы неверным. Если нужно различить два внешних ключа, проверяют e.ConstraintName: order_items_order_id_fkey или order_items_product_id_fkey.
