1Программа, провайдер и база данных

PostgreSQL — сервер баз данных: отдельная программа, которая хранит таблицы и выполняет SQL-запросы. Программа на C#, которой нужны данные, называется клиентом. Клиент и сервер обмениваются сообщениями по сети, даже когда работают на одном компьютере. Клиент подключается к адресу и порту сервера, отправляет текст запроса и получает строки результата. Формат этих сообщений задаёт протокол PostgreSQL.

Писать обмен сообщениями вручную в каждой программе долго, поэтому в .NET для работы с базами есть готовый набор классов.

Так устроена печать на компьютере. Кнопка «Печать» во всех программах одинаковая, а в команды для конкретного принтера документ переводит драйвер этого принтера. В .NET общей кнопке соответствуют классы ADO.NET, драйверу — провайдер данных. Если сменить СУБД, меняются провайдер и названия классов, а порядок действий в программе остаётся тем же.
ADO.NET — часть .NET для работы с базами данных: базовые классы DbConnection (соединение), DbCommand (команда) и DbDataReader (чтение результата) из пространства имён System.Data.Common. В них описано, какие действия есть у соединения, команды и чтения. Код для конкретной СУБД находится в провайдере данных.
Провайдер данных — библиотека, которая реализует классы ADO.NET для одной СУБД. Для PostgreSQL это Npgsql: класс NpgsqlConnection наследует DbConnection и передаёт сообщения по протоколу PostgreSQL. Провайдер подключают к проекту как пакет NuGet.

На схеме — путь запроса от программы до базы. Переключатель в заголовке меняет СУБД.

2Четыре объекта Npgsql

Работа с базой в программе проходит четыре этапа: получить настройки подключения, подключиться к серверу, передать запрос и прочитать ответ. На каждый этап в Npgsql есть свой объект.

Этапы похожи на звонок на склад. Сначала нужен номер телефона, он записан в записной книжке. Затем звонок: линия соединена, и пока идёт разговор, по ней не позвонить другому человеку. Потом вопрос: «Какие у вас заказы?». Ответ диктуют по одной строке, а вы записываете строку за строкой, пока не услышите «это всё».

Карточки стоят в том порядке, в котором объекты создаются в программе. При нажатии на карточку в коде под ними подсвечивается строка, которая создаёт этот объект.

Каждый объект получается из предыдущего: соединение — из источника данных, команда — с соединением, читатель — из команды. Поэтому в программе строки идут в этом порядке: каждая следующая использует переменную, объявленную в предыдущей.

      
Пул соединений — запас открытых соединений внутри источника данных. Подключение к серверу занимает время: нужно установить сетевой канал и выполнить вход. Поэтому при закрытии соединение возвращается в пул открытым, и следующий вызов OpenConnectionAsync получает его без повторного входа.

      
Как эти объекты работают вместе, видно на пошаговом выполнении программы.

Из пошагового выполнения видны три факта. Запросы на сервер программа отправляет в двух строках: при открытии соединения и при выполнении команды. Строки результата приходят от сервера потоком, а программа берёт их по одной, вызывая ReadAsync. Объекты, объявленные с await using, закрываются в конце программы в обратном порядке, и соединение возвращается в пул.

      
Так работает дверь с доводчиком: её не нужно закрывать вручную, она закрывается, когда человек прошёл. Объявление с await using устроено так же: объект закрывается, когда выполнение выходит за пределы блока.

      
await using — объявление переменной, после которого объект закрывается автоматически, когда выполнение выходит из блока, где она объявлена. Для переменных верхнего уровня программы это конец программы. Если соединение объявить без using, оно остаётся занятым, пока его не закроют вызовом CloseAsync. В программе, которая обрабатывает много запросов, незакрытые соединения занимают весь пул, и новые запросы стоят в очереди за свободным соединением.

      
Первая строка программы — строка подключения. От неё зависит, к какому серверу и к какой базе программа подключится.

    


    
    

      
4Строка подключения

      
На конверте пишут город, улицу, дом, квартиру и имя получателя. Каждая часть сужает место доставки, и ошибка в любой из них не даёт письму дойти. Строка подключения устроена так же: в ней по частям записано, куда и от чьего имени подключаться.

      

        
Строка подключения — текст с настройками подключения в виде пар ключ=значение, разделённых точкой с запятой. Npgsql читает её при создании источника данных. Значения в строке должны совпадать с настройками сервера. В стартовом проекте сервер описан в файле docker-compose.yml, поэтому каждое значение строки можно найти в этом файле.

      

      
При нажатии на часть строки подсвечивается строка docker-compose.yml, из которой взято значение.

Ошибка в строке подключения

      
Визит в офис проходит по порядку: найти здание по адресу, пройти охрану с пропуском, найти нужный кабинет, задать вопрос. Если здания по адресу нет, до охраны дело не доходит, а неверный пропуск останавливает человека до поиска кабинета.

      

        
Подключение проходит этапы по порядку: сетевое соединение с портом, вход пользователя, выбор базы. Запрос выполняется после них. Ошибка останавливает работу на том этапе, где она возникла, и текст исключения указывает на этот этап. По тексту ошибки можно понять, какую часть строки или запроса исправлять.

      

      
Выберите ошибку: схема покажет, на каком этапе остановилась программа, а ниже появится сообщение, которое она печатает. Сообщения получены на настоящем стенде.

Пять символов в начале сообщения, например 28P01, — код ошибки PostgreSQL (SQLSTATE). Его присылает сервер: коды на 28 — ошибки входа, 3D000 — нет такой базы, коды на 42 — ошибки в тексте запроса. Сообщение без кода, как Failed to connect, означает, что до сервера программа не дошла. Когда подключение и запрос выполнены, остаётся прочитать строки результата.

    


    
    

      
5Чтение строк: ReadAsync и Get-методы

      
Бумажный журнал читают по линейке: её кладут под строку, читают значения в столбцах и сдвигают линейку вниз. Читатель результата работает так же: он стоит на одной строке, и сдвинуть его можно только к следующей.

      

        
После выполнения команды читатель стоит перед первой строкой результата. Метод ReadAsync переводит его на следующую строку и возвращает true. Когда строки закончились, метод возвращает false. Поэтому чтение записывают циклом while (await reader.ReadAsync()): тело цикла выполняется один раз для каждой строки.

        
Значения текущей строки читают Get-методами. Аргумент метода — номер столбца в результате. Номера начинаются с нуля и идут в том порядке, в каком столбцы перечислены после SELECT. В запросе SELECT id, status, total номер 0 — id, 1 — status, 2 — total. Имя метода задаёт тип C#, в котором нужно получить значение. Этот тип должен подходить к типу столбца в PostgreSQL:
