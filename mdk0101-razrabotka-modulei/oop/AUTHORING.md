# Отдельные главы справочника ООП

Цель переработки: одна тема — одна самостоятельная HTML-страница. Модули содержат оглавления. Материал выпускается партиями по несколько завершённых глав; прежние обзоры ещё не переработанных модулей временно остаются доступны и явно подписаны.

## Образец

Вёрстка: книга по синтаксису Python, глава «Словари» (`temy/46-slovari/index.html` в её репозитории).
Исходный текст: предоставленный PDF, модули 8–10, страницы 541–740; завершение темы `__slots__` включено. Исходный PDF и временные извлечения в репозиторий не добавлять.
Стиль: `styles.css`, `oop.css` и `book.js` в корне этой книги.
Страницы находятся в `modul-NN/NN-slug/index.html`; CSS/JS подключать через `../../`.

## Что писать

Каждая глава подробно разбирает только свою тему. Не ограничиваться вырезанным абзацем из прежнего модуля. Материал PDF — содержательная основа, но ошибки исправлять. Объяснять последовательно; термин сразу определять. Нужные ранее понятия кратко напоминать. Не ссылаться на ещё не написанное объяснение.

Ориентир на главу: 5–8 смысловых разделов, 450–800 русских слов объяснения, 4–7 независимых исполняемых примеров. Это ориентир на полноту, а не повод добавлять воду. Для узкого понятия допустимо меньше при полном разборе. Сложным темам (MRO, дескрипторы, метаклассы) дать больше внимания.

Последовательность: задача и определение → простой пример → код → точный вывод → подробный разбор → развитие механизма/границы → ошибки → шпаргалка → глоссарий → краткий итог. Один раздел — одна мысль. Связки и переходы должны продолжать предыдущую мысль.

Бытовые аналогии — в `details.simple`, минимум две на основную тему. Внутри: подводка, `.flow.scheme` с карточками `.node` и стрелками `.arrow`, строка «Что есть что», границы сравнения. Не придумывать свойства Python по аналогии. Для остальных механизмов — таблицы/схемы с реальными числами из своего примера, не только код и вывод. Подводка перед таблицей/схемой и разбор после обязательны.

Без сюжетных сценок, афоризмов, риторических вопросов, «не просто», «ключевой», «магия», одушевления инструментов. Не писать «вслух». Текст — взрослая лекция для новичка.

## HTML

Полный документ `<!doctype html><html lang="ru">`. Заголовок страницы: номер главы, тема, «ООП на Python». Структура: `.book > .book__body > .spine + main.leaf`; `.running`, `.chapter-head`, `.chapter-num`, `h1`, `.lead`, `.passport`, `nav.contents`, разделы `section.part` с `h2 id=sN`.

Пример с исполняемым кодом:

```html
<figure class="code" data-run="python"><figcaption><span>main.py</span><span>назначение примера</span></figcaption><pre><code class="language-python">КОД</code></pre></figure>
<figure class="code code--out"><figcaption><span>Вывод</span></figcaption><pre>ТОЧНЫЙ STDOUT</pre></figure>
```

Код HTML-экранировать. Каждый пример самостоятельный (импорты и определения повторить), без ввода, файлов, сети, случайных величин, адресов памяти, внешних пакетов. Ошибки перехватывать и печатать их тип/стабильное сообщение, чтобы завершение программы было успешным. `code--out` идёт сразу после соответствующей фигуры с программой.

Для инструментов качества кода показывать файлы/команды без `data-run=python`; рядом 3–4 самостоятельных примера Python о том, что инструмент проверяет/не проверяет. Не выдавать непрогнанный вывод внешних утилит за проверенный.

Внизу `.pager`: ссылки предыдущая глава, `../../index.html` (вся книга), `../index.html` (модуль), следующая глава. Точные пути и номера берите из `chapters.json`. Глоссарий каждой главы — термины с определением, примером и соответствием в code/стрелках; повторять ранее изученные термины, если они нужны для этой главы.

## Выпуск партиями

Полный план — `chapters.json`: 64 темы (17 + 30 + 17). Поле `status` принимает `ready` или `planned`. Статус `ready` ставить после проверки содержания и примеров. `build_catalog.py` публикует ссылки только для готовых глав; остальные темы отображаются текстом. Обзоры модулей без готовых отдельных глав генератор не изменяет.

После добавления партии: `python3 build_catalog.py`, `python3 check_examples.py`, вычитка, проверка в браузере. Навигация последней готовой главы ведёт в оглавление, пока следующая не выпущена. При следующем выпуске добавить ссылку в предыдущую главу.

Черновики и временные генераторы не считать завершёнными главами.

## Технические границы

__init__ — инициализатор, __new__ — создание. super продолжает поиск по MRO; ромб требует согласованных параметров/кооперативных вызовов. Подчёркивания и name mangling не безопасность. Композиция/агрегация — семантика владения, а не автоматическое удаление. property не обеспечивает непроницаемой защиты. ABC не проверяет сигнатуры; аннотации/Protocol обычно проверяются статическим анализатором. frozen не глубокая неизменяемость. Слоты возможны у подтипов list/dict; ограничения некоторых других builtin объяснять точно. __del__ не гарантирует закрытия ресурсов. NotImplemented не NotImplementedError.

Изменять только назначенные страницы своего модуля. Не менять общие файлы, индексы модулей, настройки и контекст. Не коммитить и не пушить. Если объём не позволяет завершить всё — прямо сообщить готовые и оставшиеся главы. Не помечать заглушки готовыми.
