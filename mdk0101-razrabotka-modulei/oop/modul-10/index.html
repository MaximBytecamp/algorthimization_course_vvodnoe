§1Класс как объект

Экземпляр хранит данные конкретного предмета. Класс описывает устройство таких экземпляров, но сам тоже существует в программе как объект: его можно сохранить в переменную и передать функции.

Форма для выпечки задаёт вид изделий. Печенье сделали формой, но саму форму тоже изготовили на заводе. В Python обычный экземпляр создают вызовом класса, а обычный класс — механизмом типа type.

factory — второе имя того же класса, а не копия. Вызов создаёт экземпляр Ticket. У класса Ticket свой тип — type. Это объясняет, почему функции могут принимать классы как обычные значения.

По-простому: кто изготовил форму

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Формакласс Ticket
→
Печеньеэкземпляр ticket
→
Завод формтип type

Что есть что. Форма — класс; результат выпечки — экземпляр; изготовитель обычных классов — type. Порядок создания: type → Ticket → ticket.

У класса и файла есть имена, доступные во время работы программы.

§2Имена __name__ и __module__

__name__ — имя, записанное у класса или функции. Оно помогает вывести понятное сообщение вместо адреса объекта. __module__ показывает модуль, в котором определён класс. Это не то же самое, что переменная __name__ самого запускаемого файла.

Переименование ссылки не меняет имя класса: Alias.__name__ по-прежнему Ticket. Здесь файл выполняется как программа, поэтому его имя — __main__. При импорте __module__ будет именем модуля, где класс определён.

Именованные атрибуты можно также рассмотреть как пространство имён.

§3__dict__ и vars(): где видны атрибуты

У обычного экземпляра пользовательского класса есть словарь атрибутов __dict__. Функция vars(obj) возвращает этот словарь. У класса есть отдельное пространство имён: атрибуты экземпляра и класса не складываются в один ящик.

В словаре экземпляра есть только title. Когда собственный атрибут category не найден, обычный поиск продолжает работу в классе. У класса __dict__ представлен доступным для чтения отображением mappingproxy; менять класс следует через присваивание атрибута. Не у всякого объекта есть __dict__: ниже встретим экземпляры со слотами.

По-простому: личный ящик и общая инструкция

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Личный ящикvars(item): title
→
Общая инструкцияvars(Ticket): category
→
Чтениеitem.category → класс

Что есть что. Личный ящик — атрибуты экземпляра, общая инструкция — атрибуты класса. Это схема обычного поиска; свойства и другие дескрипторы данных могут иметь приоритет над словарём экземпляра.

Повторяющиеся операции над атрибутами можно вынести в примесь.

§4Примесь: небольшое дополнение к классу

Примесь, или mixin, — класс с небольшой повторно используемой возможностью. В Python её обычно подключают множественным наследованием. Отдельного ключевого слова trait нет; названия «примесь» и «миксин» здесь относятся к одному приёму.

Примесь добавила as_dict(), но не отвечает за создание заявки. Метод предполагает, что у экземпляра есть словарь атрибутов. Это ограничение нужно знать: со слотами без __dict__ такой код не подойдёт. Не стоит превращать примесь в скрытый набор требований к десяткам полей.

Для управления чтением и записью отдельного поля применяется дескриптор.

§5Дескриптор: объект управляет доступом к атрибуту

Дескриптор — объект, у типа которого определён хотя бы один из методов __get__, __set__, __delete__. Когда такой объект хранится в атрибуте класса, Python может поручить ему чтение и запись этого атрибута. Так одну проверку можно использовать в разных классах.

__set_name__ получает имя поля при создании класса. Присваивание self.price = price вызывает __set__, а чтение — __get__. Значение хранится у конкретного товара под именем _price. Общий объект Positive хранит только правило доступа. Неудачная проверка срабатывает до записи: цена остаётся 120.

Дескриптор с __set__ или __delete__ называют дескриптором данных. При обычном поиске атрибута он имеет приоритет над одноимённой записью в словаре экземпляра. Дескриптор только с __get__ такого приоритета не имеет. Уже знакомый property — дескриптор данных.

По-простому: контролёр на приёмке

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Покупательitem.price = -5
→
КонтролёрPositive.__set__
→
Складitem._price остаётся 120

Что есть что. Контролёр — дескриптор, полка конкретного товара — атрибут экземпляра. Проверка отбрасывает неправильную запись до изменения данных. Прямое изменение внутреннего поля позволяет обойти это правило.

Другой способ распределить ответственность — передать работу помощнику.

§6Делегирование: передать работу другому объекту

Делегирование означает, что объект принимает запрос, но выполнение поручает своему помощнику. Класс не обязан наследоваться от помощника: достаточно хранить ссылку на него и вызывать нужный метод.

Пользователь обращается к отчёту, а преобразование текста выполняет Formatter. «Имплементация» означает реализацию договорённости о поведении. В Python не нужно копировать чужой метод в класс, чтобы воспользоваться его работой.

По-простому: передать заказ мастеру

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Клиентreport.render("готово")
→
Приёмщикобъект Report
→
Мастеробъект Formatter

Что есть что. Приёмщик — отчёт, мастер — форматировщик. Ссылка self.formatter соединяет объекты; вызов format передаёт работу помощнику.

Для классов, которые хранят данные, часть методов можно сгенерировать.

§7dataclass: класс данных без повторяющихся методов

Когда класс в основном хранит данные, повторяются инициализация, представление и сравнение. Декоратор @dataclass из стандартной библиотеки создаёт эти методы по объявленным полям. Тип поля записывают после двоеточия.

Сгенерированный __init__ принимает две координаты. __repr__ показывает их. __eq__ сравнивает значения полей экземпляров одного класса. == даёт равенство значений, is — проверку одного и того же объекта. Аннотация int сама по себе не проверяет аргументы во время выполнения.

Для изменяемых полей важно отдельно настроить начальные значения.

§8default_factory и __post_init__

Изменяемому полю нужна новая коллекция для каждого экземпляра. field(default_factory=list) вызывает list() при создании каждой записи. Проверки после сгенерированной инициализации удобно помещать в __post_init__.

Два списка независимы. Значение items=[] здесь использовать не следует: dataclass отвергает многие изменяемые значения по умолчанию. Фабрика вызывается без аргументов и возвращает новый объект. __post_init__ запускается сгенерированным __init__; если написать собственный инициализатор, автоматического вызова не будет.

По-простому: отдельная корзина каждому

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Первый заказCart("Ира")
→
Новая корзинаlist() → []
→
Второй заказCart("Олег") → другая []

Что есть что. Фабрика — выдача новой корзины, поле items — корзина одного владельца. Изменение первого списка не затрагивает второй.

После создания экземпляра может понадобиться ограничить изменение его полей.

§9frozen и изменение вложенных коллекций

Параметр frozen=True запрещает обычное присваивание и удаление полей dataclass. Это полезно для значений, которые не должны меняться после создания. Вложенный список при этом не становится кортежем.

Поле tags сохранило ссылку на тот же список. Изменилось содержимое этого списка. Для неизменяемой коллекции подойдёт кортеж из неизменяемых значений. Автоматический хеш у frozen dataclass не означает, что любой экземпляр хешируем: список в поле по-прежнему не имеет хеша.

Хранение и передача ссылок определяют связи между объектами.

§10Ассоциация и зависимость: связь или разовый вызов

Ассоциация — связь объектов в модели: преподаватель ведёт курс, клиент имеет заказы. Если объект хранит ссылку на другой объект, связь видна прямо в его состоянии. Зависимость шире: код пользуется другим типом или объектом, даже если получает его лишь на время вызова.

Course хранит принтер — это устойчивая связь. Функция show_once только использует аргумент. Композиция и агрегация из предыдущего модуля уточняют смысл связи «целое — часть». Эти названия описывают модель и ответственность. Освобождение памяти подчиняется правилам работы со ссылками.

При чтении метода ссылка на получателя сохраняется автоматически.

§11Связывание: почему метод получает self

При чтении обычной функции через экземпляр Python создаёт связанный метод: он помнит и функцию, и объект, который нужно передать первым аргументом. Поэтому в объявлении есть self, а при вызове его обычно не пишут.

__self__ — получатель, __func__ — исходная функция. Два последних вызова дают одинаковый результат. Это конкретный механизм связывания методов. В разговорах об архитектуре «связанностью» также называют зависимость компонентов друг от друга; это другое значение слова.

По-простому: конверт с адресом

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

ФункцияGreeter.hello
→
Адрес получателяperson
→
Готовое отправлениеperson.hello

Что есть что. Связанный метод — функция вместе с получателем. Метод не копирует весь объект: он хранит ссылку на него.

Создание самого получателя начинается до инициализации.

§12__new__: создание прежде инициализации

При обычном вызове класса сначала __new__ создаёт экземпляр, затем __init__ настраивает его. Большинству классов достаточно __init__. Переопределение __new__ нужно редко, например для подтипов неизменяемых встроенных значений.

__new__ получает класс и должен вернуть объект. Если возвращён экземпляр этого класса или его подкласса, обычный механизм вызова класса переходит к инициализации. Если возвращён объект другого типа, этот __init__ не вызывается. Результатом __init__ должен быть None. Экземпляр уже создан к моменту вызова инициализатора.

§13Подкласс неизменяемого типа

Строку нельзя изменить после создания. Поэтому подтип строки, который всегда хранит текст без крайних пробелов, должен подготовить значение в __new__, до создания самой строки.

Вызов родительского __new__ создаёт именно экземпляр CleanText с уже подготовленным содержимым. Присваивание в __init__ не смогло бы заменить внутреннее строковое значение.

После создания экземпляр тоже может поддерживать вызов со скобками.

§14__call__: экземпляр можно вызвать

Метод __call__ позволяет использовать экземпляр как функцию. Это удобно, когда действие должно помнить состояние между вызовами. Если состояния нет, обычная функция обычно проще.

Counter() вызывает класс и создаёт счётчик. Следующие counter() вызывают уже экземпляр и попадают в Counter.__call__. Это два разных действия с одинаковыми круглыми скобками.

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Первый проходcounter() → 1
→
Ещё триcounter(3) → 4
→
Тот же приборvalue хранится в экземпляре

Что есть что. Прибор — вызываемый объект, нажатие — __call__, показание — self.value. Отдельный Counter() получил бы независимое состояние.

Процесс создания класса можно настраивать отдельно от вызова его экземпляра.

§15Метакласс: настройка создания класса

Метакласс — тип класса. Обычный метакласс type создаёт класс из имени, базовых классов и пространства имён. Его подкласс может изменить этот процесс. Это инструмент для библиотек и инфраструктуры, а не обязательная часть каждого проекта с ООП.

NamedMeta.__new__ создаёт класс Ticket, а не заявку. В его пространство имён заранее добавлен kind. Затем вызов Ticket() создаёт обычный экземпляр. Для большинства задач проще декоратор класса или __init_subclass__, чем собственный метакласс.

Атрибуты созданного класса могут изменяться и во время работы программы.

§16Monkey patching: заменить поведение во время работы

Monkey patching — изменение атрибутов существующего класса или модуля во время работы программы. Оно бывает полезно в тестах, но глобальная подмена влияет и на уже созданные экземпляры, если они читают метод из класса.

Замена выполнена в классе: при следующем чтении service.status находится новая функция и связывается с экземпляром. Блок finally восстанавливает прежнее значение даже при ошибке. Присваивание обычной функции прямо экземпляру не создаёт такое же автоматическое связывание. В прикладном коде передача зависимости обычно яснее глобальной подмены.

В последней строке показан результат: исходный ответ. Он соответствует выводу программы выше.

При повторном использовании поведения важно сохранять единое место для каждого правила.

§17DRY и WET: повторение правил

DRY — «не повторяй себя»: одно правило должно иметь одно место изменения. WET — ироничное название повторяющегося кода. Совпадение двух строк ещё не означает, что их нужно немедленно объединять: правила могут быть разными по смыслу.

Правило расчёта находится в одном методе и применяется к двум ценам. Не стоит выносить ставку налога и скидку в одну переменную только потому, что обе сегодня равны 0,2: это разные знания и меняться они будут независимо. Ни DRY, ни WET не являются возможностями интерпретатора.

Представление объекта также является частью выбранного интерфейса.

§18__str__ и __repr__: для читателя и для отладки

__str__ задаёт удобное представление для пользователя. __repr__ задаёт информативное представление для разработчика. Желательно, чтобы repr был однозначным; если восстановление объекта выражением неуместно, достаточно полезного описания.

print(item) использует строковое представление, а список показывает элементы через repr. Модификатор !r внутри f-строки явно выбирает repr. Если своего __str__ нет, стандартная реализация использует __repr__. Оба метода должны возвращать строку. Не помещайте в представления пароли и токены: они попадут в журналы.

По-простому: ценник и складская наклейка

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Ценникstr(item): для покупателя
→
Наклейкаrepr(item): для разработчика
→
Коробка со списком[item] показывает repr

Что есть что. Ценник — __str__, техническая наклейка — __repr__. Это два представления одного объекта, а не два разных объекта.

Способ хранения атрибутов можно настроить через слоты.

§19__slots__: фиксированный набор полей

__slots__ позволяет выделить места под перечисленные атрибуты вместо обычного словаря экземпляра. Это может уменьшить расход памяти, когда экземпляров очень много. Начинать стоит с обычного класса; оптимизацию выбирают после измерений.

Слоты не делают поля неизменяемыми: x успешно изменился. Отсутствие __dict__ не позволяет добавить произвольное поле. Вариант __slots__ = ("x", "y", "__dict__") снова разрешит дополнительные атрибуты, но вернёт часть затрат. Для слабых ссылок при необходимости добавляют __weakref__.

По-простому: шкаф с подписанными ячейками

Сравним механизм с понятной бытовой ситуацией. Схема отделяет участников, чтобы не смешивать их роли.

Ячейка xможно заменить содержимое
→
Ячейка yможно заменить содержимое
→
Место для colorне предусмотрено

Что есть что. Ячейки — объявленные слоты. Фиксируется набор мест хранения, а не значения внутри них; это не механизм приватности.

В подклассе наличие словаря атрибутов нужно проверять отдельно.

§20Слоты при наследовании и измерение памяти

Если подкласс не объявит собственные слоты, у его экземпляров обычно снова появится словарь. Пустые слоты __slots__ = () означают, что подклассу не нужны новые поля. Они не убирают словарь, если он уже есть у базового класса.

Наследование не отменяет слоты родителя: у Fixed осталось поле x. Некоторые встроенные типы ограничивают слоты подклассов; например, у подтипов tuple непустые слоты не поддерживаются. Общего запрета на наследование от list или dict со слотами нет.

sys.getsizeof(obj) показывает лишь размер самого объекта, а не всей достижимой структуры. Для обычного экземпляра нужно как минимум отдельно учитывать словарь; строки, списки и общие ссылки требуют дополнительного анализа. Поэтому универсальных процентов экономии в этой главе нет. Для dataclass на Python 3.10+ доступно @dataclass(slots=True).

Частые ошибки

  • Хранить значение поля прямо в общем дескрипторе: экземпляры начнут делить одно значение.
  • Считать frozen=True глубокой неизменяемостью: вложенная коллекция может остаться изменяемой.
  • Подменять метод глобально и не восстанавливать его после теста.
  • Выбирать метакласс там, где достаточно функции или декоратора класса.
  • Ожидать, что слоты обеспечат приватность или автоматически сохранятся в любом подклассе.
