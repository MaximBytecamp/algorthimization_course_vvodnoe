§1Наследование выражает специализацию

Наследование создаёт новый класс на основе существующего. В базовом классе оставляют общие данные и действия, а в подклассе — отличие. Курьерская доставка является доставкой: это отношение is-a. Наследник получает методы родителя без копирования текста.

Аналогия: общий бланк

У всех доставок один бланк, а у курьерской есть дополнительное поле.

Delivery→Courier→курьер

Что есть что: бланк — базовый класс, особый бланк — подкласс, поле — новое свойство.

Общее пишут один раз, а подкласс добавляет только нужное.

Вызов Courier().status() находит status в Delivery и возвращает строку «в пути». Подкласс пока не добавляет полей: pass оставляет тело пустым.

Полученный метод можно заменить реализацией подкласса.

§2Переопределение меняет один шаг

Подкласс может объявить метод с тем же именем. Python найдёт его раньше родительского метода. Так одна операция сохраняет смысл, но получает результат для конкретного вида объекта.

У каждого класса своя реализация price. Вызов Delivery().price() вернул 300, Pickup().price() — 0. Исходный метод базового класса сохранился.

Инициализация подкласса может включать общую часть базового класса.

§4super() в инициализаторе

Инициализатор подкласса настраивает общие и дополнительные атрибуты. super() возвращает посредник для поиска метода дальше по порядку классов, связанному с экземпляром. В цепочке из двух классов так вызывается метод базового класса.

Аналогия: эстафета

Каждый участник делает свой участок и передаёт палочку дальше.

Pickup→super()→Delivery

Что есть что: участник — класс, палочка — управление, маршрут — порядок поиска методов среди классов.

Такой вызов не привязывает код к одному конкретному родителю.

super().__init__(number) записал number в тот же экземпляр. Следующая строка создала point. Поэтому у item доступны оба значения.

Порядок продолжения поиска можно получить программно.

§5super() ищет следующий класс по MRO

MRO (Method Resolution Order) — порядок разрешения методов: последовательность классов для поиска атрибута. super() продолжает поиск после класса, в котором записан вызов. В цепочке из двух классов дальше находится базовый класс.

Список начинается с B, затем содержит A и завершает поиск базовым object. Метод mro() показывает порядок для этого класса.

Особенно полезен этот порядок при нескольких базовых классах.

§6Множественное наследование с общим предком

При множественном наследовании два класса могут иметь общего предка. Алгоритм C3 строит единый MRO: каждый класс появляется один раз. Для последовательного выполнения методы передают управление через super() и согласуют параметры вызова.

Аналогия: маршрут по кабинетам

Посетитель не должен дважды заходить в общую приёмную.

D→B → C→A один раз

Что есть что: кабинеты — классы, приёмная — общий предок, маршрут — порядок поиска методов среди классов.

Прямой вызов A.method(self) обходит этот маршрут.

Печать выполняется до передачи управления: D, затем B, C и A. Внутри B вызов super() продолжил маршрут в C, хотя C не является непосредственным родителем B.

Общий способ вызова также позволяет работать с разными объектами в одном цикле.

§7Полиморфизм работает с общей операцией

Полиморфизм позволяет вызвать один метод у разных объектов. Вызывающему коду не нужна ветка для каждого класса: он использует согласованное имя и параметры метода.

Цикл дважды вызывает label с одинаковой записью. Реализация выбирается по текущему объекту item.

§8Duck typing: использование доступного поведения

Duck typing означает: важен нужный метод, а не общий предок. Если у объекта есть scan(), функция может его использовать. Отсутствующий метод даст AttributeError во время выполнения.

Аналогия: турникет

Турникет считывает данные карты через совместимый интерфейс.

функция→scan()→результат

Что есть что: турникет — функция, карта — объект, считывание — метод.

Это не проверка типа, а договор поведения.

Функция admit обращается к scan у переданного ticket. Объект QRCode поддерживает этот метод и возвращает текст для печати.

Выбор между наследованием и хранением ссылки зависит от смысла связи объектов.

§9is-a и has-a выбирают структуру

Order сохраняет переданный адрес в self.address. Выражение address.city последовательно читает две связи и получает «Казань».

Для связи целого с частью нужно уточнить ответственность за часть.

§10Композиция создаёт части

В композиции целое создаёт объект-часть и отвечает за его роль. Это удобнее наследования, когда поведение надо заменять или собирать из деталей. Но Python не удаляет части по правилу композиции автоматически: время жизни определяют ссылки и правила программы.

Аналогия: чек в заказе

Заказ создаёт свой чек, а не является чеком.

Order→Receipt→номер

Что есть что: заказ — целое, чек — часть, создание внутри — композиция.

Если нужно удалить данные чека в хранилище, это пишут отдельным действием.

Каждый Order() создаёт Receipt() внутри своего инициализатора. Поле receipt указывает на полученную часть; у неё читается number.

Часть может быть создана снаружи и передана уже существующей.

§13Иногда функция лучше класса

Имена внутренних атрибутов обозначают границу публичного интерфейса.

§15Имена _name и __name

Служебную папку в кабинете помечают, чтобы посетители обращались к сотруднику. Метка задаёт порядок работы; физически закрыть папку она не может. В Python ведущие подчёркивания тоже описывают назначение имени.

_name — соглашение о внутреннем атрибуте. Имя __name без двух подчёркиваний в конце преобразуется с учётом имени класса. Это называют name mangling. Приём уменьшает случайные совпадения имён при наследовании и не ограничивает доступ извне.

В теле Base имя преобразовано в _Base__value, в теле Child — в _Child__value. Получились разные поля. Прямое чтение этих имён снаружи успешно, поэтому хранить секреты таким способом нельзя. Имена вроде __init__ с подчёркиваниями с обоих краёв так не преобразуются.

Записано в классеИмя у экземпляраЗначение
Base: __value_Base__value10
Child: __value_Child__value20

Таблица показывает два независимых поля из одного прогона. Имя преобразуется при обработке тела класса; класс-потомок не затирает внутреннее поле предка.

Доступ к полю можно дополнить проверкой через свойство.

§16Свойство property, геттер и сеттер

Геттер, или аксессор, читает значение. Сеттер, или мутатор, изменяет его. property позволяет обращаться как к атрибуту, но выполнять проверку. Не нужны геттеры для каждого простого поля: свойство оправдано вычислением, проверкой или скрытием хранения.

Аналогия: окно выдачи

Посетитель видит одно окно, а сотрудник за ним проверяет заявку.

price = 120→setter→_price

Что есть что: окно — property, сотрудник — сеттер, архив — внутренний атрибут.

Внешний синтаксис остаётся простым.

Проверим отказ записи отдельно: отрицательная цена не должна заменить прежнее значение.

Сеттер вызван присваиванием. Проверка завершилась исключением до записи в _price, поэтому геттер вернул прежние 120.

Общие требования к набору методов можно выразить базовым классом.

§17ABC задаёт обязательный каркас

Абстрактный базовый класс наследует ABC. Пока в классе остаются абстрактные методы, создать его экземпляр нельзя. Подкласс реализует необходимые методы и становится конкретным. Однако декоратор не проверяет совместимость сигнатуры переопределения: он проверяет наличие реализации, а не её параметры.

Report.show() вызывает self.text(). Реализация найдена в SalesReport и возвращает «Продажи: 12». Метод show выводит результат.

§18Интерфейс и сигнатура — это договор

Интерфейс — набор ожидаемых операций. Сигнатура описывает параметры вызова, их значения по умолчанию и аннотации, включая тип результата. Аннотация типа полезна читателю и инструментам, но сама по себе не запускает проверку во время работы Python.

notify вызывает send с одним текстовым аргументом. Метод EmailSender возвращает строку с префиксом email; результат передаётся print.

Структурный интерфейс можно записать через typing.Protocol.

§19Protocol описывает структуру для mypy

typing.Protocol задаёт структурный интерфейс. Класс не обязан наследоваться от него: статический анализатор проверит наличие нужного метода и его сигнатуру. Это отличается от duck typing: он проявляется при настоящем вызове в runtime, Protocol нужен прежде всего для статической проверки.

Аналогия: чертёж разъёма

Чертёж показывает контакты, но не проверяет устройство сам.

Protocol→mypy→runtime

Что есть что: чертёж — Protocol, инспектор — mypy, соединение — запуск.

Аннотации не становятся проверками Python во время выполнения.

Многоточие в Protocol обозначает описание метода без реализации. Printer предоставляет метод с той же сигнатурой. При запуске first вызывает его и печатает «страница 1».

Небольшую готовую реализацию дополнительного поведения можно вынести в примесь.

§20Миксин добавляет одну способность

Миксин — небольшой класс с узкой дополнительной возможностью. Его обычно не создают отдельно. Полезно ограничить его одной возможностью и явно указать, какие атрибуты ему нужны. При множественном наследовании следите за MRO и избегайте одинаковых имён методов.

DictMixin ожидает у экземпляра атрибут name. Инициализатор Product создаёт этот атрибут, поэтому as_dict может вернуть словарь с товаром.

§21Абстракция: действия, нужные вызывающему коду

Для оплаты покупки достаточно суммы и подтверждения результата. Устройство кассового аппарата покупателю для этого не требуется. Так же код отчёта может запрашивать итог, не обращаясь ко всем промежуточным данным.

Абстракция — выбор существенных свойств и операций для решаемой задачи. Она определяет, что доступно пользователю объекта. Инкапсуляция помогает поддерживать выбранные правила внутри реализации. Абстракция возможна и без ABC.

Функция receipt использует только total(). Она не перебирает внутренний список и не повторяет расчёт. Реализация корзины может измениться при сохранении результата и интерфейса total.

§22Стиль, ошибки и итог

PEP 8 — рекомендации по оформлению кода Python. Классы именуют в стиле CapWords. Функции и методы — в стиле snake_case. Для отступа используют четыре пробела. flake8 ищет частые ошибки и нарушения стиля. black форматирует код, isort сортирует импорты. pylint анализирует качество кода. mypy проверяет совместимость типов по аннотациям. bandit ищет потенциально опасные конструкции. Анализаторы проверяют лишь часть свойств программы. Работу предметных правил подтверждают тестами.

Полиморфизм позволяет одинаково вызывать разные реализации. ABC и Protocol выражают требования к классам и методам. Инкапсуляция состояния объекта, а простую задачу часто решает функция. Стиль и анализаторы помогают поддерживать такой код.
