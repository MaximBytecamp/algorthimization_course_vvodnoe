§1Зачем программе объекты

Парадигма — способ организовать программу. При процедурном подходе мы часто передаём данные отдельным функциям. Объектно-ориентированный подход объединяет состояние и действия в объектах. Объект счёта хранит баланс и умеет пополнять его.

ООП не заменяет функции и не требует изображать весь мир классами. Оно помогает, когда у нескольких сущностей одинаковые правила работы, но собственные данные.

class начинает описание класса. Вызов Account(100) создаёт счёт, а deposit(50) обращается к действию этого счёта. __init__ задаёт начальные значения полей. Параметр self ссылается на экземпляр, данные которого меняет метод.

По-простому: банковская карточка

Разделим ситуацию на три части, чтобы увидеть роль каждого участника.

СчётБаланс 100
→
ПополнениеДобавить 50
→
Тот же счётБаланс 150

Что есть что. Счёт — объект account, баланс — его состояние, пополнение — метод deposit. Стрелки показывают изменение одного счёта, а не создание нового.

Отдельные объекты могут изменяться независимо друг от друга.

§2Объект: состояние, поведение и отдельность

Состояние — текущие данные объекта. Поведение — доступные действия. Кроме значений важна отдельность: два объекта могут хранить одинаковые данные и всё равно оставаться разными объектами.

Включение первой лампы не изменило вторую. Оператор is проверяет, ссылаются ли имена на один объект, а не сравнивает поля. В Python числа, строки, списки и функции являются объектами. Пользовательские классы добавляют новые типы объектов.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера
Действие или состояниеРезультат
first.turn_on()first.is_on → True
Вторая лампаsecond.is_on → False
Сравнение ссылокfirst is second → False

В последней строке показан результат: first is second → False. Он соответствует выводу программы выше.

Для группы объектов с одинаковыми действиями нужно общее описание — класс.

§3Класс и экземпляр

Класс описывает общий тип объектов. Экземпляр — конкретный объект этого класса. После имени класса пишут двоеточие, а тело выделяют отступом в четыре пробела. pass — пустая инструкция: она позволяет пока оставить тело без действий.

Круглые скобки вызывают класс. Точка обращается к атрибуту — именованному значению, связанному с объектом. Функция type сообщает тип, а isinstance проверяет принадлежность экземпляра классу с учётом наследования. Ни один из этих вызовов не копирует студента.

По-простому: бланк и заполненные карточки

Разделим ситуацию на три части, чтобы увидеть роль каждого участника.

БланкStudent
→
Карточка 1name = Анна
→
Карточка 2name = Борис

Что есть что. Бланк — класс, две заполненные карточки — экземпляры. Обе сделаны по одному описанию, но хранят разные имена.

Начальные значения можно задавать сразу при создании экземпляра.

§4__init__: начальная настройка экземпляра

Инициализатор __init__ вызывается при обычном создании экземпляра после того, как объект уже выделен. Он задаёт начальное состояние. Сам объект обычно создаёт специальный метод __new__. Затем запускается инициализация.

Аргументы вызова Book(...) попадают в инициализатор после self. Параметр pages имеет значение по умолчанию, как у обычной функции. Запись self.title = title сохраняет переданное значение в объекте. Инициализатор не возвращает экземпляр: его результатом должен быть None; обычно return вообще не пишут.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера
Действие или состояниеРезультат
Book("Python", 240)title → Python, pages → 240
Book("SQL")title → SQL, pages → 100

В последней строке показан результат: title → SQL, pages → 100. Он соответствует выводу программы выше.

Первый параметр инициализатора связывает его с полученным экземпляром.

§5self: кому принадлежит действие

self — принятое имя первого параметра метода экземпляра. Это ссылка на получателя вызова. Имя не является ключевым словом, но менять его без причины не стоит: все разработчики Python ожидают именно такую запись.

При чтении anna.greet Python связывает функцию из класса с получателем anna. Поэтому в первом вызове объект передаётся автоматически, а во втором — явно. Если забыть параметр self в объявлении, число переданных аргументов не совпадёт с объявленным.

По-простому: одна инструкция для разных работников

Разделим ситуацию на три части, чтобы увидеть роль каждого участника.

Вызовanna.greet()
→
Получательself ссылается на anna
→
Чтениеself.name → Анна

Что есть что. Инструкция — тело метода, получатель — конкретный экземпляр. self не обозначает весь класс и не является копией объекта.

Такая передача получателя действует и для остальных методов экземпляра.

§6Метод меняет состояние или возвращает результат

Метод объявляют через def внутри класса. Он может изменить состояние, вернуть вычисленное значение или выполнить оба действия. Полезно различать эти роли: чтение цены не должно неожиданно менять её.

total только вычисляет результат, а change_price записывает новое состояние. Выражение product.total без скобок получает метод, но не выполняет его. Скобки с аргументами запускают действие. Один метод может вызывать другой через self.имя_метода(...).

Действия и результаты примера

price = 80, total(3)80 × 3 → 240
change_price(90)price → 90
total(3)90 × 3 → 270

В последней строке показан результат: 90 × 3 → 270. Он соответствует выводу программы выше.

Значения, которые должны сохраниться после вызова, записывают в атрибуты.

§7Атрибуты экземпляра и локальные переменные

Имя внутри метода без self обычно является локальной переменной. Оно нужно лишь для вычисления. Атрибут self.name остаётся доступным после завершения вызова, пока жив объект и атрибут не удалён.

Локальная переменная cleaned не стала полем. Сохранилось значение, записанное через self.name. Функция hasattr попыталась прочитать атрибут cleaned и вернула False после AttributeError.

Кроме личных атрибутов у экземпляров могут быть общие настройки класса.

§8Атрибут класса и затенение

Значение в теле класса хранится у самого класса. Экземпляр может прочитать его, если собственное значение с таким именем не найдено. Присваивание через экземпляр обычно создаёт его собственный атрибут и затеняет общий.

У первого студента появилось личное school, поэтому изменение класса его не затронуло. Второй продолжает читать общее значение. Это описание обычного поиска: свойства и другие дескрипторы могут менять приоритет. Их устройство разберём позднее.

По-простому: общий стенд и личная записка

Разделим ситуацию на три части, чтобы увидеть роль каждого участника.

Стенд группыStudent.school
→
Личная запискаfirst.school
→
Чтениеличная запись важнее общей

Что есть что. Стенд — атрибут класса; записка — собственный атрибут экземпляра. Изменение стенда видно только тем, кто ещё читает общее значение.

У общего изменяемого значения есть дополнительная особенность: его содержимое разделяют все получатели.

§9Ловушка общего изменяемого списка

Изменение списка и присваивание нового атрибута — разные действия. Если список хранится у класса, append меняет этот единственный общий список. Для личной коллекции создавайте новый список при инициализации.

В первом случае поиск нашёл список класса, и append изменил его. Во втором [] выполняется заново при каждом вызове инициализатора: получились два независимых списка. По той же причине изменяемые значения по умолчанию у параметров требуют осторожности.

По-простому: общая тетрадь против личных

Разделим ситуацию на три части, чтобы увидеть роль каждого участника.

Одна тетрадьBadTeam.members
→
Запись Аннывидна всем
→
Личные тетрадиself.members = []

Что есть что. Тетрадь — список. Для общей коллекции хранение у класса уместно; ошибка возникает, когда общий список приняли за личный.

Собственный тип можно также подключить к встроенным операциям Python.

§10Магические методы и представление объекта

Методы с двумя подчёркиваниями по краям имени подключают класс к встроенным операциям Python. Их называют специальными, или магическими. Названия не придумывают произвольно: интерпретатор ожидает конкретные имена.

print использует строковое представление, а список показывает элементы через отладочное. !r в f-строке выбирает repr, чтобы строковый заголовок был показан с кавычками. Оба метода возвращают строку, а не печатают её. str используется для пользовательского представления, repr — для отладки и представления элементов коллекции.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера
Действие или состояниеРезультат
print(item)__str__ → Заявка: Принтер
print([item])__repr__ → [Ticket('Принтер')]

В последней строке показан результат: __repr__ → [Ticket('Принтер')]. Он соответствует выводу программы выше.

Каждая встроенная операция поддерживается определённой договорённостью о методах.

§11Протокол: договорённость об операции

Протокол — набор правил, позволяющий объекту участвовать в операции. Для длины нужен __len__, для перебора — подходящее поведение итерации. Наследование от специального родителя для этого не обязательно.

len(shelf) получает количество, а list(shelf) запрашивает перебор элементов. __iter__ возвращает итератор, поэтому здесь используется iter для внутреннего списка. Специальные методы обычно определяют в классе; встроенные операции ищут их через тип объекта. Такой протокол определяется поведением объекта при выполнении операции.

По-простому: подходящий разъём

Разделим ситуацию на три части, чтобы увидеть роль каждого участника.

Запросlen(shelf)
→
РазъёмShelf.__len__
→
Ответ2

Что есть что. Встроенная операция — устройство, специальный метод — совместимый разъём. Одинаковая договорённость позволяет len работать со списком, строкой и нашим классом.

Такие договорённости задают и смысл операторов для нового типа.

§12Перегрузка оператора и NotImplemented

Перегрузка позволяет задать смысл операции для своего типа. Например, складывать две денежные суммы. Если тип второго операнда не поддерживается, верните NotImplemented: это сигнал интерпретатору, а не исключение.

Для пары сумм создан новый объект, исходные суммы не менялись. Для строки Python может попробовать отражённую операцию правого типа; когда совместимой реализации нет, возникает TypeError. NotImplementedError — другое понятие: это класс исключения. Перегружать операторы стоит только при понятном пользователю смысле.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера

Money(20) + "30"NotImplemented → TypeError

В последней строке показан результат: NotImplemented → TypeError. Он соответствует выводу программы выше.

Несколько специальных методов позволяют описать контейнер с элементами.

§13Контейнер, коллекция и структура данных

В обычной речи контейнером называют объект, который хранит другие объекты, а коллекцией — группу элементов. Структура данных определяет организацию хранения и доступ. В стандартном модуле collections.abc термины точнее: Container описывает проверку вхождения, а Collection объединяет её с длиной и перебором.

in использует __contains__, длина — __len__, а квадратные скобки — __getitem__. Наш объект передаёт действия внутреннему списку. Наличие __getitem__ не делает любой объект полноценным списком: для добавления, удаления и других операций нужны собственные договорённости.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера

"ключ" in bag__contains__ → True
len(bag)__len__ → 2
bag[1]__getitem__ → карта

В последней строке показан результат: __getitem__ → карта. Он соответствует выводу программы выше.

Кроме доступа к элементам полезно управлять атрибутами по их именам.

§14Атрибут по строковому имени

Когда имя поля получено из настройки, вместо записи через точку используют функции getattr, setattr и delattr. Они работают с атрибутами, а не со словарными ключами.

Первый вызов записал то же, что settings.theme = "dark". Третий удалил атрибут. Последний вернул запасное значение, потому что поле больше не найдено. Без третьего аргумента отсутствие поля привело бы к AttributeError. Эти функции могут запускать свойства и дескрипторы, то есть это не гарантированно «пассивное» чтение.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера
Действие или состояниеРезультат
setattr(settings, "theme", "dark")theme → dark
delattr(settings, "theme")Атрибут удалён
getattr с запасным значениемlight

В последней строке показан результат: light. Он соответствует выводу программы выше.

Проверка наличия атрибута также выполняется через попытку чтения.

§15hasattr: проверка через попытку чтения

hasattr(obj, name) пытается получить атрибут. Если чтение заканчивается AttributeError, результат — False. Другие исключения не скрываются. Это важно для свойств, которые исполняют код при чтении.

Декоратор @property делает метод вычисляемым атрибутом: чтение user.broken вызывает тело метода без круглых скобок. В этом вызове проверка наличия тоже запустила вычисление и не поглотила его ошибку. Это не проверка одной записи в словаре.

Сопоставим действия с результатами этого запуска. Таблица показывает, на каком шаге получается каждое значение.

Действия и результаты примера
Действие или состояниеРезультат
hasattr(user, "name")Чтение успешно → True
hasattr(user, "email")AttributeError → False
hasattr(user, "broken")RuntimeError → передаётся вызывающему коду

В последней строке показан результат: RuntimeError → передаётся вызывающему коду. Он соответствует выводу программы выше.

Управление ресурсами требует явных действий с понятным временем выполнения.

§16__del__ и управление ресурсами

__del__ — финализатор: метод, который может быть вызван при завершении жизни объекта. Время его вызова не гарантировано; при завершении интерпретатора вызова может не быть. Инструкция del удаляет ссылку, а не обязательно сам объект.

Вторая ссылка сохранила объект. Поэтому критическое освобождение ресурсов не стоит поручать __del__. Для настоящих файлов и соединений используйте контекстный менеджер with, если он поддерживается, или явное закрытие в try/finally. Наш пример моделирует закрытие печатью: реального сетевого соединения здесь нет.

Отдельные методы могут работать с самим классом.

§17cls и classmethod: альтернативное создание

Метод с @classmethod получает класс первым аргументом. Первый параметр принято называть cls. Это удобно для альтернативного способа создать объект: например, разобрать строку вместо передачи готового числа.

SchoolYear — подкласс: он получает поведение Year. При вызове фабрики через него cls равно именно SchoolYear. Поэтому cls(...) создаёт объект нужного типа. Жёсткая запись Year(...) потеряла бы это свойство. В данном примере подкласс использует инициализацию и фабрику базового класса.

По-простому: один рецепт для разных цехов

Для действия без данных экземпляра и класса подходит статический метод или функция.

§18staticmethod и обычная функция

При вызове статического метода все аргументы передаются явно. Это обычная функция, размещённая в пространстве имён класса. Размещение оправдано, если операция тесно относится к этому типу; для общей утилиты достаточно функции уровня модуля.

У valid_age нет доступа к конкретному пользователю, если его явно не передать. normalize_name вообще не требует класса. Выбор между методом экземпляра, методом класса и статическим методом определяется тем, какие данные нужны действию, а не желанием поместить весь код внутрь class.

§19Три вида методов рядом

Сравним получателей без дополнительных сущностей. Обычный метод работает с конкретным значением, метод класса — с настройкой самого класса, статический — только со своими аргументами.

show получает self, unit_name — cls, а double не получает скрытого первого аргумента. Связь с классом у последней операции условная: в реальном проекте её вполне можно оставить функцией. Такую операцию можно использовать независимо от класса.

Частые ошибки

  • Хранить личный изменяемый список у класса: создавайте его в __init__.
  • Забывать self или записывать поле в локальную переменную вместо атрибута.
  • Печатать внутри __str__ вместо возврата строки.
  • Возвращать строку «NotImplemented» или бросать NotImplementedError вместо сигнала NotImplemented.
  • Ожидать гарантированного закрытия ресурсов от __del__.

Глоссарий

Парадигма
Способ организации программы. данные + отдельные функции → данные и методы объекта — смена подхода, а не обязательная замена всех функций.
Класс
Описание нового типа объектов. class Lamp → Lamp() → экземпляр.
Экземпляр, объект
Конкретная сущность в программе. first = Lamp(), second = Lamp() → два разных объекта.
Состояние и поведение
Текущие данные и действия. balance: 100 → deposit(50) → balance: 150.
Атрибут
Именованное значение у объекта или класса. user.name → 'Анна'.
Локальная переменная
Имя внутри вызова функции. cleaned → self.name: только второе сохраняется в объекте.
Метод и связывание
Функция класса при обращении через получателя. anna.greet() → Person.greet(anna).
Инициализатор
Настройка созданного объекта. Book('Python') → __init__ → self.title.
self и cls
Принятые имена ссылок на экземпляр и класс. self → year; cls → SchoolYear.
Затенение
Личное значение закрывает общее при обычном поиске. first.school → собственное; second.school → класс.
Специальный, магический метод
Метод с определённым Python именем для встроенной операции. len(obj) → __len__.
Протокол
Договорённость о поддерживаемом поведении. __iter__ → for и list.
Перегрузка оператора
Определение операции для типа. Money(20) + Money(30) → __add__ → Money(50).
Контейнер / коллекция
Хранение объектов и группа операций над ними. Bag → in, len, перебор.
Структура данных
Организация хранения и доступа. список → позиция → элемент.
Финализатор
Действие при завершении жизни объекта с ограниченными гарантиями. del имя → исчезла ссылка ≠ гарантированно выполнен __del__.
Фабрика
Действие, создающее объект. from_text('2026') → SchoolYear(2026).
Статический метод / утилитарная функция
Функции без автоматической передачи получателя. User.valid_age(20) размещён в классе; normalize_name('анна') — на уровне модуля.
