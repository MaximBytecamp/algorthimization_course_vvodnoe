§1Тип значения

Тип — вид значения, от которого зависит, что с ним можно делать. У числа 5 тип int: его можно складывать и делить. У строки "5" тип str: её можно разрезать и склеить с другой строкой, а сложить с числом нельзя. Узнать тип любого значения можно функцией type: type(5) вернёт <class 'int'>, type("5") — <class 'str'>.

Python определяет тип значения во время работы программы, в момент, когда значение уже получено. Такой подход называют динамической типизацией. Объявлять заранее, какие значения принимает функция, не требуется: в def calculate_average(grades) можно передать список чисел, список строк или одно число. Если значение не подходит, ошибка возникнет только при выполнении той строки, которая с ним не справится.

Пока функция и её вызов лежат в одном файле, это не мешает: тело функции видно рядом. Когда функций десятки и они разнесены по пакетам, как в проекте из темы 02, при каждом вызове приходится открывать чужой модуль и выяснять одно и то же: что передавать и что вернётся. Аннотации типов записывают ответ на этот вопрос прямо в первой строке функции.

§2Проект темы

Трудность из §1 видна только в проекте, где функций много и они лежат в разных модулях. Поэтому все примеры темы взяты из одного такого проекта — «Отчёт кафе». Он читает файл смены с заказами, считает выручку по каждому официанту и печатает отчёт в консоль. Десять модулей разложены по пакетам: domain — заказ и смена, services — чтение файла и расчёты, utils — имена, суммы и дата, ui — печать. Суммы в проекте хранятся в копейках, целыми числами: 125000 означает 1 250,00 ₽.

Проект выдаётся в трёх архивах с одним и тем же кодом на разных этапах темы. Первый — код без аннотаций: на нём видно, каких сведений не хватает при вызове функций. Второй — тот же код с аннотациями. В этой главе оба архива открыты рядом, и каждое свойство аннотаций показано сравнением: что видно в первом архиве и что — во втором. Третий архив, с описаниями функций, нужен во второй части темы.

Откройте в обоих архивах файл app/services/calculator.py и сравните первую строку функции calculate_average:

→
С аннотациями

def calculate_average(grades: list[int]) -> float:

Параметр — список целых чисел, результат — дробное число. Тело для этого читать не нужно.

Добавленные во втором архиве : list[int] и -> float — это аннотации. Аннотация типа — запись в коде, которая указывает, значения какого типа ожидаются в параметре, в переменной или в результате функции.

У calculate_average аннотации стоят в двух местах — у параметра и у результата. Всего таких мест три: третье — переменная. Все три показаны на схеме. Для неё взята функция format_title из app/utils/formatter.py, потому что у неё есть и обычный параметр, и параметр со значением по умолчанию, и результат; пример переменной — строка из функции revenue_by_waiter.

В таблице те же три места, что на схеме, и два частных случая: -> None у функции, которая ничего не возвращает, и аннотация атрибута объекта self.orders — она пишется так же, как у переменной.

Кроме места, у аннотаций есть правила оформления; они соблюдаются во всём проекте. После двоеточия ставят один пробел, перед ним — ни одного: text: str. Вокруг стрелки — по пробелу: ) -> str:. У параметра со значением по умолчанию вокруг знака равенства ставят пробелы, если есть аннотация (width: int = 40), и не ставят, если её нет (width=40).

В примерах уже встречались составные записи: list[int] — «список, в котором лежат целые числа», dict[str, int] — «словарь со строковыми ключами и целыми значениями». В квадратных скобках после имени коллекции указывают, что в ней хранится. Для чтения подписей в этой главе этого достаточно; все такие записи разобраны в главе 4.2.

§4Как читать подпись функции

Запись аннотаций разобрана. Теперь можно вернуться к трудности из §1 — что передать функции и что она вернёт — и посмотреть, как подписи с аннотациями отвечают на этот вопрос для всего проекта.

Подпись функции — первая строка её объявления: имя, параметры и результат. С аннотациями подпись отвечает на три вопроса: какие значения передать, в каком порядке и что вернётся. §5Что Python делает с аннотацией

Подписи из §4 сообщают, что функция ожидает. Следующий вопрос — следит ли Python за этими ожиданиями, когда программа работает. Ответ дают опыты в интерактивном Python. Ошибка внутри функцииВызов начал выполняться, и ошибка возникла в строке с sum: сложить число со строкой нельзя. Сообщение говорит о сложении числа со строкой. О неверном аргументе в нём ничего нет, и строка вызывающего кода, где передано не то, из него не видна.

Неверный результат без ошибкиДля строк оператор + означает склейку, поэтому вместо суммы 350 получилась строка "150200". Программа продолжит работу с неверным значением. Такой случай реален: числа из CSV-файла читаются строками, и в load_orders сумму переводят в число вызовом int(row["kopeks"]).

Из четырёх вызовов следует, что аннотация описывает ожидание, но при запуске его не обеспечивает. Неверный тип либо проходит незамеченным, либо приводит к ошибке внутри функции, далеко от места вызова. Сверку вызовов с аннотациями до запуска выполняют отдельные программы — Pylance в редакторе и mypy в терминале. Работе с ними посвящена глава 4.3.

Ассоциация: разметка на парковке

В жизни

Линии на асфальте показывают, где место для легковой машины, а где для грузовика. Сами по себе они не мешают грузовику встать на легковое место. Нарушение замечает человек, который обходит парковку и сверяет машины с разметкой.

В коде

Аннотация — разметка: она показывает, какое значение ожидается. При запуске Python её не проверяет. Сверку выполняет программа проверки типов, по тексту кода.

Где не совпадаетНа парковке нарушение видно, когда машина уже стоит. Программа проверки находит неверный вызов в тексте, до того как программа запущена.

§7Автодополнение

Подсказка показывает типы, когда код уже написан. Те же типы редактор использует, пока код набирается, — в автодополнении.

Автодополнение — список, который редактор показывает при наборе: имена переменных, функций, атрибутов и методов, подходящих в этом месте. После точки в нём перечислены атрибуты значения слева от точки. Составить такой список редактор может, только если знает тип значения. Опыт снова в двух архивах: откройте app/services/orders.py, поставьте курсор в конец тела функции sort_orders_in_place — последней в файле, — нажмите Enter и наберите orders[0].: первый элемент списка заказов и точку. Если список не появился сам, вызовите его клавишами Ctrl + Пробел. На macOS это сочетание часто занято переключением раскладки; тогда список вызывают командой Trigger Suggest из палитры команд (Cmd + Shift + P). После опыта отмените набранное: Ctrl + Z.

Что аннотации дают при работе с кодом: итог §4–§7

  • Вызов без чтения тела функции. Подсказка показывает, какие значения передавать и что вернётся.
  • Имена атрибутов из списка. Автодополнение предлагает поля объекта, и order.kopeks выбирается из списка; набирать имя по памяти не нужно.
  • Проверка до запуска. Программы проверки типов сверяют каждый вызов с аннотациями и показывают строку, где передано не то.

Первые два пункта работают сразу, их показали кадры §6 и §7. Третий требует отдельных программ: они разобраны в главе 4.3. Перед этим, в главе 4.2, собраны все виды типов, которые пишут в аннотациях, — от int до «значение или None».

§8Частые вопросы

Обычно думаютС аннотацией Python не даст передать значение другого типа.
На самом делеПри запуске аннотации не проверяются. Вызов add_kopeks("150", "200") выполняется и возвращает "150200", вызов со строками в calculate_average завершается ошибкой внутри функции. Несовпадения находит программа проверки типов.
Обычно думаютАннотация превращает значение в указанный тип.
На самом делеАннотация ничего не превращает. Для перевода строки в число вызывают int(...), как в функции load_orders при чтении файла: kopeks=int(row["kopeks"]).
Обычно думаютЕсли тип понятен из имени, аннотация не нужна.
На самом делеПо имени orders не видно, список это или словарь и что в нём лежит. Редактор и программа проверки тип по имени не определяют: в первом архиве у orders тип Any, и автодополнение ничего не предлагает.

§9Проверьте себя

Где пишется аннотация у параметра, у результата и у переменной?

У параметра — после имени через двоеточие: text: str. У результата — после закрывающей скобки через стрелку: -> str. У переменной — между именем и знаком равенства: totals: dict[str, int] = {}.

Прочитайте подпись: def is_big(kopeks: int, limit: int = 100_000) -> bool.

Функция принимает целое число копеек и, по желанию, порог — тоже целое число, по умолчанию 100_000. Возвращает True или False. Подчёркивание внутри числа 100_000 Python пропускает, оно только разделяет разряды.

Прочитайте подпись: def save_report(path: Path, lines: list[str]) -> int.

Функция принимает путь — объект Path — и список строк. Возвращает целое число. Что это за число — количество записанных строк, — из подписи не видно: такие сведения пишут в описании функции.

Что вернёт calculate_average([5.5, 4.0]), если в аннотации записано list[int]?

4.75. Python при запуске аннотации не проверяет, а для дробных чисел сложение и деление определены.

Почему у self в методах класса нет аннотации?

self — сам объект, и его тип известен из класса, в котором записан метод. Редактор и программа проверки выводят его сами.

Почему в первом архиве после orders[0]. редактор ничего не предлагает?

У параметра orders нет аннотации, и тип его элементов неизвестен. Перечень атрибутов редактор берёт из типа значения, а типа нет.

Итог главы

Аннотация типа записывает в подпись функции, какие значения она принимает и что возвращает. По подписям с аннотациями можно составить вызов, не открывая модуль. При запуске Python аннотации не проверяет: неверный тип проходит незамеченным или приводит к ошибке внутри функции. Редактор использует аннотации в подсказке и в автодополнении, а сверку вызовов до запуска выполняют программы проверки типов из главы 4.3.

Откуда взяты факты
  1. Синтаксис аннотаций функций — PEP 3107, переменных — PEP 526, оформление — PEP 8, Function Annotations.
  2. Назначение аннотаций и то, что интерпретатор их не проверяет, — PEP 484, Type Hints.
  3. Атрибут __annotations__ — документация Python, Annotations Best Practices.
