# Тема 04 · Аннотации типов и документация кода

Формат: одна книга, одиннадцать последовательных глав в двух частях. Вход — `index.html` из меню
дисциплины. Главы — самостоятельные статические HTML, `styles.css` и `book.js`
общие. Сборка и серверная часть не требуются.

Вёрстка взята из справочника по Git и GitHub (`~/git_github_makarov`): корешок
и лист, паспорт главы, блок «В этой главе», врезки, «Проверьте себя», шпаргалка,
итог, колофон. Палитра перекрашена в синюю, как у дисциплины; номера глав и
параграфов набраны моноширинным шрифтом, потому что в Pixelify Sans цифры на
мелком кегле читаются неверно.

## Место в курсе

Идёт после темы 02 (структура проекта, модули, пакеты, окружение) и практикума
темы 03 (сборка проекта, разделение на модули). Отвечает на следующий вопрос
по тому же коду: как понять назначение функции из соседнего модуля, не читая её
тело. Sphinx в эту тему не входит — он следующая тема, и здесь пишется то, из
чего он собирает сайт.

## Учебная последовательность

Тема из двух частей. Первая — аннотации типов (главы 4.1–4.5), вторая —
документация (главы 4.6–4.11). Порядок выбран по зависимости: в докстринге
не повторяют типы, поэтому сначала типы оказываются в подписи.

**Часть 1. Аннотации типов**

Роли глав разведены 09.10.2026: в 4.2 — только запись типов (как читается,
какие значения подходят), без вывода mypy; в 4.4 — ошибки по каждому типу на
полных примерах `proba.py` с ответом mypy. Запись в 4.4 не повторяется:
каждый раздел начинается ссылкой на параграф 4.2. Номера §1–5 в 4.2 менять
нельзя: на них ссылается практикум `05-praktikum-podpisi`.

1. **4.1 Аннотация типа.** Тип и динамическая типизация; проект темы, три
   архива и подготовка первых двух; запись у параметра, результата,
   переменной, атрибута (схема подписи, правила пробелов); таблица из
   одиннадцати подписей проекта «что передают — что получают»; методы класса
   и `self`; `__annotations__`; блок-разбор «целые / дробные / строки /
   строки без ошибки» (`add_kopeks("150", "200")` → `"150200"`); кадры
   подсказки и автодополнения без аннотаций и с ними.
2. **4.2 Типы в аннотациях.** Только запись: простые типы, общая таблица
   коллекций и таблица «подходит / не подходит», классы, `Order | None` и
   необязательный параметр, объединения, `Iterator`, `Callable`, псевдонимы,
   `Any`, поля dataclass. Вывода mypy и `reveal_type` нет. Примеры —
   фрагменты, поэтому в `verify_examples.py` глава не входит.
3. **4.3 Проверка типов: Pylance и mypy по шагам.** Пошаговая инструкция
   с кадрами (блок `.walk`): Pylance — расширение, интерпретатор, режим `off`,
   включение `basic` через окно настроек на вкладке Workspace, подчёркивания,
   сообщение по частям, панель Problems, исправление; mypy — версия, проверка
   файла, переход по ссылке, повтор, весь пакет. §4 — четыре режима на одном
   файле: шесть ошибок разного рода, таблица-лестница «какой режим что
   находит и что будет при запуске», вкладки с кадрами off · 1, basic · 2,
   standard · 3 (possibly unbound), strict · 9; на первом архиве strict даёт
   86 замечаний, basic и standard — ноль; почему курс выбрал basic. Разбор строки вывода, таблица
   кодов mypy с правилами Pylance, одна ошибка в двух программах,
   `disallow_untyped_defs` и 17 ошибок первого архива, наведение и
   `reveal_type`, чего проверка не находит, `# type: ignore[код]`.
4. **4.4 Ошибки типов: примеры с разбором.** Разделы названы по ошибке;
   §15 — сводная таблица десяти кодов mypy со ссылками на разделы. Двадцать примеров `proba.py` с настоящим
   выводом mypy и разбором каждой строки: простые типы и правило «int вместо
   float», `-> None` и пропущенный `return`, списки, словари, кортежи,
   множества и старая запись, классы проекта и стандартной библиотеки, `X | None`
   (вкладки, `dict.get`, необязательный параметр, ранний выход), объединения,
   генераторы и `Callable`, псевдонимы, `Any`, пустые коллекции и поля dataclass.
5. **4.5 Практика: аннотации в проекте.** Первый архив, 17 функций без
   типов; порядок от листьев к корню (схема пакетов); как выбрать тип;
   подсказки типа результата Pylance (inlay hints) по шагам с кадром — вставка
   двойным щелчком, `-> Any` не вставлять; `orders.py` до и после во вкладках;
   трудные места; лента отсчёта mypy `17 → 12 → 8 → 1 → Success`; итог

- рабочий VS Code развёрнут на своём рабочем столе, система возвращается туда
  между запусками, а AX-интерфейс видит окна только текущего рабочего стола.
  Поэтому все кадры серии снимаются одним процессом: `shoot.py series …`;
- перед каждым нажатием и перед каждым снимком проверяется владелец окна под
  точкой, при промахе действие повторяется, а не идёт в чужое окно;
- ⌘W закрывает последнее окно экземпляра съёмки, и он завершается: вкладки
  закрываются только ⌘K ⌘W;
- панель чата открывается заново после каждого открытия файла, а команда
  палитры её переключает. Состояние определяется по кадру (`chat_open`);
- курсор паркуется внутри окна: за его границей остаётся подсказка кнопки;
- после `help()` в терминале остаётся пейджер, поэтому каждая команда идёт
  в свежем терминале;
- генератор докстрингов не срабатывает на вставку кавычек из буфера —
  вызывается командой палитры, курсор при этом на пустой строке тела;
- первый запуск mypy строит кэш и не укладывается в паузу стадии: кэш
  прогревается тем же запуском из обычного терминала перед съёмкой;
- ⌃Пробел на macOS переключает раскладку; список подсказок редактора на
  кадре не удерживается — проверка фокуса перед снимком его закрывает,
  поэтому кадра автодополнения в книге нет.

## Кадры глав 4.1–4.5: фоновая съёмка

Кадры первой части пересняты 01.10.2026 скриптами `shots/shoot_types.py`
(стадии) и `shots/cdp.py` (управление редактором). Отдельный экземпляр VS Code
запускается с портом отладки, а нажатия, движения мыши и снимки идут по
протоколу DevTools — экран пользователя не переключается, ввод в чужие окна
не попадает. Обрезка — `shots/crop_types.py`: из окна 1240 × 780 вырезается
нужная панель, ширина файла не больше 1600.

    python3 shoot_types.py prepare start      # второй архив, редактор с портом 9337
    python3 shoot_types.py ext interpreter off settings json squiggle mypy fixed app reveal hovercall completion
    python3 shoot_types.py prepare bez        # первый архив
    python3 shoot_types.py app hovercall completion inlay
    python3 crop_types.py

Ловушки этого способа:

- из терминала VS Code наследуется `ELECTRON_RUN_AS_NODE=1`, и бинарник Code
  стартует как Node; переменная убирается в `launch()` вместе с `VIRTUAL_ENV`;
- без `Emulation.setFocusEmulationEnabled` редактор не принимает сочетания
  клавиш — окно считает себя неактивным;
- окно с несохранённым файлом не завершается по сигналу (ждёт ответа
  «сохранить?»), и новый запуск открывает второе окно в том же экземпляре;
  `launch()` добивает его `pkill -9`;
- `Enter` в редакторе вводится как текст `\n` (`Input.insertText`), иначе
  строка не переносится; ⌃Пробел для подсказок работает;
- строки терминала рисуются на холсте, в разметке их нет — щелчок по ссылке
  в выводе не снят, шаг описан текстом;
- в профиле съёмки терминал — `bash --norc` с приглашением `\W $`, без имени
  компьютера; авто-активация окружения выключена, команды идут через `.venv/bin/`.

Примеры глав сверяются с запуском: `python3 shots/verify_examples.py` вынимает
из разметки пары «`proba.py` → вывод `mypy proba.py` / `python proba.py`»,
запускает их на втором архиве и сравнивает построчно. На 01.10.2026 — 22
примера, расхождений 0.
