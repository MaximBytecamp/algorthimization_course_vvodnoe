§1Простые типы

Простые типы записываются своими именами — теми же, что используются в коде для преобразований: int(...), str(...).

ТипКакие значенияПример из проекта
intцелые числаkopeks: int — сумма заказа
floatдробные числа-> float у calculate_average
strстрокиname: str у normalize_name
boolTrue и Falseфлаги вида strict: bool = False
Noneотсутствие значения-> None у print_report

Запись -> None означает, что функция ничего не возвращает. Её ставят и у функций, которые только печатают или записывают файл: проверка тогда предупредит, если результат такой функции случайно попытаются использовать.

§2Списки, словари, кортежи, множества

Для коллекции указывают, что в ней лежит. Тип элементов пишется в квадратных скобках после имени коллекции.

ЗаписьЧто означаетГде в проекте
list[int]список целых чисел любой длиныоценки в calculate_average
list[Order]список заказоврезультат load_orders
dict[str, int]словарь: ключ — строка, значение — целоевыручка по официантам
tuple[int, int]ровно два целых числарезультат grade_bounds
tuple[int, ...]сколько угодно целых чиселнеизменяемый набор оценок
set[str]множество строк без повторовимена официантов смены

У кортежа запись зависит от длины. tuple[int, int] — ровно два элемента, и кортеж из трёх проверка отклонит. Многоточие в tuple[int, ...] означает «любое количество элементов этого типа».

Старая запись

from typing import List, Dict
def f(x: List[int]) -> Dict[str, int]:

→
Запись в Python 3.9 и новее

def f(x: list[int]) -> dict[str, int]:

Импорт не нужен: встроенные коллекции принимают тип в скобках.

Запись с заглавной буквы и импортом из typing встречается в старом коде и в старых статьях. В проектах курса используется запись со встроенными именами.

§3Собственные классы

Класс, объявленный в проекте, — тоже тип. Его имя пишется в аннотации так же, как int. Чтобы имя было доступно в файле, класс импортируют.

Path из стандартной библиотеки и Order из проекта записываются одинаково. Когда тип параметра — класс, редактору доступны его поля: после order. в автодополнении появятся waiter и kopeks.

На полях: импорт только ради аннотации

В архиве без аннотаций остались строки вроде from datetime import date в app/domain/shift.py, хотя date в коде не используется. Импорт стоял там ради аннотации day: date. Когда аннотации возвращаются на место, эти импорты снова нужны.

§4Значение или None

Часто функция возвращает значение, а если его нет — None. Например, поиск заказа по имени официанта: заказ найден или не найден. Такой результат записывают через вертикальную черту: Order | None — «заказ или None».

С аннотацией Order | None проверка не пропустит вызывающий код, который учитывает только один исход. Разница между вызовом с проверкой на None и без неё — в блоке ниже; выводы получены запуском.

В старом коде тот же тип записывали как Optional[Order] с импортом из typing. Запись Order | None доступна с Python 3.10 и означает то же самое.

§5Несколько возможных типов

Та же вертикальная черта перечисляет любые варианты: int | str — «целое число или строка». Такой тип называют объединением. Передать можно значение любого из перечисленных типов, а внутри функции обращаться к нему как к строке или как к числу можно только после проверки, какой вариант пришёл.

Вывод показывает три вещи. Внутри условия isinstance(value, str) тип сужен до str (строка 3), после условия — до int (строка 5). Вызовы с числом и строкой прошли, а с дробным числом — нет: float в перечне вариантов не значится. Объединения используют там, где данные приходят в разном виде; когда вариант один, объединение только усложняет вызов.

§6Итераторы и функции

Генератор возвращает итератор — объект, из которого значения берут по одному; список целиком при этом не создаётся. Его тип записывают как Iterator[...] с импортом из collections.abc:

Функцию, которую передают как аргумент, записывают через Callable. В скобках сначала список типов параметров, затем тип результата: Callable[[Order], int] — «функция, которая принимает заказ и возвращает целое число». Так описывают, например, ключ сортировки.

Функция len тоже возвращает целое число, но её параметр — любой объект с длиной, в сообщении он назван Sized. Проверка сравнила оба описания функций и нашла несовпадение в типе параметра.

§7Псевдонимы типов

Когда один и тот же составной тип повторяется в нескольких местах, ему дают имя. Такое имя называют псевдонимом типа. В Python 3.12 для этого есть инструкция type:

Для проверки Kopeks и int — один тип: в выводе результат показан как builtins.int. Псевдоним меняет только чтение кода: -> Kopeks сообщает единицы измерения, которых не видно в -> int. Отличить копейки от рублей проверка при этом не сможет — для неё это одно и то же число.

§8Тип Any

Any из модуля typing означает «любой тип». С ним проверка разрешает всё: передать что угодно, вызвать любой метод.

У строки нет метода to_kopeks, и при запуске будет AttributeError, но проверка ошибок не нашла: для значения типа Any она ничего не сверяет. Поэтому Any ставят только там, где тип неизвестен заранее, и не используют как способ убрать замечание проверки.

§9Аннотации переменных и полей

Локальным переменным аннотация обычно не нужна: проверка выводит тип из значения. Её ставят, когда из значения тип не ясен. Пустой словарь {} ничего не говорит о будущих ключах и значениях, поэтому в revenue_by_waiter записано totals: dict[str, int] = {}.

В теле класса аннотации работают иначе. У dataclass строка kopeks: int — это объявление поля: по ней создаётся параметр конструктора. Без аннотации поля не будет.

Поэтому в архиве без аннотаций поля Order оставлены как были: это единственное место в проекте, где аннотация меняет поведение программы.

§10Как узнать, какой тип вывела проверка

Проверка выводит типы значений сама: по аннотациям функций и по выражениям. Чтобы посмотреть, что она вывела, в код временно вставляют reveal_type(...) — mypy напечатает тип в своём отчёте. При запуске программы этой функции нет, поэтому после просмотра строку удаляют.

Приставки builtins. и typing. — полные имена: builtins.int — встроенный int. Так смотрят и тип результата цепочки вызовов, когда по коду он неочевиден.

§11Проверьте себя

Как записать «словарь, где ключ — имя официанта, значение — сумма в копейках»?

dict[str, int]. Первым в скобках идёт тип ключа, вторым — тип значения.

Чем tuple[int, int] отличается от tuple[int, ...]?

Первое — ровно два целых числа, кортеж из трёх проверка отклонит. Второе — любое количество целых чисел.

Функция возвращает Order | None. Почему проверка не даёт сразу обратиться к result.kopeks?

В результате может оказаться None, у которого поля kopeks нет. Сначала нужна проверка if result is not None: внутри неё тип сужается до Order, и обращение к полю разрешено.

Что означает Callable[[Order], int]?

Функцию, которая принимает один аргумент типа Order и возвращает целое число. В первых скобках — типы параметров, после запятой — тип результата.

Почему Any не стоит ставить, чтобы убрать замечание проверки?

С Any проверка перестаёт сверять значение: вызов несуществующего метода проходит проверку и завершается ошибкой только при запуске. Замечание исчезает вместе с самой проверкой.

Почему у полей dataclass аннотации нельзя убрать?

В dataclass аннотация в теле класса — объявление поля: по ней создаётся параметр конструктора. Без аннотации поле не появится.

Итог главы

Простые типы записываются своими именами: int, float, str, bool, а отсутствие результата — None. У коллекций в квадратных скобках указывают содержимое: list[int], dict[str, int], tuple[int, int] для пары и tuple[int, ...] для набора любой длины. Собственные классы проекта пишутся так же, как встроенные типы, после импорта. Вертикальная черта перечисляет варианты: с Order | None вызывающий код проверяет результат на None, и внутри такой проверки тип сужается. Генератор описывают через Iterator, функцию-аргумент — через Callable. Псевдоним типа даёт составному типу имя и для проверки ничем не отличается от исходного типа. Any выключает проверку значения. В теле dataclass аннотация объявляет поле. В следующей главе все эти записи начинают работать: разобрано, как настроить проверку в редакторе и запускать mypy в терминале.
