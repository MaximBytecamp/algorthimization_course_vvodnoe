§1Простые типы

Простые типы записываются своими именами — теми же, что используются в коде для преобразований: int(...), str(...), float(...), bool(...).

ТипКакие значенияПримеры аннотаций из проекта
intцелые числа: 0, 125000, -3kopeks: int — сумма заказа, width: int = 40
floatдробные числа: 4.4, 0.5-> float у calculate_average
strстроки: "Иванов Пётр", ""name: str у normalize_name, -> str у format_kopeks
boolTrue и Falseфлаги вида strict: bool = False
Noneотсутствие значения-> None у print_report

Запись -> None означает, что функция ничего не возвращает. Её ставят у функций, которые только печатают, записывают файл или меняют переданный объект. В проекте так записаны print_report(lines: list[str]) -> None, sort_orders_in_place(orders: list[Order]) -> None и Shift.add(self, order: Order) -> None.

Первая подпись читается так: функция принимает два целых числа и возвращает True или False. Вторая принимает два целых и возвращает дробное число: деление / в Python всегда даёт float. Третья принимает строку и ничего не возвращает.

§2Списки, словари, кортежи, множества

Для коллекции указывают, что в ней лежит. Тип содержимого пишется в квадратных скобках после имени коллекции.

ЗаписьЧто означаетПример значения
list[int]список целых чисел любой длины[5, 4, 5] — оценки в calculate_average
list[str]список строкстроки отчёта в print_report
list[Order]список заказоврезультат load_orders
list[list[int]]список списков целых чисел[[5, 4], [3, 5, 5]] — оценки по группам
dict[str, int]словарь: ключ — строка, значение — целое{"Иванов Пётр": 168500} — выручка по официантам
dict[str, str]строка → строка{"waiter": "Сидоров Илья", "kopeks": "77200"} — строка CSV-файла
dict[str, list[int]]строка → список целых{"Иванова": [5, 4]} — журнал оценок
tuple[int, int]ровно два целых числа(3, 5) — результат grade_bounds
tuple[str, int]ровно два элемента: строка, затем целое("Петрова Анна", 248050)
tuple[int, ...]сколько угодно целых чисел, в том числе ни одного(5, 4, 5, 3), ()
set[str]множество строк без повторов{"Иванов Пётр", "Петрова Анна"} — официанты смены

У трёх видов коллекций скобки устроены по-разному:

  • Список и множество — в скобках один тип. Он относится ко всем элементам: в list[int] каждый элемент — целое число.
  • Словарь — в скобках два типа через запятую: сначала тип ключей, затем тип значений.
  • Кортеж — тип указан для каждого места по порядку. tuple[int, int] — ровно два элемента. Многоточие в tuple[int, ...] означает «любое количество элементов этого типа».

Составную запись читают изнутри наружу. В dict[str, list[int]] значение — список целых чисел, а весь тип — словарь, где по строке лежит такой список.

В таблице ниже для каждой записи дано значение, которое под неё подходит, и значение, которое не подходит.

ЗаписьПодходитНе подходитПочему
list[int][5, 4, 5][5, "4", 5]второй элемент — строка
dict[str, int]{"Иванов Пётр": 100}{1: 100}ключ — число, а записана строка
dict[str, list[int]]{"Сидоров": [5]}{"Сидоров": 5}значение — число, а записан список
tuple[int, int](3, 5)(3, 5, 4)три элемента вместо двух
tuple[str, int]("Петрова Анна", 248050)(248050, "Петрова Анна")элементы переставлены
set[str]{"Иванов Пётр"}{"Иванов Пётр", 125000}один из элементов — число
Старая запись

from typing import List, Dict
def f(x: List[int]) -> Dict[str, int]:

→
Запись в Python 3.9 и новее

def f(x: list[int]) -> dict[str, int]:

Импорт не нужен: встроенные коллекции принимают тип в скобках.

Запись с заглавной буквы и импортом из typing встречается в старом коде и в старых статьях. В проектах курса используется запись со встроенными именами.

§3Собственные классы

Класс — тоже тип. Его имя пишется в аннотации так же, как int. Это относится и к классам проекта — Order, Shift, — и к классам стандартной библиотеки: Path из pathlib, date из datetime. Чтобы имя было доступно в файле, класс импортируют.

Когда тип параметра — класс, редактору доступны его поля: после order. в автодополнении появятся waiter и kopeks. Словарь с такими же ключами под запись Order не подходит: {"waiter": "Петрова Анна", "kopeks": 98050} — это dict, полей .waiter и .kopeks у него нет.

На полях: импорт только ради аннотации

В архиве без аннотаций остались строки вроде from datetime import date в app/domain/shift.py, хотя date в коде не используется. Импорт стоял там ради аннотации day: date. Когда аннотации возвращаются на место, эти импорты снова нужны.

§4Значение или None

Часто функция возвращает значение, а если его нет — None. Например, поиск заказа по имени официанта: заказ найден или не найден. Такой результат записывают через вертикальную черту: Order | None — «заказ или None».

Так же записывают параметр, который можно не передавать. Значение по умолчанию None означает «не передан», и тип параметра — «строка или None»:

В старом коде тот же тип записывали как Optional[Order] с импортом из typing. Запись Order | None доступна с Python 3.10 и означает то же самое.

§5Несколько возможных типов

Та же вертикальная черта перечисляет любые варианты: int | str — «целое число или строка». Такой тип называют объединением. Передать можно значение любого из перечисленных типов. Внутри функции обращаться к нему как к строке или как к числу можно только после того, как выяснено, какой вариант пришёл. Обычно это делают через isinstance.

Объединения используют там, где данные приходят в разном виде. Когда вариант один, объединение только усложняет вызов.

§6Итераторы и функции

Генератор возвращает итератор — объект, из которого значения берут по одному; список целиком при этом не создаётся. Его тип записывают как Iterator[...] с импортом из collections.abc:

Iterator[dict[str, str]] читается изнутри наружу: элемент — словарь «строка — строка», а функция отдаёт такие элементы по одному.

Функцию, которую передают как аргумент, записывают через Callable. В скобках сначала список типов параметров, затем тип результата: Callable[[Order], int] — «функция, которая принимает заказ и возвращает целое число». Так описывают, например, ключ сортировки.

Подпись by_sum совпадает с записью: один параметр типа Order, результат — int. Функция len тоже возвращает целое число, но принимает объект, у которого есть длина, а у заказа длины нет.

§7Псевдонимы типов

Когда один и тот же составной тип повторяется в нескольких местах, ему дают имя. Такое имя называют псевдонимом типа. В Python 3.12 для этого есть инструкция type:

Kopeks и int — один и тот же тип под двумя именами. Псевдоним меняет только чтение кода: -> Kopeks сообщает единицы измерения, которых не видно в -> int, а Revenue короче, чем dict[str, int]. Копейки от рублей псевдоним не отличает: это одно и то же целое число.

§8Тип Any

Any из модуля typing означает «любой тип». Под такую запись подходит любое значение, и со значением типа Any разрешено всё: передать его куда угодно, вызвать любой метод.

У строки нет метода to_kopeks, и при запуске будет AttributeError. Запись Any об этом не предупреждает: она ничего не сообщает о значении. Поэтому Any ставят только там, где тип неизвестен заранее. В работах курса Any не используется.

§9Аннотации переменных и полей

Локальным переменным аннотация обычно не нужна: тип виден из значения. count = 0 — это int, names = ["Иванов Пётр"] — list[str]. Аннотацию ставят, когда из значения тип не ясен. Пустой словарь {} ничего не говорит о будущих ключах и значениях, поэтому в revenue_by_waiter записано totals: dict[str, int] = {}.

В теле класса аннотации работают иначе. У dataclass строка kopeks: int — это объявление поля: по ней создаётся параметр конструктора Order(waiter, kopeks). Без аннотации поля не будет.

Поэтому в архиве без аннотаций поля Order оставлены как были: это единственное место в проекте, где аннотация меняет поведение программы.

§10Проверьте себя

Как записать «словарь, где ключ — имя официанта, значение — сумма в копейках»?

dict[str, int]. Первым в скобках идёт тип ключа, вторым — тип значения.

Как записать «словарь, где ключ — фамилия, значение — список оценок»?

dict[str, list[int]]. Значение само составное: список целых чисел.

Чем tuple[int, int] отличается от tuple[int, ...]?

Первое — ровно два целых числа, кортеж из трёх под эту запись не подходит. Второе — любое количество целых чисел.

Функция возвращает Order | None. Что нужно сделать перед обращением к result.kopeks?

Сравнить результат с None: if result is not None. В результате может оказаться None, у которого поля kopeks нет.

Что означает Callable[[Order], int]?

Функцию, которая принимает один аргумент типа Order и возвращает целое число. В первых скобках — типы параметров, после запятой — тип результата.

Почему Any не стоит ставить вместо настоящего типа?

Any ничего не сообщает о значении: под него подходит всё, и вызов несуществующего метода обнаружится только при запуске.

Почему у полей dataclass аннотации нельзя убрать?

В dataclass аннотация в теле класса — объявление поля: по ней создаётся параметр конструктора. Без аннотации поле не появится.

Итог главы

Простые типы записываются своими именами: int, float, str, bool, а отсутствие результата — None. У коллекций в квадратных скобках указывают содержимое: list[int], dict[str, int], tuple[int, int] для пары и tuple[int, ...] для набора любой длины. Классы проекта и стандартной библиотеки пишутся так же, как встроенные типы, после импорта. Вертикальная черта перечисляет варианты: с Order | None вызывающий код сначала сравнивает результат с None. Генератор описывают через Iterator, функцию-аргумент — через Callable. Псевдоним типа даёт составному типу имя. Any означает любой тип и ничего не сообщает о значении. В теле dataclass аннотация объявляет поле. В главе 4.3 разобрано, какие программы сверяют код с этими записями, в главе 4.4 — что они отвечают на ошибку в каждом из типов.
