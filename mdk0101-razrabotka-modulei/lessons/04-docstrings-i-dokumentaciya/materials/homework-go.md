# Домашнее задание №4 (Go) — lesson_04: типы и комментарии документации

В личном репозитории дисциплины создайте lesson_04/. Папки lesson_01,
lesson_02 и lesson_03 не изменяйте. Основа работы — ваш проект Student Tools
на Go из домашнего задания темы 02: скопируйте его в lesson_04 и добавьте две
функции, чтобы в проекте встретились случаи разного вида.

Функция SaveReport в новом файле internal/services/report_file.go записывает
готовый отчёт в текстовый файл в кодировке UTF-8, возвращает число записанных
строк и ошибку, существующий файл перезаписывает. Функция GradeBounds в
internal/services/calculator.go возвращает минимум, максимум и ошибку; для
пустого среза — переменную ошибки пакета, например ErrNoGrades. Обе
вызываются из main.go и покрыты тестами: обычный и пустой срез для расчёта,
запись в новый и в существующий файл (папку для файлов даёт t.TempDir()).

Работа делается в два шага, как тема. Сначала типы: проект собирается,
go vet ./... ничего не печатает, каждый результат error проверяется, any и
_ на месте ошибки, которую можно проверить, не используются.

Затем комментарии документации по правилам Go Doc Comments. Они обязательны
у каждого пакета (комментарий пакета — в одном файле или в doc.go) и у каждого
экспортируемого имени: функций, типов, методов, переменных ошибок. Первое
предложение начинается с имени. В описаниях укажите то, чего не видно из
подписи: ограничения на входные данные, единицы измерения, порядок значений
в результате, перезапись файла, в каком случае возвращается какая ошибка —
со ссылкой в квадратных скобках, например [ErrNoGrades]. Типы словами не
повторяйте, тело функции не пересказывайте. У функции форматирования добавьте
функцию-пример Example… со строкой // Output: в файле example_test.go.

Включите проверку в редакторе: .vscode/settings.json со строками
"go.lintTool": "revive" и "go.lintOnSave": "package". Команда

    go run github.com/mgechev/revive@latest -set_exit_status ./...

должна завершаться без замечаний.

Состав папки: go.mod и go.sum, main.go с комментарием программы, internal/
с комментариями пакетов и экспортируемых имён, тесты *_test.go (не меньше
семи тестов) и example_test.go, .vscode/settings.json, README.md и
docs/help.txt с сохранённой документацией двух пакетов:

    go doc -all ./internal/services > docs/help.txt
    go doc -all ./internal/utils >> docs/help.txt

В README добавьте два раздела к тем, что были в теме 02: правила
комментариев документации и команды проверки с их выводом. В Git не должны
попасть собранная программа и файл отчёта, созданный при запуске.

Перед сдачей скачайте свою работу в отдельную папку и проверьте: go build ./...,
go vet ./..., revive из команды выше, go test ./... -v, go run ., чтение
docs/help.txt подряд.

Сдача: задача в своём репозитории, ветка lesson-04-docs, запрос на слияние
в main со ссылкой в ответ. В описании запроса укажите команды проверки и их
вывод.

Критерии: согласованные типы и проверка ошибок, чистые go build и go vet 2,
комментарии пакетов и экспортируемых имён по правилам Go Doc Comments 2,
ограничения, единицы и ошибки со ссылками 2, настроенная проверка revive и
пример Example с // Output: 2, новые функции, тесты и README 2. Максимум 10 баллов.
