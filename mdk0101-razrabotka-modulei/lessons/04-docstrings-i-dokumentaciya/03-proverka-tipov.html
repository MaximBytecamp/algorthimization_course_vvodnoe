§1Что такое проверка типов

В главе 4.1 опыты показали, что Python аннотации при запуске не проверяет: вызов с неверным типом либо проходит, либо падает внутри функции. В главе 4.2 разобрано, как записать тип в аннотации. Остался вопрос, кто сверяет вызовы с этими типами. Этим занимаются программы проверки типов.

Проверка типов — чтение кода программой, которая сверяет каждый вызов, присваивание и возврат значения с аннотациями. Сам код при этом не запускается: программа проверки работает с текстом файлов. Если в функцию format_title(text: str, ...) передано число, она сообщит об этом и назовёт строку, хотя до выполнения этой строки дело не дошло.

В курсе используются две такие программы. Правила сверки у них почти одинаковые, различаются место и момент работы. В главе обе разобраны на одном и том же файле с ошибками: сначала Pylance, затем mypy, в конце их ответы сравниваются.

ПрограммаГде работаетКогда проверяетЧто проверяет
PylanceВнутри VS Code, ставится вместе с расширением PythonВо время набора, после каждого измененияОткрытые файлы
mypyВ терминале, ставится через pipПо команде: перед коммитом и в проверках запроса на слияниеУказанный файл, папку или весь пакет

Ассоциация: проверка орфографии

В жизни

Текстовый редактор подчёркивает слово с ошибкой сразу при наборе. Перед отправкой большого документа запускают проверку всего текста, и она выдаёт полный список ошибок по страницам.

В коде

Pylance подчёркивает неверный вызов при наборе, в открытом файле. mypy по команде проверяет весь проект и печатает список ошибок с именами файлов и номерами строк.

Где не совпадаетПроверка орфографии сверяет слова со словарём. Проверка типов сверяет код с аннотациями, которые записаны в этом же проекте: где аннотаций нет, сверять не с чем.

  • Pylance(reportArgumentType) — кто сообщил и по какому правилу. По имени правила его находят в документации.

Что добавилосьСверка с аннотациями: аргументы, присваивания, возвраты, обращения к значению, которое может быть None. Это то, что разбирается в главах 4.2–4.4, и ближе всего к тому, что проверяет mypy.

Что добавилосьПравила, которые не связаны с аннотациями напрямую, но находят настоящие ошибки: переменная, созданная только в одной ветке if, обращение к несуществующему атрибуту функции, несовместимое переопределение метода в классе-наследнике. mypy без дополнительных настроек строку 14 не отмечает.

Что добавилосьТребование полной типизации: у каждого параметра должна быть аннотация, у каждого значения — известный тип. Плюс правила аккуратности кода — неиспользуемые импорты, служебные имена.

Как это сказывается на учебном проекте. На втором архиве, где аннотации расставлены, все четыре режима дают ноль замечаний. На первом архиве, без аннотаций, basic и standard тоже молчат — сверять вызовы не с чем, — а strict выдаёт 86 замечаний, большая часть из них — «тип неизвестен» и «нет аннотации».

§5mypy: проверка в терминале

Pylance нашёл обе ошибки, но у него два ограничения: он проверяет только файлы, открытые в редакторе, и работает только у того, кто пишет код в VS Code. Для проверки всего проекта и для проверок при сдаче работы нужна программа, которую запускают командой.

mypy — программа проверки типов для Python, которая запускается командой в терминале. В отличие от Pylance, она проверяет и те файлы, которые сейчас не открыты, и печатает один отчёт на весь проект. Поэтому в проверках запроса на слияние запускают её. В проекте mypy перечислен в requirements.txt и уже установлен в .venv.

Чтобы сравнить две программы на одном материале, mypy проверяет тот же файл. Верните в proba.py оба неверных вызова — format_title(40) и format_kopeks("1250") — и сохраните файл.

§8Функции без аннотаций

По умолчанию mypy пропускает функции, у которых нет ни одной аннотации: их тела он не проверяет и об отсутствии типов не сообщает. §9Какой тип видит проверка

В сообщениях выше проверка называла типы значений: int, str, Literal[40]. Не все эти типы записаны в коде: у локальных переменных аннотаций обычно нет, и тип проверка выводит сама — из присвоенного значения. Когда сообщение непонятно, полезно посмотреть, какой тип она вывела. Способов два.

В редакторе — наведением указателя на имя переменной. Замените содержимое proba.py: первая строка — импорт from app.services.calculator import grade_bounds, вторая пустая, третья — присваивание bounds = grade_bounds([5, 3, 4]). Аннотации у переменной bounds нет. Наведите указатель на её имя:

В mypy — временной строкой reveal_type(...). Допишите её в тот же файл четвёртой строкой. Импортировать её не нужно: mypy узнаёт это имя сам и печатает тип выражения в скобках строкой с уровнем note.

Приставка builtins. — полное имя встроенного типа: builtins.int и есть int. При запуске программы функции reveal_type нет, и строка завершится ошибкой NameError, поэтому после просмотра её удаляют. Этим приёмом пользуются в главе 4.4: в примерах он показывает, как проверка понимает тип внутри условий и циклов.

§10Чего проверка не находит

Две программы, разобранные в главе, находят любые несовпадения с аннотациями. Есть ошибки другого рода, которых они не видят. Проверка работает с текстом программы. Данные, которые появятся при запуске, ей недоступны. В load_orders сумма читается из файла смены вызовом int(row["kopeks"]). Для проверки всё верно: int(...) возвращает целое число. Если же в файле окажется строка сто, программа завершится ошибкой ValueError, и проверка об этом не предупредит.

Правую колонку закрывают тесты и проверки данных внутри функций. Проверка типов находит один класс ошибок — несовпадение типов — сразу во всём проекте.

Бывает, что замечание верно по форме, но в конкретной строке исправлять нечего: например, в тесте намеренно передаётся неверный тип, чтобы проверить сообщение об ошибке. Такое замечание подавляют комментарием # type: ignore с кодом правила в квадратных скобках:

§11Проверьте себя

Pylance установлен, а неверный вызов не подчёркнут. Что проверить?

Режим проверки: по умолчанию он off. В настройках проекта нужно выбрать basic — в файле .vscode/settings.json появится строка "python.analysis.typeCheckingMode": "basic". Если подчёркнуты строки import, выбран не тот интерпретатор: нужен .venv.

Строка return label стоит после if, внутри которого создаётся label. В каком режиме Pylance её подчеркнёт и чем она опасна?

В режимах standard и strict, сообщение "label" is possibly unbound. Если условие ложно, переменная не создаётся, и при запуске будет UnboundLocalError. В basic строка не подчёркнута: это не противоречие аннотациям, а подозрительное место в логике.

Чем отличается настройка на вкладке Workspace от настройки на вкладке User?

Workspace записывает настройку в .vscode/settings.json внутри проекта: она действует только в нём и попадает в репозиторий вместе с кодом. User меняет настройки редактора на этом компьютере для всех проектов.

Что означает строка proba.py:4: error: … [arg-type]?

В файле proba.py на строке 4 ошибка: аргумент не того типа. arg-type — код правила, по которому ошибку находят в документации.

Файл исправлен, Pylance подчёркиваний не показывает, а mypy по-прежнему сообщает об ошибке. Почему?

Файл не сохранён. Pylance проверяет текст в редакторе, mypy — файл на диске.

Проект без единой аннотации проходит mypy app без ошибок. Почему и как это исправить?

По умолчанию mypy не проверяет функции без аннотаций. Параметр disallow_untyped_defs = true в разделе [tool.mypy] файла pyproject.toml превращает каждую такую функцию в ошибку no-untyped-def.

Проверка типов прошла. Может ли программа завершиться ошибкой при запуске?

Может. Данные из файлов и сети проверке недоступны, расчёты и ограничения значений она не проверяет, а значения типа Any пропускает. Такие ошибки находят тесты и проверки внутри функций.

§1Что такое проверка типов в Go

В главе 4.1 опыты показали, что Go не собирает программу, в которой тип аргумента не совпадает с подписью. В главе 4.2 разобрано, как типы записываются. Остался вопрос, где и когда эта сверка происходит и как увидеть её результат.

Проверка типов — чтение кода программой, которая сверяет каждый вызов, присваивание и возврат значения с объявленными типами. Сам код при этом не запускается: программа работает с текстом файлов. Если в FormatTitle(text string, width int) передано число вместо строки, она сообщит об этом и назовёт строку файла.

В Python проверку выполняют отдельные программы, и её можно не запускать. В Go проверка типов — часть компилятора: без неё программа не собирается. Поэтому вопрос не в том, включать ли проверку, а в том, где удобнее видеть её результат. Мест три, а четвёртая программа добавляет проверки сверх типов:

ПрограммаГде работаетКогда проверяетЧто находит

Ассоциация: проверка орфографии

В жизни

Текстовый редактор подчёркивает слово с ошибкой сразу при наборе. Перед отправкой большого документа запускают проверку всего текста, и она выдаёт полный список ошибок по страницам.

В коде

gopls подчёркивает неверный вызов при наборе. go build по команде проверяет весь модуль и печатает список ошибок с именами файлов и номерами строк.

Где не совпадаетДокумент с орфографическими ошибками всё равно можно отправить. Программу на Go с ошибкой типа собрать нельзя: компилятор не создаст исполняемый файл, пока ошибка не исправлена.

§3gopls: проверка в редакторе

gopls — языковой сервер Go, который запускает расширение Go в VS Code. Подсказки и автодополнение из главы 4.1 строил он. Ошибки типов gopls показывает сразу: включать проверку, как режим Pylance в ветке Python, не нужно. Ниже шесть шагов: первые два готовят редактор, остальные — работа с найденными ошибками.

Убедитесь, что стоит расширение Go

Откройте любой файл .go проекта. В правом нижнем углу окна, в строке состояния, появится версия Go — на кадрах этой главы 1.27.1. Это значит, что расширение нашло установленный Go.

То же делает команда палитры Go: Install/Update Tools: в открывшемся списке отметьте gopls и нажмите OK. Установка выполняется командой go install и занимает до минуты.

Откройте proba/main.go из проводника. Через секунду-две gopls проверит файл.

Прочитайте сообщение

Наведите указатель на подчёркнутое 40 или поставьте на него курсор и нажмите CtrlCmd + K, затем CtrlCmd + I.

Сообщение читается по частям:

  • cannot use 40 — нельзя использовать значение 40;
  • (untyped int constant) — что это за значение: целое число, записанное прямо в коде, у которого ещё нет окончательного типа. Такую константу Go переводит в нужный тип сам, если это возможно без потерь, но в строку число не переводится;
  • as string value — там, где ожидается строка;
  • in argument to utils.FormatTitle — в аргументе функции FormatTitle пакета utils;
  • compiler(IncompatibleAssign) — кто сообщил и вид ошибки: сообщение компилятора, вид «несовместимое присваивание». Передача аргумента для Go — тоже присваивание: значение кладётся в параметр.

Имя файла с номером строки в выводе — ссылка. Удерживайте CtrlCmd и щёлкните по proba/main.go:6:29: VS Code откроет файл и поставит курсор в строку 6, столбец 29. В длинном отчёте так не приходится искать файл в проводнике.

Исправьте и проверьте снова

Замените вызовы на исправленные, как в последнем шаге §3, сохраните файл (CtrlCmd + S) и выполните сборку вместе с go vet. Стрелка ↑ в терминале возвращает предыдущую команду.

go build читает файлы с диска, поэтому перед запуском файл нужно сохранить. gopls проверяет и несохранённый текст. Если редактор ошибок не показывает, а терминал показывает, первым делом проверьте, сохранён ли файл: на вкладке несохранённого файла вместо крестика стоит точка.

Пара go build ./... и go vet ./... запускается перед коммитом и в проверках репозитория. Вместе с go test ./... из темы 02 это три команды, после которых работу можно сдавать. Папку proba после опытов удаляют.

Причина — порядок сборки. Пакеты собираются от тех, что ни от чего не зависят, к тем, что их импортируют: сначала utils, затем domain, который импортирует utils, затем services, последним main. §9Какой тип видит проверка

В сообщениях выше компилятор называл типы значений: untyped int constant, []string. Не все эти типы записаны в коде: у переменных, объявленных через :=, тип выводится из значения. Когда сообщение непонятно, полезно посмотреть, какой тип вывел компилятор. Способов два.

В редакторе — наведением указателя на имя переменной. Замените содержимое proba/main.go программой ниже и наведите указатель на low в строке 10:

При запуске — указателем %T в fmt.Printf: он печатает тип значения. Отдельной команды вроде reveal_type в mypy в Go нет, и она не нужна: тип известен на любом шаге, и программа с %T обычная, её можно запустить.

Третий тип напечатан как <nil>, а не error: %T показывает тип значения, которое лежит в переменной при работе. Ошибки не было, и в переменной типа error пусто. Так видна разница между типом переменной — его знает компилятор — и типом значения внутри интерфейса, который становится известен только при работе.

§10Чего проверка не находит

Компилятор находит любые несовпадения с типами. Есть ошибки другого рода, которых он не видит: проверка работает с текстом программы, а данные, которые появятся при работе, ей недоступны. В LoadOrders сумма читается из файла вызовом strconv.Atoi(row["kopeks"]). Для компилятора всё верно: функция возвращает целое число и ошибку. Если в файле окажется слово «сто», Atoi вернёт ошибку при работе, и только проверка if err != nil не даст программе продолжить с нулём вместо суммы.

Находит компиляторНе находит компилятор

Неверное число аргументов и результатовОшибку в расчёте: + вместо - между числами

Ошибки из правой колонки при работе останавливают программу с сообщением panic — их примеры в главах 4.2 и 4.4. Их закрывают тесты, проверки данных внутри функций и проверка ошибок после каждого вызова. Часть таких мест находит go vet: например, неверный формат в Printf, как в §4.

Подавить ошибку компиляции нельзя: аналога # type: ignore в Go нет. Ошибку исправляют, иначе программа не собирается. Для замечаний staticcheck подавление есть — комментарий //lint:ignore КОД причина на строке перед замечанием, но в работах курса подавления не используются: каждое замечание исправляется кодом.

§11Проверьте себя

Расширение Go установлено, но ошибки в коде не подчёркиваются. Что проверить?

Что расширение нашло Go и gopls: в строке состояния внизу справа должна стоять версия Go, а уведомления об отсутствии gopls быть не должно. Если gopls не установлен, выполните команду палитры Go: Install/Update Tools и отметьте его. И что открыта папка с go.mod, а не папка выше неё.

Что означает строка proba/main.go:7:30: cannot use "1250" (untyped string constant) as int value in argument to utils.FormatKopeks?

В файле proba/main.go, строка 7, столбец 30, передана строка "1250" туда, где функция FormatKopeks ждёт целое число.

Файл исправлен, gopls подчёркиваний не показывает, а go build по-прежнему сообщает об ошибке. Почему?

Файл не сохранён. gopls проверяет текст в редакторе, go build — файл на диске.

Почему go build ./... на первом архиве показывает 3 ошибки, а панель Problems — 12?

Компилятор не собирает пакеты, которые зависят от несобранного пакета, поэтому видны только ошибки internal/utils. gopls проверяет каждый пакет отдельно, опираясь на подписи, и показывает ошибки всех пакетов сразу.

Программа собирается. Что найдёт go vet в строке fmt.Printf("Итог: %d\n", utils.FormatKopeks(total))?

Что указатель %d ждёт целое число, а передана строка: fmt.Printf format %d has arg … of wrong type string. Компилятор это не находит: Printf принимает аргументы любого типа.

Программа прошла go build и go vet. Может ли она остановиться с ошибкой при запуске?

Может. Данные из файлов и сети проверке недоступны, а обращение через nil, запись в нулевой словарь, выход за границу среза и неверное утверждение типа обнаруживаются только при работе. Такие ошибки находят тесты и проверки внутри функций.

Итог главы

В Go проверку типов выполняет компилятор, и отключить её нельзя: программа с ошибкой типа не собирается. gopls в редакторе проверяет код по тем же правилам во время набора, показывает ошибки подчёркиванием, во всплывающем сообщении и в панели Problems — сразу для всех пакетов модуля. go build ./... в терминале печатает по строке на ошибку: файл, строка, столбец и сообщение «что передано / что ожидалось», и останавливается на первом пакете с ошибками. go vet находит ошибки в коде, который собирается, staticcheck — ещё больше таких мест. Тип, который вывел компилятор, показывает наведение в редакторе, а при работе — %T.
