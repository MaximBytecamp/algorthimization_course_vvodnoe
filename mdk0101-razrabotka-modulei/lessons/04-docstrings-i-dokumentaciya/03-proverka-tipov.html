§1Что такое проверка типов

Проверка типов — чтение кода программой, которая сверяет каждый вызов, присваивание и возврат значения с аннотациями. Сам код при этом не запускается: программа проверки работает с текстом файлов. Если в функцию format_title(text: str, ...) передано число, она сообщит об этом и назовёт строку, хотя до выполнения этой строки дело не дошло.

В курсе используются две такие программы. Правила сверки у них почти одинаковые, различаются место и момент работы.

ПрограммаГде работаетКогда проверяетЧто проверяет
PylanceВнутри VS Code, ставится вместе с расширением PythonВо время набора, после каждого измененияОткрытые файлы
mypyВ терминале, ставится через pipПо команде: перед коммитом и в проверках запроса на слияниеУказанный файл, папку или весь пакет

Ассоциация: проверка орфографии

В жизни

Текстовый редактор подчёркивает слово с ошибкой сразу при наборе. Перед отправкой большого документа запускают проверку всего текста, и она выдаёт полный список ошибок по страницам.

В коде

Pylance подчёркивает неверный вызов при наборе, в открытом файле. mypy по команде проверяет весь проект и печатает список ошибок с именами файлов и номерами строк.

Где не совпадаетПроверка орфографии сверяет слова со словарём. Проверка типов сверяет код с аннотациями, которые записаны в этом же проекте: где аннотаций нет, сверять не с чем.

§3Pylance: проверка в редакторе

Pylance — расширение VS Code, которое разбирает код на Python: строит подсказки, автодополнение и переходы к определениям, а при включённой проверке подчёркивает ошибки типов. Ниже восемь шагов — от проверки расширения до исправленного файла.

Убедитесь, что стоит Pylance

Откройте панель расширений: CtrlCmd + Shift + X, или значок из четырёх квадратов на левой полосе. Введите в поле поиска @installed — останутся только установленные расширения.

Выберите интерпретатор из окружения проекта

Откройте палитру команд: CtrlCmd + Shift + P. Наберите Python: Select Interpreter и нажмите Enter.

Этот шаг нужен, чтобы Pylance искал импортируемые модули там же, где их найдёт программа при запуске. С другим интерпретатором он не увидит пакеты из .venv и подчеркнёт строки import как ошибочные.

Откройте proba.py и посмотрите на него без проверки

Откройте proba.py из проводника. В обоих вызовах типы не совпадают с аннотациями, но подчёркиваний нет.

Включите режим basic в настройках проекта

Откройте настройки: CtrlCmd + ,. Вверху окна две вкладки — User и Workspace. Выберите Workspace: так настройка запишется в папку проекта и будет действовать у каждого, кто откроет этот проект. Вкладка User меняет настройки редактора для всех проектов на этом компьютере. В поле поиска введите python.analysis.typeCheckingMode.

Щёлкните по полю со значением off и выберите basic.

VS Code сам создаст файл .vscode/settings.json, если его не было, и допишет в него строку. В проекте темы такой файл уже есть, и строка добавится в конец:

Посмотрите на подчёркивания

Вернитесь на вкладку proba.py. Через секунду-две после смены режима Pylance проверит файл заново.

Прочитайте сообщение

Наведите указатель на подчёркнутое 40 или поставьте на него курсор и нажмите CtrlCmd + K, затем CtrlCmd + I.

Сообщение читается по частям:

  • Argument of type "Literal[40]" — передан аргумент типа Literal[40]. Так Pylance называет тип конкретного значения: «ровно число 40». Это частный случай int.
  • cannot be assigned to parameter "text" of type "str" — нельзя передать в параметр text, который ожидает строку;
  • in function "format_title" — функция, которую вызывали;
  • "Literal[40]" is not assignable to "str" — короткая причина: число не подходит туда, где ждут строку;
  • Pylance(reportArgumentType) — кто сообщил и по какому правилу. По имени правила его находят в документации.

Ниже сообщения две ссылки. View Problem раскрывает описание прямо в тексте файла, Quick Fix предлагает готовые исправления, если они есть. Для ошибок типов готового исправления обычно нет: какое значение нужно передать, решает разработчик.

§4mypy: проверка в терминале

mypy — программа проверки типов для Python, которая запускается командой в терминале. В отличие от Pylance, она проверяет и те файлы, которые сейчас не открыты, и печатает один отчёт на весь проект. Поэтому в проверках запроса на слияние запускают её. В проекте mypy перечислен в requirements.txt и уже установлен в .venv.

§7Функции без аннотаций

По умолчанию mypy пропускает функции, у которых нет ни одной аннотации: их тела он не проверяет и об отсутствии типов не сообщает. Проект совсем без аннотаций прошёл бы проверку с ответом Success, хотя сверять в нём нечего. Чтобы такие функции считались ошибкой, в файле pyproject.toml включают параметр disallow_untyped_defs. §8Какой тип видит проверка

Аннотации пишут не везде: у локальных переменных тип выводится из присвоенного значения. Посмотреть, какой тип вывела проверка, можно двумя способами.

В редакторе — наведением указателя на имя переменной. В файле ниже переменной присвоен результат grade_bounds, аннотации у переменной нет:

В mypy — временной строкой reveal_type(...). Импортировать её не нужно: mypy узнаёт это имя сам и печатает тип выражения в скобках строкой с уровнем note.

Приставка builtins. — полное имя встроенного типа: builtins.int и есть int. При запуске программы функции reveal_type нет, и строка завершится ошибкой NameError, поэтому после просмотра её удаляют. Этим приёмом пользуются в главе 4.4: в примерах он показывает, как проверка понимает тип внутри условий и циклов.

§9Чего проверка не находит

Проверка работает с текстом программы. Данные, которые появятся при запуске, ей недоступны. В load_orders сумма читается из файла смены вызовом int(row["kopeks"]). Для проверки всё верно: int(...) возвращает целое число. Если же в файле окажется строка сто, программа завершится ошибкой ValueError, и проверка об этом не предупредит.

Находит проверка типовНе находит проверка типов
Вызов с аргументом не того типаНеверные данные в файле или в ответе сервера
Обращение к атрибуту значения, которое может быть NoneОшибку в расчёте: + вместо - между числами
Возврат значения не того типаНарушение ограничений вроде «оценка от 2 до 5»
Опечатку в имени атрибутаВсё, что помечено типом Any

Правую колонку закрывают тесты и проверки данных внутри функций. Проверка типов находит один класс ошибок — несовпадение типов — сразу во всём проекте.

Бывает, что замечание верно по форме, но в конкретной строке исправлять нечего: например, в тесте намеренно передаётся неверный тип, чтобы проверить сообщение об ошибке. Такое замечание подавляют комментарием # type: ignore с кодом правила в квадратных скобках:

Код в скобках обязателен: без него подавляются все замечания на строке, в том числе те, что появятся после будущих правок. В работах курса подавления не используются: каждое замечание исправляется аннотацией или кодом.

§10Проверьте себя

Pylance установлен, а неверный вызов не подчёркнут. Что проверить?

Режим проверки: по умолчанию он off. В настройках проекта нужно выбрать basic — в файле .vscode/settings.json появится строка "python.analysis.typeCheckingMode": "basic". Если подчёркнуты строки import, выбран не тот интерпретатор: нужен .venv.

Чем отличается настройка на вкладке Workspace от настройки на вкладке User?

Workspace записывает настройку в .vscode/settings.json внутри проекта: она действует только в нём и попадает в репозиторий вместе с кодом. User меняет настройки редактора на этом компьютере для всех проектов.

Что означает строка proba.py:4: error: … [arg-type]?

В файле proba.py на строке 4 ошибка: аргумент не того типа. arg-type — код правила, по которому ошибку находят в документации.

Файл исправлен, Pylance подчёркиваний не показывает, а mypy по-прежнему сообщает об ошибке. Почему?

Файл не сохранён. Pylance проверяет текст в редакторе, mypy — файл на диске.

Проект без единой аннотации проходит mypy app без ошибок. Почему и как это исправить?

По умолчанию mypy не проверяет функции без аннотаций. Параметр disallow_untyped_defs = true в разделе [tool.mypy] файла pyproject.toml превращает каждую такую функцию в ошибку no-untyped-def.

Проверка типов прошла. Может ли программа завершиться ошибкой при запуске?

Может. Данные из файлов и сети проверке недоступны, расчёты и ограничения значений она не проверяет, а значения типа Any пропускает. Такие ошибки находят тесты и проверки внутри функций.

Итог главы

Pylance проверяет открытые файлы во время набора, когда в настройках проекта выбран режим basic; ошибки видны подчёркиванием, во всплывающем сообщении и в панели Problems. mypy проверяет указанный файл или весь пакет по команде в терминале и печатает по строке на ошибку: файл, номер строки, сообщение «пришло / ожидалось» и код правила. Параметр disallow_untyped_defs заставляет mypy сообщать о функциях без аннотаций — на первом архиве их семнадцать. Тип, который вывела проверка, показывают наведение в редакторе и reveal_type в mypy.

  3. Выбор интерпретатора — VS Code, Python environments.
