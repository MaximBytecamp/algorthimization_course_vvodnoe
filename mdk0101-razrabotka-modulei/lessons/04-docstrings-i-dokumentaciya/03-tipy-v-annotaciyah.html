§1Как проверять примеры

Каждый пример главы — содержимое файла proba.py в корне второго архива проекта, того же, что в главе 4.2. Под файлом — ответ команды .venv/bin/mypy proba.py, полученный запуском. Номера строк в ответе считаются от первой строки файла, поэтому файл нужно копировать целиком, вместе с импортами и пустыми строками.

Порядок работы с каждым примером одинаковый:

  1. Замените содержимое proba.py кодом примера и сохраните файл.
  2. Посмотрите, какие строки подчеркнул Pylance, и наведите указатель на подчёркивание.
  3. Выполните в терминале .venv/bin/mypy proba.py (в Windows — .venv\Scripts\mypy proba.py) и сверьте ответ с книгой.
  4. Исправьте ошибки по разбору под примером и запустите проверку снова: ответ должен смениться на Success.

Pylance в режиме basic подчёркивает почти те же строки, что mypy, но формулирует сообщения по-своему. Где поведение двух программ различается, об этом сказано в разборе.

Простые типы записываются своими именами — теми же, что используются для преобразований: int(...), str(...), float(...), bool(...).

Разбор по строкам:

  • Строка 14 — сумма передана строкой "1250". Так бывает, когда значение прочитано из файла и не переведено в число. Исправление — передать число: format_kopeks(1250), а если значение пришло строкой — format_kopeks(int(value)).

§3Функции без результата: None

None — значение «ничего». Функция, в которой нет return со значением, возвращает None, и её результат аннотируют как -> None. Так записаны все функции проекта, которые печатают, записывают файл или меняют переданный объект: print_report(lines: list[str]) -> None, sort_orders_in_place(orders: list[Order]) -> None, Shift.add(self, order: Order) -> None.

С аннотацией результата проверка следит за двумя ошибками: функция обещает значение, но не во всех случаях его возвращает, и результат функции -> None пытаются использовать.

  • Строка 4 — Missing return statement, «нет инструкции return». Функция обещает строку, но при kopeks, равном нулю, условие не выполнится, и функция вернёт None. Исправление — вернуть строку и во втором случае: добавить в конце return "выручки нет".
  • Строка 9 — результат print_report сохраняется в переменную, но функция всегда возвращает None: «не возвращает значение». Исправление — вызвать функцию без присваивания: print_report(["Смена"]).

Вторую ошибку Pylance в режиме basic не показывает; первую подчёркивает с правилом reportReturnType.

§4Списки

У коллекции указывают, что в ней лежит. Тип элементов пишется в квадратных скобках после имени коллекции. list[int] — список целых чисел любой длины. Все элементы списка должны быть одного типа: тип в скобках один.

ЗаписьЧто означаетГде встречается
list[int]список целых чиселоценки: calculate_average(grades: list[int])
list[str]список строкстроки отчёта: print_report(lines: list[str])
list[Order]список заказоврезультат load_orders
list[list[int]]список списков целых чиселоценки по группам: [[5, 4], [3, 5, 5]]

Аннотация списка проверяет не только присваивание, но и всё, что со списком делают потом: добавление элементов, чтение элемента в переменную.

  • Строки 3–6 — четыре верных объявления, ошибок нет.
  • Строка 8 — в список оценок добавлена строка "5". Сообщение Argument 1 to "append" of "list" — «первый аргумент метода append у списка»: проверка подставила тип элементов int в метод append и сверила с ним аргумент.
  • Строка 9 — в список имён добавлено None. Список, где могут быть пропуски, записывают как list[str | None] — об этом в §9.
  • Строка 10 — вместо объекта Order добавлен словарь с теми же полями. Для проверки это разные типы: у словаря нет полей .waiter и .kopeks, и следующая строка order.kopeks упала бы при запуске. Исправление — orders.append(Order("Сидоров Илья", 77200)).
  • Строка 11 — элемент списка list[int] — целое число, а переменная объявлена строкой. Сообщение Incompatible types in assignment читается как «несовместимые типы при присваивании»: выражение справа имеет тип int, переменная — str.

§6Кортежи

Кортеж в аннотации записывается иначе, чем список: тип указывают для каждого места по порядку. tuple[int, int] — ровно два целых числа, tuple[str, int] — ровно два элемента, строка и число в таком порядке. Кортеж, в котором элементов может быть сколько угодно, записывают с многоточием: tuple[int, ...].

ЗаписьЧто означаетПример значения
tuple[int, int]два целых числа(3, 5) — результат grade_bounds
tuple[str, int]строка, затем целое("Петрова Анна", 248050) — пара из revenue.items()
tuple[int, ...]сколько угодно целых, в том числе ни одного(5, 4, 5, 3), ()
  • Строка 3–4 — результат grade_bounds разобран на две переменные, и каждая получила тип своего места: low — int.
  • Строка 6 — три элемента там, где обещано два. Проверка сравнивает длину: tuple[int, int, int] не совпадает с tuple[int, int].
  • Строка 8 — элементы переставлены. Длина совпадает, но на первом месте ждут строку, а стоит число.
  • Строки 9–10 — с многоточием подходит кортеж любой длины, в том числе пустой.

Порядок элементов в паре проверка видит только по типам. В tuple[int, int] у grade_bounds что идёт первым — минимум или максимум, — аннотация не сообщает: это пишут в описании функции.

§7Множества и старая запись коллекций

Множество — коллекция без повторов и без порядка. Тип элементов пишут так же, как у списка: set[str] — множество строк, например имён официантов смены.

Сообщение такое же, как у append в §4: метод множества add принимает только элементы объявленного типа.

В старом коде и в статьях коллекции записывают с заглавной буквы и импортом из модуля typing. Обе записи означают одно и то же; в проектах курса используется новая, без импорта.

Старая запись

from typing import Dict, List, Optional
def f(x: List[int]) -> Dict[str, int]:
def g() -> Optional[str]:

→
Запись в Python 3.10 и новее

def f(x: list[int]) -> dict[str, int]:
def g() -> str | None:

Встроенные коллекции принимают тип в скобках с Python 3.9, вертикальная черта — с 3.10.

§9Значение или None

Часто функция возвращает значение, а если вернуть нечего — None. Например, поиск заказа по имени официанта: заказ найден или не найден. Такой тип записывают через вертикальную черту: Order | None — «заказ или None». В старом коде тот же тип записан как Optional[Order].

§10Несколько возможных типов

Вертикальная черта перечисляет любые варианты, не только None. int | str — «целое число или строка». Такой тип называют объединением. Передать можно значение любого из перечисленных типов. Внутри функции работать с ним как со строкой или как с числом можно только после проверки, какой вариант пришёл: обычно это isinstance(value, str).

Внутри условия isinstance(value, str) тип сужен до str (строка 3), после условия — до int (строка 5): строки туда уже не доходят, остаётся второй вариант. Вызовы с числом и со строкой прошли, с дробным числом — нет: float в перечне вариантов не значится.

Без проверки варианта проверка отклонит код, даже если для одного из вариантов он верен:

Для строки выражение "125" * 100 даёт строку из ста повторов "125". Сообщение Incompatible return value type (got "int | str", expected "int") — «тип возвращаемого значения несовместим: получено int | str, ожидалось int». Объединения используют там, где данные действительно приходят в разном виде. Когда вариант один, объединение только добавляет проверок в вызывающий код.

§11Генераторы и функции-аргументы

Генератор — функция с yield: она отдаёт значения по одному, не собирая их в список. Вызов такой функции возвращает итератор — объект, из которого значения берут по одному, например циклом for. Его тип записывают как Iterator[тип элемента] с импортом из collections.abc.

Переменная цикла получила тип элемента — int. В проекте генератор один — read_rows, он отдаёт строки CSV-файла словарями:

Iterator[dict[str, str]] читается изнутри наружу: элемент — словарь «строка — строка», а функция отдаёт такие элементы по одному.

Функцию тоже можно передать аргументом — как ключ сортировки в sorted(..., key=...). Тип такого параметра записывают через Callable из collections.abc: в первых квадратных скобках — типы параметров функции, после запятой — тип её результата. Callable[[str], str] — «функция, которая принимает строку и возвращает строку».

Строки 10 и 11 проходят: normalize_name и метод str.upper принимают строку и возвращают строку. В строке 12 передана len — она возвращает число и принимает любой объект с длиной, в сообщении он назван Sized. Проверка сравнила описание переданной функции с ожидаемым и нашла несовпадение в результате.

§12Псевдонимы типов

Когда один составной тип повторяется в нескольких местах, ему дают короткое имя — псевдоним типа. В Python 3.12 для этого есть инструкция type:

Для проверки Kopeks и int — один и тот же тип: результат показан как builtins.int. Псевдоним меняет только чтение кода: -> Kopeks сообщает единицы измерения, которых не видно в -> int, а Revenue короче, чем dict[str, int]. Отличить копейки от рублей проверка не сможет — для неё это одно и то же целое число.

§13Тип Any

Any из модуля typing означает «любой тип». Для значения типа Any проверка разрешает всё: передать его куда угодно, вызвать любой метод. Тот же Any Pylance показывал в главе 4.1 у параметров без аннотаций.

У строки нет метода to_kopeks, и при запуске будет AttributeError, но проверка ошибок не нашла: для Any она ничего не сверяет. Any ставят там, где тип действительно неизвестен заранее, например у данных из внешней библиотеки без аннотаций. Убирать им замечание проверки нельзя: замечание исчезнет вместе с самой проверкой. В работах курса Any не используется.

§14Аннотации переменных и полей

Локальным переменным аннотация обычно не нужна: проверка выводит тип из присвоенного значения. count = 0 — это int, names = ["Иванов Пётр"] — list[str]. Аннотацию ставят, когда из значения тип не ясен. Так бывает с пустыми коллекциями:

Need type annotation — «нужна аннотация типа». В скобках mypy подсказывает форму записи: вместо <type> подставляют типы, например totals: dict[str, int] = {}, как в revenue_by_waiter. Если в той же функции ниже в коллекцию что-то добавляется, mypy иногда выводит тип по этому добавлению; аннотация у пустой коллекции всё равно делает код понятнее. Pylance в режиме basic об этом случае не сообщает.

В теле класса аннотации работают иначе. У dataclass строка kopeks: int — это объявление поля: по ней создаётся параметр конструктора Order(waiter, kopeks). Без аннотации поля не будет.

Это единственное место в проекте, где аннотация меняет поведение программы. Поэтому в первом архиве поля Order оставлены с аннотациями.

§15Проверьте себя

Как записать «словарь, где ключ — имя официанта, значение — список сумм его заказов в копейках»?

dict[str, list[int]]. Первым в скобках идёт тип ключа, вторым — тип значения; значение само составное.

Чем tuple[int, int] отличается от tuple[int, ...] и от list[int]?

tuple[int, int] — ровно два целых числа, кортеж другой длины проверка отклонит. tuple[int, ...] — кортеж из любого количества целых. list[int] — список любой длины, в который можно добавлять элементы.

Почему average_check(4937, 5) проходит проверку при total: float, а average_check(4937.5, 5.0) — нет?

Где ожидается float, разрешено передать int. Второй параметр — count: int, и дробное 5.0 туда не подходит, хотя по значению равно пяти.

Функция возвращает Order | None. Почему проверка не даёт сразу обратиться к result.kopeks?

В результате может оказаться None, у которого нет поля kopeks. Сначала нужна проверка if result is not None: внутри неё тип сужается до Order.

Что вернёт revenue.get("Сидоров Илья") для revenue: dict[str, int] и как получить всегда число?

Тип результата — int | None: если ключа нет, вернётся None. Со значением по умолчанию — revenue.get("Сидоров Илья", 0) — результат всегда int.

Что означает Callable[[Order], int]?

Функцию, которая принимает один аргумент типа Order и возвращает целое число. Такую функцию можно передать ключом сортировки заказов по сумме.

Почему Any нельзя ставить, чтобы убрать замечание проверки?

С Any проверка перестаёт сверять значение: вызов несуществующего метода проходит проверку и завершается ошибкой только при запуске.

Почему у totals = {} нужна аннотация, а у count = 0 — нет?

По нулю проверка выводит тип int. По пустому словарю нельзя узнать тип ключей и значений, и mypy сообщает Need type annotation.

Итог главы

Простые типы записываются своими именами, у коллекций в квадратных скобках указывают содержимое, классы проекта и стандартной библиотеки пишутся так же после импорта. Вертикальная черта перечисляет варианты; с X | None проверка требует сначала убедиться, что значение не None. Генераторы описывают через Iterator, функции-аргументы — через Callable. Аннотации переменных нужны там, где тип не выводится из значения, а в dataclass аннотации объявляют поля. Почти все ошибки в примерах — это «передан не тот тип», и mypy называет в сообщении, что пришло и что ожидалось.

Откуда взяты факты
  1. Составные типы и их запись — документация модуля typing; правило «int вместо float» — спецификация типов Python.
  2. Коллекции с типом в скобках — PEP 585, запись через вертикальную черту — PEP 604, инструкция type — PEP 695.
  3. Сужение типов и reveal_type — документация mypy, Type narrowing.
  4. Все выводы получены запуском примеров на втором архиве проекта, mypy 1.15; сверка книги с запуском — shots/verify_examples.py.
