Модуль, пакет и точки в импорте

Два слова, которые дальше встречаются постоянно. Модуль — это один файл .py, например calculator.py. Пакет — это папка с модулями, которую тоже можно импортировать, например app. Точки в записи app.services.calculator — не «части имени», а вложенность: папка app → папка services → файл calculator.py. Читая импорт, вы читаете путь по дереву проекта.

Что делает сам файл __init__.py

Он играет две роли сразу.

  • Объявляет папку обычным пакетом. Для Python наличие этого файла — явный признак: «это не просто папка с файлами, это пакет».
  • Является телом пакета. Код внутри __init__.py выполняется в момент первого импорта пакета — так же, как код верхнего уровня обычного модуля из главы 2.4. Пустой файл просто ничего не делает.

Причём выполняется он не только при import app. Импортируя что-то в глубине, Python проходит весь путь по дереву и выполняет __init__.py каждого пакета по дороге — сверху вниз.

Почему в учебном проекте он пустой

В __init__.py обычно складывают то, что относится к пакету целиком: короткие псевдонимы для импортов, версию, общие настройки. Но помните предыдущий пункт: этот код выполнится при любом импорте из пакета, даже если нужна одна маленькая функция. Тяжёлый или «делающий что-то» __init__.py — частая причина медленных и непредсказуемых импортов, поэтому по умолчанию его оставляют пустым. Так делаем и мы.

Почему иногда пакет работает и без него

Вы можете удалить __init__.py, и импорт всё равно сработает. Начиная с Python 3.3 папка без этого файла тоже импортируется — как namespace package. Разница видна, если посмотреть на сам объект пакета.

Вывод для вашей работы: в своих проектах создавайте __init__.py явно. Пакет получает тело, поведение импорта становится предсказуемым, а инструменты и старые версии библиотек надёжнее видят вашу папку как пакет. При этом отсутствие файла в чужом проекте само по себе не является ошибкой.

Две разные вещи с одинаковым именем

Файл __init__.py — тело пакета. Метод __init__ внутри класса — подготовка объекта при его создании; к пакетам он отношения не имеет. Общее у них только соглашение об именах: такие имена с двойными подчёркиваниями называют dunder (от double underscore) и придумывать свои не нужно — их набор задан языком.

-m просит Python найти модуль по имени и выполнить его как главный. Здесь это app/main.py. Корень проекта попадает в путь поиска, поэтому абсолютные импорты с app разрешаются.

Частая ошибка

При python app/main.py стартовый путь поиска отличается: Python может не найти пакет app. Не исправляйте это добавлением случайных путей в sys.path. Вернитесь в student-tools и используйте python -m app.main.

Почему один и тот же код запускается по-разному

Запуская программу, Python первым делом решает, откуда искать импортируемые пакеты. Стартовая папка поиска зависит от способа запуска — и именно она решает, будет ли виден пакет app.

Интерактивная схема · откуда Python ищет пакеты
student-tools/ ← корень проекта
└ app/ ← папка пакета
   └ main.py

Python начинает поиск с текущей папки — корня проекта. Внутри него виден пакет app, поэтому импорт from app.services.calculator работает.

Структура и архитектура

Структура отвечает на вопрос «где лежит файл?». Архитектура — «какая у части ответственность и от кого она зависит?». Папка services сама не делает программу правильно устроенной: важно, чтобы вычисления не зависели от интерфейса вывода.

Имена app, src, core зависят от команды и проекта. Здесь services хранит прикладной расчёт, utils — небольшую функцию оформления. Создавать пустые папки «на будущее» не требуется.

Куда смотрят стрелки

Главное правило этой структуры — направление зависимостей. Точка запуска знает про расчёт и оформление, а они про неё — нет. Расчёт вообще ни от чего не зависит: ему всё равно, кто его вызвал и куда пойдёт результат.

Интерактивная схема · кто от кого зависит
app/main.pyточка запуска
↓ импортирует↑ импортирует обратно
services/calculator.pyтолько вычисления
utils/formatter.pyтолько оформление строки

Стрелка одна и вниз: main.py импортирует расчёт и оформление. Калькулятор можно вызвать из тестов, из другой программы, из будущего веб-интерфейса — он ничего не знает о том, кто его использует.

Если стрелка появляется в обратную сторону — расчёт импортирует точку запуска, — получается цикл: два модуля ждут друг друга, и Python сообщает об этом ошибкой partially initialized module. Данные передают вниз аргументами, а результат возвращают вверх через return; обратный импорт для этого не нужен.
