# Практика: разобрать доставку файлов (Go)

Это те же Student Tools, но файлы прислали без структуры. Имена не соответствуют
правилам Go, а импорты в точке запуска уже указывают на будущую структуру пакетов.
Не собирайте заготовку до раскладки. Код функций менять не требуется.

1. Создайте папку student-tools, внутри неё — internal/services и internal/utils.
2. Прочитайте файлы и переименуйте по ответственности: calculator.go, formatter.go,
   main.go, calculator_test.go. В Go имена файлов пишут маленькими буквами слитно,
   слова разделяют подчёркиванием только в суффиксе _test.
3. Разложите файлы по папкам. Точка запуска — main.go — остаётся в корне;
   файл теста лежит рядом с проверяемым кодом, в той же папке services.
4. Проверьте первую строку каждого файла: package main в корне, package services
   и package utils в своих папках. Имя пакета совпадает с именем папки.
5. Объявите модуль: go mod init example.com/student-tools. Имя модуля должно
   совпадать с началом путей в импортах — посмотрите их в main.go.
   Файл «библиотеки.txt» — это готовый go.mod: из него видно имя модуля и версии.
6. Восстановите зависимости: go mod tidy. Команда дочитает импорты и допишет go.mod.
7. Соберите и запустите из корня: go build ./... и go run .
   Ожидается: Средний результат: 4.40.
8. Выполните go test ./... -v. Ожидаются PASS у двух тестов и строка ok
   для пакета internal/services.
9. Добавьте .gitignore и README с назначением, версией Go, командами и ожидаемым
   выводом. Собранный бинарник в сдачу не включайте.

Подсказки и готовый пример доступны в главе 2.7 книги.
