# За что отвечает каждый файл

Правило раскладки: файл лежит там, где лежит его ответственность.
Ниже перечислено, что именно отвечает за каждую часть проекта.

## app/

Код программы. Всё, что запускается и считает, лежит здесь.

- `main.py` — точка запуска. Знает путь к данным, вызывает чтение и печать.
  Расчётов внутри нет.
- `services/orders.py` — заказы: чтение CSV-файла, выручка, средний чек,
  суммы по официантам. Ничего не печатает.
- `services/report.py` — текст отчёта. Берёт готовые расчёты и превращает их
  в список строк. Файлы не читает.
- `utils/money.py` — суммы: перевод копеек в рубли и запись `1 280,50 ₽`.
- `utils/text.py` — строки: приведение имени к виду «Анна Петрова»
  и выравнивание колонки по ширине.

Разница между `services/` и `utils/`: в `services/` лежат правила именно этого
проекта — что считать выручкой и как выглядит отчёт. В `utils/` лежат мелкие
функции, которые можно перенести в другой проект без изменений.

## data/

Исходные данные — `orders.csv`. Код и данные не смешивают: файл с заказами
можно заменить, не трогая программу.

## tests/

Проверки. Каждый файл проверяет свою часть кода: `test_orders.py` — расчёты,
`test_report.py` — отчёт и вспомогательные функции.

## Файлы в корне

- `README.md` — назначение проекта, команды запуска и ожидаемый результат.
- `requirements.txt` — список зависимостей. Сейчас проект обходится
  стандартной библиотекой, но место для списка уже готово.
- `.gitignore` — что не попадает в репозиторий: окружение `.venv/`, кеш
  `__pycache__/`, файл с секретами `.env`, служебный `.DS_Store`.
