§1Было ли такое: дубликаты и пара с суммой

Самый частый вопрос к хеш-структуре: встречалось ли это значение раньше. Перебор отвечает на него за O(n) на каждый элемент, и весь проход стоит O(n²). Множество из главы 0.2 отвечает в среднем за O(1), и проход становится O(n).

Первая задача занятия 17 — есть ли в списке повторы. Если повторы есть, множество из этих элементов короче списка:

Это решение строит множество целиком. Проход с множеством уже встреченных останавливается на первом повторе и может вернуть сам повтор вместо ответа «да» или «нет». Оба способа сравниваются в модуле 17.

Вторая задача — индексы двух чисел с заданной суммой. Для числа 7 при сумме 9 пара — число 2. Вопрос «было ли число 2» задаёт множество, но ответ должен содержать индекс, поэтому нужен словарь «значение → индекс».

В этом признаке и состоит выбор структуры, о котором спрашивает контроль занятия 17. Если нужен только ответ «есть или нет» — множество. Если вместе с ключом нужно ещё что-то: индекс, число, запись, — словарь. Обе структуры стоят O(n) дополнительной памяти, и глава 0.2 показала, насколько это больше, чем у списка.

§2Счётчики и группировка

Второй вид задач — словарь, в котором по ключу накапливается результат. В частотном словаре значение — число, сколько раз ключ встретился. В словаре группировки значение — список элементов с одним ключом. Counter из модуля collections считает частоты одной строкой, как в книге о строках.

Задачи занятия 18 по КТП — группы анаграмм и самые частые элементы. Группы строятся по ключу группировки: значение, которое одинаково у всех элементов группы и различно у разных групп. У анаграмм «листок» и «слиток» одинаковы отсортированные буквы. Ключ должен быть хешируемым — строка или кортеж, но не список, глава 0.6. Контроль занятия требует сравнить два подхода к ключу: отсортированные буквы и кортеж из 33 частот.

§3Операции над множествами

Третий вид задач работает с множествами целиком: пересечение, объединение и разность из главы 0.1. Задача занятия 19 об общих пользователях двух сервисов — это пересечение. Повторы во входе на результат не влияют.

Вторая задача занятия — самая длинная последовательность подряд идущих чисел. Сортировка решает её за O(n log n), множество — за O(n). Последовательность начинается с числа x, у которого нет x - 1: во второй строке примера это 1, 100 и 200. От каждого начала идут вверх, пока x + 1 есть во множестве: 1, 2, 3, 4 — длина 4. Каждое число проверяется на вхождение несколько раз, но каждая проверка стоит в среднем O(1). Контроль занятия 19 требует объяснить, почему решение O(n), и не полагаться на порядок множества — глава 0.6.

§4Индекс и кэш

Четвёртый вид задач — словарь как готовый ответ на будущие запросы. Индекс — словарь «ключ → запись», построенный один раз, чтобы потом находить запись по ключу без перебора. Кэш — словарь, в котором программа запоминает уже вычисленные ответы. Если ответ в кэше есть, это попадание (hit), если нет — промах (miss): ответ вычисляют и запоминают.

Здесь цена вычисляется по длине названия — это заглушка вместо долгого запроса к базе. Второй вызов для болта ничего не вычислял. Такой кэш растёт без ограничений. Задача занятия 20 по КТП — ограниченный кэш: когда места нет, он удаляет ключ, к которому дольше всего не обращались. Эту стратегию называют LRU (least recently used). Для неё нужен порядок обращений, и словарь с порядком вставки из главы 0.6 здесь подходит: ключ при обращении переставляют в конец, а самый старый оказывается первым.

На LeetCode вход всегда корректен, а в задачах занятий нужно заранее решить, что с такими данными делать. Для этого в каждом модуле есть глава «как узнать задачу» с вопросами до кода. Модуль 17 начинается с неё.

Проверьте себяСервис получает поток номеров платежей и должен для каждого номера сказать, приходил ли он раньше, и если приходил — в какое время. Что хранить?

  • Множество ответит, приходил ли номер, но время ему хранить негде.

  • Верно. Ключ отвечает на «было ли», значение хранит то, что нужно вернуть вместе с ответом. Это тот же признак, что в задаче о паре с суммой.

  • Список ответит верно, но каждый поиск O(n), а весь поток — O(n²). Время пришлось бы хранить в другом списке.

  • Ищут по номеру, значит, ключом должен быть номер. Поиск по значениям словаря перебирает их по порядку.
