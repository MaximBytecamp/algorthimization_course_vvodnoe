§1Множество

На проходной офиса турникет записывает номер пропуска при каждом входе. За день сотрудник с пропуском 12 вошёл три раза, и в журнале его номер стоит трижды. Охране нужен другой ответ: кто сегодня был в здании. Для этого ответа важно только, встречался ли номер, а сколько раз и в каком порядке — нет.

Такой набор называют множеством. Это слово из математики: множество — набор различных элементов, у которого нет порядка. Каждый элемент в нём либо есть, либо его нет. В Python множество — тип set. Его создают из любой последовательности функцией set() или записывают элементы в фигурных скобках через запятую.

На схеме — тот же журнал и множество, построенное из него. Зелёные записи — первое появление номера, оранжевые — повторы.

В журнале шесть записей, во множестве — три номера: повторы исчезли при создании. Функция len даёт число разных элементов, оператор in отвечает, есть ли элемент. Порядок номеров в выводе другой, чем в журнале. Обратиться к элементу по индексу нельзя: у множества нет первого и второго элемента. Порядок, в котором Python печатает множество, от порядка в журнале не зависит, и опираться на него нельзя.

Последняя строка показывает частую ошибку. Пустые фигурные скобки {} создают пустой словарь. Пустое множество записывается только как set().

§2Изменение множества

Множество можно менять: добавлять и удалять элементы. Метод add добавляет элемент. Если элемент уже есть, ничего не происходит, и ошибки нет. Удаляют элемент двумя методами, и разница между ними — в том, что происходит, когда элемента нет.

Номер 12 уже был, поэтому после двух вызовов add элементов четыре. Метод discard удаляет элемент, если он есть, и молча ничего не делает, если его нет. Метод remove в этом случае бросает KeyError. Выбирают по смыслу программы: если отсутствие элемента означает ошибку в данных, берут remove, и ошибка будет видна сразу. Если элемента может не быть, берут discard.

§3Операции над множествами

Множества сравнивают и объединяют операторами. Пусть yesterday — покупатели магазина вчера, today — сегодня. Вопросы «кто приходил оба дня», «кто вчера был, а сегодня нет», «сколько всего разных покупателей за два дня» решаются одной операцией каждый. На схеме выберите операцию: в строках yesterday и today останутся яркими элементы, которые попали в результат.

ЗаписьНазваниеЧто в результате
a | bобъединениеэлементы, которые есть хотя бы в одном множестве
a & bпересечениеэлементы, которые есть в обоих
a - bразностьэлементы a, которых нет в b
a ^ bсимметрическая разностьэлементы, которые есть ровно в одном из двух
a <= bподмножествоTrue, если каждый элемент a есть в b

Результат каждой операции — новое множество, исходные не меняются. Разность зависит от порядка: yesterday - today и today - yesterday — разные множества. В примере результаты обёрнуты в sorted: множество строк Python печатает в порядке, который меняется от запуска к запуску, а отсортированный список печатается одинаково. Пересечение и разность — основа задач занятия 19 по КТП.

§4Словарь

Кладовщик ведёт карточку остатков: напротив каждого товара записано, сколько его на складе. «Болт — 120, гайка — 80». Чтобы узнать остаток гаек, он находит строку «гайка» и читает число рядом. Название товара здесь — то, по чему ищут, а число — то, что находят.

Такая карточка в Python — словарь, тип dict. Словарь хранит пары «ключ — значение». Ключ — то, по чему ищут, в карточке это название товара. Значение — то, что связано с ключом, здесь остаток. Словарь записывают в фигурных скобках: пары через запятую, ключ и значение через двоеточие.

В таблице — карточка кладовщика, записанная как словарь {'болт': 120, 'гайка': 80}. Каждая строка — одна пара.

Ключ — название товараЗначение — остатокКак прочитать
'болт'120stock['болт'] → 120
'гайка'80stock['гайка'] → 80

Ниже — как читать, добавлять, менять и удалять пары.

Разберём по строкам. Запись stock['болт'] читает значение по ключу. Присваивание stock['шайба'] = 50 добавляет новую пару, потому что ключа 'шайба' не было. Такое же присваивание для гайки заменяет значение 80 на 75: ключ в словаре один, и у него одно значение. Чтение по ключу, которого нет, бросает KeyError. Метод get в этом случае возвращает None или второй аргумент.

Оператор in для словаря проверяет ключи: 75 in stock даёт False, хотя остаток 75 в словаре есть. Удаляют пару инструкцией del или методом pop, который ещё и возвращает удалённое значение.

Словарь часто собирают из двух списков одинаковой длины: функция zip составляет пары из элементов с одним индексом. Есть и короткая запись цикла — генератор словаря.

Python в этой строке: {name: len(name) for name in names}

Генератор словаря строит словарь за один проход. Запись читается так: «для каждого name из names — пара с ключом name и значением len(name)». Это короткая форма такого цикла:

>>> lengths = {}
>>> for name in names:
...     lengths[name] = len(name)
...
>>> lengths
{'болт': 4, 'гайка': 5, 'шайба': 5}

§5Обход словаря

Цикл for по словарю перебирает ключи. Когда в цикле нужны и ключ, и значение, перебирают пары методом items. На каждом шаге он даёт кортеж из ключа и значения, и кортеж сразу раскладывают на две переменные. Метод values даёт только значения, keys — только ключи.

Ключи идут в том порядке, в котором их добавляли. Это гарантия языка, начиная с Python 3.7. У множества такой гарантии нет, это видно в §1.

Пока цикл идёт по словарю, ключи в нём добавлять и удалять нельзя. Допустим, со склада нужно убрать товары, которых меньше ста штук.

Первый цикл удалил гайку, на следующем шаге заметил, что размер словаря изменился, и остановился с ошибкой. Шайба осталась: словарь изменён наполовину. Во втором цикле list(stock) сначала копирует ключи в список, и цикл идёт по копии. Поэтому словарь в таком цикле можно менять. Менять значения у существующих ключей в цикле можно и без копии: размер словаря от этого не меняется.

§6Что общего у множества и словаря

Множество похоже на словарь, в котором есть только ключи. У обеих структур три общих свойства.

  1. Каждый ключ хранится один раз. Повторный add во множество ничего не меняет, повторное присваивание в словарь заменяет значение.
  2. Ключ должен быть неизменяемым. Числа, строки и кортежи годятся в ключи, список и другой словарь — нет. Значение в словаре может быть любым, в том числе списком.
  3. Поиск по ключу быстрый. Оператор in, чтение d[k], add и удаление не перебирают все элементы.

Список в роли ключа даёт ошибку со словом unhashable — «нехешируемый». Кортеж из тех же двух строк работает: так ключом становится пара «товар и размер». Список в роли значения допустим. Слово «хешируемый» объясняет, на чём держатся все три свойства: и множество, и словарь — хеш-таблицы. Чтобы понять, откуда берётся быстрый поиск, дальше он сравнивается с поиском в списке — это глава 0.2.

Проверьте себяВ журнале доступа log = [7, 12, 7, 30, 12, 7] записаны номера пропусков в порядке входа. Что даст len(set(log))?

  • 6 — длина журнала. Во множество каждый номер попадает один раз, повторы 7 и 12 не сохраняются.

  • Верно. Разных номеров три: 7, 12 и 30. Множество хранит каждый из них один раз.

  • len возвращает число элементов, а не элемент. Первого элемента у множества нет: порядка в нём нет.

  • len работает со множеством и даёт число разных элементов. Ошибку даёт обращение по индексу, например visited[0].

Проверьте себяПосле строк stock = {'болт': 120} и stock['болт'] = 40 что напечатает print(stock)?

  • Двух одинаковых ключей в словаре не бывает. Присваивание по существующему ключу заменяет значение.

  • Присваивание не складывает значения. Чтобы прибавить, пишут stock['болт'] += 40.

  • Верно. Ключ 'болт' уже был, поэтому новая пара не появилась: прежнее значение 120 заменено на 40.

  • KeyError бывает при чтении отсутствующего ключа. Присваивание по существующему ключу ошибки не даёт.
