Самые частые
элементы

Вторая задача занятия 18 — k самых частых чисел, LeetCode 347. Решение идёт в две фазы: частотный словарь, затем восстановление ответа по частотам. В главе два способа восстановить ответ — сортировка частот и вёдра, замер, который расходится с оценкой, и правило для равных частот, на котором держится стабильность результата.

§1Подсчёт и восстановление ответа

На выборах старосты группы сначала считают бюллетени: напротив каждой фамилии ставят число голосов. Это первая фаза. Затем по числам составляют список: кто на первом месте, кто на втором. Это вторая фаза. Если двое набрали поровну, заранее нужно договориться, кого записать выше.

Задача о самых частых числах устроена так же. Первая фаза — частотный словарь за один проход, O(n). Вторая — по частотам выбрать k чисел. Вернуть нужно сами числа, а не частоты: это восстановление ответа из главы 18.1. Готовый Counter делает обе фазы, но возвращает пары «число — частота», и числа из пар приходится доставать.

Числа 3 и 2 встречаются по два раза, и в ответ попала тройка: она встретилась раньше. Документация Counter это гарантирует — элементы с равной частотой идут в порядке первого появления. Контракт из главы 18.1 требует того же. Ниже обе фазы написаны вручную, без Counter, — так их просят написать на собеседовании.

§2Сортировка частот

Первый способ второй фазы — отсортировать разные числа по убыванию частоты и взять первые k. Сортируются только d разных чисел — ключи словаря. Напишите функцию сами: тесты проверяют порядок при равных частотах, k больше числа разных и пустой список.

Python в этой строке: sorted(count, key=lambda x: -count[x])

sorted(count) перебирает ключи словаря. Аргумент key задаёт, по чему сравнивать: для каждого ключа x вычисляется -count[x], и сортировка идёт по этим числам по возрастанию. Минус превращает «по убыванию частоты» в «по возрастанию». lambda x: -count[x] — короткая запись функции одной строкой.

Сортировка в Python устойчивая: элементы с равным ключом сохраняют исходный порядок. Ниже слова длины 2 и 3 остались в том порядке, в котором стояли.

>>> sorted(['кот', 'ёж', 'дом', 'ус'], key=len)
['ёж', 'ус', 'кот', 'дом']

Прогон выполнен настоящим запуском на [3, 1, 1, 2, 2, 3, 4, 1] и k = 2.

После первой фазы count = {3: 2, 1: 3, 2: 2, 4: 1}: ключи стоят в порядке первого появления. Сортировка ставит единицу первой, а 3 и 2 с равной частотой оставляет в том порядке, в котором они стоят в словаре. Поэтому правило контракта для равных частот выполняется без дополнительного кода: его дают порядок словаря и устойчивость sorted. Время — O(n) на подсчёт и O(d log d) на сортировку d разных чисел. Множитель log d можно убрать.

§3Вёдра «частота → числа»

Частота числа — целое от 1 до n. Поэтому числа можно разложить по вёдрам: ведро с номером c хранит числа с частотой c. Сортировка не нужна — вёдра уже идут по номерам. Остаётся пройти их от n вниз к 1 и собрать первые k чисел. Впишите в схему свои числа и k.

Числа 3 и 2 лежат в одном ведре в порядке первого появления: вёдра заполняются проходом по словарю count, а он хранит этот порядок. Ответ [1, 3] совпадает с сортировкой. Если k больше числа разных, схема соберёт все числа и остановится на последнем ведре.

Вёдер n + 1, по номеру от 0 до n: ведро 0 никогда не заполняется, но так номер ведра равен частоте без сдвига. Прогон показывает, что вёдра 8…4 пустые, и проход по ним — лишняя работа. По оценке её немного: всего вёдер n + 1, и каждое число попадает ровно в одно. Время O(n), память O(n). Насколько это быстрее сортировки, показывает замер.

§4Сортировка, вёдра и Counter: замер

В замере миллион случайных чисел из диапазона d, k = 10. При d = 100 разных чисел сто, при d = 106 — 631 862.

Разных чиселсловарь и sorted, мсвёдра, мсCounter.most_common, мс
10031,0167,220,8
10 00040,6168,526,0
631 862140,4237,486,9

Замер выполнен на ноутбуке автора, Python 3.12.12, Apple M4, медиана трёх запусков по три повтора. Результат расходится с оценкой: вёдра O(n) медленнее сортировки O(n + d log d) при любом d. Причина — строка buckets = [[] for _ in range(len(nums) + 1)]. Она создаёт миллион пустых списков, и только это занимает около 100 мс. Сортировка же упорядочивает только d разных чисел: при d = 100 это сто чисел.

Вёдра можно ускорить: создавать их по наибольшей частоте, max(count.values()) + 1. Тогда при d = 100 вёдер около 10 тысяч, и функция укладывается примерно в 29 мс, наравне с сортировкой. Counter быстрее всех: подсчёт в нём идёт кодом на C, а most_common(k) при малом k выбирает k наибольших через кучу и не сортирует всё.

Отсюда ответ на собеседовании. Вёдра — единственное решение O(n), и о нём спрашивают как об улучшении сортировки: «Можно ли быстрее, чем O(n log n)?». В Python на практике быстрее Counter(nums).most_common(k), а постоянный множитель у вёдер большой. Называют оба решения, а выбор объясняют замером. Обе версии дают одинаковый ответ, пока частоты разные. Для равных частот правило задаёт контракт.

§5Равные частоты

Частая ошибка — при равной частоте сравнивать сами числа: key=lambda x: (-count[x], x). Код выглядит аккуратнее, ответ однозначен, но он противоречит контракту: при равной частоте контракт требует порядок первого появления, а эта версия ставит меньшее число выше.

изменённая версия
верная версия

На [5, 5, 2, 2, 7] и k = 1 изменённая версия возвращает [2], верная — [5]. На LeetCode обе приняты: там ответ гарантированно единственный, и равных частот на границе k нет. Здесь равные частоты бывают, и устойчивость результата — часть контракта. Сортировка по значению нужна в другой задаче, LeetCode 692: там при равной частоте слова прямо требуют упорядочить по алфавиту. Правило для равных частот всегда берут из условия, а если в условии его нет, — спрашивают до кода.

Вторая ошибка той же фазы — вернуть не те данные: пары most_common вместо чисел или частоты вместо чисел. Тест test_numbers_not_counts в песочнице §2 ловит её на [7, 7, 7, 0]: ответ [7], а не [3] и не [(7, 3)]. Обе задачи занятия решены. Граничные входы и ошибки модуля собраны в главе 18.4.

Проверьте себяЧто вернёт верная top_k_frequent([4, 6, 6, 4, 9], 1)?

  • Верно. У 4 и 6 частота 2, и 4 встретилась раньше. Устойчивая сортировка оставляет её первой.

  • 6 встретилась позже четвёрки. При равной частоте контракт требует порядок первого появления.

  • 2 — это частота. В ответе должны быть числа из списка, это восстановление ответа.

  • k = 1: в ответе одно число.

Проверьте себяПочему вёдра в замере §4 медленнее сортировки, хотя оценка у них лучше?

  • Оценка верная: каждое число попадает в одно ведро, вёдер n + 1. Дело в постоянном множителе.

  • Верно. Миллион пустых списков — около 100 мс. Сортировка ста разных чисел почти ничего не стоит.

  • Код на C уменьшает множитель, но сортировка остаётся O(d log d).

  • Обе версии строят частотный словарь одним проходом. Разница — во второй фазе.
