§1Ключ строится из записи

В регистратуре поликлиники карточки стоят по фамилиям. Новая медсестра завела карточку «ИВАНОВ» рядом с уже существующей «Иванов», а у третьей карточки фамилия записана с пробелом в начале и стоит в начале ящика. Пациент один, карточек три. Чтобы найти такие повторы, фамилии сначала приводят к единому виду, а потом сравнивают.

В задачах 17.2 и 17.3 ключом был сам элемент. В данных из форм и таблиц ключ приходится строить: из записи берут поле и приводят к единому виду. Такой ключ называют нормализованным. Для почты нормализация — email.strip().casefold(): убрать пробелы по краям и привести буквы к нижнему регистру. Тогда 'Ivan@Mail.ru', ' ivan@mail.ru' и 'IVAN@mail.ru ' дают один ключ 'ivan@mail.ru'.

Правила нормализации задаёт условие или заказчик. Слишком слабая нормализация пропускает повторы. Слишком сильная сливает разных людей. Если, например, удалять из почты все точки, ivan.petrov@mail.ru и ivanpetrov@mail.ru станут одним клиентом, хотя на многих почтовых сервисах это разные ящики. Поэтому правило записывают в контракт до кода, как в главе 17.1.

У построенного ключа есть граница, которой не было у чисел: он может оказаться пустым. Почта '' и почта из одних пробелов после strip дают ''. Если считать пустую строку обычным ключом, все клиенты без почты окажутся дубликатами друг друга. Контракт из главы 17.1 выносит их в отдельный список no_email.

§2Код и пошаговый прогон

Функция строит словарь «ключ → список id». Для каждого клиента вычисляется ключ. Пустой ключ отправляет id в no_email. Иначе id добавляется в список своего ключа, и если ключа ещё не было, сначала создаётся пустой список. В конце остаются только группы, где id больше одного. Напишите функцию сами: тесты проверяют все три условия ошибочного сценария.

Python в этой строке: if not key: … continue

Пустая строка в условии ложна, непустая — истинна. Поэтому if not key читается «если ключ пустой». Инструкция continue заканчивает текущий шаг цикла: строки ниже не выполняются, цикл переходит к следующему клиенту.

>>> bool(''), bool('  '.strip()), bool('a@b')
(False, False, True)

Прогон выполнен настоящим запуском на пяти клиентах из теста. На ленте — пары [id, почта], кавычки показывают пробелы в почте.

Клиенты 1 и 2 записаны по-разному, но ключ у них один, и на шаге 12 второй клиент находит группу первого. Клиенты 3 и 5 пропущены: их ключи пустые. Ольга после прохода — группа из одного id, и последний шаг её отбрасывает. Ответ — одна группа дубликатов и два клиента без почты. Каждая из трёх частей кода отвечает за одно условие ошибочного сценария. Если убрать любую из них, ответ на этом же входе станет неверным.

§5Исправьте функции

В окне три функции модуля, в каждой одна ошибка из таблицы. Сначала запустите тесты и посмотрите, какие падают. Затем по симптому найдите строку и исправьте её.

В two_sum одна ошибка ломает два теста: при записи до поиска пары перезаписывается и индекс повторного числа. Исправление тоже одно — перенести запись после поиска и не перезаписывать уже записанное число. Когда все тесты зелёные, остаётся объяснить решение.

§6Как объяснить решение

Контроль занятия 17 по КТП: обосновать структуру данных, назвать память O(n), средний и худший случай и объяснить смысл редкого resize. На собеседовании ответ строится в таком порядке.

  1. Какая операция должна быть быстрой. «Для каждого элемента проверяю, встречалось ли значение или его пара левее. Перебор пар — O(n²), поэтому храню пройденное в хеш-структуре». Для ответа «да или нет» — множество, для индекса или списка id — словарь.
  2. Что хранится между итерациями. «В seen — элементы левее текущего, сам текущий добавляется после проверки». Для клиентов: «в groups — id по нормализованному ключу, пустой ключ в словарь не попадает».
  3. Оценки и цена. «Время O(n) в среднем: каждая проверка в среднем O(1). Худший случай — O(n²), если ключи коллизируют, на обычных данных его нет. Память O(n). Словарь иногда растёт и перекладывает все ключи, но таблица удваивается, поэтому рост редкий, и в сумме вставки стоят O(n)». Затем назвать граничные тесты.

«Пара должна давать target, значит, для x я ищу target − x среди чисел левее. Нужен индекс, поэтому словарь «число → индекс». Сначала ищу пару, потом записываю x, иначе x найдёт сам себя. При повторе числа оставляю первый индекс — так требует правило выбора пары. Время O(n) в среднем, память O(n)».

Что показываетПочему словарь, а не множество; порядок строк в цикле; правило из уточнения условия.

«В худшем случае, если все ключи коллизируют, проверка стоит O(n), и проход — O(n²). Для целых чисел и строк на обычных данных этого не бывает. Рост словаря стоит O(n), но случается всё реже, амортизированно вставка O(1). Тесты: [3, 5] и 6 — одно число дважды, [3, 3] и 6, [2, 2, 4] и 6 — первый индекс, пустой список».

Что показываетСредний и худший случай, смысл редкого resize, граничные тесты.
