17.3

Пара с суммой:
словарь «число → индекс»

Вторая задача занятия 17 — индексы двух чисел с заданной суммой, LeetCode 1. От задачи о повторах она отличается одним: в ответе нужен индекс найденной пары, поэтому вместо множества нужен словарь. В главе разобраны идея и код, замер против перебора пар, ошибка с порядком строк и правило, какой индекс хранить при повторе числа.

§1Идея: пара для каждого числа

Покупатель хочет потратить подарочный сертификат на 9000 рублей целиком, купив ровно два товара. Он берёт товар за 5000 и сразу знает, что второй должен стоить 4000. Ему не нужно складывать цену с каждой другой ценой: достаточно спросить у продавца, есть ли товар за 4000 и где он лежит.

Так же устроено решение. Для числа x пара известна заранее: need = target - x. Остаётся узнать, встречалось ли need левее, и если встречалось — на каком индексе. Вопрос «встречалось ли» из главы 17.2 решало множество. Здесь ответ должен содержать индекс, поэтому числа левее хранятся в словаре index: ключ — число, значение — его индекс.

Порядок действий на шаге тот же, что в главе 17.2: сначала найти пару для x среди чисел левее, потом записать x в словарь. Если пары нет и после прохода, функция возвращает None.

§2Код и пошаговый прогон

Напишите функцию сами. Тесты проверяют шесть ответов интервьюера из главы 17.1 и сравнивают результат с перебором пар на трёхстах случайных списках.

Python в этой строке: for j, x in enumerate(nums)

enumerate на каждом шаге даёт пару: индекс и элемент. Запись j, x раскладывает пару на две переменные. Так в цикле доступны и число, и его место в списке.

>>> list(enumerate([3, 8, 4]))
[(0, 3), (1, 8), (2, 4)]

Прогон выполнен настоящим запуском на списке [3, 8, 4, 5] и target 9. Пара — 4 и 5, она стоит в конце, поэтому словарь успевает заполниться.

Для первых трёх чисел пары левее нет: 6, 1 и 5 в словаре не встречаются. Каждое число записывается в словарь: для чисел правее оно может стать парой. Для пятёрки нужна четвёрка, она в словаре с индексом 2, и ответ (2, 3). Перебор пар нашёл бы тот же ответ, сложив шесть пар; словарь сделал четыре проверки.

§3Перебор пар или словарь: замер

Перебор пар для каждого j проверяет все i < j. В замере список из n чётных чисел, а target равен −1: сумма двух чётных чисел нечётной не бывает, и пары нет. Это худший случай — оба решения проходят список до конца.

nперебор пар, мссловарь, мс
1 00010,90,053
2 00040,40,101
4 000167,20,206
8 000669,60,415

Замер выполнен на ноутбуке автора, Python 3.12.12, Apple M4, медиана трёх запусков по пятнадцать повторов. Перебор растёт вчетверо при удвоении n, словарь — вдвое. На 8000 чисел перебор работает две трети секунды, словарь — 0,4 мс, в 1600 раз быстрее. Словарь медленнее множества из главы 17.2 примерно в 2,5 раза на том же n. На каждом шаге решение вычисляет need, делает две проверки и хранит индекс.

Плата — память O(n): словарь хранит все числа, у которых пока нет пары. На собеседовании эту плату называют вместе с ответом: «Время O(n) в среднем, память O(n). Если бы список был отсортирован и индексы не нужны, хватило бы двух указателей с памятью O(1)».

§4Число нашло само себя

Та же ошибка, что в главе 17.2: строку index[x] = j ставят перед поиском пары. Для чисел, у которых need равно самому x, — это x = target / 2 — поиск находит в словаре сам x. Ниже обе версии запущены на [3, 4, 2] и target 6.

Изменённая версия возвращает (0, 0): тройка в сумме с собой даёт 6. Верная версия на первом шаге пары не находит, записывает тройку и находит пару 4 + 2 на индексах 1 и 2. На входах без числа target / 2 обе версии отвечают одинаково. Поэтому в тестах занятия есть [3, 5] и target 6 — первый ответ интервьюера из главы 17.1.

§5Первое вхождение или последнее

Строка if x not in index перед записью нужна для правила из контракта: из пар с одинаковым j вернуть пару с наименьшим i. Если число повторяется, в словаре остаётся индекс его первого вхождения. На [2, 2, 4] и target 6 подходят пары (0, 2) и (1, 2).

Без проверки вторая двойка перезаписывает индекс, и ответ — (1, 2). Это тоже пара с суммой 6, и на LeetCode, где пара единственная, обе версии принимаются. По контракту занятия верна только первая. Правило выбора пары — пример ответа интервьюера, который меняет код: без вопроса «какую пару вернуть, если их несколько» обе версии кажутся одинаковыми.

Задача о повторах и задача о паре решены одним приёмом. Структура хранит то, что уже пройдено, и отвечает на вопрос о текущем элементе в среднем за O(1). Дальше этот приём применяется к данным, где ключ нужно сначала построить: почта клиента с пробелами, в разном регистре или пустая.

Проверьте себяПочему в two_sum нельзя взять множество вместо словаря?

  • Умеет, это та же хеш-таблица. Скорость одинаковая, разница — в том, что нужно вернуть.

  • Верно. Ответ — индексы, а множество хранит только числа. Индекс хранится значением словаря.

  • Можно: любое целое число хешируемо, отрицательное тоже.

  • Словарь тоже хранит каждое число один раз, как ключ. Для пары [3, 3] это не мешает: первая тройка лежит в словаре, вторая находит её.

Проверьте себяЧто вернёт верная two_sum([5, 1, 5], 10)?

  • Так ответила бы версия, которая записывает число до поиска пары. Верная версия на первом шаге пары не находит.

  • Верно. На шаге j = 2 нужна пятёрка, она в словаре с индексом 0.

  • Индексы в паре разные: один элемент дважды не берётся.

  • Пара есть: элементы с индексами 0 и 2, 5 + 5 = 10.
