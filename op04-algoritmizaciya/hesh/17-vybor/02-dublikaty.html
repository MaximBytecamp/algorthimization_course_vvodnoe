Повторы:
множество уже встреченных

Первая задача занятия 17 — есть ли в списке повтор, LeetCode 217. В главе она решена проходом со множеством уже встреченных элементов. §1Идея: что уже встречалось

Простое решение сравнивает каждый элемент со всеми, что стоят правее: для i перебираются все j > i. Если пара равных нашлась, повтор есть. Пар n(n − 1)/2, поэтому это O(n²). Внутренний цикл здесь только ищет: есть ли значение, равное items[i].

Этот поиск можно перевернуть. Вместо вопроса «есть ли такой элемент правее» задают вопрос «был ли такой элемент левее». Элементы левее уже пройдены, и их можно складывать во множество seen. Тогда на каждом шаге нужна одна проверка x in seen, в среднем O(1), и весь проход стоит O(n). Так работает кассир из главы 17.1: он смотрит в список пробитых номеров и чеки не перечитывает.

Напишите функцию сами. Тесты проверяют контракт из главы 17.1: пустой список, список без повторов, остановку на первом повторе и совпадение с перебором пар на трёхстах случайных списках.

Прогон ниже выполнен настоящим запуском Python на списке [4, 1, 7, 1, 3]. Нажимайте «шаг →» и следите за множеством seen в таблице переменных: перед проверкой в нём ровно те элементы, что стоят левее текущего.

На четвёртом элементе, единице, проверка находит её во множестве — единица стояла на индексе 1. Тройка в конце списка не проверяется: ответ уже известен. Во втором прогоне повторов нет, и цикл доходит до конца. Множество к этому моменту содержит все элементы списка — это и есть O(n) памяти из контракта.

§3Четыре способа: замер

Занятие 17 требует сравнить поиск в списке и в хеш-структуре. Ниже — четыре решения одной задачи. Перебор пар ищет в списке, сортировка ставит равные элементы рядом, два последних решения ищут во множестве.

В замере список из n разных чисел, перемешанных случайно. Повторов нет, поэтому каждое решение работает до конца — это худший случай для всех четырёх.

Замер выполнен на ноутбуке автора, Python 3.12.12, Apple M4. Каждое число — медиана трёх запусков, в каждом запуске — медиана пятнадцати повторов. Перебор пар при удвоении n замедляется вчетверо: на 8000 чисел он в 3200 раз медленнее множества. Сортировка и множество растут примерно вдвое. Сортировка медленнее множества в 2,5–4 раза: множитель log n и построение нового списка.

Короткая запись len(set(items)) быстрее цикла в 2–3 раза. Множество в ней строится кодом на C, а цикл for выполняет интерпретатор Python. Но у короткой записи нет раннего выхода: она строит множество из всего списка, даже если повтор стоит в начале. На списке из миллиона чисел, где повтор — третий элемент, цикл отвечает за 0,2 мкс, а len(set(...)) — за 7,4 мс. Контракт из главы 17.1 требует остановки на первом повторе, поэтому тест test_stops_early короткую запись не пропускает. Если ранний выход не нужен, а входы небольшие, короткая запись — нормальный ответ на собеседовании, но о нём стоит сказать.

§4Добавить до проверки

Частая ошибка — поменять местами две строки тела цикла: сначала seen.add(x), потом if x in seen. Код выглядит так же, но смысл проверки меняется: она спрашивает о множестве, в которое x уже положили. Ниже обе версии запущены на списке без повторов.

Изменённая версия отвечает True на первом же элементе любого непустого списка. Тест на список с повтором её пропускает, поэтому в тестах занятия есть [4, 1, 7] и [1, 2]: на них ответ должен быть False. Правило переносится на все задачи этого вида: во множестве на момент проверки должны быть только элементы левее текущего.

§5Порядок первого появления

КТП занятия 17 меняет условие: вернуть элементы без повторов, сохранив порядок их первого появления. Запись list(set(items)) не подходит: порядок множества определяется ячейками таблицы, глава 0.6. Порядок хранят отдельно — в списке ответа. Множество отвечает на вопрос «был ли элемент», список хранит ответ.

Повторная четвёрка и повторная единица проверку не проходят, и в ответ попадают только первые вхождения: [4, 1, 7]. Тот же ответ даёт list(dict.fromkeys(items)) из главы 0.6 — словарь хранит порядок вставки сам. Цикл со множеством длиннее, но его легко изменить: например, сравнивать элементы без учёта регистра, проверяя во множестве x.casefold(), а в ответ добавляя исходный x. Вторая задача занятия — пара с заданной суммой — устроена так же, но в ответе нужен индекс, и множества ей мало. Это глава 17.3.

Проверьте себяСтудент решил задачу так: return len(set(items)) < len(items). На каком входе его ответ не совпадёт с контрактом has_duplicate?

  • 0 < 0 — False, как и требует контракт.

  • Строки хешируемы, множество строится так же, ответ верный.

  • Верно. Значение True или False совпадает с контрактом на любом списке. Но множество строится из всего входа, и тест на ранний выход не проходит.

  • 1 < 1 — False: повтора нет, ответ верный.

Проверьте себяСколько дополнительной памяти использует has_duplicate на списке из n разных чисел?

  • Переменная одна, но к концу прохода в множестве лежат все n чисел.

  • Верно. Повторов нет, поэтому каждое число добавляется в seen. Это худший случай по памяти.

  • Множество хранит элементы, а не пары. Пары перебирает решение за O(n²), но памяти оно не берёт.

  • Сортировка в Python строит новый список, это O(n). Множество тоже O(n).
