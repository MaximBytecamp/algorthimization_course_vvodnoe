§2Порядок работы на паре

По КТП занятие 20 — дизайн и код. Сначала 15 минут на API кэша, затем 45 минут на задачи 1–3, без ИИ и поиска. Работа идёт в папке lesson_20 на своём компьютере, нужен Python с pytest. Если Python ещё не настроен, начните с песочниц в главах 20.2–20.4. Сдать всё равно нужно solution.py с зелёным pytest.

  1. Скопируйте папку lesson_20 в portfolio/lesson_20/ личного репозитория и выполните python -m pytest tests.py -v. Все 34 теста должны упасть: так проверяется, что pytest нашёл файлы и запустил тесты.
  2. Откройте initial_attempt.txt и запишите API кэша: операции, что каждая возвращает и меняет, ответы на шесть вопросов из главы 20.1, §5. Разберите руками три сценария оттуда — выпишите кэш после каждой операции. Сверить себя можно на схеме главы 20.1, §3.
  3. Засеките 45 минут. Напишите build_index и CountingCache. Проверка: python -m pytest tests.py -k "index or counting".
  4. Напишите LRUCache: -k "lru and LRUCache and not Linked". Если тест падает, найдите симптом в сводке главы 20.4, §2.
  5. Запустите замер: python bench.py > bench_results.txt. Он идёт около 5 секунд. Заполните complexity_note.md и защитите выбор реализации перед соседом по схеме из главы 20.4, §4.
  6. Если осталось время — LRUCacheLinked, LRU без OrderedDict: -k Linked. Образец — углубление в главе 20.3, §3. Это продвинутый уровень контроля КТП.
  7. Если и это готово — extra.py: своё множество на корзинах без set и dict, упорядоченный поток, среднее время поездки в метро. Проверка: python -m pytest tests_extra.py -v.

3 · Множество со случайным элементомКласс RandomizedSet, LeetCode 380: insert(val), remove(val) — True, если множество изменилось; get_random() — случайный элемент с равной вероятностью. Каждая операция — O(1) в среднем. Не меньше шести своих тестов: повторный insert, remove отсутствующего, remove последнего элемента списка, remove единственного, get_random только из множества, равномерность на 10 000 вызовах.Словарь «значение → индекс» — модуль 17; два хранилища рядом — глава 20.3

Тест к bugs_20.py засчитывается, если до исправления он падает, а после — проходит. Тест, который проходит и на ошибочной версии, ошибку не находит.

Задача 3 устроена как LRU: одной структуры мало. Множество находит элемент за O(1), но случайный элемент из него за O(1) не выбрать: у множества нет индексов. Список выбирает случайный элемент по индексу, но удаление из середины стоит O(n). Вместе они дают всё: словарь хранит, где элемент лежит в списке, а удаление ставит на его место последний элемент. Почему одной структуры не хватает, нужно объяснить в заметке.
