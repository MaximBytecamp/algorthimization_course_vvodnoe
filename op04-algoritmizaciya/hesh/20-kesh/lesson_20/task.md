## Формат пары

По КТП занятие — дизайн и код. Сначала 15 минут на API кэша: записать в `initial_attempt.txt` операции,
что каждая возвращает и что меняет, ответы на вопросы из главы 20.1, §5. Затем задачи 1–3 — 45 минут,
без ИИ и поиска. После — защита выбора по схеме из главы 20.4, §4: базовый уровень — контракт,
продвинутый — почему get и put O(1) и почему выбран OrderedDict.

## Задачи

1. **Индекс по полю.** `build_index(records, field)`: словарь «поле → запись», повтор ключа — ValueError.
2. **Кэш с подсчётом.** `CountingCache(load)`: get, поля hits и misses; значения None и 0 тоже кэшируются.
3. **LRU на OrderedDict** (LeetCode 146). `LRUCache(capacity)`: get, put, len — по контракту главы 20.1, §6.
4. **Расширение: LRU на словаре и двусвязном списке.** `LRUCacheLinked` — тот же контракт без OrderedDict
   и метод `keys()`. Это продвинутый уровень КТП.

Обязательны задачи 1–3, задача 4 — после них. Кто закончил всё, берёт `extra.py`: три задачи и 10 тестов.

## Порядок работы

1. Скопировать папку в `portfolio/lesson_20/` личного репозитория, выполнить `python -m pytest tests.py -v`.
   Все 34 теста падают.
2. Записать API кэша в `initial_attempt.txt` и разобрать руками три сценария оттуда.
3. Решить `build_index` (`python -m pytest tests.py -k index`) и `CountingCache` (`-k counting`).
4. Решить `LRUCache` (`-k "lru and LRUCache and not Linked"`).
5. Запустить `python bench.py > bench_results.txt` и заполнить `complexity_note.md`.
6. Если осталось время — `LRUCacheLinked` (`-k Linked`), затем `extra.py`.

## Ограничения

- `LRUCache.get` и `put` — O(1): тест `test_lru_fast` не пропускает порядок в списке.
- `LRUCacheLinked` не использует OrderedDict.
- ИИ и поиск решений — только после 45 минут и первой собственной версии.
