Мок-интервью
по задачам модуля

В этой главе восемь задач на проектирование структур данных в формате алгоритмической секции. Классы из LeetCode записаны функциями над списком операций, как в тестах LeetCode: так их можно проверить на странице и пройти по шагам. Каждая проходит этапы по шаблону interview canvas: условие, уточнения, примеры, перебор и идея, сложность, код, проверка. Этапы открываются по одному, рядом идёт секундомер с планом на 25 минут. Код пишется и проверяется прямо на странице. Тренажёр устроен так же, как в главах 13.6–15.6 книги о строках и в главах 8.6–12.6 книги о массивах.

§1Как устроен тренажёр

Задача разбита на семь этапов шаблона interview canvas. Сначала открыт только первый; кнопка «Этап пройден» открывает следующий и записывает, сколько минут ушло на этап. Над этапами — полоса с планом: сколько минут отводится на каждый этап, чтобы уложиться в 25.

В каждом этапе сначала работа самостоятельно, потом сверка. Пересказ, перебор, правило шага и эталонный код спрятаны в раскрывающихся блоках, ответы к примерам скрыты до нажатия кнопки. В этапе «Перебор и идея» нужно выбрать технику из шести: OrderedDict для порядка обращений, словарь как готовый ответ, список корзин вместо dict, словарь списков с двоичным поиском, два согласованных словаря и словарь времени истечения. Все шесть — словарь плюс что-то ещё, и различаются они тем, что именно добавлено.

Секундомер запускается кнопкой «Старт» и не ограничивает время. В конце задачи появляется таблица «план — фактически». Кнопка «Открыть все этапы» показывает задачу целиком: так задачу разбирают после попытки или читают как разобранный пример.

В тренажёр не входят задачи дополнительного набора extra.py — LeetCode 705, 1656, 1396 — и задача домашнего задания LeetCode 380. Их решения здесь были бы подсказкой.

    Перебор, который называет кандидат

    Хранить порядок в списке ключей: перенос — remove, O(capacity) на операцию.

    ТехникаКакая техника подходит?

    • Верно. Кроме поиска по ключу нужен порядок обращений, и меняется он при каждой операции. OrderedDict берут, когда кроме поиска по ключу нужен порядок обращений: перенос в конец и удаление первого — O(1).

    • Словарь как готовый ответ берут, когда запросы повторяются: индекс строится заранее, кэш заполняется при промахах.

    • Список корзин берут, когда словарь использовать нельзя: ключ попадает в корзину по остатку, внутри корзины — короткий перебор.

    • Словарь списков берут, когда у ключа много значений во времени. Значения приходят по возрастанию времени, поэтому список отсортирован и ищется двоичным поиском.

    • Два словаря берут, когда нужно отвечать на два разных вопроса за O(1): «сколько раз x» и «есть ли частота f», «код по ссылке» и «ссылка по коду».

    • Словарь «ключ → время истечения» берут, когда записи живут ограниченное время: продление — перезапись, проверка — сравнение со временем.

    Правило шага
    1. get. Промах — −1; попадание — move_to_end и значение.
    2. put. Существующий ключ — move_to_end; затем запись.
    3. Вытеснение. Если ключей больше capacity — popitem(last=False).

                  Перебор, который называет кандидат

                  Хранить ссылки в списке, код — индекс; повтор искать перебором: O(n) на ссылку.

                  ТехникаКакая техника подходит?

                  • Словарь как готовый ответ берут, когда запросы повторяются: индекс строится заранее, кэш заполняется при промахах.

                  • Список корзин берут, когда словарь использовать нельзя: ключ попадает в корзину по остатку, внутри корзины — короткий перебор.

                  • Словарь списков берут, когда у ключа много значений во времени. Значения приходят по возрастанию времени, поэтому список отсортирован и ищется двоичным поиском.

                  • Верно. Нужно отвечать на два вопроса: код по ссылке и ссылку по коду. Два словаря берут, когда нужно отвечать на два разных вопроса за O(1): «сколько раз x» и «есть ли частота f», «код по ссылке» и «ссылка по коду».

                  • Словарь «ключ → время истечения» берут, когда записи живут ограниченное время: продление — перезапись, проверка — сравнение со временем.

                  • OrderedDict берут, когда кроме поиска по ключу нужен порядок обращений: перенос в конец и удаление первого — O(1).

                  Правило шага
                  1. Новая ссылка. Код 'u' + str(len(code_of)), запись в оба словаря.
                  2. Повтор. Код из code_of.
                  3. Ответ. Пара (код, url_of[код]).

                  Сложность называют до кода: интервьюер соглашается с решением раньше, чем на запись потрачено время.

                  Код эталонного решения

                  Код проходят по шагам на первом примере. На секции это делают руками; ниже тот же проход — пошаговым прогоном эталонного решения. Затем интервьюер задаёт вопрос по решению.

                  Вопрос интервьюераИнтервьюер спрашивает: «Почему не хеш ссылки в качестве кода, hash(url)?»

                  • hash принимает строки. Проблема в том, что его значение меняется между запусками.

                  • Хеш длинный, около 19 цифр. Дело в изменчивости и коллизиях.

                  • Верно. Это глава 0.3: хеш строки нельзя сохранять. Для постоянных кодов берут счётчик или стойкий хеш с проверкой коллизий.
