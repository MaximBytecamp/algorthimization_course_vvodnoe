У теста есть ожидаемый результат

Тестовый случай — конкретный вход и ожидаемый результат по согласованному контракту. Запуск без заранее известного ответа показывает поведение программы, но ещё не проверяет правильность.

Обычный сценарий называют happy path. Например, максимум для [3, 8, 2] равен 8. Граничный случай проверяет край допустимого диапазона: пустой список, минимальную длину или предельное значение.

Вход для find_maxОжидаемЗачем проверяем
[3, 8, 2]8Максимум внутри
[8, 3, 2]8Максимум в начале
[2, 3, 8]8Максимум в конце
[-7]−7Один элемент
[-8, -3, -10]−3Все числа отрицательные
[5, 5, 5]5Все значения равны
[]ValueErrorОтказ на пустом входе по контракту
Здесь find_max требует непустой список и выбрасывает ValueError при нарушении требования. У second_max другой контракт: пустой вход допустим и даёт None.

Таблицу можно превратить в программу: пройти по парам «вход — ожидаемый ответ» и сравнить с фактическим результатом. Возьмём версию find_max, в которой максимум начинается с нуля.

Три строки из пяти прошли, и по ним ошибку не заметить. Две строки с отрицательными числами показывают, где функция расходится с контрактом.

[-1]: ожидаем −1, получаем 0. Условие -1 > 0 ложно, поэтому best остаётся равным нулю. Утверждение «функция находит максимум любого непустого списка целых чисел» опровергнуто.

Контрпример — вход, на котором обещание алгоритма нарушается. Одного такого входа достаточно, чтобы показать ошибку. Несколько успешных тестов не доказывают корректность для всех допустимых входов.
