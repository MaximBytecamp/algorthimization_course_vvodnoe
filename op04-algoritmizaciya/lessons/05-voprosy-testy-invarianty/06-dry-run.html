Ручной прогон и границы цикла

Записываем состояния переменных, проверяем полуинтервалы и находим пропущенный элемент.

На этой странице1. Dry run: выполняем строки вручную2. Правая граница range не включается3. Граница зависит от действия внутри цикла4. Проверьте себя

Dry run: выполняем строки вручную

Ручной прогон (dry run) — последовательное выполнение алгоритма на конкретном входе с записью состояний. Мы фиксируем значения до шага, результат условия и изменения после шага. Так видно, где фактическое выполнение расходится с контрактом.

Перед кодом · кейсВторой максимум без сортировки

Ситуация«Найдите второй максимум за один проход, дополнительная память O(1)».

Что стоит спросить и что меняет ответ
  1. Бывают ли отрицательные числа?Если бывают, пара first = 0, second = 0 не подходит: нулей может не быть во входе.
  2. Одинаковые значения считаются разными?Для [5, 5, 3] ответ 5 или 3. От этого зависит, что делать при value == first.
  3. Что вернуть, если значений меньше двух?Нужна отметка «ещё не найдено», например None.
  4. Почему память O(1)?Ограничение запрещает sorted() и set(). Остаются две переменные, которые обновляются на каждом шаге.

Правая граница range не включается

Полуинтервал [start, end) включает начало и исключает конец. range(2, 5) перебирает 2, 3, 4. Индексы списка длины n — от 0 до n − 1, поэтому полный проход задаётся range(n).

Вторая строка — индексы исходной версии для [4, 8, 0]: индекса 2 нет. Третья — полный проход range(len(numbers)).

Перед кодом · кейсЕсть ли ноль

Ситуация«Верните True, если в списке есть ноль».

Что стоит спросить и что меняет ответ
  1. Пустой список допустим?Если да, ответ False, и цикл не должен обращаться к элементам.
  2. Ноль может стоять последним?Может, поэтому тест с нулём в последней ячейке входит в набор. Он проверяет правую границу цикла.
  3. Какие типы в списке?В Python 0.0 == 0 истинно, а строка "0" с нулём не совпадает.

Граница зависит от действия внутри цикла

В проверке соседей мы читаем numbers[i + 1]. Здесь range(len(numbers) - 1) нужен, чтобы последний правый сосед имел индекс n − 1. Одинаковая граница может быть ошибкой в одном алгоритме и правильной в другом.

Перед кодом · кейсПроверка порядка

Ситуация«Проверьте, отсортирован ли список».

Что стоит спросить и что меняет ответ
  1. По возрастанию или по убыванию?Меняется знак сравнения соседей.
  2. Равные соседи допустимы?Неубывание разрешает [2, 2], строгое возрастание — нет. Разница в одном символе: > или >=.
  3. Пустой список и один элемент — упорядочены?Обычно да: в них нет пары, нарушающей порядок. Эти входы попадают в тесты.
  4. Бывают ли элементы разных типов?В Python 3 сравнение числа со строкой вызывает TypeError.

ДоговорилисьНеубывание, равные соседи допустимы, пустой и одноэлементный список дают True.
