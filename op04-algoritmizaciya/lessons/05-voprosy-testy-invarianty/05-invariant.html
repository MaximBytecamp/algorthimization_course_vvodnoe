Предусловие, инвариант и постусловие

Для функции поиска максимума контракт уже есть: вход непустой, результат — наибольший элемент. Тесты показывают, что функция работает на выбранных входах. Чтобы объяснить, почему она работает на любом допустимом входе, описывают, что верно до цикла, на каждом шаге и после него.

УтверждениеЧто означает для find_max
ПредусловиеДо основного алгоритма список непустой и содержит целые числа.
Инвариант циклаПосле обработки первых k элементов best равен максимуму среди этих k элементов.
ПостусловиеПосле успешного завершения результат принадлежит списку и не меньше любого его элемента.

Инвариант цикла — утверждение, которое истинно в одной и той же точке цикла на каждой итерации. Обычно эту точку выбирают между итерациями: предыдущие элементы уже обработаны, следующий ещё нет. Значение best по ходу цикла меняется, но утверждение «best — максимум обработанной части» остаётся верным.

То же в таблице. При k = 2 максимум всего списка ещё не найден, но инвариант уже выполняется: 4 — максимум среди первых двух элементов.

Три шага объяснения корректности

  • Инициализация. Перед циклом k = 1, best = numbers[0]. Это максимум одноэлементной обработанной части.
  • Сохранение. Сравниваем следующий элемент с best. Если он больше, заменяем best; иначе сохраняем прежний. После шага best — максимум первых k + 1 элементов.
  • Завершение. Цикл конечен: range перебирает оставшиеся индексы. Когда обработаны n элементов, инвариант даёт максимум всего списка — требуемое постусловие.
Инвариант сам по себе не доказывает, что цикл остановится. Для while дополнительно объясняют, как меняется мера оставшейся работы. Здесь число ещё не обработанных элементов уменьшается на один.

Проверка инварианта через assert

Инвариант можно проверить и во время работы программы. Добавим assert после каждого шага: best должен совпадать с максимумом обработанной части numbers[:k].

Программа дошла до конца, значит на каждом шаге утверждение было истинным. Вызов max(numbers[:k]) делает проверку медленной — O(n) на каждом шаге, — поэтому так проверяют только при отладке, а в готовом решении строку с assert убирают.

Как сформулировать инвариант

Перед кодом · кейсСумма и счётчик за один проход

Ситуация«Числа приходят по одному. После каждого нужно знать сумму и количество положительных».

Что стоит спросить и что меняет ответ
  1. Ноль считается положительным?Нет — условие value > 0, да — value >= 0. Тест с нулём отличает эти версии.
  2. Что вернуть, если чисел ещё не было?Сумма 0 и счётчик 0. Это начальные значения, и их проверяет случай k = 0.
  3. Можно ли сохранить все числа?Если чисел много или они приходят потоком, хранить их списком нельзя. Тогда остаются две переменные, и для каждой нужно точно сказать, что она содержит после очередного числа. Это и есть инварианты.

ДоговорилисьСчитаем строго положительные и не храним сами числа.

Открыть разбор

total равен сумме первых k элементов; count равен числу строго положительных среди первых k элементов. При k = 0 сумма и количество равны нулю. Добавление очередного элемента и условное увеличение счётчика сохраняют обе формулировки.

Проверим свою формулировку на входе [3, -2, 0, 5], печатая состояние после каждых k элементов:

При k = 2 сумма первых двух элементов 3 + (−2) = 1, положительный среди них один. При k = 3 ноль не увеличил счётчик: условие value > 0 строгое.

Инвариант описывает смысл переменной, поэтому формулировку проверяют на точность. Запись «best = 8» описывает состояние одного запуска на одном входе. В записи «best хранит максимум» не сказано, максимум чего. Формулировка «best — максимум среди первых k элементов» называет и смысл, и область, поэтому её можно проверить на каждом шаге. Инвариант не путают с условием цикла: while left < right определяет, будет ли следующая итерация, и после выхода из цикла становится ложным.
