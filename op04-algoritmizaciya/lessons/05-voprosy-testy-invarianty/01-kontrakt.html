Быстрое решение тоже может ошибаться

На прошлой паре мы сравнивали время и память алгоритмов. Теперь проверим другую сторону решения: соответствует ли результат условию. Линейный проход может быть быстрым и всё же вернуть число, которого во входе вообще нет.

Получили задачу «найдите второй по величине элемент массива». Для [10, 10, 5] возможны ответы 10 и 5. Сначала нужно договориться, считаем ли мы позиции в отсортированном массиве или различные значения.

Контракт задачи

Контракт описывает допустимый вход и обещанный результат. Он также задаёт поведение в особых случаях. Уточняющий вопрос помогает заполнить пробел в контракте; предположение в коде этот пробел скрывает.

Что уточняемДоговорённость для практикума
ВходСписок целых чисел; пустой список допустим.
ЗначенияОт −10⁹ до 10⁹, дубликаты и ноль допустимы.
РазмерОт 0 до 100 000 элементов.
ОтветВторое различное по величине значение.
Ответа нетВернуть None, если различных значений меньше двух.
Изменение входаИсходный список сохраняется.

Например, [10, 10, 5] → 5, [10, 10] → None, [-7, -2, -9] → -7. Ответ None означает отсутствие второго различного значения; это не то же самое, что число 0.

Ограничения влияют на выбор алгоритма

Если данные гарантированно отсортированы, число можно искать бинарным поиском за O(log n). Без этой гарантии доступен линейный поиск за O(n). Сортировать список ради одного поиска обычно невыгодно: сама сортировка требует времени.

Выбор с учётом размера

Есть решения O(n²) и O(n log n). Сравните их для n ≤ 50 и n ≤ 1 000 000. Почему нельзя назвать O(n²) плохим при любом входе?

Открыть разбор

При n = 50 квадрат размера равен 2 500; при n = 1 000 000 — 10¹². Для малого входа простой двойной цикл может быть разумным. Для большого нужен другой подход. Это оценки количества работы, а не обещание конкретного времени: учитываем лимит, стоимость операции и измерения.
