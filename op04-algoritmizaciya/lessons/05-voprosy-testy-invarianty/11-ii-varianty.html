1. Задача: повторный номер пропуска

В этой лабораторной разобраны пять способов решить один вопрос, оценка их времени и памяти, а затем выбор алгоритма для пяти наборов ограничений.

Представьте стопку номерков у входа. Можно сравнить каждый номерок со всеми следующими, складывать уже встреченные номера в отдельную коробку или выложить номерки по порядку и посмотреть на соседние. Все способы отвечают на один вопрос, но требуют разного времени и места.

На турникет за день пришёл список целых номеров пропусков. Нужно определить, встречается ли хотя бы один номер дважды.

Напишите функцию has_duplicate(cards), которая возвращает True, если в списке есть повтор, иначе False.

Контракт один для всех вариантов

cards — список целых чисел, в том числе отрицательных. Пустой список и список из одного элемента повтора не содержат. Функция возвращает только True или False. Если вариант меняет переданный список, это нужно явно указать: формально он решает задачу, но подходит не каждому заказу.

Сначала — без ИИ

За три минуты запишите свою первую идею и её предполагаемую сложность. Не обязательно писать код. Это контрольная точка: потом можно увидеть, расширил ли ИИ набор идей или только красиво оформил первую.

2. Банк задач

Преподаватель назначает две задачи. Для каждой получите у ИИ минимум четыре разных подхода, напишите код двух подходов и выберите решение для трёх условий.

№Функция и результатУсловия для выбора
1has_duplicate(cards): есть ли повторA: n ≤ 30, памяти мало. B: 10 000 000 чисел приходят потоком. C: значения 0…999, n = 5 000 000.
2has_pair_sum(numbers, target): есть ли пара с суммой targetA: n ≤ 100, память почти не выделяется. B: n = 2 000 000, память есть. C: список уже отсортирован, менять его нельзя.
3count_distinct(numbers): число разных значенийA: n ≤ 500. B: n = 10 000 000, значения любые целые. C: значения 0…9999, n = 10 000 000.
4common_unique(left, right): общие значения без повторовA: по 300 элементов, памяти мало. B: по 1 000 000 элементов, память есть. C: оба списка отсортированы и менять их нельзя.
5missing_id(ids, n): пропущенное число из диапазона 0…n; пропуск ровно одинA: n ≤ 1000. B: n = 10 000 000, дополнительной памяти почти нет. C: порядок ids нужен после функции.
6most_frequent(numbers): самое частое число; при равенстве — меньшееA: n ≤ 100. B: n = 3 000 000, значения любые. C: значения 0…1000, n = 3 000 000.
7is_anagram(left, right): строки состоят из латинских букв; регистр важенA: строки до 50 символов, памяти мало. B: строки по 10 000 000 символов. C: только буквы a…z.
8first_repeat_index(numbers): индекс второго появления первого повторившегося значения; если повторов нет — -1A: n ≤ 100. B: n = 5 000 000, результат нужен сразу при чтении потока. C: значения 0…10000.
Для каждой задачи

Проверьте пустой вход, один элемент, повтор или нужный результат в начале, в конце и отсутствие результата. Добавьте тест под ограничение C.

Запрос 2. Получить код по одному контракту

Запрос 3. Проверить ИИ как рецензента

Проверяйте ответы ИИ

Нейросеть предлагает гипотезы, которые нужно проверить. Утверждение «O(1) памяти» для сортировки списка Python требует проверки по документации выбранного метода. Оценку для множества тоже уточняют: O(n) может быть средней, а не худшей оценкой. В отчёт включают найденные ограничения и неточности.

Проверьте две оценки сложности

  1. Что означает O(n) у множества? Для хеш-таблицы отдельно запишите ожидаемую и худшую оценку. Почему они могут отличаться?
  2. Что означает «на месте» в выбранном языке? Если вы сортируете исходный список, контракт нарушается. Если делаете копию — растёт память. Проверьте утверждение ИИ по документации или коротким опытом, а не по интуиции.

Запустите обе функции на тестах задачи. Добавьте два теста: на границу контракта и на ограничение одного варианта.

6. Что сдать

Сдаётся папка lesson_05_ai. Выполните две назначенные задачи. В паре выводы к A, B и C каждый пишет сам.
