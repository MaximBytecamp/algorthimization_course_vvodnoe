Как выбрать начальное значение

Запись best = 0 содержит неявное предположение: максимум списка не меньше нуля. Для списка из отрицательных чисел оно неверно. С минимумом то же самое: старт с нуля даёт неверный ответ, если все числа положительные. Начальное значение выбирают так, чтобы оно соответствовало смыслу переменной на любом допустимом входе. Для максимума или минимума непустого списка это первый элемент.

Пустой вход

Перед кодом · кейсПустой вход

СитуацияОтрицательные числа уже учтены: начальный максимум берётся из списка. Осталось решить, что делать, если список пуст и первого элемента нет.

Что стоит спросить и что меняет ответ
  1. Пустой список — допустимый вход?Если нет, в контракте пишут «вход непустой», и numbers[0] безопасен. Если да, нужна отдельная ветка.
  2. Для пустого списка вернуть None или ошибку?None легко пропустить: вызывающий код сложит его с числом и упадёт в другом месте. Исключение останавливает программу там, где нарушен контракт.
  3. Может ли вместо списка прийти None?Это отдельный случай. Условие if not numbers истинно и для None, поэтому функция выбросит ту же ошибку с неточным сообщением «numbers must not be empty».

ДоговорилисьПустой список — ошибка ValueError. Функция ниже проверяет это первой строкой.

Условие if not numbers истинно для пустого списка. Тогда инструкция raise прерывает функцию и выбрасывает исключение ValueError. Если список не пустой, первый элемент гарантированно существует, и его можно взять как начальный максимум.

Проверим оба случая: обычный вход и пустой список.

Первая строка — ответ для [-8, -3, -10]. Дальше Python печатает трассировку (traceback) — цепочку вызовов, которая привела к ошибке. Её читают снизу вверх: в последней строке тип ошибки ValueError и текст сообщения, выше — строка с raise. Такой результат для пустого входа и записан в контракте.

Проход начинается с индекса 1: элемент с индексом 0 уже учтён. Мы обращаемся к элементам по индексам и не создаём срез numbers[1:]. Поэтому дополнительная память прохода O(1); срез списка потребовал бы O(n).

В оценках здесь считаем сравнение целых чисел из заданного диапазона операцией O(1). Время полного прохода O(n).

Ситуация«Есть ли в списке два числа, сумма которых равна target?»

Что стоит спросить и что меняет ответ
  1. Можно ли взять один элемент дважды?Для [3] и target = 6 ответ True или False. От этого зависит, с какого индекса начинается внутренний цикл.
  2. Вернуть True/False, пару индексов или все пары?Всех пар может быть порядка n², и вывести их быстрее, чем за n² шагов, не получится.
  3. Отсортирован ли список?Если да, подходят два указателя с концов списка: O(n) времени без дополнительной памяти.
  4. Сколько элементов?При n = 1000 перебор пар — около 500 тысяч сравнений, это быстро. При n = 10⁶ нужен set просмотренных чисел: O(n) времени и O(n) памяти.
