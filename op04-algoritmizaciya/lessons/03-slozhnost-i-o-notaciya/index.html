I · МЕРА

Раздел I · выбор меры

Время выполнения не является характеристикой алгоритма

Одна и та же программа на разных запусках даёт разное время. Величина зависит от факторов, к алгоритму не относящихся, поэтому сравнивать решения по секундам можно только при полностью совпадающих условиях эксперимента.

Число выполненных операций от перечисленных факторов не зависит: оно определяется алгоритмом и входными данными. Эту величину и принимают за меру трудоёмкости.

Экспериментальные замеры при этом не отменяются: они показывают влияние констант и особенностей реализации. Методика замеров — занятие 4.

I · МЕРА

Раздел I · на чём основан подсчёт

Модель вычислений RAM и её допущения

Подсчёт операций ведётся не «вообще», а в рамках модели. Стандартная модель анализа алгоритмов — RAM (Random Access Machine): память с произвольным доступом, последовательное выполнение команд, каждая элементарная команда стоит одну единицу времени.

Допущение 1

Обращение к любой ячейке памяти по адресу стоит одинаково.

Нарушается на практике: обращение к данным в кэше в десятки раз быстрее обращения к оперативной памяти
Допущение 2

Арифметическая операция над числом выполняется за постоянное время.

Нарушается для длинных чисел: сложение чисел из k разрядов стоит O(k)
Допущение 3

Команды выполняются последовательно, по одной.

Нарушается при параллельных вычислениях и векторных инструкциях процессора
Допущение 4

Объём доступной памяти не ограничен.

Нарушается при работе с данными, не помещающимися в оперативную память

Модель сознательно упрощает устройство машины. Это упрощение делает оценку сравнимой между разными компьютерами; цена упрощения — расхождение с экспериментом, которое разбирается в разделе VI.

I · МЕРА

Раздел I · происхождение записи

Откуда взялась запись O

Обозначение пришло из математического анализа, где применялось для описания поведения функций, а не программ.

  • 1894 Пауль Бахман вводит символ O в работе по теории чисел
  • 1909 Эдмунд Ландау распространяет обозначение; отсюда название «символы Ландау»
  • 1976 Дональд Кнут переносит нотацию в анализ алгоритмов и вводит систематическое употребление O, Ω и Θ

Из этого происхождения следует существенное свойство: запись описывает поведение функции при стремлении аргумента к бесконечности. Утверждения о конкретных значениях при малых n из неё не выводятся.

Что означает «асимптотическая» оценка

Асимптотика — описание поведения функции вблизи предельной точки; здесь предельная точка — бесконечность. Оценка утверждает, как ведёт себя T(n) при неограниченном росте n, и ничего не утверждает о значениях при n = 5 или n = 100.

Практическое следствие: для входов известного и небольшого размера асимптотическая оценка — не главный аргумент при выборе решения. Этот случай разбирается на экране 44.

I · МЕРА

Раздел II · базовые понятия

Размер входа и элементарная операция

Размер входа n — числовая характеристика входных данных, определяющая объём работы: количество элементов списка, длина строки, число вершин и рёбер графа, разрядность числа.

Элементарная операция — действие, выполняемое за постоянное время в принятой модели: сравнение, присваивание, обращение по индексу, арифметическое действие.

При анализе выделяют базовую операцию — ту, которая выполняется чаще прочих и определяет порядок роста. Для поиска и сортировки это сравнение, для суммирования — сложение, для обхода графа — просмотр ребра.

Выбор размера входа зависит от задачи

список из n чисел → n элементов

строка длины m → m символов

граф → V вершин и E рёбер, оценка вида O(V + E)

два списка → n и m, оценка вида O(n + m)

одно число k → размером входа служит число разрядов, то есть log k

II · АППАРАТ

Раздел II · функция трудоёмкости

T(n) — число операций как функция размера входа

Временная сложность T(n) — функция, задающая количество элементарных операций, выполняемых алгоритмом на входе размера n.

Функция строится по тексту программы: каждой строке приписывается число выполнений, результаты суммируются. Справа — подсчёт для фрагмента 07 из fragments.py: два последовательных цикла по списку температур.

Строго говоря, T(n) определена не однозначно: на входах одного размера алгоритм может выполнять разное число операций. Поэтому рассматривают три функции — для лучшего, среднего и худшего случая. Разбор — на экране 31.

Раздел II · определение

Асимптотическая верхняя оценка O(f(n))

T(n) = O(f(n)) ⟺ ∃ c > 0, n₀ ≥ 0 : T(n) ≤ c · f(n) для всех n ≥ n₀

Существуют постоянный множитель c и размер входа n₀, начиная с которого функция T(n) не превосходит c · f(n). Запись читается «T(n) есть O от f(n)» и означает: T(n) растёт не быстрее f(n).

II · АППАРАТ

Раздел II · родственные обозначения

Пять символов и различия между ними

O ограничивает функцию сверху, Ω — снизу, Θ — с двух сторон одновременно. Малые o и ω выражают строгое неравенство: рост существенно медленнее или существенно быстрее.

Пример различия. Для линейного поиска: T(n) = O(n) — гарантия сверху; T(n) = Ω(1) — в лучшем случае одно сравнение; Θ(n) для него неверно, поскольку нижняя и верхняя оценки не совпадают. А для суммирования списка, где ранний выход невозможен, верно T(n) = Θ(n).

В курсе используется O: на собеседовании и в проверяющих системах требуется гарантия для худшего случая. Остальные обозначения нужны, чтобы читать чужой анализ.

Раздел II · правила действий с оценками

Свойства асимптотических оценок

Постоянный множитель

O(c · f) = O(f)

O(4n) = O(n). Множитель поглощается константой c из определения.
Сумма

O(f) + O(g) = O(max(f, g))

O(n) + O(n²) = O(n²). Последовательные участки программы: остаётся дороже́е.
Произведение

O(f) · O(g) = O(f · g)

Вложенные циклы: O(n) · O(n) = O(n²); при разных величинах — O(n·m).
Транзитивность

f = O(g), g = O(h) ⟹ f = O(h)

Позволяет оценивать сверху через промежуточную функцию.
Рефлексивность

f = O(f)

Следует из определения при c = 1.
Несимметричность

f = O(g) ⇏ g = O(f)

n = O(n²), но n² ≠ O(n). Запись O не является равенством, хотя использует его знак.

Последнее свойство — источник частой путаницы: = в записи T(n) = O(f(n)) означает принадлежность классу функций, а не равенство. В строгой записи пишут T(n) ∈ O(f(n)).

II · АППАРАТ

Раздел II · упорядочение классов

Иерархия функций роста

Классы упорядочены по скорости роста. Формально порядок устанавливается через предел отношения: если f(n)/g(n) → 0 при n → ∞, то f растёт строго медленнее g.

1 ≺ log n ≺ √n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ 2ⁿ ≺ n!

Отношение log n / n стремится к нулю: при n = 10 оно равно 0,33, при n = 1000 — 0,0100, при n = 10⁶ — 0,00002. Значит, log n = o(n), и никакой постоянный множитель этого не изменит.

Основание логарифма на класс не влияет: log₂n и log₁₀n отличаются постоянным множителем 3,32, который отбрасывается. Поэтому в записи основание не указывают.

Раздел II · требования к форме ответа

Как записывается оценка

В записи остаётся одно слагаемое — старшее — без постоянного множителя. Правило следует из свойств суммы и множителя с предыдущего экрана.

Почему O(n + m) не упрощается

Правило суммы применимо, когда обе функции зависят от одной величины. Если списков два и их размеры не связаны, ни одно слагаемое не является старшим: при n = 10, m = 10⁶ преобладает m, при обратном соотношении — n.

Запись O(n) в таком случае означала бы дополнительное предположение о том, что второй вход мал. Условие задачи такого предположения не даёт — значит, в ответе остаются обе величины.

Квадратичный класс — частный случай полиномиального O(n^k). Третья степень возникает при трёх вложенных циклах и встречается в задачах на матрицы и тройки элементов.

Раздел III · кривые роста

Пять классов на одной координатной сетке

По горизонтальной оси — размер входа, по вертикальной — число операций. Кривые построены по функциям из соответствующих оценок.

  • O(1) горизонтальная прямая: значение не зависит от n
  • O(log n) возрастает всё медленнее: удвоение n добавляет одну операцию
  • O(n) прямая: во сколько раз вырос вход, во столько же выросла работа
  • O(n log n) растёт быстрее линейной, оставаясь сопоставимой с ней
  • O(n²) покидает область графика на втором десятке

Верхняя граница шкалы выбрана по кривой n log n: при шкале по n² три нижних кривых были бы неразличимы. Точки пересечения в левой части — область малых n, где асимптотическая оценка не определяет выбор.

Раздел IV · стоимость библиотечных операций

Операции, содержащие скрытый проход

Отсутствие цикла в тексте не означает постоянной стоимости: часть операций языка выполняет полный просмотр внутри себя. Ниже фрагмент 10 из fragments.py: цикл записан один, сложность квадратичная.

def unique_keep_order(rows):
    result = []
    for row in rows:            # n итераций
        if row not in result:   # до n сравнений
            result.append(row)
    return result

Число операций: n итераций × до n сравнений = O(n²). На отчёте из 10 000 строк без повторов это до 50 миллионов сравнений. Замена списка result на множество снижает оценку до O(n) ценой O(n) памяти.

Раздел IV · рекурсивные алгоритмы

Дерево вызовов и подсчёт по уровням

Для рекурсивного решения число операций считают не по строкам, а по дереву вызовов: сколько работы выполняется на каждом уровне и сколько уровней всего.

Сортировка слиянием: вызов на массиве длины n порождает два вызова на половинах и выполняет слияние за O(n). На каждом уровне суммарная длина обрабатываемых участков равна n, а уровней — log₂n. Произведение даёт O(n log n).

Тот же приём применяется к любой рекурсии: выписать работу одного уровня, определить число уровней, перемножить. Если работа по уровням неодинакова, суммируют геометрическую прогрессию.

Раздел IV · амортизированный анализ

Стоимость, усреднённая по последовательности операций

Отдельная операция может быть дорогой, но если такие операции редки, средняя стоимость по всей последовательности остаётся постоянной. Эта средняя величина называется амортизированной стоимостью.

Список в Python хранится в непрерывном участке памяти фиксированной ёмкости. Когда ёмкость исчерпана, выделяется новый участок примерно вдвое больше и элементы копируются: одна операция append стоит O(n). Все остальные — O(1).

Раздел IV · разбор ошибок

Три ошибки анализа и их исправление

Ошибка 1 · сложение вместо умножения 
for order in orders:      # n
    for item in order:    # m
        check(item)

Неверно: O(n + m). Верно: O(n·m) — циклы вложены, значит стоимости перемножаются. Если m — среднее число позиций в заказе, оценку записывают через суммарное число позиций.

правило произведения
Ошибка 2 · пропущенная стоимость операции 
for value in data:
    if value in seen_list:
        ...

Неверно: O(n), «цикл один». Верно: O(n²) — проверка принадлежности списку сама стоит O(n). Замена seen_list на множество даёт O(n).

правило вызова
Ошибка 3 · оценка по лучшему случаю 
for i in range(len(data)):
    if data[i] == target:
        return i

Неверно: O(1), «обычно находится быстро». Верно: O(n) — оценка берётся по худшему случаю, когда элемент отсутствует. Ранний выход указывают отдельно.

выбор случая

IV · АНАЛИЗ

Раздел V · пространственная сложность

S(n) — объём дополнительной памяти

S(n) — функция, задающая объём памяти, который алгоритм использует сверх памяти, занятой входными данными.

Входной список в оценку не входит: он существовал до вызова. Переменные, число которых не зависит от n, дают O(1), сколько бы их ни было: три счётчика — постоянная величина.

Алгоритм с оценкой S(n) = O(1) называют работающим на месте (in-place). Такое требование часто ставится в условии задачи и исключает решения, создающие копию входных данных.

не входит в S(n)

  • входной список
  • переданная строка
  • аргументы-числа

входит в S(n)

  • множество или словарь: O(n)
  • копия списка, срез data[1:]: O(n)
  • результат sorted(): O(n)
  • кадры стека рекурсии: O(глубины)
  • счётчики и индексы: O(1)

Раздел V · память рекурсивных решений

Стек вызовов как расход памяти

Каждый незавершённый вызов функции занимает кадр стека: аргументы, локальные переменные, адрес возврата. Рекурсия глубины d расходует O(d) дополнительной памяти, даже если явных структур данных алгоритм не создаёт.

Отсюда практическое следствие: рекурсивный обход списка из 10⁶ элементов завершится ошибкой переполнения стека, тогда как эквивалентный цикл отработает без затрат памяти. В CPython предел глубины по умолчанию — около 1000 вызовов.

Для сортировки слиянием глубина равна log₂n, что даёт O(log n) памяти под стек плюс O(n) под вспомогательные массивы. Для рекурсивного суммирования списка глубина равна n, то есть S(n) = O(n) при том, что итеративный вариант даёт O(1).

Рекурсивно · S(n) = O(n) 
def total(data, i=0):
    if i == len(data):
        return 0
    return data[i] + total(data, i + 1)

Глубина рекурсии равна длине списка: одновременно существует n незавершённых вызовов.

T(n) = O(n) · S(n) = O(n)
Итеративно · S(n) = O(1) 
def total(data):
    result = 0
    for value in data:
        result += value
    return result

Одна переменная независимо от длины списка. Время то же, память постоянна.

T(n) = O(n) · S(n) = O(1)

Раздел V · соотношение времени и памяти

Три решения одной задачи

Задача: определить, содержит ли список из 1000 пропусков два одинаковых номера. Три решения с разными оценками; выбор определяется ограничениями условия, а не предпочтением.

Перебор пар 
for i in range(len(badges)):
    for j in range(i + 1, len(badges)):
        if badges[i] == badges[j]:
            return True

Дополнительной памяти не требует. 499 500 сравнений при n = 1000.

T(n) = O(n²) · S(n) = O(1)
Сортировка и проход 
badges.sort()
for i in range(1, len(badges)):
    if badges[i] == badges[i - 1]:
        return True

Промежуточный вариант: изменяет исходный список, дополнительной памяти почти не требует.

T(n) = O(n log n) · S(n) = O(1)
Множество просмотренных 
seen = set()
for badge in badges:
    if badge in seen:
        return True
    seen.add(badge)

Самое быстрое решение. Хранит до 1000 номеров и не изменяет исходные данные.

T(n) = O(n) · S(n) = O(n)

Формулировка для собеседования: «Есть три варианта. Перебор пар — O(n²) времени и O(1) памяти. Сортировка — O(n log n) и O(1), но изменяет входные данные. Множество — O(n) и O(n). Какой выбрать, зависит от того, что ограничено в задаче». Такой ответ показывает владение разменом, а не одним решением.

Раздел VI · границы метода

Нижняя граница сортировки сравнениями

Асимптотическая оценка отвечает не только на вопрос «сколько стоит этот алгоритм», но и на вопрос «насколько быстрым он может быть в принципе». Для сортировки сравнениями ответ известен и доказан.

Работу алгоритма представляют деревом решений: узел — сравнение двух элементов, две ветви — два исхода, лист — итоговый порядок. Для n элементов различных порядков n!, значит листьев не меньше n!. Двоичное дерево с L листьями имеет высоту не менее log₂L, а высота — это число сравнений в худшем случае.

log₂(n!) ≈ n·log₂n − 1,44n = Ω(n log n)

Следствие: ни один алгоритм, основанный на сравнениях, не может отсортировать быстрее, чем за O(n log n). Сортировка слиянием этой границы достигает, то есть является оптимальной по порядку.

Раздел VI · расхождение с экспериментом

Что оценка не учитывает

Отброшенные постоянные множители существуют и влияют на время. Асимптотика утверждает, что при достаточно большом n они не важны; вопрос в том, насколько большим должно быть n.

Константа реализации. Пусть алгоритм с оценкой O(n log n) имеет множитель 100, а квадратичный — множитель 1. Тогда квадратичный выигрывает вплоть до n ≈ 1000: при n = 128 это 16 384 операции против 89 600.

Расположение данных в памяти. Модель RAM считает все обращения равноценными, но обращение к соседним ячейкам быстрее произвольного в десятки раз за счёт кэша. Поэтому проход по массиву на практике быстрее прохода по связному списку той же длины, хотя оценка у обоих O(n).

Стоимость самих операций. Сложение малых чисел и сложение чисел из тысячи разрядов в модели равноценны, в действительности различаются на порядки.

VI · ГРАНИЦЫ

Раздел VI · где худшая оценка не показательна

Малые входы и особые распределения данных

Оценка худшего случая описывает гарантию. Если реальные данные систематически отличаются от худшего случая, гарантия остаётся верной, но перестаёт описывать типичное поведение программы.

  • 01 Почти упорядоченные данные. Сортировка вставками имеет O(n²) в худшем случае и O(n) на почти упорядоченном входе. Timsort в CPython опирается именно на это свойство и находит уже упорядоченные участки.
  • 02 Малые входы. Библиотечные сортировки переключаются на вставки при длине участка менее 64 элементов: на таком размере простой алгоритм с меньшей константой выигрывает.
  • 03 Хеш-таблица. O(1) в среднем и O(n) в худшем случае — при массовых совпадениях хешей. На практике исходят из среднего, но в задачах на устойчивость к худшему случаю это учитывают.

Как это формулируют на собеседовании

Указание среднего случая рядом с худшим показывает понимание предмета: «В худшем случае O(n²), но на почти отсортированных данных — O(n); если известно, что вход приходит почти упорядоченным, разница существенна».

Обратная ошибка — назвать средний случай, умолчав о худшем. Проверяющая система подаёт предельный вход, и решение, рассчитанное на типичные данные, на нём не проходит.

Раздел VI · классы задач

Полиномиальная разрешимость: P и NP

Классы сложности описывают алгоритмы. Существует и классификация задач — по тому, известен ли для них полиномиальный алгоритм.

P — задачи, решаемые за полиномиальное время O(n^k): сортировка, поиск кратчайшего пути, проверка связности графа.

NP — задачи, для которых готовое решение проверяется за полиномиальное время, но способ его найти за такое время неизвестен: задача коммивояжёра, о рюкзаке, о раскраске графа.

Вопрос о совпадении P и NP остаётся открытым с 1971 года и входит в список семи задач тысячелетия. Практическое следствие: для NP-полных задач ищут не точное решение, а приближённое либо решение для ограниченного размера входа.

Почему это относится к теме занятия

Если задача известна как NP-полная, попытки найти для неё точный полиномиальный алгоритм на собеседовании неуместны: ожидается перебор с отсечениями, динамическое программирование по подмножествам либо приближённый алгоритм.

Пример: задача о рюкзаке решается динамическим программированием за O(n·W), где W — вместимость. Это не полиномиальная оценка относительно размера входа: W записывается log W разрядами, поэтому такую оценку называют псевдополиномиальной. Разбор — раздел 7 курса.

Раздел VII · формулировка оценки

Как оценка сообщается на собеседовании

Ответ состоит из четырёх элементов: класс по времени с указанием подсчитанных операций, класс по памяти с указанием хранимого, худший случай и рассмотренные альтернативы.

Образец полного ответа

Время — O(n): один проход, на каждом элементе проверка по множеству за O(1).

Память — O(n): храню множество просмотренных номеров.

Худший случай — все номера различны: ранний выход не срабатывает, множество заполняется целиком.

Альтернатива — перебор пар: O(n²) времени и O(1) памяти; выбрал первый вариант, поскольку ограничения по памяти в условии нет.

Что оценивает интервьюер

  • названы операции, а не только запись класса
  • память оценена отдельно от времени
  • указан вход, на котором достигается худший случай
  • назван отвергнутый вариант и причина отказа
  • оценка произнесена до написания кода, а не после

Последний пункт существеннее прочих: обсуждение сложности до кодирования показывает, что решение выбрано осознанно. Эти же четыре элемента составляют заметку о сложности в портфолио.

Справка · материал занятия в сжатом виде

Сводка

Определение

T(n) = O(f(n))
⟺ ∃ c, n₀: T(n) ≤ c·f(n)
при всех n ≥ n₀

Классы

1 ≺ log n ≺ n ≺ n log n
≺ n² ≺ n³ ≺ 2ⁿ ≺ n!

Свойства

O(c·f) = O(f)
O(f) + O(g) = O(max)
O(f) · O(g) = O(f·g)

Правила анализа

подряд — складываем
вложено — перемножаем
деление — логарифм
вызов в цикле — умножаем

Дорогие операции

x in список — O(n)
sorted() — O(n log n)
data[1:] — O(n)
insert(0, x) — O(n)

Рекуррентности

T(n/2)+1 → log n
2T(n/2)+n → n log n
T(n−1)+n → n²
2T(n−1)+1 → 2ⁿ

Форма ответа: «Время O(?), поскольку подсчитанные операции. Память O(?): хранится что. Худший случай — входные данные. Альтернатива — вариант и причина отказа».

СПРАВКА

Справка · распространённые ошибки

Шесть неверных утверждений

Два цикла подряд дают O(n²)

Последовательные участки складываются: n + n = 2n, класс O(n). Перемножаются только вложенные.

Половина пар — другой класс

n(n−1)/2 отличается от n² постоянным множителем, который отбрасывается по свойству оценок.

Нет цикла — значит O(1)

sorted(), in для списка и срез выполняют проход по всем элементам без явного цикла.

O(n²) всегда хуже O(n log n)

При постоянном множителе 100 у второго квадратичное решение выигрывает до n ≈ 1000. Оценка описывает поведение при росте n.

Сложность зависит от языка

Число операций определяется алгоритмом. От реализации и машины зависит время выполнения — занятие 4.

Рекурсия не расходует память

Каждый незавершённый вызов занимает кадр стека: глубина d даёт O(d) дополнительной памяти.

Словарь занятия

    

      
O-нотация
Запись верхней границы роста: число операций растёт не быстрее указанной функции. O(n) — «порядка n», а не «ровно n операций».

      
T(n)
Временная сложность: как растёт число операций с ростом размера входа n.

      
S(n)
Пространственная сложность: сколько памяти решение занимает дополнительно к полученному входу.

      
Худший случай
Вход, на котором решение делает больше всего работы. Именно по нему называется оценка.

      
Средний случай
Оценка по всем возможным входам сразу. Для линейного поиска это n/2 — тот же класс O(n).

      
Логарифмическое время
O(log n): каждый шаг отбрасывает половину оставшихся данных. Тысяча элементов — десять шагов.

      
Размен время/память
Ускорение решения за счёт дополнительной структуры: множество или словарь снимают перебор, но занимают память O(n).

      
Complexity note
Заметка о сложности рядом с решением: подход, инвариант, T(n), S(n), худший случай и отвергнутые варианты.
