I · МЕРА

Раздел I · первый вариант меры

Секунды описывают запуск, а не алгоритм

Одна и та же программа на одних и тех же данных даёт разное время на разных запусках и на разных машинах.

Машина

Процессор, объём кэша, скорость памяти. На другом ноутбуке та же программа отработает за другое время.

Обстановка

Фоновые процессы, режим питания, температура. Два запуска подряд дают разные числа.

Реализация

Версия интерпретатора, библиотеки. Python 3.11 быстрее 3.8 на том же коде.

Ни один из этих факторов не относится к алгоритму. Значит, по секундам нельзя сказать, какое решение лучше, — можно сказать только, какой запуск оказался быстрее.

I · МЕРА

Раздел I · выбранная мера

Считаем операции, а не секунды

Число выполненных действий зависит только от двух вещей: от алгоритма и от входных данных. Оно одинаково у всех, кто запустит тот же код на том же входе.

Это и есть мера трудоёмкости, принятая в анализе алгоритмов. Дальше разбираемся, что именно считать за одно действие.

на компьютере в аудитории → 0,000011 с

при запущенном браузере → 0,000019 с

Раздел II · стоимость 1 · часть 2

Множество и словарь: почему это тоже единица

Проверка «есть ли такой номер» в списке стоит n, а в множестве — 1. Разница в том, как хранятся данные.

В списке номера лежат подряд, и найти нужный можно только перебором. В множестве позиция вычисляется из самого значения: хеш-функция превращает номер в адрес ячейки, и программа сразу смотрит туда.

Плата за это — память: под множество из n номеров выделяется таблица, и она тем больше, чем больше элементов. Размен «время за память» разбирается в разделе о памяти.

Строки, которые копируют или сдвигают

Дешевле полного прохода и дороже его

Список из 1000 номеров. Полный проход по нему стоит 1000 действий. Первая строка справляется за 10, вторая тратит 10 000 — и обе записаны в одну строку кода.

Одно и то же действие стоит по-разному в списке, множестве, словаре и очереди. Выбор структуры — главный рычаг, которым меняют сложность решения.

Размер входа n — та характеристика данных, при росте которой растёт объём работы. Прежде чем считать операции, нужно назвать, что именно в задаче является n.

II · СЧЁТ

Раздел III · функция трудоёмкости

Как считается T(n)

T(n) — число операций, выполненных алгоритмом на входе размера n. Считается по тексту программы, а не запуском.

  1. Каждой строке приписать её стоимость: 1 или n.
  2. Умножить на число выполнений: строка внутри цикла выполняется n раз.
  3. Сложить всё, что получилось.

Дальше — пять примеров подряд, от самого простого к самому неочевидному. Каждый разбирается построчно.

Что получится в примерах

① обращение по индексу → T(n) = 3

② поиск перебором → T(n) = 2n + 2

③ два цикла подряд → T(n) = 4n + 5

④ вложенные циклы → T(n) = n² + n + 2

⑤ скрытый проход → T(n) = n² + 2n + 2

III · T(n)

Пример 1 из 5 · пункт выдачи

Обращение по индексу

Функция возвращает первую и последнюю заявки смены. Циклов нет, каждая строка выполняется один раз.

Число операций не зависит от того, 10 заявок в журнале или 10 миллионов: обращений всё равно два плюс возврат.

T(n) = 3 — в записи нет буквы n. Это первый признак того, что алгоритм не зависит от размера входа.

fragments.py · 02построчный подсчёт
def first_and_last(orders):
    a = orders[0]                1
    b = orders[-1]               1
    return a, b                  1

T(n) = 1 + 1 + 1 = 3

III · T(n)

Пример 2 из 5 · стадион

Один цикл по списку

Поиск пропуска перебором. Появляется цикл: строки внутри него выполняются столько раз, сколько элементов в списке.

Считаем худший случай — искомого номера нет, поэтому цикл проходит до конца. Заголовок цикла выполняется n раз, сравнение внутри — тоже n раз.

T(n) = 2n + 2. При n = 8 это 18 операций, при n = 16 — 34. Удвоение входа удвоило работу.

fragments.py · 01худший случай
def find_pass(passes, code):
    for i in range(len(passes)):     n + 1
        if passes[i] == code:        n
            return i
    return -1                        1

T(n) = (n + 1) + n + 1 = 2n + 2

III · T(n)

Пример 3 из 5 · теплица

Два цикла подряд

Среднее значение и число выбросов выше среднего. Два цикла идут друг за другом, а не один внутри другого.

Каждый цикл даёт по 2n операций: заголовок и тело. Вне циклов выполняется пять действий. Складываем: 2n + 2n + 5.

T(n) = 4n + 5. Работы вдвое больше, чем в примере 2, но растёт она так же: удвоили вход — удвоили работу.

Пример 5 из 5 · отчёт по заказам

Цикл один, а работы как при вложенных

Удаление повторов с сохранением порядка. Вложенного цикла в тексте нет — но строка row not in result стоит не 1, а n, как мы разобрали на экране про стоимость строк.

Цикл выполняется n раз. На каждом шаге проверка просматривает список result, в котором к концу работы до n элементов. Перемножаем: n · n.

Раздел IV · правило 1 из 2

Постоянный множитель отбрасывается

Примеры ② и ③ дали 2n + 2 и 4n + 5. Второй делает вдвое больше работы — и всё же при удвоении входа оба удваиваются одинаково.

Множитель зависит от того, что мы посчитали за операцию. Считать ли заголовок цикла отдельным действием? Считать ли присваивание внутри? От ответа множитель меняется, а поведение функции — нет.

Поэтому множитель в оценку не входит: O(2n) = O(4n) = O(n).

Раздел IV · правило 2 из 2

Младшие слагаемые отбрасываются

Пример ④ дал n² + n + 2. С ростом n доля слагаемых n и 2 в общей сумме падает: при n = 1000 они составляют одну десятую процента.

Правило применяется только к слагаемым одной переменной. Если величины две и растут независимо, ни одна не является младшей: O(n + m) так и остаётся.

Раздел IV · строгое определение

Что означает запись O(f(n))

T(n) = O(f(n)) ⟺ ∃ c > 0, n₀ ≥ 0 : T(n) ≤ c · f(n) при всех n ≥ n₀

Найдутся такое число c и такой размер входа n₀, что начиная с n₀ функция T(n) не превосходит c · f(n). Читается «T(n) есть O от f(n)» и означает: T(n) растёт не быстрее f(n).

c

постоянный множитель. Позволяет не различать 2n и 100n: обе функции укладываются под c · n при подходящем c.

n₀

размер входа, начиная с которого неравенство выполняется. На меньших входах оно может нарушаться — определение этого не запрещает.

≤

оценка сверху. O не утверждает, что T(n) растёт именно как f(n), — только что не быстрее.

Обозначение пришло из математического анализа: символ ввёл Пауль Бахман в 1894 году, в анализ алгоритмов его перенёс Дональд Кнут в 1976-м. Отсюда и свойство записи — она описывает поведение функции при больших n.

Раздел IV · соседние обозначения

Кроме O существуют Ω и Θ

O ограничивает функцию сверху. Для полноты картины нужны ещё два символа: Ω ограничивает снизу, Θ — с двух сторон сразу.

Разница видна на трёх знакомых алгоритмах: у одних верхняя и нижняя границы совпадают, у других расходятся. Совпали — значит подходит Θ; разошлись — остаётся называть O и Ω по отдельности.

В курсе используется O: и на собеседовании, и в проверяющей системе нужна гарантия сверху. Ω и Θ нужны, чтобы читать чужой анализ и не путать «не хуже» с «ровно столько».

Раздел IV · упорядочение оценок

Какая оценка лучше другой

Оценки упорядочены по скорости роста. Порядок устанавливается отношением функций: если отношение стремится к нулю, первая растёт медленнее.

1 ≺ log n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ 2ⁿ ≺ n!

Как проверить, что одна функция растёт медленнее другой. Разделить первую на вторую и посмотреть, что происходит с частным при росте n. Если оно стремится к нулю — первая безнадёжно отстаёт; если держится около постоянного числа — функции одного порядка. Именно это и посчитано в таблице справа.

Основание логарифма на порядок не влияет: log₂n и log₁₀n отличаются множителем 3,32, который отбрасывается по первому правилу. Поэтому основание в записи не указывают.

Делим меньшую функцию на бо́льшую: частное падает к нулю — значит, слева растёт медленнее

Каждый указатель проходит свой список один раз и не возвращается назад. Слияние, поиск пары с заданной суммой — тема занятия 8.

T(n) = O(n + m) · S(n) = O(1) без учёта результата

Признак класса: один проход по входу, тело которого выполняется за постоянное время. Несколько последовательных проходов класс не меняют: n + n + n = 3n = O(n).

Где встречается линейно-логарифмическая сложность

В CPython применяется Timsort — сортировка слиянием, которая сначала находит уже упорядоченные куски и склеивает их. На почти отсортированных данных приближается к O(n).

    if orders[i] == orders[i - 1]:
        return True

Поиск дубликата без дополнительной памяти: O(n log n) на сортировку плюс O(n) на проход. По свойству суммы остаётся старшее слагаемое.

k-й по величине элемент 
def kth_largest(prices, k):
    return sorted(prices, reverse=True)[k - 1]

Третья по величине цена, десятый по времени заказ. Весь список упорядочивается ради одного элемента — отсюда n log n. Способ решить это за O(n) разбирается в разделе про кучу.

Класс 5 из 6 · примеры

Где встречается квадратичная сложность

Перебор всех пар 
for i in range(len(points)):
    for j in range(i + 1, len(points)):
        distance(points[i], points[j])

Ближайшая пара точек, поиск дубликатов, сравнение каждого с каждым. Множитель 1/2 от условия j > i на класс не влияет.

T(n) = O(n²) · S(n) = O(1)
Сортировка вставками 
for i in range(1, len(data)):
    j = i
    while j > 0 and data[j-1] > data[j]:
        data[j-1], data[j] = data[j], data[j-1]
        j -= 1

В худшем случае — обратный порядок — каждый элемент проходит весь пройденный участок. На почти упорядоченных данных вырождается в O(n).

Линейный поиск внутри цикла 
for row in rows:
    if row not in result:
        result.append(row)

Цикл записан один, но not in для списка выполняет собственный проход. Скрытый случай квадратичной сложности — раздел V.

Признак класса: вложенные циклы по одному входу либо операция стоимостью O(n) внутри цикла по входу. Если внутренний цикл идёт по другой величине m, оценка равна O(n·m).

Полиномиальные классы выше второго

Квадратичный класс — частный случай полиномиального O(n^k). Третья степень возникает при трёх вложенных циклах и встречается в задачах на матрицы и тройки элементов.

Умножение матриц 
for i in range(n):
    for j in range(n):
        for k in range(n):
            c[i][j] += a[i][k] * b[k][j]

Тройки с нулевой суммой 
for i in range(n):
    for j in range(i+1, n):
        for k in range(j+1, n):
            if a[i] + a[j] + a[k] == 0:
                ...

Полный перебор троек. Существует решение за O(n²) — сортировка плюс два указателя; типичная задача собеседования на переход от перебора к оптимизации.

T(n) = O(n³) перебором, O(n²) после сортировки

Раздел V · кривые роста

Пять классов на одной координатной сетке

По горизонтальной оси — размер входа, по вертикальной — число операций. Кривые построены по функциям из соответствующих оценок.

  • O(1) горизонтальная прямая: значение не зависит от n
  • O(log n) возрастает всё медленнее: удвоение n добавляет одну операцию
  • O(n) прямая: во сколько раз вырос вход, во столько же выросла работа
  • O(n log n) растёт быстрее линейной, оставаясь сопоставимой с ней
  • O(n²) покидает область графика на втором десятке

Верхняя граница шкалы выбрана по кривой n log n: при шкале по n² три нижних кривых были бы неразличимы. Точки пересечения в левой части — область малых n, где асимптотическая оценка не определяет выбор.

Раздел VI · стоимость библиотечных операций

Операции, содержащие скрытый проход

Отсутствие цикла в тексте не означает постоянной стоимости: часть операций языка выполняет полный просмотр внутри себя. Ниже фрагмент 10 из fragments.py: цикл записан один, сложность квадратичная.

def unique_keep_order(rows):
    result = []
    for row in rows:            # n итераций
        if row not in result:   # до n сравнений
            result.append(row)
    return result

Число операций: n итераций × до n сравнений = O(n²). На отчёте из 10 000 строк без повторов это до 50 миллионов сравнений. Замена списка result на множество снижает оценку до O(n) ценой O(n) памяти.

Раздел VI · рекурсивные алгоритмы

Дерево вызовов и подсчёт по уровням

Зачем отдельный приём. Всё, что было раньше, работало с циклами: посчитал итерации — получил оценку. У рекурсии циклов нет, а функция вызывает саму себя, и сколько раз — по коду сразу не видно.

Поэтому считают по дереву вызовов: сколько работы на одном уровне и сколько уровней всего.

Сортировка слиянием: вызов на массиве длины n порождает два вызова на половинах и выполняет слияние за O(n). На каждом уровне суммарная длина обрабатываемых участков равна n, а уровней — log₂n. Произведение даёт O(n log n).

Как считать любую рекурсию: ① выписать, что делает один вызов кроме рекурсивных; ② определить, на сколько частей задача делится и какого они размера; ③ посчитать число уровней; ④ умножить работу уровня на число уровней.

Здесь: один вызов делает слияние за n, деление пополам даёт log₂n уровней, значит n × log n. Тот же счёт для примеров с других экранов — на следующем.

Раздел VI · типовые рекуррентные соотношения

Как по форме рекурсии сразу назвать класс

Считать дерево вызовов каждый раз заново не нужно: почти вся рекурсия, которая встречается на собеседовании, укладывается в пять форм. Запись T(n) = 2·T(n/2) + O(n) читается так: «вызов на задаче размера n порождает два вызова на половинах и делает сам ещё O(n) работы».

Общий метод решения таких соотношений даёт мастер-теорема; в курсе она не разбирается — хватает узнавания пяти форм.

Раздел VI · амортизированный анализ

Стоимость, усреднённая по последовательности операций

Зачем это нужно. Мы записали append в таблицу со стоимостью 1. Но иногда это неправда: изредка одно добавление стоит n. Вопрос — можно ли всё равно считать его единицей.

Ответ даёт амортизированная стоимость: средняя стоимость операции по всей последовательности, если дорогие случаи редки.

Список в Python хранится в непрерывном участке памяти фиксированной ёмкости. Когда ёмкость исчерпана, выделяется новый участок примерно вдвое больше и элементы копируются: одна операция append стоит O(n). Все остальные — O(1).

Подсчёт для 1000 добавлений: расширений — 10, суммарно скопировано 1023 элемента, всего около 2023 операций, то есть 2,02 операции на одно добавление. Величина не растёт с n, поэтому append считают операцией амортизированной стоимости O(1).

РУКИ

Раздел VII · память

S(n) — сколько решение создало сверх входа

У каждого решения две оценки. T(n) — сколько действий оно сделает. S(n) — сколько новых ячеек памяти заведёт.

Список, который пришёл в функцию, в S(n) не входит: он существовал до вызова, и его память уже занята. Считается только то, что решение создало само.

Зачем это нужно: в условии задачи бывает написано «дополнительной памяти O(1)». Такое требование сразу отсекает решения, которые заводят множество или копию списка, — даже если по времени они лучше.

список из 1000 номеров пришёл в функцию
0сам список — не считаем, он был до вызова
1count = 0 — одна переменная
3low, high, mid — три переменные
1000seen = set(badges) — множество из всех номеров
1000copy = badges[:] — копия списка
1000sorted(badges) — новый упорядоченный список

Число переменных не зависит от n → S(n) = O(1). Новая структура растёт вместе с n → S(n) = O(n).

Раздел VII · память · примеры

Сколько памяти у знакомых решений

Четыре функции, которые уже разбирались. Время у них разное, а память определяется одним: завели новую структуру или обошлись переменными.

S(n) = O(1) 
def count_late(orders):
    late = 0
    for order in orders:
        if order.delay > 0:
            late += 1
    return late

Одна переменная late. Список из десяти заказов и из миллиона обрабатываются с одной и той же дополнительной памятью.

создано: 1 ячейка
S(n) = O(1) 
def has_pair(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return True
    return False

Перебор пар — самое медленное решение из четырёх, O(n²) по времени. Но памяти не занимает вовсе: только счётчики i и j.

создано: 2 ячейки · медленно, зато экономно
S(n) = O(n) 
def has_duplicate(badges):
    seen = set()
    for badge in badges:
        if badge in seen:
            return True
        seen.add(badge)
    return False

Самое быстрое решение, O(n) по времени. Плата — множество, которое в худшем случае вырастет до размера входа.

создано: до n ячеек · быстро, но за память
S(n) = O(n) 
def top_three(prices):
    return sorted(prices)[:3]

Циклов нет, но sorted() возвращает новый список из всех цен. Срез из трёх элементов берётся уже от него.

создано: n ячеек, хотя нужны три

Отсюда правило, которое пригодится в разметке: если решение завело множество, словарь, копию или результат sorted() — это O(n) памяти. Если обошлось счётчиками и индексами — O(1). Промежуточных случаев на этом занятии не встретится.

Раздел VIII · границы метода

Два случая, когда оценка не отвечает на вопрос

Оценка говорит, что будет при большом n. Есть две ситуации, где этого недостаточно, и решение выбирают не по ней.

Случай 1 · данных мало

Квадратичное решение с простым телом цикла может обгонять «правильное» n log n, пока элементов немного: у второго больше действий на каждый шаг.

Множитель 100 здесь — цена одного шага: рекурсия, вызовы, работа с памятью. У простого двойного цикла такой цены нет.

Случай 2 · данные особенные

Оценка берётся по худшему случаю. Если реальные данные до него не доходят, программа работает быстрее, чем обещает запись.

  • Почти упорядоченный список. Сортировка вставками в худшем случае O(n²), а на таких данных — O(n). Встроенная сортировка Python на этом и построена.
  • Элемент обычно в начале. Поиск перебором — O(n) в худшем случае, но если искомое почти всегда первое, реально это одно-два сравнения.
  • Словарь и множество. O(1) в среднем и O(n) в худшем — при массовых совпадениях хешей. На практике исходят из среднего.
Что с этим делать

Оценку называют всегда: она отсекает заведомо неподходящие решения до написания кода.

Когда её мало

Если размер данных известен и невелик — сравнивают решения замером, а не записью в скобках.

Итог

Оценка и замер отвечают на разные вопросы. Оценка — «что будет, когда данных станет много». Замер — «что быстрее вот на этих данных». Замерами занимаемся на занятии 4.

VIII · ГРАНИЦЫ

Раздел VIII · классы задач

Полиномиальная разрешимость: P и NP

Классы сложности описывают алгоритмы. Существует и классификация задач — по тому, известен ли для них полиномиальный алгоритм.

P — задачи, решаемые за полиномиальное время O(n^k): сортировка, поиск кратчайшего пути, проверка связности графа.

NP — задачи, для которых готовое решение проверяется за полиномиальное время, но способ его найти за такое время неизвестен: задача коммивояжёра, о рюкзаке, о раскраске графа.

Вопрос о совпадении P и NP остаётся открытым с 1971 года и входит в список семи задач тысячелетия. Практическое следствие: для NP-полных задач ищут не точное решение, а приближённое либо решение для ограниченного размера входа.

Почему это относится к теме занятия

Если задача известна как NP-полная, попытки найти для неё точный полиномиальный алгоритм на собеседовании неуместны: ожидается перебор с отсечениями, динамическое программирование по подмножествам либо приближённый алгоритм.

Пример: задача о рюкзаке решается динамическим программированием за O(n·W), где W — вместимость. Это не полиномиальная оценка относительно размера входа: W записывается log W разрядами, поэтому такую оценку называют псевдополиномиальной. Разбор — раздел 7 курса.

IX · ПРИМЕНЕНИЕ

Раздел IX · формулировка оценки

Как оценка сообщается на собеседовании

Ответ состоит из четырёх элементов: класс по времени с указанием подсчитанных операций, класс по памяти с указанием хранимого, худший случай и рассмотренные альтернативы.

Образец полного ответа

Время — O(n): один проход, на каждом элементе проверка по множеству за O(1).

Память — O(n): храню множество просмотренных номеров.

Худший случай — все номера различны: ранний выход не срабатывает, множество заполняется целиком.

Альтернатива — перебор пар: O(n²) времени и O(1) памяти; выбрал первый вариант, поскольку ограничения по памяти в условии нет.

Что оценивает интервьюер

  • названы операции, а не только запись класса
  • память оценена отдельно от времени
  • указан вход, на котором достигается худший случай
  • назван отвергнутый вариант и причина отказа
  • оценка произнесена до написания кода, а не после

Последний пункт существеннее прочих: обсуждение сложности до кодирования показывает, что решение выбрано осознанно. Эти же четыре элемента составляют заметку о сложности в портфолио.

СПРАВКА

Справка · распространённые ошибки

Шесть неверных утверждений

Два цикла подряд дают O(n²)

Последовательные участки складываются: n + n = 2n, класс O(n). Перемножаются только вложенные.

Половина пар — другой класс

n(n−1)/2 отличается от n² постоянным множителем, который отбрасывается по свойству оценок.

Нет цикла — значит O(1)

sorted(), in для списка и срез выполняют проход по всем элементам без явного цикла.

O(n²) всегда хуже O(n log n)

При постоянном множителе 100 у второго квадратичное решение выигрывает до n ≈ 1000. Оценка описывает поведение при росте n.

Сложность зависит от языка

Число операций определяется алгоритмом. От реализации и машины зависит время выполнения — занятие 4.

Рекурсия не расходует память

Каждый незавершённый вызов занимает кадр стека: глубина d даёт O(d) дополнительной памяти.

Словарь занятия

    

      
O-нотация
Запись верхней границы роста: число операций растёт не быстрее указанной функции. O(n) — «порядка n», а не «ровно n операций».

      
T(n)
Временная сложность: как растёт число операций с ростом размера входа n.

      
S(n)
Пространственная сложность: сколько памяти решение занимает дополнительно к полученному входу.

      
Худший случай
Вход, на котором решение делает больше всего работы. Именно по нему называется оценка.

      
Средний случай
Оценка по всем возможным входам сразу. Для линейного поиска это n/2 — тот же класс O(n).

      
Логарифмическое время
O(log n): каждый шаг отбрасывает половину оставшихся данных. Тысяча элементов — десять шагов.

      
Размен время/память
Ускорение решения за счёт дополнительной структуры: множество или словарь снимают перебор, но занимают память O(n).
