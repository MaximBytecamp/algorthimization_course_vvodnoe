§1Как устроен тренажёр

Задача разбита на семь этапов шаблона interview canvas. Сначала открыт только первый; кнопка «Этап пройден» открывает следующий и записывает, сколько минут ушло на этап. Над этапами — полоса с планом: сколько минут отводится на каждый этап, чтобы уложиться в 25.

В каждом этапе сначала работа самостоятельно, потом сверка. Пересказ, перебор, правило шага и эталонный код спрятаны в раскрывающихся блоках, ответы к примерам скрыты до нажатия кнопки. В этапе «Перебор и идея» нужно выбрать технику из четырёх: префиксный массив с ответом на запрос из двух ячеек, величина слева и справа за проход, префиксная сумма со словарём или окно переменного размера из модуля 10. Первые три — формы префиксных сумм из глав 11.2 и 11.3, четвёртая проверяет, что окно не берут по привычке. В последнем этапе эталонное решение проходится по шагам, и интервьюер задаёт вопрос, который меняет условие.

Секундомер запускается кнопкой «Старт» и не ограничивает время. В конце задачи появляется таблица «план — фактически». Кнопка «Открыть все этапы» показывает задачу целиком: так задачу разбирают после попытки или читают как разобранный пример.

В тренажёр не входят задачи дополнительного набора extra.py — LeetCode 525, 974 и 304 — и задача домашнего задания LeetCode 2559. Их решения здесь были бы подсказкой.

    Сначала называют медленное решение, которое точно верное, и его сложность. Потом ищут быстрое: выбирают форму техники и формулируют правило шага.

    Перебор, который называет кандидат

    На каждый запрос складывать числа участка заново: до n сложений на запрос, всего O(n·q).

    ТехникаКакая техника подходит?

    • Верно. Список не меняется, запросов на сумму участка много. Префиксный массив строят один раз, когда к неизменному списку приходит много запросов на участок: каждый ответ — одна операция над двумя ячейками.

    • Величину слева накапливают по ходу прохода, величину справа получают из итога по всему списку или вторым проходом справа налево.

    • Словарь префиксных сумм нужен, когда считают все отрезки с точной суммой: для каждого конца ищут, сколько раз раньше встречалась сумма prefix − k.

    • Окно переменного размера ищет лучший отрезок и на каждый конец держит одно начало. Здесь границы задаёт запрос, нужна величина для каждой позиции или нужно посчитать все отрезки — окно этого не даёт.

    Правило шага
    1. Подготовка. prefix[i + 1] = prefix[i] + nums[i], ячеек n + 1, prefix[0] = 0.
    2. Проверка. 0 <= l <= r <= len(nums), иначе ValueError.
    3. Ответ. prefix[r] − prefix[l].

    Посчитайте префиксы руками и ответьте на запросы: для каждого щёлкните две ячейки prefix. Неверный ответ не принимается, вместо него появляется объяснение.

    Сложность называют до кода: интервьюер соглашается с решением раньше, чем на запись потрачено время.

                  • Величину слева накапливают по ходу прохода, величину справа получают из итога по всему списку или вторым проходом справа налево.

                  • Верно. Нужно посчитать все отрезки с точным количеством. После замены нечётных на 1 это отрезки с суммой k. Словарь префиксных сумм нужен, когда считают все отрезки с точной суммой: для каждого конца ищут, сколько раз раньше встречалась сумма prefix − k.

                  Правило шага
                  1. Префикс. odd += nums[r] % 2.
                  2. Подсчёт. count += seen.get(odd − k, 0).
                  3. Запись. seen[odd] += 1.
