§1Идея: показания счётчика

Счётчик воды в квартире не хранит расход по дням. Он показывает одно число — сколько воды прошло с момента установки. Чтобы узнать расход за неделю, из показания в конце недели вычитают показание в её начале.

Список prefix — такой счётчик для списка чисел. В ячейке prefix[i] лежит сумма первых i чисел: nums[0], …, nums[i − 1]. Сумма участка [l, r) — показание в r минус показание в l:

Числа левее участка входят в обе суммы и при вычитании сокращаются. Каждая ячейка prefix получается из предыдущей одним сложением: prefix[i + 1] = prefix[i] + nums[i].

Посчитайте prefix для журнала склада из главы 11.1, затем ответьте на три запроса. Для ответа щёлкните две ячейки prefix: сначала ту, из которой вычитают, затем ту, которую вычитают.

На подготовку ушло 8 сложений, на каждый запрос — одно вычитание. Перебор на эти три запроса сложил бы 3 + 3 + 4 = 10 чисел.

§2Почему ячеек n + 1

У списка из n чисел n + 1 префикс: сумма нуля чисел, одного, двух, …, всех n. Ячейка prefix[0] = 0 нужна для участков, которые начинаются с первого дня. Запрос (0, 3) считается по той же формуле: prefix[3] − prefix[0] = 10 − 0. Без этой ячейки начало списка пришлось бы обрабатывать отдельным условием, а пропуск такого условия в Python не вызывает ошибку. Это видно в §5.

Полуинтервал [l, r) выбран по той же причине, что в range и срезах Python. Длина участка равна r − l, пустой участок записывается как l = r, а два соседних участка [a, b) и [b, c) вместе дают [a, c) без пропусков и наложений.

§3Код и пошаговый прогон

Функция состоит из двух циклов. Первый один раз строит prefix. Второй идёт по запросам: проверяет границы и записывает разность двух ячеек. Напишите функцию сами — тесты проверяют её на примере из главы 11.1, на неверных запросах и сравнивают с перебором на двухстах случайных списках.

Python в этой строке: for l, r in queries:

Каждый запрос — пара чисел. Если перед in записать две переменные через запятую, Python на каждом шаге раскладывает пару по ним: первое число попадает в l, второе — в r.

>>> queries = [(2, 5), (0, 8)]
>>> for l, r in queries:
...     print(l, r)
...
2 5
0 8
Python в этой строке: if not 0 <= l <= r <= len(nums):

Сравнения можно записывать цепочкой. Запись 0 <= l <= r <= len(nums) означает «0 <= l, и l <= r, и r <= len(nums)». not переворачивает результат: условие истинно, когда хотя бы одно сравнение нарушено.

>>> nums = [5, -2, 7]
>>> l, r = 1, 3
>>> 0 <= l <= r <= len(nums)
True
>>> l, r = 3, 1
>>> 0 <= l <= r <= len(nums)
False

Прогон ниже — на журнале склада с тремя запросами: участок (2, 5), весь журнал (0, 8) и пустой участок (3, 3). На ленте показан список prefix. На шагах 2–17 он заполняется слева направо, на шагах 21–28 подсвечены две ячейки, которые вычитаются для текущего запроса.

То, что верно после каждого шага, называют инвариантом. При подготовке он такой: после шага с индексом i в prefix[i + 1] лежит сумма первых i + 1 чисел. Когда цикл закончен, это верно для всех ячеек, и формула из §1 работает для любого запроса.

§4Почему время O(n + q)

Подготовка — n сложений. Каждый запрос — одна проверка границ и одно вычитание, на q запросов это O(q). Всего O(n + q). Память — O(n) на список prefix. Перебор на каждый запрос складывает до n чисел, всего O(n·q).

Замер на ноутбуке автора: n чисел и столько же запросов, каждый запрос — весь список. Это худший случай для перебора.

n = qПеребор, мсПрефиксы, мс
1 00018,60,06
2 00081,50,12
4 000311,40,28

Когда n и q удваиваются, время перебора растёт примерно в 4 раза, время префиксов — примерно в 2. Скрипт замера будет в стартовом наборе, глава 11.5.

§5Две ошибки в индексах

Обе ошибки меняют одну строку, и на первом запросе прогона ни одна не вызывает исключения. Обе версии запущены на журнале склада с запросами (2, 5) и (0, 3). Верный ответ — [6, 10].

range_sums(журнал, [(2, 5), (0, 3)])переключите вкладку

В prefix n ячеек, prefix[i] — сумма чисел с 0 по i включительно. Ответ — prefix[r - 1] - prefix[l - 1].

[6, -6]На запрос (2, 5) ответ верный. На шаге 24 при l = 0 индекс l − 1 равен −1, а prefix[-1] в Python — последняя ячейка, сумма всего журнала. Исключения нет, ответ неверный.

Ответ — prefix[r + 1] - prefix[l], как будто день r входит в запрос.

[12, 6]В каждый ответ попадает лишнее число nums[r]. На запросе (0, 8) эта версия упала бы с IndexError: ячейки prefix[9] нет.

Первая ошибка видна только на запросе с начала списка, поэтому в тестах нужен запрос с l = 0. Вторая ошибка — несогласованная индексация. В LeetCode 303 правый конец запроса включён, и там prefix[right + 1] - prefix[left] — верная формула. Поэтому в §4 главы 11.1 первым делом выясняли, входит ли день r в запрос.

§6Двумерный случай: обзор

Та же идея работает для таблицы. В p[i][j] лежит сумма прямоугольника из первых i строк и первых j столбцов. Сумма прямоугольника со строками [r1, r2) и столбцами [c1, c2) получается из четырёх ячеек: из большого прямоугольника вычитают полосу сверху и полосу слева. Угол p[r1][c1] при этом вычтен дважды, его прибавляют обратно.

Прямоугольник со строками 1–2 и столбцами 1–2 — числа 6, 3, 2 и 0, их сумма 11. Так решается задача LeetCode 304. В КТП двумерный случай дан обзором, задач на него в модуле нет.
