§2Порядок работы на паре

Работа идёт в папке lesson_11 на своём компьютере, нужен Python с pytest. Если Python ещё не настроен, начните с песочниц в главах 11.2–11.3: там те же функции пишутся прямо на странице и проверяются похожими тестами. Сдать при этом нужно solution.py с зелёным pytest.

  1. Скопируйте папку lesson_11 в portfolio/lesson_11/ личного репозитория и выполните python -m pytest tests.py -v. Все 36 тестов должны упасть: так проверяется, что pytest нашёл файлы и запустил тесты.
  2. До кода откройте initial_attempt.txt. Запишите вопросы к условиям задач 1 и 2, перебор с его сложностью и примеры с ответами: запрос с первого дня, пустой запрос, неверный запрос, индекс 0, «индекса нет». Образец вопросов — глава 11.1, §4.
  3. Разминка — highest_altitude: LeetCode 1732, наибольшая высота на маршруте. Высота в каждой точке — префиксная сумма изменений, из них нужна наибольшая. Проверка: python -m pytest tests.py -k altitude.
  4. Напишите range_sums. Проверка: -k range, затем тесты границ: -k "bad_query or range_edges". Если тест падает, найдите симптом в сводке главы 11.4, §2.
  5. Напишите pivot_index: -k pivot.
  6. Запустите замер: python bench.py > bench_results.txt. Он идёт несколько секунд.
  7. Заполните complexity_note.md для трёх обязательных функций.
  8. Если осталось время — count_k_sums из главы 11.3, §6: -k ksum.
  9. Если и это готово — extra.py: самый длинный отрезок с равным числом нулей и единиц, отрезки с суммой, кратной k, и суммы прямоугольников в таблице. Проверка: python -m pytest tests_extra.py -v.

1 · Довести решенияsolution.py проходит все 36 тестов. bench_results.txt — ваш замер. complexity_note.md заполнен по трём функциям: что считается заранее, что хранится, как записан запрос и какая из этого формула, время, память и таблица замера.Главы 11.2–11.4
2 · Три ошибки на границеВ bugs_11.py функции longest_zero_sum, last_pivot_index, max_query_sum. Каждая верно отвечает на обычных входах и ошибается на граничном. Для каждой: вход, на котором ответ неверный; падающий тест в tests_bugs_11.py; исправление одной строки; повторный прогон. Вывод pytest — в bugs_run.txt.Глава 11.4: граничные входы и сводка ошибок
3 · Слова на гласную в диапазонахФункция count_vowel_ranges(words, queries), LeetCode 2559. Слово подходит, если начинается и заканчивается гласной. Запрос [l, r] — оба конца включительно: сколько подходящих слов среди words[l], …, words[r]. Пример: ["aba", "bcb", "ece", "aa", "e"], запросы [[0, 2], [1, 4], [1, 1]] → [2, 3, 0]. Время O(n + q). Не меньше шести своих тестов: запрос из одного слова, весь список, запрос с индекса 0, слово из одной гласной, подходящих слов нет.Глава 11.2: префиксы и формула; глава 11.2, §5: включённый правый конец

Тест к bugs_11.py засчитывается, если до исправления он падает, а после — проходит. Тест, который проходит и на ошибочной версии, ошибку не находит.
