11.3

Префикс и суффикс:
равновесный индекс

Вторая задача КТП — равновесный индекс: позиция, где сумма чисел слева равна сумме чисел справа. Сумма слева — префикс, сумма справа — суффикс. В главе обе суммы получают за один проход без лишних списков, разбирают две ошибки и в конце применяют префиксы к отрезкам с заданной суммой, где окно из модуля 10 ошибается.

§1Задача и перебор

Условие LeetCode 724: дан список целых чисел, нужно найти индекс i, для которого сумма чисел левее i равна сумме чисел правее i. Само nums[i] не входит ни в одну из сумм. Если таких индексов несколько, вернуть самый левый, если нет ни одного — вернуть −1. Задача стоит в разделе Prefix Sum плана LeetCode 75.

Пример из условия: [1, 7, 3, 6, 5, 6]. Для индекса 3 слева 1 + 7 + 3 = 11, справа 5 + 6 = 11. Ответ — 3. Два крайних случая: левее индекса 0 чисел нет, и сумма слева там равна 0, поэтому для [2, 1, -1] ответ 0. Для [1, 2, 3] ответ −1.

Перебор для каждого индекса считает обе суммы заново: sum(nums[:i]) == sum(nums[i + 1:]). Это n сложений на индекс и O(n²) на весь список. Суммы соседних индексов отличаются на одно-два числа, и пересчитывать их целиком не нужно.

§2Сумма справа из суммы всего списка

Сумму всего списка total считают один раз, до прохода. Сумму слева left накапливают по ходу, как префиксную сумму в главе 11.2. Сумма справа — всё, что осталось: из total убирают левую часть и само nums[i].

Сумма справа — суффиксная сумма: сумма от позиции до конца списка. Хранить суффиксы отдельным списком не нужно, они получаются вычитанием. Пройдите пример сами: на каждом индексе введите сумму справа.

Если суммы не равны, nums[i] переходит в левую часть: left += nums[i], и проверяется следующий индекс. Порядок важен: сначала сравнение, потом сдвиг. В §4 видно, что будет при другом порядке.

§3Код и пошаговый прогон

Напишите функцию сами. Тесты проверяют пример из условия, крайние случаи из §1, пустой список и сравнивают ответ с перебором на двухстах случайных списках с отрицательными числами.

В прогоне зелёным отмечены числа левее i — они в left, синим — правее i, они в right. На шаге 17 суммы равны: 11 и 11.

Инвариант цикла: перед сравнением в left лежит сумма nums[:i], а в right — сумма nums[i + 1:]. Время O(n): один проход для total и один для поиска. Память O(1): кроме трёх чисел, ничего не хранится.

§4Две ошибки в порядке действий

Обе версии запущены на примере из условия. Исключений нет, обе возвращают −1 вместо 3.

pivot_index([1, 7, 3, 6, 5, 6])переключите вкладку

Сумма справа: right = total - left.

−1В right осталось само nums[i]. На шаге 17 для индекса 3 сравниваются 11 и 17 — разница ровно nums[3] = 6.

Строка left += nums[i] стоит перед вычислением right.

−1nums[i] попало в левую сумму раньше сравнения. На шаге 18 для индекса 3 сравниваются 17 и 11.

Вторая версия на некоторых списках находит «равновесие», которого нет. Для [1, 2, 3] она возвращает 1: сравнивает 1 + 2 и 3, хотя слева от индекса 1 стоит только 1. Поэтому в тестах нужен и пример, где ответ −1.

§5Префиксы и суффиксы списками

Ту же задачу можно решить двумя списками: prefix из главы 11.2 и suffix, где suffix[i] — сумма nums[i:]. Суффиксы заполняют справа налево. Индекс i равновесный, если prefix[i] == suffix[i + 1].

Python в этой строке: range(n - 1, -1, -1)

Третий аргумент range — шаг. При шаге −1 счёт идёт вниз от первого числа до второго, второе не входит. Чтобы дойти до индекса 0, вторым числом пишут −1.

>>> n = 4
>>> list(range(n - 1, -1, -1))
[3, 2, 1, 0]

Для этой задачи вариант со списками тратит лишнюю память O(n). Он нужен, когда для каждой позиции требуется величина слева и справа одновременно и вычитанием её не получить. Пример — LeetCode 238 из Top Interview 150: для каждой позиции произведение всех остальных чисел, деление запрещено. Произведение слева и произведение справа собирают двумя проходами, второй идёт справа налево.

После первого прохода в answer[i] лежит произведение чисел левее i — префикс. Второй проход домножает его на произведение чисел правее i — суффикс.

§6Отрезки с суммой k: префикс и словарь

В главе 10.1 окно отказало на отрицательных числах. Задача LeetCode 560: сколько отрезков подряд имеют сумму ровно k, числа любого знака. Возьмём [1, -1, 2, 1, -2, 3] и k = 2. Таких отрезков четыре: [1, -1, 2], [2], [-1, 2, 1], [1, -2, 3]. Окно из модуля 10, которое сжимается, пока сумма больше k, находит три. Отрезок [2] оно пропускает: у конца r = 2 два подходящих отрезка, а окно на каждый конец даёт не больше одного.

Префиксные суммы решают задачу формулой из главы 11.2. Сумма отрезка nums[l:r] равна prefix[r] − prefix[l]. Она равна k, когда prefix[l] = prefix[r] − k. Значит, для каждого конца нужно знать, сколько раз раньше встречалась префиксная сумма prefix[r] − k. Это число хранит словарь.

Метод get разобран в главе 10.3: он возвращает 0 для ключа, которого в словаре нет. Запись {0: 1} — префикс из нуля чисел, тот же prefix[0] = 0, что в главе 11.2. На шаге 14 прогона она даёт отрезок [1, -1, 2], который начинается с первого числа.

Перебор всех отрезков стоит O(n²). Словарь даёт O(n) по времени и O(n) по памяти: каждый конец обрабатывается одним обращением к словарю и одной записью. Границы и ошибки этой функции разобраны в главе 11.4.
