§1Как читать ошибочный прогон

Все прогоны в главе получены запуском ошибочного кода, подписи к шагам описывают, что делает строка, без оценки. При чтении нужно найти шаг, после которого нарушается инвариант функции. Удобно идти так:

  1. Вспомнить инвариант: что должно быть верно перед каждым шагом. Для задачи 1 — «если пара есть, она внутри участка с i по j».
  2. Прокрутить прогон до конца и сравнить результат с ожидаемым.
  3. Идти по шагам с начала и после каждого проверять инвариант.
  4. На первом шаге, где инвариант нарушен, искать строку кода, которая выполнилась прямо перед ним.

В коде каждой версии ошибочная строка выделена красным, исправление — зелёным.

§2Один товар дважды

В условии цикла pair_sum стоит <= вместо <. Когда указатели сходятся на одном элементе, цикл выполняется ещё раз, и цена складывается сама с собой.

На [100, 250, 600] с целью 500 функция вернула (1, 1): 250 + 250 = 500, но это один товар. Верный ответ — None. На большинстве входов ошибки не видно, потому что пара находится раньше, чем указатели сойдутся.

Какие тесты ловят

test_pair_single_item_is_not_a_pair[pair_sum] — на [250] ошибочная версия возвращает (0, 0). test_pair_answers_match_on_many_inputs — среди случайных входов находятся такие, где перебор отвечает None, а ошибочная версия — пару.

§3Указатель сдвигается не в ту сторону

Ветки перепутаны: при сумме меньше цели сдвигается j, при сумме больше — i. Код выглядит почти как верный, и в нём нет ни одной ошибки синтаксиса.

На каталоге из примера функция вернула None, хотя пара (2, 3) есть. Инвариант нарушен на первом же ходе: сумма 1800 больше цели, а сдвигается i, то есть исключается цена 300. У 300 пары действительно нет, но исключили её без основания: правило требовало исключить 1500. На следующих ходах сумма уходит всё дальше от цели.

Какие тесты ловят

Четыре: test_pair_example, test_pair_neighbours_in_the_middle, test_pair_negative_numbers для pair_sum и test_pair_answers_match_on_many_inputs.

§4Запись вместо обмена

В move_zeros вместо обмена стоит запись, как в задаче 2. Ненулевое число копируется вперёд, а ноль из позиции w пропадает. В задаче 2 после цикла хвост обрезался, и потерянные значения были не нужны. Здесь длина списка не меняется, и в хвосте остаются старые копии.

Результат [4, 7, 2, 0, 7, 2] вместо [4, 7, 2, 0, 0, 0]: нулей стало меньше, числа 7 и 2 повторились. Инвариант «в nums[w:r] только нули» нарушен на первом копировании: в позиции 1 осталась копия 4.

Какие тесты ловят

test_zeros_example и test_zeros_returns_none_and_keeps_object. Тест test_zeros_none эту ошибку не ловит: без нулей копирование ничего не портит.

§5Сравнение с соседом справа

Другой способ убрать повторы: оставить элемент, если он отличается от соседа справа. Цикл тогда идёт до предпоследнего элемента, потому что у последнего соседа справа нет. Последний элемент при этом не записывается никогда.

На [101, 101, 102, 105] результат [101, 102]: значение 105 потеряно. Это ошибка на единицу из занятия 7: элементов n, а пар соседей n − 1, и цикл по парам не доходит до последнего элемента. На списке из одного элемента функция вернёт 0 и удалит его.

Идею можно исправить — после цикла отдельно записать последний элемент. Но проще вернуться к сравнению с последним записанным ids[w - 1]: там последний элемент обрабатывается так же, как остальные.

Какие тесты ловят

Пять из шести тестов задачи 2: test_dedup_example, test_dedup_single, test_dedup_all_equal, test_dedup_no_duplicates, test_dedup_duplicates_at_the_end. Проходит только тест на пустом списке.

§6Длина серии одной строкой

В compress длина серии записывается одним элементом str(count), без разбиения на цифры. Пока серии короче десяти символов, разницы нет: строка из одной цифры совпадает с самой цифрой.

В списке символов появился элемент из двух символов '12', и длина ответа 2 вместо 3. Условие LeetCode 443 требует, чтобы каждый элемент был одним символом.

Какие тесты ловят

Один тест: test_compress_one_long_run с серией из 12 символов. Остальные тесты задачи 3 используют серии короче десяти и эту ошибку пропускают. Поэтому в наборе и нужен тест на длинную серию.

§8Найдите ошибку

В каждом вопросе — код, который проходит часть тестов. Выберите вход, на котором он даёт неверный ответ.

Код 1Функция должна вернуть пару индексов с суммой target в отсортированном списке.
def pair_sum(prices, target):
    i, j = 0, len(prices) - 1
    while i < j:
        s = prices[i] + prices[j]
        if s == target:
            return (i, j)
        if s < target:
            i += 1
        else:
            j -= 1
            i += 1
    return None

  • Первая же сумма 100 + 400 = 500, ошибочная ветка не выполняется, ответ (0, 3) верный.

  • На пустом списке цикл не выполняется, функция возвращает None — это верный ответ.

  • Верно. 100 + 900 = 1000 больше цели, ветка else сдвигает оба указателя и исключает 100 без основания. Пара (0, 2), 100 + 300, потеряна.

Код 2Функция должна удалить повторы из отсортированного списка на месте и вернуть число различных значений.
def dedup_sorted(ids):
    if not ids:
        return 0
    w = 1
    for r in range(1, len(ids)):
        if ids[r] != ids[w - 1]:
            ids[w] = ids[r]
            w += 1
    return w

  • Верно. Функция вернёт 2, но в списке останется [4, 5, 5]: нет строки del ids[w:], хвост не обрезан.

  • Повторов нет, все значения записываются на свои же места, список не меняется. Ответ 3 и список [4, 5, 6] верные.

  • Цикл не выполняется, функция возвращает 1, список [4] — верно.
