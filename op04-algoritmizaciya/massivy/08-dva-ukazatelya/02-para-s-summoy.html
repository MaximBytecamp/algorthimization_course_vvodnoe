8.2

Указатели навстречу:
пара с заданной суммой

В этой главе решается первая задача КТП — найти в отсортированном списке два элемента с заданной суммой. Сначала правило сдвига и поиск руками, затем код с пошаговым прогоном, доказательство, что пара не теряется, и замер против перебора.

В этой главе
  1. Правило сдвига
  2. Код и пошаговый прогон
  3. Почему пара не теряется

§1Правило сдвига

Перебор не пользуется тем, что цены отсортированы. А по порядку сразу видно, какие пары проверять бесполезно. Поставим i на самую дешёвую цену, j — на самую дорогую и посмотрим на их сумму.

  1. Сумма равна цели. Пара найдена, вернуть (i, j).
  2. Сумма меньше цели. Правая цена уже самая большая из оставшихся, поэтому увеличить сумму может только более дорогая левая. Сдвинуть i вправо.
  3. Сумма больше цели. Левая цена уже самая маленькая, поэтому уменьшить сумму может только более дешёвая правая. Сдвинуть j влево.
  4. Указатели встретились. Пар не осталось, ответ None. Поиск идёт, пока i < j: один товар дважды брать нельзя.

Пройдите алгоритм сами. Ход, который противоречит правилу, не выполняется, и появляется объяснение, какую пару он бы потерял. Два примера из пяти без ответа: там закончить нужно кнопкой «Пары нет».

§2Код и пошаговый прогон

Напишите функцию сами. Тесты проверяют пример, отсутствие пары, пустой список, один товар дважды, одинаковые цены у разных товаров и отрицательные числа.

Прогон на двух входах: в первом пара есть, во втором нет. Бледные ячейки — цены, которые уже исключены.

§3Почему пара не теряется

Доказательство держится на одном утверждении, которое верно перед каждой проверкой условия цикла. Такое утверждение называют инвариантом: если в списке есть пара с суммой target, хотя бы одна такая пара лежит на участке с индекса i по индекс j.

До цикла участок — весь список, и утверждение верно. Пусть сумма меньше цели. Цена prices[i] с любой ценой участка даёт не больше этой суммы, потому что prices[j] — самая большая цена участка. Значит, пары с prices[i] нет, и после i += 1 нужная пара осталась внутри. Для суммы больше цели рассуждение то же, только с j. Когда i ≥ j, в участке не больше одного элемента, пары в нём нет — и по инварианту её нет во всём списке.

Сортировка нужна ровно в одном месте рассуждения: «prices[j] — самая большая цена участка». В неотсортированном списке это неверно, и указатели могут пропустить пару.

Отсюда и время. Каждый указатель двигается только в одну сторону, это называют монотонностью. За шаг сдвигается хотя бы один, а встретиться они могут не позже чем через n − 1 шаг. Время O(n).

§4Замер против перебора

Контроль занятия по КТП: «Сопоставить O(n²) и O(n) с экспериментом». Замер на ноутбуке автора, пары в списке нет — худший случай для обоих способов:

nПеребор, мсУказатели, мс
4 000170,10,13
8 000751,50,28
16 0002 785,60,55

При удвоении n время перебора растёт примерно в 4 раза, время указателей — в 2. Если цены не отсортированы, у задачи два решения. Можно отсортировать копию за O(n log n) и пустить указатели. Можно пройти список один раз со словарём уже просмотренных цен: O(n) по времени и памяти. Скрипт bench.py в стартовом наборе меряет все четыре способа, глава 8.5.
