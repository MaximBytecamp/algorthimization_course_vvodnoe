§1Ошибки в паре с суммой

В коде pair_sum три места, где одна изменённая строка ломает ответ: начальное значение j, условие цикла и место проверки суммы. На каждой вкладке — ошибочная версия на входе, где ошибка видна.

pair_sum с одной изменённой строкойпереключите вкладку

IndexErrorИндексы списка из шести цен — от 0 до 5, а j = 6. Обращение prices[6] прерывает функцию до первого сравнения с целью.

(1, 1)Вход — [100, 250, 600] с целью 500, верный ответ None. Указатели сходятся на цене 250, условие 1 <= 1 истинно, и цена складывается сама с собой: 250 + 250 = 500.

(2, 2)Сумма 700 + 900 = 1600 посчитана для нужной пары, но сначала выполняется ветка сдвига: j уменьшается с 3 до 2. Функция возвращает уже сдвинутые индексы — один товар дважды.

Верная версия — прогон в главе 8.2, §2.

§4Что проверяют на review

По КТП решение сдаётся Pull Request, и проверяющий спрашивает о трёх вещах. Этот же порядок годится для объяснения решения интервьюеру.

  1. Монотонность указателей. Каждый указатель двигается только в одну сторону, за шаг сдвигается хотя бы один — поэтому шагов не больше n, время O(n).
  2. Границы применимости. Указатели навстречу требуют отсортированного входа: в доказательстве используется, что правая цена участка самая большая. Указатели в одну сторону требуют, чтобы запись не обгоняла чтение.
  3. Влияние сортировки. Если вход не отсортирован, сортировка стоит O(n log n), и итоговая сложность — O(n log n). Альтернатива — словарь: O(n) по времени, но O(n) по памяти.
