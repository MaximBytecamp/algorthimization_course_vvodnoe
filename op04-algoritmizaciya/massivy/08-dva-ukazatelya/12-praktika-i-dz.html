§2Порядок работы на паре

Работа идёт в папке lesson_08 на своём компьютере, нужен Python с pytest. Если Python ещё не настроен, начните с песочниц в главах 8.4, 8.7, 8.8 и 8.11: там те же функции пишутся прямо на странице и проверяются похожими тестами. Сдаётся всё равно solution.py с зелёным pytest.

  1. Скопируйте папку lesson_08 в portfolio/lesson_08/ личного репозитория и выполните python -m pytest tests.py -v. Все 37 тестов должны упасть с NotImplementedError — так проверяется, что pytest видит файлы.
  2. До кода откройте initial_attempt.txt и запишите три вопроса к условию задачи 1 и пять примеров с ответами. Образец — главы 8.3 и 8.6.
  3. Напишите pair_sum_brute. Запустите python -m pytest tests.py -k pair: тесты для перебора должны пройти, для указателей — ещё падать.
  4. Напишите pair_sum. Если какой-то тест падает, найдите его в блоках «Какие тесты ловят» главы 8.9: там показано, какая ошибка его роняет и как она выглядит в прогоне.
  5. Напишите dedup_sorted и проверьте: -k dedup. Затем compress: -k compress.
  6. Запустите замер: python bench.py > bench_results.txt. Он идёт около 20 секунд.
  7. Заполните в complexity_note.md разделы для трёх обязательных функций.
  8. Если осталось время — move_zeros, -k zeros.
  9. Если и это готово — extra.py: наибольший объём воды, палиндром с пропуском знаков, тройки с нулевой суммой. Проверка: python -m pytest tests_extra.py -v.
На полях: когда можно открыть главы

Код функций есть в главах модуля. На занятии 9 решение объясняется без подсказок, поэтому сначала пишется своя версия по правилу из главы, не открывая код. Если тест падает, откройте пошаговый прогон нужной главы и сравните шаги со своим кодом.

§4Вопросы для review

В КТП контроль занятия записан так: «Сопоставить O(n²) и O(n) с экспериментом. На review объяснить монотонность указателей, границы применимости и возможное влияние сортировки на итоговую сложность». Ниже эти требования разложены на вопросы и на то, что должно прозвучать в ответе. Главы в правом столбце — где это разобрано.

Вопрос на reviewЧто должно прозвучать в ответеГде разобрано
Как ваш замер подтверждает O(n²) у перебора и O(n) у указателей?При удвоении n время перебора растёт примерно в 4 раза, указателей — примерно в 2; назвать свои числа из bench_results.txt8.4, 8.10
Что такое монотонность указателей и почему из неё следует O(n)?Каждый указатель движется только в одну сторону и не возвращается; каждый шаг сдвигает хотя бы один, поэтому шагов не больше n8.5, §4
Когда указатели навстречу применять нельзя?Вход не отсортирован и нужны исходные индексы; пример из главы, где пара теряется на неотсортированном списке; запасной способ — словарь8.2, 8.5, 8.10
Как сортировка влияет на итоговую сложность?Если вход не отсортирован, добавляется O(n log n), и итог становится O(n log n) вместо O(n); копия списка — ещё O(n) памяти8.10, 8.11

§5Шпаргалка по модулю

Указатели навстречуi, j = 0, len(a) - 1 while i < j: s = a[i] + a[j] if s == target: return (i, j) if s < target: i += 1 else: j -= 1 return None

Нужен отсортированный вход. Каждый ход исключает один элемент. O(n), O(1).

Чтение и записьw = 0 for r in range(len(a)): if оставить(a[r]): a[w] = a[r] w += 1 del a[w:] return w

w ≤ r, запись не затирает непрочитанное. Для переноса нулей — обмен вместо записи.

Признаки в условии

«отсортирован», «пара», «сумма двух» — навстречу. «на месте», «верните длину», «подряд» — в одну сторону. «два отсортированных» — по двум спискам. «за один проход», «O(n)» — перебор исключён.

Вопросы до кода

Отсортирован ли вход и в какую сторону. Можно ли взять элемент дважды. Что вернуть, если ответа нет. Индексы или значения. Можно ли менять вход. Размер n и ограничение по памяти.

Условие цикла

i < j — когда нужна пара разных элементов (задача 1). i <= j — когда каждый элемент нужно отнести к группе (разделение). В одну сторону — for r in range(len(a)).

Сложность и замер

Перебор пар — n·(n − 1) / 2, O(n²): при удвоении n время ×4. Указатели — не больше n − 1 шагов, O(n): ×2. Словарь — O(n) и O(n) памяти. Сортировка + указатели — O(n log n).

Инвариант задачи 1

Если пара с суммой target есть, она лежит на участке с i по j. Сортировка нужна во второй проверке: a[j] — самый большой элемент участка.

Типичные ошибки

<= вместо < — пара (k, k). Перепутаны ветки — None при существующей паре. Запись вместо обмена — пропали нули. Цикл по парам соседей — пропал последний элемент.

§9Что дальше

Перед занятием 9 задачи модуля можно прорешать в формате собеседования: в главе 8.13 восемь задач, каждая по этапам секции с секундомером.

Занятие 9 — скользящее окно фиксированного размера. Окно — это два указателя в одну сторону, между которыми всегда одно и то же расстояние k. На каждом шаге правый указатель добавляет элемент в окно, левый убирает, и сумма или счётчик окна пересчитываются за O(1). Правило «элементов n, окон длины k — n − k + 1» из занятия 7 там понадобится сразу.
