§1Из чего состоит условие

Условие задачи на собеседовании обычно короткое, и в нём четыре части. Легенда объясняет, откуда данные: цены товаров, идентификаторы заказов, показания датчика. Входные данные — что передаётся в функцию. Результат — что вернуть. Ограничения — по времени, по памяти, можно ли менять вход. Технику подсказывают три последние части. Легенду можно заменить любой другой, и решение от этого не изменится.

§3Признаки в условии

Подсвеченные слова повторяются от задачи к задаче. Таблица собирает их вместе. Одного признака мало: технику выбирают по сочетанию признаков.

«отсортирован», «по возрастанию», «по неубыванию»Сравнение с целью показывает, в какую сторону двигаться: слева значения меньше, справа большенавстречу
«пара», «два элемента», «сумма двух»Ответ — два элемента; перебор всех пар стоит O(n²)навстречу, если есть порядок

«верните новую длину», «верните число оставшихся»Ответ — первые k элементов списка, остальное не важнов одну сторону

§4Когда техника не подходит

Указателям навстречу нужен порядок в данных, указателям в одну сторону — чтобы решение по каждому элементу принималось один раз. Если требование не выполнено, нужна другая техника.

УсловиеНайдите два числа с заданной суммой. Массив не отсортирован, вернуть нужно исходные индексы.

РешениеУказатели навстречу требуют порядка, а сортировка перемешает индексы. Подходит словарь уже просмотренных чисел: O(n) по времени и O(n) по памяти. Это LeetCode 1 Two Sum, хеш-таблицы — занятие 17.

УсловиеНайдите число подотрезков с суммой ровно S. В массиве есть отрицательные числа.

РешениеПри сдвиге правой границы сумма может и вырасти, и уменьшиться, поэтому нельзя решить, какую границу двигать. Решают префиксными суммами со словарём — занятие 11.

УсловиеВерните все пары с суммой S, если их может быть много.

РешениеУказатели работают, но после найденной пары двигаются дальше, а повторы значений пропускаются отдельно. Время остаётся O(n) плюс размер ответа. Такой проход работает внутри задачи 3Sum.

На полях: отсортировать самим

Если вход не отсортирован, но индексы в ответе не нужны — достаточно самих значений, — его можно отсортировать и применить указатели. Сортировка стоит O(n log n), и это время добавляется к решению.

§5Тренажёр: выберите технику

Ниже шесть условий. Для каждого выберите способ, который подходит при указанных ограничениях и работает быстрее остальных вариантов. В вариантах — перебор, три формы двух указателей и встроенные средства Python: set, sorted, срез. После ответа открывается разбор верного и выбранного вариантов.

Условие 1Температуры за месяц записаны по дням. Проверьте, есть ли два разных дня, сумма температур в которых равна 40, и верните номера дней. Список менять нельзя.

  • Температуры записаны по дням и по возрастанию не упорядочены. Без порядка сумма крайних элементов не показывает, какой указатель двигать, и пара может быть пропущена.

  • Верно, из этих трёх способов подходит только перебор: он не требует порядка и не меняет список. Время O(n²). Для неотсортированного входа есть и более быстрый способ — словарь просмотренных значений.

  • Чтение и запись нужны, когда список изменяется на месте. Здесь его менять нельзя, а ответ — пара номеров.

Условие 2Список номеров билетов отсортирован по возрастанию, некоторые номера продублированы при выгрузке. Уберите повторы в том же списке и верните количество различных номеров.

  • Верно. r читает каждый номер, w указывает место для следующего нового. Повторы в отсортированном списке стоят рядом, поэтому хватает сравнения с последним записанным.

  • Навстречу ищут пару с двух концов. Здесь каждый элемент нужно сравнить с предыдущим оставленным, по порядку.

  • Условие требует работать в том же списке. Кроме того, set не сохраняет порядок.

  • Сравнивать каждый номер с каждым не нужно: одинаковые номера в отсортированном списке стоят подряд.

Условие 3Даны два списка с временем событий из двух журналов, каждый отсортирован. Получите общий отсортированный список событий.

  • Решение верное, но стоит O((n + m) log (n + m)) и не использует того, что оба списка уже отсортированы.

  • Склеенный список не отсортирован целиком, а указатели навстречу ищут пару и порядок не строят.

  • Верно. На каждом шаге в ответ идёт меньший из двух текущих элементов, и его указатель сдвигается. Время O(n + m).

Условие 4Расстояния от склада до пунктов выдачи отсортированы по возрастанию. Курьер может проехать ровно 300 км. Найдите два пункта, расстояния до которых в сумме дают 300, и верните их номера. Дополнительная память — O(1).

  • Список не нужно менять, нужна пара элементов. Чтение и запись здесь ничего не дают.

  • Перебор даст верный ответ, но за O(n²). Расстояния отсортированы, поэтому есть способ за O(n).

  • Верно. Это задача 1 модуля с другой легендой: отсортированный вход, пара с заданной суммой, память O(1).

Условие 5Проверьте, что пароль, записанный как список символов, читается одинаково с обоих концов. Копию списка создавать нельзя.

  • Верно. Первый символ сравнивается с последним, второй с предпоследним; указатели сходятся к середине. Время O(n), память O(1).

  • Срез s[::-1] создаёт копию, а условие это запрещает.

  • Список не нужно менять. Нужно сравнить элементы парами с двух концов.

Условие 6Отменённые заказы в списке помечены нулём. Перенесите их в конец, сохранив порядок остальных заказов. Новый список не создавать.

  • Обмены с двух концов переставят заказы, и исходный порядок не сохранится. Этот вариант подходит, когда порядок не важен.

  • Устойчивая сортировка сохранит порядок, но стоит O(n log n), а задача решается за O(n).

  • Верно. w указывает место для следующего неотменённого заказа, обмен с r уводит нули назад. Порядок оставшихся не меняется.
