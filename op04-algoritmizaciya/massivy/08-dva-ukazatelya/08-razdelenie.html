§1Что такое разделение

Разделениеpartition

Перестановка элементов списка на месте, после которой в начале стоят все элементы, для которых условие верно, а за ними — все остальные. Функция обычно возвращает границу между группами: сколько элементов попало в первую.

Условие может быть любым: «не ноль», «меньше порога», «не спам». В быстрой сортировке условие — «меньше опорного элемента»: после разделения опорный элемент встаёт на своё место, а две группы сортируются отдельно.

Разделение отличается от сортировки: внутри групп порядок не определён. Поэтому оно дешевле — O(n) за один проход, тогда как сортировка стоит O(n log n). Способ зависит от одного вопроса к условию: нужно ли сохранить порядок элементов внутри групп.

Нужно сохранить порядок?СпособЗадача
ДаУказатели в одну сторону, обмен nums[w] и nums[r]Перенос нулей в конец, LeetCode 283
НетУказатели навстречу, обмен элементов, которые стоят не на своих сторонахРазделение по порогу; шаг быстрой сортировки

§2Перенос нулей: указатели в одну сторону

move_zeros(nums)расширение · LeetCode 283

Перенести все нули в конец списка, сохранив порядок остальных чисел. Список меняется на месте, функция возвращает None.

Пример: [0, 4, 0, 0, 7, 2] → [4, 7, 2, 0, 0, 0].

Схема та же, что в главе 8.7: r читает каждое число, w показывает место для следующего ненулевого. Отличие в одном: вместо записи nums[w] = nums[r] выполняется обмен nums[w], nums[r] = nums[r], nums[w]. Ноль, который стоял в позиции w, при этом переезжает на место r. Поэтому после цикла обрезать хвост не нужно: в нём и так стоят нули, и длина списка не меняется.

Пройдите алгоритм сами: на каждом шаге решите, переносить прочитанное число вперёд или пропустить.

Python в этой строке: обмен nums[w], nums[r] = nums[r], nums[w]

Справа сначала вычисляются оба значения, и только потом они записываются слева по порядку. Поэтому два элемента меняются местами без временной переменной.

>>> nums = [0, 4]
>>> nums[0], nums[1] = nums[1], nums[0]
>>> nums
[4, 0]

§3Код и прогон переноса нулей

Инвариант: перед шагом r в nums[0:w] стоят все ненулевые числа из прочитанной части в исходном порядке, а в nums[w:r] — только нули. Обмен сохраняет его: ненулевое число встаёт в конец первой зоны, ноль из позиции w уходит в конец второй. Порядок ненулевых не меняется, потому что каждое следующее встаёт правее предыдущего.

На полях: обмен с самим собой

Пока нулей не встретилось, w == r, и строка обмена меняет элемент местами с самим собой. Список от этого не меняется. Можно добавить проверку if w != r, но код станет длиннее, а число операций почти не изменится.

§4Разделение по порогу: указатели навстречу

Второй способ подходит, когда порядок внутри групп не важен. Задача: переставить числа так, чтобы все числа меньше порога limit стояли в начале, и вернуть их количество. Указатели стартуют с двух концов. i идёт вправо, пока число под ним уже на своей стороне — меньше порога. j идёт влево, пока число под ним не меньше порога. Когда оба остановились, числа под ними стоят не на своих сторонах, и их меняют местами.

Python в этой строке: if … elif … else

Условия проверяются сверху вниз, выполняется ветка первого истинного. elif проверяется, только если все условия выше ложны; else — если ложны все.

>>> x = 5
>>> if x < 0:
...     print("меньше нуля")
... elif x == 0:
...     print("ноль")
... else:
...     print("больше нуля")
...
больше нуля

Условие цикла здесь i <= j. Когда указатели стоят на одном элементе, его тоже нужно проверить, иначе он останется неотнесённым ни к одной группе и возвращённое i окажется неверным. Например, на [8, 0, 12, 9, 5, 3] с порогом 10 версия с i < j возвращает 4, хотя чисел меньше 10 пять. В задаче 1 условие строже, i < j: один элемент пары не образует.

Зелёные ячейки в прогоне — числа, которые уже стоят на своих сторонах: слева от i — меньше 10, справа от j — не меньше.

Инвариант: всё левее i меньше порога, всё правее j — не меньше. После цикла i = j + 1, и граница между группами проходит по индексу i. В примере функция вернула 4: числа 5, 1, 3, 7 меньше 10.

§5Сравнение двух способов

Посмотрим на результат второго способа внимательнее. Исходный список [5, 12, 3, 18, 7, 25, 1], результат [5, 1, 3, 7, 18, 25, 12]. Числа 12, 18, 25 шли в исходном списке в этом порядке, а в результате стоят как 18, 25, 12: порядок внутри группы не сохранился. Для разделения это допустимо, для переноса нулей по условию — нет.

В карточке изменения занятия 7 была задача split_spam: сначала обычные комментарии в исходном порядке, потом спам в любом порядке. Это разделение с сохранением порядка первой группы — то есть первый способ.

§6Три группы за один проход

Задача LeetCode 75 Sort Colors просит разложить список из чисел 0, 1 и 2 по возрастанию за один проход. Её решают тремя указателями: low — граница нулей, high — граница двоек, mid читает. Нули обмениваются к low, двойки — к high, единицы остаются посередине. Это сочетание обеих форм: low и mid идут в одну сторону, mid и high — навстречу. Ниже код, пошаговый прогон на списке [2, 0, 2, 1, 1, 0] и проверка запуском. Зелёные ячейки в прогоне — готовые группы: нули левее low и двойки правее high.

После обмена с high указатель mid не двигается: на его место пришло число из непрочитанной части, и его ещё нужно проверить. После обмена с low двигать mid можно: оттуда пришло уже прочитанное число, ноль или единица.

§7Проверьте себя

Вопрос 1Список заказов нужно разложить так, чтобы сначала шли оплаченные в исходном порядке, а за ними неоплаченные. Какой способ подходит?

  • Верно. Оплаченные заказы встают в позицию w по очереди и сохраняют исходный порядок.

  • Обмены с правого конца переставят оплаченные заказы, как 12, 18, 25 в примере главы.

  • Устойчивая сортировка даст нужный порядок, но создаст новый список и потратит O(n log n) времени.

Вопрос 2Почему в split_by_limit условие цикла i <= j, а в pair_sum — i < j?

  • Длина списка на выбор условия не влияет.

  • Верно. Элемент, на котором сошлись указатели, при разделении ещё не проверен. В задаче 1 одного элемента для пары недостаточно.

  • В pair_sum условие i <= j даёт ответ (1, 1) на [100, 250, 600] с целью 500.
