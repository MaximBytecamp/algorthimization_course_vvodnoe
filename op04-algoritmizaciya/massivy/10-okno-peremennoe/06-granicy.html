В этой главе разобран контроль КТП занятия 10: «Кандидат объясняет условие while и состояние окна. Проверяются дубликаты и пустая строка». §1Разбор двух функций по строкам

В главах 10.4 и 10.5 функции собраны из строк и пройдены по шагам на обычных входах. Здесь каждая строка разобрана с другой стороны: на каком граничном входе она проявляется и что получится, если записать её иначе. Граничный вход — это вход на краю допустимого: пустой список, один элемент, порог, которого не достигает сумма, строка из одинаковых символов. На таких входах цикл выполняется ноль раз или один раз, и ошибки, незаметные на обычном примере, дают неверный ответ.

§2Запуск изменённых версий

Четыре изменения из таблиц, которые в главах 10.3–10.5 ещё не запускались. На каждой вкладке сначала прогон версии с изменённой строкой, под ним — верная версия на том же входе. Вход подобран так, чтобы изменение проявилось.

Функции с одной изменённой строкойпереключите вкладку

В shortest_window нет проверки порога. Вход — [1, 2], s = 0.

изменённая версия

IndexErrorПри пороге 0 подходит любое окно, в том числе пустое: его сумма 0 не меньше 0. На шаге 12 окно уже пустое, а цикл while продолжается. На шаге 16 из суммы вычитается nums[1] — элемент, который в окно ещё не входил. На шаге 25 индекс l = 2 выходит за конец списка, и функция заканчивается исключением IndexError. На пустом списке эта версия возвращает 0 без исключения, поэтому одного теста на пустой список для неё мало.

верная версия

ValueErrorПроверка в первой строке останавливает функцию до работы с окном. Исключение называет неверный аргумент.

В shortest_window начальное значение ответа — длина списка, сравнение — if length < best. Вход — [1, 1, 1, 1], s = 5: сумма всего списка 4, отрезка нет.

изменённая версия

4Цикл while не выполняется ни разу, в best остаётся начальное значение 4. Функция сообщает, что подходит весь список. На входе [1, 2, 3] с s = 6 эта версия возвращает верный ответ 3: весь список там действительно подходит. Отличить два случая по ответу нельзя.

верная версия

0Значение 0 не может быть длиной подходящего окна, поэтому оно однозначно означает «отрезка нет».

В longest_unique начальное значение ответа — 1. Вход — пустая строка.

изменённая версия

1Цикл не выполняется, функция возвращает начальное значение. На любой непустой строке эта версия верна: подстрока из одного символа в ней есть, и ответ не меньше 1. Ошибка видна только на пустой строке — поэтому контроль КТП называет её отдельно.

верная версия

0В пустой строке нет подстрок, кроме пустой, её длина 0.

В longest_unique символ приводится к нижнему регистру: ch = text[r].lower(). Вход — 'aA'.

изменённая версия

1На шаге 10 буква A записывается в карту под ключом 'a', и на шаге 12 окно 'aA' считается окном с повтором. По контракту из главы 10.2 регистр различается, верный ответ 2. На строке 'Aa' эта версия заканчивается исключением KeyError: в карте есть только ключ 'a', а при сжатии уменьшается счётчик 'A'.

верная версия

2'a' и 'A' — разные ключи словаря, повтора нет.

Если интервьюер ответил бы, что регистр не различается, верной стала бы версия с приведением регистра, но приводить нужно всю строку до цикла: text = text.lower(). Тогда и расширение, и сжатие работают с одними и теми же символами, и KeyError не возникает.

На полях: почему пустой вход проверяют отдельно

Ни в одной функции модуля нет строки if not nums. Пустой вход всё равно нужно проверять тестом: верный ответ на нём даёт только начальное значение ответа, а оно не участвует ни в одном шаге обычного прогона. Ошибка best = 1 из §2 не видна ни на одном непустом входе.

§4Ответ «отрезка нет» и ошибка вызова

В задаче о минимальном отрезке два разных случая, когда ответа в обычном смысле нет. Первый — подходящего отрезка в списке нет, например сумма всех чисел меньше порога. Второй — неверный вызов: порог 0 или отрицательный. Интервьюер в главе 10.2 дал на них разные ответы: в первом случае вернуть 0, во втором — исключение ValueError.

Различие следует из того, где источник проблемы: в данных или в вызове функции. Список без подходящего отрезка — обычные данные: за час с маленькими продажами ответ «не набралось» правильный, и программа продолжает работу. Порог 0 — ошибка в коде, который вызвал функцию: задача с таким порогом не имеет смысла, и продолжать работу с ответом на неё нельзя. Об ошибках вызова, как в главе 9.6, сообщают исключением.

Способ сообщить «отрезка нет»Где встречаетсяЧто нужно вызывающему коду

ИсключениеВ этом модуле — только для неверного порогаДля отсутствия отрезка не подходит: это обычный результат, его не перехватывают через try

Для longest_unique вопроса «что вернуть, если ответа нет» не возникает: в любой непустой строке есть подстрока из одного символа без повторов. Остаётся только пустая строка, для неё ответ 0 — длина пустой подстроки.

§7Как объяснить условие while и состояние окна

Первая часть контроля КТП — «кандидат объясняет условие while и состояние окна». На собеседовании это звучит как вопросы «что хранится в этой переменной между итерациями?» и «почему здесь while с таким условием?». Ответ строится из трёх частей, они одинаковы для всех задач модуля.

  1. Состояние окна. Назвать переменную и то, что она хранит для окна с l по r. Например: «total — сумма элементов окна», «count — для каждого символа окна, сколько раз он в нём встречается». Назвать, как она меняется при сдвиге каждой границы.
  2. Условие цикла. Назвать условие допустимости и объяснить, почему цикл проверяет его или его отрицание. Для короткого отрезка: «сжимаем, пока окно подходит, — total >= s». Для длинного: «сжимаем, пока окно недопустимо, — count[ch] > 1». Назвать, почему здесь нужен цикл: одного сжатия может не хватить, и if оставит повтор в окне.
  3. Инвариант после цикла. Сказать, что верно, когда цикл закончился: «после цикла в окне нет повторов, и это самая длинная подстрока без повторов с концом в r». Из инварианта следуют место записи ответа и время O(n).

Объяснение принято, если кандидат

Называет состояние окна и его смыслНапример: «для каждого символа окна — сколько раз он в нём встречается». Слова «словарь» для этого мало.
Показывает обновление при каждой границеРасширение добавляет пришедший элемент, сжатие убирает ушедший до сдвига l.
Выводит условие цикла из задачиКороткий отрезок — пока окно подходит, длинный — пока недопустимо.
Объясняет, зачем нужен цикл whileИ приводит вход, на котором if ошибается: 'abba'.
Говорит, где записывается ответ и почемуВнутри цикла — для короткого отрезка, после цикла — для длинного.
Называет граничные входы и ответы на нихПустой вход, повторы, отрезка нет, неверный порог.
Разбор 1Кандидат объясняет shortest_window. Какое объяснение условия цикла верное?
while total >= s:
    length = r - l + 1
    ...
    total -= nums[l]
    l += 1

  • Большая сумма ответу не мешает: подходит любое окно с суммой не меньше s. Окно сжимают, чтобы проверить, подойдёт ли окно короче.

  • Верно. Условие цикла совпадает с условием допустимости, длина записывается перед каждым сжатием, а после цикла окно уже не подходит.

  • Слева уходят элементы, которые могли бы войти в более короткое окно, если бы суммы хватило. Причина сжатия — поиск самого короткого окна.

Разбор 2Кандидат говорит: «В count хранятся все символы строки, которые мы уже видели». Что не так в этом объяснении?

  • При сжатии счётчики ушедших символов уменьшаются. Если бы в карте были все просмотренные символы, условие count[ch] > 1 срабатывало бы на повторах вне окна.

  • Позиции хранит словарь last в варианте из главы 10.5, §8. В count — числа вхождений.

  • Верно. Состояние окна описывает только окно с l по r. Символ, который ушёл, остаётся ключом со счётчиком 0 и на условие цикла не влияет.

Разбор 3В Pull Request к longest_unique добавлены тесты. Каких тестов не хватает до контроля КТП?
def test_example():
    assert longest_unique("abcabcbb") == 3

def test_all_different():
    assert longest_unique("abcdef") == 6

def test_case():
    assert longest_unique("aA") == 2

  • Верно. Контроль КТП — «проверяются дубликаты и пустая строка». Пустой строки в тестах нет, а версии с if и с count[ch] -= 1 проходят все три теста.

  • Скорость проверяют замером, глава 10.7. Тесты границ проверяют правильность на крайних входах.

  • На 'abcabcbb' версия с count[ch] -= 1 возвращает верный ответ 3, глава 10.5, §7. Одного примера с повторами мало.
