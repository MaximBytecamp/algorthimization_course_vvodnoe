В этой главе решается первая задача КТП занятия 10 — найти самый короткий отрезок с суммой не меньше S. Схема прохода взята из главы 10.3, в ней меняются два места: окно сжимается, пока оно подходит, и длина записывается внутри цикла while. В конце — отправка решения на LeetCode 209 и задача LeetCode 1004 со счётчиком нулей.

§1Условие задачи

Условие уточнено в главе 10.2, здесь оно записано в окончательном виде. В главе используются два списка из таблицы примеров той же главы: заказы магазина по часам и пример из условия LeetCode 209.

shortest_window(nums, s)задача 1 занятия 10 · минимальный отрезок с суммой не меньше S

nums — список целых неотрицательных чисел, может быть пустым. s — порог суммы, s ≥ 1, иначе ValueError. Вернуть длину самого короткого отрезка подряд с суммой не меньше s. Если такого отрезка нет, вернуть 0. Список не меняется.

Пример 1: заказы nums = [5, 8, 3, 12, 20, 6, 22, 9], s = 30. Ответ 2: отрезок [12, 20] с суммой 32. Пример 2: nums = [2, 3, 1, 2, 4, 3], s = 7. Ответ 2: отрезок [4, 3] с суммой точно 7.

Условие допустимости — total >= s. Окно, для которого оно выполнено, дальше называется подходящим.

§2Сжатие подходящего окна

В главе 10.3 искали самый длинный отрезок. Расширение там могло сделать окно недопустимым, и цикл while сжимал окно, пока оно снова не становилось допустимым. Здесь нужен самый короткий отрезок, и роли меняются. Расширение приближает окно к подходящему: сумма растёт. Когда окно стало подходящим, его сжимают, чтобы проверить, останется ли оно подходящим при меньшей длине.

Сравнение из жизни: в копилку опускают монеты, пока не наберётся нужная сумма. Когда набралось, из копилки достают монеты, положенные раньше всех, пока суммы ещё хватает, и каждый раз записывают, сколько монет осталось. Наименьшее из записанных чисел — ответ.

  1. Расширение. Правая граница r сдвигается на один элемент: total += nums[r].
  2. Запись и сжатие. Пока окно подходит, то есть пока total >= s: сравнить длину окна r − l + 1 с лучшей, затем убрать левый элемент: total -= nums[l], l += 1.
  3. Ответ. После цикла for вернуть лучшую длину или 0, если подходящего окна не было.

Отличия от схемы главы 10.3 собраны в таблице. Строки расширения и сжатия те же, меняются условие цикла и место, где записывается длина.

Место записи следует из четвёртой строки таблицы. В этой задаче окно после цикла while уже не подходит, поэтому записывать его длину после цикла нельзя. Подходящим окно бывает только внутри цикла, в момент проверки условия.

§3Проход вручную

Сделайте проход сами на списке заказов с порогом 30. На каждом шаге выберите, какую границу сдвинуть. Перед каждым сжатием длина подходящего окна сравнивается с лучшей автоматически. Неверный ход не выполняется, вместо него появляется объяснение.

§4Сборка цикла и песочница

Начало функции написано: проверка s и три переменные — best = 0, total = 0, l = 0. Ниже девять строк остальной части. Длина окна сначала кладётся в переменную length, затем сравнивается с лучшей. Расставьте строки по порядку.

Python в этой строке: if best == 0 or length < best

Оператор or даёт истину, если истинно хотя бы одно из двух условий. Первое условие срабатывает, когда подходящих окон ещё не было: тогда записывается любая длина. Второе — когда новое окно короче лучшего. Если первое условие истинно, второе Python не проверяет.

>>> best, length = 0, 4
>>> best == 0 or length < best
True
>>> best, length = 4, 3
>>> best == 0 or length < best
True
>>> best, length = 3, 3
>>> best == 0 or length < best
False

§5Код и пошаговый прогон

Прогон на примере 2: список [2, 3, 1, 2, 4, 3], порог 7. В нём стоит проследить за тремя местами. На шагах 16–21 найдено первое подходящее окно длины 4, оно записано и сжато. На шагах 25–35 окно сжимается два раза подряд, длина уменьшается до 3. На шагах 44–47 сумма окна [4, 3] равна порогу точно, и в best попадает ответ 2.

Инвариантсамый короткий подходящий отрезок

После цикла while на шаге с индексом r: total — сумма элементов с l по r, и эта сумма меньше s. В best — наименьшая длина подходящего отрезка, который заканчивается не правее r, или 0, если таких отрезков нет.

Сохранение: цикл while записывает длину каждого подходящего окна с концом в r и сжимает окно. Последнее записанное окно — самое короткое подходящее с этим концом: следующее за ним уже не подходит. Начала левее l больше не нужны. Отрезок с таким началом и более правым концом содержит уже записанное подходящее окно целиком, поэтому он длиннее его и ответом быть не может.

Оценка времени та же, что в главе 10.3: правая граница сдвигается n раз, левая — не больше n раз за весь проход, всего не больше 2·n сдвигов. Цикл while останавливается без отдельной проверки l <= r: сумма пустого окна равна 0, а порог не меньше 1. На этом держится проверка s в первой строке: при s = 0 условие total >= s было бы истинно и для пустого окна, и на непустом списке индекс l вышел бы за его конец: функция закончилась бы исключением IndexError.

§6Место записи и знак в условии цикла

Первая ошибка — перенести в эту задачу схему главы 10.3 без изменений и записывать длину после цикла while. Вторая — поставить в условии цикла строгий знак. Обе версии запущены на примере 2 и возвращают число, исключений нет. Верный ответ — 2.

shortest_window([2, 3, 1, 2, 4, 3], 7)переключите вкладку

Строки записи длины стоят после цикла while, как в функции longest_within.

1После цикла окно не подходит: его сумма меньше порога. На шагах 8 и 9 в best записывается длина 1 окна [2] с суммой 2. Подходящие окна на шагах 23, 31, 34, 42 и 45 сжимаются без записи. Функция возвращает 1, хотя ни один элемент списка не равен 7 и не больше.

Условие цикла: while total > s вместо while total >= s.

3На шаге 30 сумма окна [1, 2, 4] равна 7, условие 7 > 7 ложно, и длина 3 остаётся незаписанной. На шаге 44 то же происходит с окном [4, 3] длины 2. Функция возвращает 3. Окна с суммой точно s эта версия не считает подходящими, хотя интервьюер в главе 10.2 ответил, что они подходят.

Верная версия — прогон в §5. Первую ошибку находят тесты песочницы test_example, test_exact_sum, test_whole_list, test_no_window и сравнение с перебором, вторую — test_exact_sum, test_whole_list, test_zeros и сравнение с перебором. На примере 1 вторая версия возвращает верный ответ 2: сумма лучшего отрезка заказов равна 32, это строго больше порога. Поэтому пример с суммой точно на пороге записан в таблицу главы 10.2 отдельной строкой.

§7Начальное значение ответа

В задаче на самый длинный отрезок ответ начинается с 0 и растёт через max. Здесь ответ уменьшается, и перенести тот же приём с заменой max на min нельзя. Ниже версия, в которой три строки записи заменены одной: best = min(best, r - l + 1), а начальное значение осталось best = 0.

shortest_window([2, 3, 1, 2, 4, 3], 7)переключите вкладку

0На шаге 17 найдено подходящее окно длины 4, но min(0, 4) равно 0. Начальное значение меньше любой длины, поэтому best не меняется до конца. Функция возвращает 0, то есть сообщает, что подходящего отрезка нет.

2На шаге 18 условие best == 0 истинно, и первая найденная длина 4 записывается без сравнения. Дальше длина записывается, только если она меньше лучшей.

В верной версии число 0 в переменной best означает «подходящего окна ещё не было». Настоящая длина подходящего окна не меньше 1, поэтому спутать эти значения нельзя. Интервьюер в главе 10.2 попросил вернуть 0, если отрезка нет, и это значение возвращается без преобразования.

Распространён и другой вариант: начать с бесконечности, best = float("inf"). Любая длина меньше неё, поэтому работает запись через min. Но бесконечность нельзя вернуть как ответ, и последняя строка функции должна её заменить: return 0 if best == float("inf") else best.

Python в этой строке: float("inf")

float("inf") — число с плавающей точкой «плюс бесконечность». Оно больше любого целого числа, поэтому min с ним возвращает второе число. Сравнение двух бесконечностей на равенство даёт True.

>>> best = float("inf")
>>> 4 < best
True
>>> best = min(best, 4)
>>> best
4
>>> min(float("inf"), 3)
3
>>> float("inf") == float("inf")
True

Оба варианта верны. В модуле используется первый: в нём последняя строка функции — return best без преобразования.

§9Счётчик в окне, LeetCode 1004

Состояние окна не обязательно сумма. В LeetCode 1004 дан массив из нулей и единиц и число k. Нужно найти наибольшее число единиц подряд, которое получится, если заменить единицами не больше k нулей. В главе 10.2 задача пересказана так: найти самый длинный отрезок, в котором нулей не больше k. Массив при этом не меняется.

Это задача на самый длинный отрезок, поэтому схема взята из главы 10.3 целиком. Меняется состояние окна: вместо суммы — счётчик нулей zeros. Пришедший ноль увеличивает счётчик на 1, ушедший — уменьшает. Условие допустимости — zeros <= k, условие цикла — его отрицание.

Прогон на списке [1, 0, 1, 1, 0, 1, 0, 1] с k = 1, ответ 4. На шагах 24–31 в окно пришёл второй ноль, и окно сжимается два раза: первый раз уходит единица, счётчик не меняется, и только после ухода нуля окно снова допустимо. На шагах 40–50 сжатий три.

Сравнение с функцией longest_within показывает, какие строки в решении общие для всех задач на самый длинный отрезок, а какие зависят от задачи.

§10Проверьте себя

Вопрос 1Порог 7. Окно [1, 2, 4] с суммой 7, лучшая длина пока 4. Что сделает цикл while?

  • Условие цикла — total >= s, и 7 >= 7 истинно. Так вела бы себя версия со строгим знаком из §6.

  • Длина записывается перед сжатием, пока окно подходит. Окно [2, 4] с суммой 6 уже не подходит, его длина не записывается.

  • Верно. Окно подходит, 3 меньше 4, длина записывается. После сжатия сумма 6 меньше порога, и цикл заканчивается.

Вопрос 2Почему длина записывается внутри цикла while, а в главе 10.3 — после него?

  • Верно. Цикл работает, пока окно подходит, и заканчивается, когда суммы перестало хватать. В главе 10.3 наоборот: цикл работает, пока окно недопустимо.

  • Запись стоит одно сравнение в любом месте. Место определяется тем, в какой момент окно удовлетворяет условию задачи.

  • Переменная r доступна во всём теле цикла for. После цикла while окно существует, но его сумма меньше порога.

Вопрос 3Что вернёт shortest_window([3, 3, 3], 10) и почему?

  • Сумма всего списка равна 9, это меньше 10. Подходящего отрезка в списке нет.

  • Верно. Сумма окна не достигает 10 ни при каком положении правой границы, запись не выполняется, и в best остаётся начальное значение 0.

  • Исключение даёт только порог меньше 1. Порог, которого сумма не достигает, — обычный вход, ответ на него 0.
