§2Порядок работы на паре

Работа идёт в папке lesson_10 на своём компьютере, нужен Python с pytest. Если Python ещё не настроен, начните с песочниц в главах 10.2–10.3: там те же функции пишутся прямо на странице и проверяются похожими тестами. Сдаётся всё равно solution.py с зелёным pytest.

  1. Скопируйте папку lesson_10 в portfolio/lesson_10/ личного репозитория и выполните python -m pytest tests.py -v. Все 39 тестов должны упасть: так проверяется, что pytest нашёл файлы и запустил тесты.
  2. До кода откройте initial_attempt.txt и запишите вопросы к условиям задач 1 и 2 и примеры с ответами: «отрезка нет», сумма точно равна s, пустая строка, повторы. Образец — глава 10.1, §4.
  3. Напишите longest_within. Проверка: python -m pytest tests.py -k within.
  4. Напишите shortest_window. Проверка: -k shortest, затем тесты границ: -k "bad_s or shortest_edges". Если тест падает, найдите симптом в сводке главы 10.4, §2.
  5. Напишите longest_unique: -k unique.
  6. Запустите замер: python bench.py > bench_results.txt. Он идёт около 25 секунд.
  7. Заполните complexity_note.md для трёх обязательных функций.
  8. Если осталось время — total_fruit из главы 10.3, §5: -k fruit.
  9. Если и это готово — extra.py: единицы с заменой нулей, единицы после удаления, число подотрезков без повторов. Проверка: python -m pytest tests_extra.py -v.

Для каждой: вход, на котором ответ неверный; падающий тест в tests_bugs_10.py; исправление одной строки; повторный прогон. Вывод pytest — в bugs_run.txt.Глава 10.4: граничные входы и сводка ошибок
3 · Отрезки с произведением меньше kФункция count_small_products(nums, k), LeetCode 713: сколько отрезков подряд имеют произведение строго меньше k. Числа от 1 и больше, k — любое целое, в том числе 0 и 1. Пример: [10, 5, 2, 6], k = 100 → 8. Время O(n), память O(1). Не меньше шести своих тестов: k = 0, k = 1, пустой список, один элемент, отрезок с произведением ровно k.Глава 10.2: схема прохода; глава 10.4: границы

Тест к bugs_10.py засчитывается, если до исправления он падает, а после — проходит. Тест, который проходит и на ошибочной версии, ошибку не находит.
