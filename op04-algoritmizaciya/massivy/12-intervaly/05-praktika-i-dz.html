§2Порядок работы на паре

Работа идёт в папке lesson_12 на своём компьютере, нужен Python с pytest. Если Python ещё не настроен, начните с песочниц в главах 12.2–12.3: там те же функции пишутся прямо на странице и проверяются похожими тестами. Сдать при этом нужно solution.py с зелёным pytest.

  1. Скопируйте папку lesson_12 в portfolio/lesson_12/ личного репозитория и выполните python -m pytest tests.py -v. Все 39 тестов должны упасть: так проверяется, что pytest нашёл файлы и запустил тесты.
  2. До кода откройте initial_attempt.txt. Запишите вопросы к условиям задач 1 и 2, перебор с его сложностью и примеры с ответами: пустой список, один интервал, касание, вложенный интервал, повтор, конфликт в последней паре. Образец вопросов — глава 12.1, §5.
  3. Разминка — overlaps: условие пересечения двух интервалов из главы 12.1, §2. Проверка: python -m pytest tests.py -k overlaps.
  4. Напишите merge_intervals. Проверка: -k merge. Если тест падает, найдите симптом в сводке главы 12.4, §2.
  5. Напишите can_attend: -k attend.
  6. Запустите замер: python bench.py > bench_results.txt. Он идёт несколько секунд.
  7. Заполните complexity_note.md для трёх обязательных функций.
  8. Если осталось время — insert_interval из главы 12.3, §6: -k insert.
  9. Если и это готово — extra.py: общее время отравления по моментам атак (интервалы уже упорядочены), число способов разделить отрезки на две группы и свободные окна рабочего дня. Проверка: python -m pytest tests_extra.py -v.

ЗадачаЧто сделатьГде помогут
1 · Довести решенияsolution.py проходит все 39 тестов. bench_results.txt — ваш замер. complexity_note.md заполнен по трём функциям: запись интервала, ключ сортировки и зачем он, что хранится между итерациями, время, память и таблица замера.Главы 12.2–12.4
2 · Три ошибки на границеВ bugs_12.py функции busy_hours, first_conflict, longest_busy. Каждая верно отвечает на обычных входах и ошибается на граничном. Для каждой: вход, на котором ответ неверный; падающий тест в tests_bugs_12.py; исправление одной строки; повторный прогон. Вывод pytest — в bugs_run.txt.Глава 12.4: граничные входы и сводка ошибок
3 · Дни без встречФункция count_free_days(days, meetings), LeetCode 3169. Дни пронумерованы от 1 до days, встреча [start, end] занимает дни с start по end включительно. Вернуть, сколько дней без встреч. Пример: days = 10, [[5, 7], [1, 3], [9, 10]] → 2. Время O(n log n), где n — число встреч; days бывает до 10⁹, поэтому перебирать дни нельзя. Не меньше шести своих тестов: встреч нет, встреча на все дни, вложенная встреча, встречи в соседние дни [1, 3] и [4, 5], встреча из одного дня.Глава 12.2: объединение; глава 12.1, §2: запись с включённым концом

Тест к bugs_12.py засчитывается, если до исправления он падает, а после — проходит. Тест, который проходит и на ошибочной версии, ошибку не находит.
