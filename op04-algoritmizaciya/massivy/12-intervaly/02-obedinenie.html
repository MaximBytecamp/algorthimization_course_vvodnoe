§1Перебор и зачем сортировать

Без порядка бронь может пересечься с любым из уже собранных блоков. Возьмём брони в порядке заявок: [13, 15], [9, 12], [16, 18]. Пока это три отдельных блока. Следующая бронь [15, 16] касается и первого блока, и третьего, и после неё эти два блока сливаются в один. Перебор поэтому устроен так: найти любую пару блоков, которые пересекаются или касаются, склеить её и искать снова. Одна проверка всех пар — O(n²) сравнений, а повторов бывает много.

Сортировка по началу меняет картину. Так склеивают куски ленты, разложенные на столе по месту, где начинается каждый: слева направо, и каждый следующий кусок прикладывают только к концу последнего склеенного, потому что остальные куски лежат левее и уже закончились. С бронями так же. После сортировки текущую бронь сравнивают с последним блоком в списке merged, и вариантов два.

  • Начало брони не больше конца блока. Бронь пересекает блок или касается его. Свободного времени между ними нет, блок продлевается до большего из двух концов.
  • Начало брони больше конца блока. Между ними свободное время. Блок закончен: у всех следующих броней начало не меньше текущего, значит, тоже больше конца блока. Бронь начинает новый блок.

Каждая бронь обрабатывается одним сравнением. Порядок, в котором это работает, даёт только сортировка: в списке заявок бронь [9, 12] идёт после [13, 15], и правило «сравнить с последним блоком» ошибается. Это видно в §6.

§2Объединение вручную

Отсортируйте брони и пройдите их сами. На каждой брони выберите: продлить последний блок или начать новый. Неверный ход не выполняется, вместо него появляется объяснение.

Пять броней дали четыре решения, каждое — одно сравнение начала брони с концом последнего блока. На брони [10, 11] блок не изменился: она лежит внутри [9, 12], и конец блока — большее из 12 и 11. На бронях [15, 16] и [16, 18] начало равно концу блока: брони касаются, и блок продлевается.

§3Сортировка в Python

Функция sorted принимает список и возвращает новый, отсортированный. Исходный список не меняется. Списки из двух чисел Python сравнивает по первому числу, а при равных первых — по второму. Поэтому sorted(intervals) упорядочивает брони по началу, а брони с одинаковым началом — по концу. Для объединения этого достаточно.

У списков есть и метод sort: intervals.sort() сортирует сам список и ничего не возвращает. По контракту из главы 12.1 входной список не меняется, поэтому в решении стоит sorted. Что происходит при sort, показано в главе 12.4.

Сортировка n элементов в Python стоит O(n log n) сравнений. На занятии это готовый инструмент: как устроены алгоритмы сортировки и откуда берётся n log n, разбирается на следующих занятиях по КТП.

§4Код и пошаговый прогон

Функция — сортировка и один цикл с условием из §1. Напишите её сами. Тесты проверяют пример с бронями рампы, касание, вложенную бронь, пустой список, то, что входной список не изменился, и сравнивают ответ с перебором на двухстах случайных списках.

Python в этой строке: if merged and start <= merged[-1][1]:

Пустой список в условии if считается ложным, непустой — истинным. Если merged пуст, and не вычисляет вторую часть, и обращения к merged[-1] не происходит. Индекс −1 — последний элемент списка, второй индекс [1] — конец этого блока.

>>> merged = []
>>> bool(merged)
False
>>> merged = [[9, 12], [13, 15]]
>>> merged[-1]
[13, 15]
>>> merged[-1][1]
15

В строке 8 в merged кладётся новый список [start, end]. Строка 6 потом меняет конец блока. Если бы блок был тем же списком, что лежит во входных данных, изменился бы и вход. Этот случай разобран в главе 12.4.

Прогон ниже — на бронях рампы. На оси верхние дорожки — список ordered, текущая бронь подсвечена. Нижняя дорожка — блоки merged, она растёт по ходу прогона.

Инвариант цикла: после обработки брони все блоки merged, кроме последнего, закончены и не пересекаются и не касаются ни одной брони, которая ещё впереди, а последний блок покрывает все пройденные брони, которые с ним пересекаются. Инвариант держится на сортировке: следующие брони начинаются не раньше текущей.

§5Почему время O(n log n)

Сортировка стоит O(n log n). Цикл проходит n броней, на каждой — одно сравнение и одна запись: O(n). Вместе O(n log n + n) = O(n log n): слагаемое n при росте n отстаёт от n log n. Память — O(n): копия ordered и список блоков merged. Перебор из §1 только на одну проверку всех пар тратит O(n²).

Замер на ноутбуке автора, Python 3.12: n броней, которые не пересекаются и не касаются, в случайном порядке. Для перебора это худший случай: склеивать нечего, и проверяются все пары.

Когда n удваивается, время перебора растёт примерно в 4 раза, время решения с сортировкой — чуть больше чем в 2. Это первый опыт скрипта bench.py из стартового набора, глава 12.5. Третий опыт того же скрипта показывает, что на входах от 20 000 до 80 000 броней около 70 % времени merge_intervals уходит на sorted, остальное — на проход. Каждое число — медиана пяти запусков.

§6Три изменённые версии

В каждой версии изменена одна строка. Все три запущены на бронях рампы, исключений нет. Верный ответ — [[9, 12], [13, 18]].

merge_intervals(брони рампы)переключите вкладку

Условие склейки записано со строгим знаком: start < merged[-1][1].

[[9, 12], [13, 15], [15, 16], [16, 18]]На шагах 13 и 16 брони касаются блока, и строгое условие ложно. Касающиеся брони остаются отдельными блоками, хотя рампа занята без перерыва с 13 до 18.

Конец блока заменяется концом брони: merged[-1][1] = end.

[[9, 11], [13, 18]]На шаге 8 бронь [10, 11] лежит внутри блока [9, 12], и конец блока уменьшается до 11. Час с 11 до 12 пропадает из ответа. Ошибку видно только на вложенной брони: если каждая следующая бронь заканчивается позже блока, эта версия отвечает верно.

Строки с sorted нет, цикл идёт по intervals в порядке заявок.

[[13, 15], [16, 18]]На шаге 6 бронь [9, 12] вливается в блок [13, 15]: условие сравнивает её начало только с концом блока. Начало блока остаётся 13, и часы с 9 до 13 теряются. Правило «сравнить с последним блоком» верно только для отсортированного списка.

Первая ошибка видна только на касании, вторая — только на вложенной брони. Поэтому в тестах занятия есть оба случая: [[9, 11], [11, 12]] и [[1, 10], [2, 3], [4, 5]]. Третья ошибка видна на любом неотсортированном входе.
