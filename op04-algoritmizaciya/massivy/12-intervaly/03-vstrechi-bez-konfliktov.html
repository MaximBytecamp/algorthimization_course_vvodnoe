Встречи без конфликтов:
ключ сортировки

Вторая задача КТП — проверить, можно ли провести все встречи в одной переговорной. В главе разобрано, почему после сортировки достаточно сравнить соседние встречи, код с прогоном и две ошибки. §1Задача и перебор

Условие LeetCode 252 «Meeting Rooms»: дан список встреч, каждая — пара «начало, конец». Нужно выяснить, можно ли побывать на всех встречах, то есть нет ли двух встреч, которые пересекаются. Задача на LeetCode платная, поэтому условие здесь пересказано. В занятии та же задача звучит так: хватит ли одной переговорной на все встречи дня. Встреча записана полуинтервалом [start, end), касание конфликтом не считается: одна встреча заканчивается в 11:00, следующая в 11:00 начинается.

Перебор сравнивает каждую пару встреч условием пересечения из главы 12.1: a[0] < b[1] and b[0] < a[1]. Пар n·(n − 1)/2, это O(n²). В замере bench.py на 4 000 встреч без конфликтов перебор тратит около 300 мс, решение с сортировкой — меньше 1 мс.

§2Почему достаточно соседей

После сортировки по началу каждую встречу сравнивают только с предыдущей: ordered[i][0] < ordered[i - 1][1], то есть начинается ли встреча раньше, чем заканчивается предыдущая. Почему соседей достаточно, видно на трёх встречах.

Встречи ordered[0] = [9, 13] и ordered[2] = [12, 14] пересекаются, хотя в списке они не соседи. Между ними стоит ordered[1] = [10, 11]. После сортировки её начало лежит между началами соседей: 9 ≤ 10 ≤ 12. Встреча [12, 14] начинается раньше 13, конца первой встречи, а [10, 11] начинается ещё раньше. Значит, и она пересекает первую встречу. Так в любом отсортированном списке: если встреча пересекается с какой-то из предыдущих, то пересекается и одна из соседних пар между ними. Поэтому проверка соседей находит конфликт всегда, когда он есть.

Найдите конфликт сами. После сортировки сравните каждую встречу с предыдущей. Среди пар есть касания: их нужно отличить от конфликта.

§3Код и пошаговый прогон

Напишите функцию сами. Тесты проверяют встречи без конфликтов с касаниями, конфликт в последней паре, повтор одной встречи, пустой список и сравнивают ответ с перебором всех пар на двухстах случайных списках.

Цикл начинается с 1: у первой встречи нет предыдущей. Для пустого списка и списка из одной встречи range(1, len(ordered)) пуст, и функция сразу возвращает True. В прогоне подсвечены текущая встреча и предыдущая. На шагах 3 и 7 встречи касаются, конфликта нет.

Время — O(n log n) на сортировку и O(n) на проход. Если конфликт найден рано, цикл заканчивается раньше, но сортировка всё равно проходит целиком. Память — O(n) на копию ordered.

§4Две изменённые версии

Обе версии запущены на встречах из прогона. Встречи не пересекаются, верный ответ — True. Обе версии возвращают False.

can_attend([[13, 15], [9, 11], [15, 16], [11, 12]])переключите вкладку

Условие конфликта записано с нестрогим знаком: ordered[i][0] <= ordered[i - 1][1].

FalseНа шаге 3 встреча [11, 12] начинается в момент, когда заканчивается [9, 11]. Нестрогий знак считает касание конфликтом. В задаче 1 тот же знак <= был верным: там касающиеся брони склеиваются.

Строка с сортировкой заменена на ordered = intervals.

FalseНа шаге 3 встреча [9, 11] стоит после [13, 15]. Её начало 9 меньше конца 15, и условие сообщает о конфликте, хотя встреча заканчивается до начала [13, 15].

Без сортировки функция ошибается только в одну сторону: находит конфликт там, где его нет. Конфликт она не пропускает. Если она вернула True, каждая встреча в списке начинается не раньше конца предыдущей, и встречи действительно идут одна за другой. Это проверено запуском на 20 000 случайных списков: пропусков 0, ложных конфликтов 3 174.

§5По какому ключу сортировать

Контроль занятия по КТП требует объяснить, по какому ключу сортируются данные. Ключ — то, по чему сравниваются элементы при сортировке. Его задают параметром key: это функция, которая для каждого элемента возвращает значение для сравнения.

Python в этой строке: sorted(intervals, key=lambda iv: iv[1])

lambda iv: iv[1] — короткая функция без имени: она получает интервал iv и возвращает его конец. sorted вызывает её для каждого интервала и сортирует по полученным числам. Сами интервалы при этом не меняются.

>>> sorted([[1, 10], [2, 3], [4, 5]], key=lambda iv: iv[1])
[[2, 3], [4, 5], [1, 10]]
>>> sorted([[1, 4], [3, 6], [1, 8]], key=lambda iv: (iv[0], -iv[1]))
[[1, 8], [1, 4], [3, 6]]

Для проверки конфликтов годится и сортировка по концу. Если встречи упорядочены по концу и какая-то встреча пересекается с одной из предыдущих, она начинается раньше конца той встречи, а значит, и раньше конца своей соседки слева: у соседки конец не меньше. Сравнение соседей снова находит конфликт. На 20 000 случайных списков ответы обеих сортировок совпали.

Для объединения сортировка по концу не годится. Объединение рассчитывает на то, что следующие интервалы начинаются не раньше текущего. При сортировке по концу длинный интервал с ранним началом окажется в конце списка. Обе версии ниже запущены на [[1, 10], [2, 3], [4, 5]]: все три интервала лежат внутри [1, 10], ответ — один блок.

merge_intervals([[1, 10], [2, 3], [4, 5]])переключите вкладку

сортировка по концу

[[2, 3], [4, 10]]На шаге 7 блок [2, 3] закрыт: следующий интервал начинается в 4. Но [1, 10] идёт последним и начинается в 1. На шаге 10 он вливается в блок [4, 5], а блок [2, 3] остаётся отдельным.

сортировка по началу

[[1, 10]][1, 10] стоит первым, остальные интервалы лежат внутри него и блок не меняют.

Иногда ключ состоит из двух чисел. Задача LeetCode 1288: сколько интервалов останется, если удалить те, что целиком лежат внутри другого. Интервалы сортируют по началу, а при равном начале — по убыванию конца: ключ (iv[0], -iv[1]). Тогда из интервалов с одним началом первым идёт самый длинный, и все остальные оказываются внутри уже пройденного. Дальше хватает одного прохода с переменной reach — самым дальним концом среди пройденных интервалов.

Во втором примере при сортировке только по началу [1, 4] шёл бы раньше [1, 8] и был бы посчитан как непокрытый: в момент его проверки [1, 8] ещё не пройден. Ключ с -iv[1] ставит [1, 8] первым, и ответ верный — 1.

§6Вход уже отсортирован: вставка интервала

Задача LeetCode 57 из плана Top Interview 150: дан список блоков, отсортированный по началу, без пересечений, и новый интервал. Нужно вставить интервал и склеить его с блоками, которые он задевает. Такой список возвращает merge_intervals, поэтому задача отвечает на вопрос диспетчера «пришла ещё одна бронь — как теперь выглядят блоки занятости».

Можно добавить бронь в список и вызвать merge_intervals заново: O(n log n). Но список уже отсортирован, и сортировка не нужна. Проход делится на три части: блоки, которые целиком левее новой брони, переходят в ответ как есть; блоки, которые пересекаются с ней или касаются её, вливаются в неё; блоки правее переходят в ответ как есть. Время O(n).

Прогон — на блоках рампы [[9, 12], [13, 15], [16, 18]] и новой брони [11, 14]. Пунктиром показана новая бронь после каждого слияния. Она задевает два блока и склеивает их: [9, 15].

Это стартовая задача 3 занятия, расширение: insert_interval в solution.py. Её тесты сравнивают ответ с объединением всего списка заново.
