§1Разбор best_window по строкам

В главе 9.4 функция собрана из строк и пройдена по шагам. Здесь каждая строка разобрана отдельно: за что она отвечает и что получится, если записать её иначе. Под таблицей изменённые версии запущены.

СтрокаЧто делаетЕсли записать иначе
if k < 1 or k > len(nums):Отсекает неверный k и пустой список до работы с окнамиБез строки при k = 0, k > n и на пустом списке функция молча возвращает ответ для окна, которого нет. С k >= len(nums) она отказывается работать на допустимом k = n
total = sum(nums[:k])Сумма первого окна — единственного, которое складывается целикомsum(nums[:k - 1]) — в первом окне на элемент меньше, и каждая сумма отличается от верной на nums[k − 1]
best, start = total, 0Первое окно — пока лучшееbest = 0 — неверный ответ при всех отрицательных суммах, глава 9.4, §6
for r in range(k, len(nums)):r — индекс элемента, который входит в окно, от k до последнегоrange(k + 1, …) — пропущен один сдвиг, все суммы после него неверны

§2Запуск изменённых версий

Три изменения из таблицы, которые в главах 9.3 и 9.4 ещё не запускались. На каждой вкладке отличается одна строка, вход подобран так, чтобы изменение проявилось. Ошибочный ответ сопоставлен с верным.

best_window с одной изменённой строкойпереключите вкладку

Проверки k нет. Вход — [1, 2], k = 0. Верный ответ — ValueError: окна длины 0 не бывает.

(0, 0)Срез nums[:0] пустой, его сумма 0. На каждом шаге прибавляется и вычитается один и тот же элемент, сумма остаётся 0. Функция возвращает ответ, и ничто не говорит, что вход был неверным.

Проверки k нет. Вход — [1, 2], k = 3. Верный ответ — ValueError.

(0, 3)Срез за границей списка в Python ошибки не даёт: nums[:3] возвращает весь список из двух элементов. Цикл range(3, 2) пуст. Функция возвращает сумму «окна длины 3» в списке из двух элементов.

Цикл начинается с k + 1. Вход — список посещений, k = 3. Верный ответ — (4, 50).

(4, 42)На шаге 4 цикл начинается с r = 4, и сдвиг, на котором в окно входит nums[3] = 20, не выполняется. Дальше total на каждом шаге отличается от настоящей суммы окна: 39 вместо 47, 37 вместо 45, 42 вместо 50.

Проверка k >= len(nums). Вход — [4, 1, 2], k = 3: одно окно — весь список, верный ответ (0, 7).

ValueErrorУсловие 3 >= 3 истинно, и функция отказывается работать на допустимом входе. Это ошибка на единицу в проверке: окно длины n в списке из n элементов есть.

Верная версия на том же входе [4, 1, 2], k = 3.

(0, 7)Проверка пропускает k = 3, первое окно — весь список. Цикл range(3, 3) пуст: сдвигов нет, окно одно.

Первые две вкладки показывают, почему проверку пишут первой строкой. Без неё функция на неверном входе возвращает правдоподобный ответ: (0, 0) и (0, 3) выглядят как обычные результаты.

В модуле четыре функции. Три написаны по контракту курса и проверяют вход. max_vowels — решение LeetCode 1456, где условие гарантирует 1 ≤ k ≤ len(s), поэтому проверки в нём нет. Все значения в таблице получены запуском.

При k = 1 окно — один элемент: суммы окон совпадают со списком, лучшее окно — наибольший элемент. При k = n окно одно, цикл сдвигов не выполняется ни разу. Эти два значения k проверяют, что код верен и тогда, когда сдвигов максимальное число, и тогда, когда их нет совсем.

У max_events вместо k — длина окна по времени w. w = 0 и отрицательное w дают ValueError, пустой список — 0, а очень большое w допустимо: все события попадают в одно окно. На [1, 2] при w = 100 функция возвращает 2.

На полях: решения LeetCode и проверка входа

На LeetCode ограничения входа записаны в разделе Constraints, и тесты сайта их не нарушают. Поэтому решения задач с сайта обычно не проверяют k, и на собеседовании это допустимо, если ограничение названо вслед за условием. В коде, который вызывают другие функции, такой гарантии нет — отсюда проверка в best_window.

§4Почему исключение

На неверный k функция могла бы ответить по-разному: вернуть None, вернуть (0, 0) или бросить исключение. Интервьюер в главе 9.2 выбрал исключение. Причины видны в §2.

Ответ на неверный kЧто видит вызывающий кодЧем это опасно
Число или пара, например (0, 0)Обычный результатНеверный вход неотличим от настоящего ответа, ошибка уходит дальше по программе
NoneОсобое значениеКод, который не проверяет None, упадёт позже и в другом месте — там, где с результатом начнут работать
raise ValueErrorИсключение в строке вызоваПрограмма останавливается сразу и сообщает, какой аргумент неверен; перехватить можно через try … except ValueError

ValueError выбран потому, что тип аргумента верный — целое число, — а значение недопустимое. Так же поступает и стандартная библиотека: int("abc") бросает ValueError.

Проверку можно было бы записать через assert, но assert выключается при запуске Python с ключом -O. Тогда проверки нет совсем, и функция возвращает ответ на неверный вход:

Поэтому проверку входных данных пишут через if … raise, а assert оставляют для тестов и проверок, без которых программа может работать.

§7Review обновления окна

В КТП контроль занятия 9 включает «Git review на корректность обновления окна»: решение сдаётся Pull Request, и проверяющий читает код окна по строкам. Ниже — что он проверяет, затем три фрагмента для самостоятельного review.

Обновление окна проверено, если

Вход проверен до работы с окнамиk < 1 or k > len(nums) → ValueError; граница k = n пропускается.
Первое окно посчитано целикомsum(nums[:k]) — ровно k элементов, и оно учтено в ответе.
Цикл начинается с первого сдвигаrange(k, len(nums)): первый пришедший элемент — nums[k].
Ушедший элемент — nums[r − k]Для пришедшего nums[r] окно после сдвига — nums[r − k + 1:r + 1].
Состояние обновлено до сравненияСначала сдвиг, потом сравнение с лучшим, иначе сравнивается прошлое окно.
Знак сравнения совпадает с условием> — самое левое из равных окон, >= — самое правое.

Review 1Функция должна вернуть сумму каждого окна длины k. Какая строка неверна?
def window_sums(nums, k):
    if k < 1 or k > len(nums):
        raise ValueError("k должно быть от 1 до len(nums)")
    total = sum(nums[:k])
    sums = [total]
    for r in range(k, len(nums)):
        sums.append(total)
        total += nums[r] - nums[r - k]
    return sums

  • Границы цикла верные: r проходит индексы пришедших элементов от k до последнего.

  • Верно. Записывается сумма прошлого окна, поэтому первое окно попадает в ответ дважды, а последнее не попадает. На [1, 2, 3] с k = 2 функция вернёт [3, 3] вместо [3, 5].

  • Первое окно должно быть в ответе, эта строка верна. Ошибка в порядке двух строк в теле цикла.

Review 2Функция должна вернуть начало и сумму лучшего окна, при равных — самого левого. Какая строка неверна?
def best_window(nums, k):
    if k < 1 or k > len(nums):
        raise ValueError("k должно быть от 1 до len(nums)")
    total = sum(nums[:k])
    best, start = total, 0
    for r in range(k, len(nums)):
        total += nums[r] - nums[r - k]
        if total > best:
            best, start = total, r - k
    return (start, best)

  • Строгий знак соответствует условию «самое левое из равных».

  • Первое окно начинается с индекса 0, эта строка верна.

  • Верно. Окно, которое заканчивается на r, начинается с r − k + 1. r − k — индекс ушедшего элемента, на единицу левее. На списке посещений функция вернёт (3, 50) вместо (4, 50).

Review 3В Pull Request к best_window добавлены тесты. Каких тестов не хватает до контроля КТП?
def test_example():
    assert best_window([12, 15, 9, 20, 18, 7, 25], 3) == (4, 50)

def test_negative():
    assert best_window([-5, -2, -8, -1], 2) == (0, -7)

def test_bad_k():
    with pytest.raises(ValueError):
        best_window([1, 2], 0)

  • Верно. Контроль КТП — «тесты k=0/1/n и неверного k». Есть только k = 0; нет одного элемента в окне, одного окна на весь список и k больше n.

  • Скорость проверяют замером, глава 9.7. Тесты границ проверяют правильность на крайних входах.

  • Пример не проверяет ни k = 1, ни k = n: на нём цикл выполняется обычное число раз.
