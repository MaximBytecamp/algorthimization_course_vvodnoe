§2Порядок работы на паре

Работа идёт в папке lesson_09 на своём компьютере, нужен Python с pytest. Если Python ещё не настроен, начните с песочниц в главах 9.3–9.6: там те же функции пишутся прямо на странице и проверяются похожими тестами. Сдаётся всё равно solution.py с зелёным pytest.

  1. Скопируйте папку lesson_09 в portfolio/lesson_09/ личного репозитория и выполните python -m pytest tests.py -v. Все 34 теста должны упасть — так проверяется, что pytest видит файлы.
  2. До кода откройте initial_attempt.txt и запишите три вопроса к условию задачи 1 и пять примеров с ответами, среди них k = 1, k = n и неверный k. Образец — глава 9.2.
  3. Напишите window_sums_slices, затем window_sums. Проверка: python -m pytest tests.py -k sums.
  4. Напишите best_window. Проверка: -k best, затем тесты границ: -k "bad_k or k_is". Если тест границы падает, сравните код со строками таблицы из главы 9.6, §1.
  5. Напишите max_events: -k events.
  6. Запустите замер: python bench.py > bench_results.txt. Он идёт около 35 секунд.
  7. Заполните complexity_note.md для четырёх обязательных функций.
  8. Если осталось время — max_vowels, -k vowels.
  9. Если и это готово — extra.py: перекраска блоков, подстроки из трёх разных букв, сердитый продавец. Проверка: python -m pytest tests_extra.py -v.
На полях: когда можно открыть главы

Код функций есть в главах модуля. На занятии 10 окно переменной длины строится на этом коде, поэтому сначала пишется своя версия по правилу из главы, не открывая код. Если тест падает, откройте пошаговый прогон нужной главы и сравните шаги со своим кодом.

§4Вопросы для review

В КТП контроль занятия записан так: «Оценка O(n), тесты k=0/1/n и неверного k. Git review на корректность обновления окна». Ниже эти требования разложены на вопросы и на то, что должно прозвучать в ответе. Главы в правом столбце — где это разобрано.

Вопрос на reviewЧто должно прозвучать в ответеГде разобрано
Почему сдвиг окна — O(n), а срезы — O(n·k)?Срез заново читает k элементов для каждого из n − k + 1 окон; сдвиг исправляет сумму по двум изменившимся элементам за O(1). Свои числа из опыта 2 замера9.3, 9.7
Почему вложенный while в max_events не даёт O(n²)?l только растёт и не превышает r, за всю работу сдвигается не больше n раз9.5, §4
Какие тесты проверяют границы и что проверяет каждый?k = 1 — окно из одного элемента, сдвигов больше всего. k = n — одно окно, сдвигов нет. k = 0, k < 0, k > n и пустой список — ValueError9.6, §3 и §5
Как проверить, что окно обновляется верно?Первое окно — ровно k элементов и оно учтено; цикл с range(k, n); ушедший — nums[r − k]; сдвиг до сравнения; знак сравнения из условия9.6, §7
Почему на неверный k — исключение?Без проверки функция молча возвращает ответ для несуществующего окна; ValueError останавливает программу в строке вызова9.6, §2 и §4

§5Шпаргалка по модулю

Окно длины k: суммаtotal = sum(nums[:k]) best = total for r in range(k, len(nums)): total += nums[r] - nums[r - k] best = max(best, total)

r — пришедший, r − k — ушедший. Окно после сдвига — nums[r − k + 1:r + 1]. O(n), O(1).

Окно по времениl = 0 for r in range(len(times)): while times[r] - times[l] >= w: l += 1 best = max(best, r - l + 1)

Окно [s, s + w): при >= событие на правой границе не входит. l монотонный — O(n).

Признаки в условии

«длины k», «за k минут», «подряд», «подмассив», «подстрока» — окно фиксированной длины. «сумма не меньше S», «без повторов» без числа k — окно переменной длины, занятие 10.

Вопросы до кода

Что вернуть: значение, начало окна или само окно. Какое окно при равных ответах. Бывают ли отрицательные числа. Каким бывает k, что делать при k = 0 и k > n. Для окна по времени — открыта ли правая граница.

Состояние окна

Сумма, счётчик гласных, число белых блоков — исправляются по ушедшему и пришедшему за O(1). Максимум окна так не исправить — нужен дек, занятие 25.

Границы

k = 1 — окна совпадают с элементами. k = n — одно окно, цикл не выполняется. Неверный k и пустой список — ValueError до работы с окнами.

Сложность и замер

Срезы — O(n·k): при k = 100 время ×2 по n, при k = n/2 — ×4. Сдвиг — O(n) при любом k. Элемент среза дешевле шага цикла, поэтому при малых k разница меньше оценки.

Типичные ошибки

nums[r − k + 1] вместо nums[r − k]. Первое окно не в ответе. best = 0 при отрицательных. >= вместо > при «самом левом». range(k + 1, …). r − l вместо r − l + 1.
