# Как мы работаем с git

Каждая учебная задача проходит один и тот же путь. Он повторяет то, как
устроена работа в команде, поэтому отдельного «курса git» на дисциплине нет —
мы просто им пользуемся.

## Путь одной задачи

```
Issue или карточка задания
   ↓
git switch -c lesson-07          отдельная ветка на задачу
   ↓
git commit                       осмысленные коммиты по ходу решения
   ↓
git push -u origin lesson-07
   ↓
Pull Request                     описание подхода, сложности и тестов
   ↓
review                           замечания однокурсника или преподавателя
   ↓
исправления отдельным коммитом
   ↓
merge в main
```

## Имена веток

| Что делаем | Ветка |
|---|---|
| занятие | `lesson-07` |
| домашнее задание | `hw-01` |
| исправление после review | та же ветка, новый коммит |
| разбор mock-интервью | `mock-01` |

## Сообщения коммитов

Пишем, что сделано, а не «fix» и «update»:

```
lesson_07: максимальная серия за один проход
lesson_07: тест на пустой список
hw-01: три алгоритма из дня, разбор вход-правила-результат
mock-01: перенос решения и ретроспектива
```

## Что должно быть в Pull Request

1. Что за задача и что требовалось.
2. Какой подход выбран и почему именно он.
3. Время и память: `T(n)`, `S(n)`, худший случай.
4. Какие тесты добавлены, включая краевые случаи.
5. Что осталось непонятным — это нормальный пункт, его читают.

## Review

Смотрим не на стиль, а на решение: правильно ли выбрана структура данных,
учтены ли границы, сходится ли заявленная сложность с кодом.
Замечание формулируем конкретно: «на пустом списке будет IndexError,
нужен ранний выход», а не «тут плохо».

Исправление вносится **отдельным коммитом** — так видно, что изменилось
после review.
