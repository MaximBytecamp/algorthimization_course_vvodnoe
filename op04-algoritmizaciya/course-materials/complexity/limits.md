# Выбор решения под ограничения · занятие 3

Вторая часть работы на паре. Первая — разметить чужой код (`fragments.py`);
здесь обратный ход: по ограничению из условия назвать, какое решение вообще
имеет шанс пройти.

## Ориентир, которым пользуются на секции

Проверяющая система обычно даёт 1–2 секунды на тест. Для Python берут
ориентир **около 10⁷ простых операций в секунду**. Это не характеристика
языка и не константа из стандарта: цифра зависит от машины, от того, что
именно делается внутри цикла, и от версии интерпретатора. Она нужна ровно
для одного — прикинуть за десять секунд, укладывается решение или нет.

| Ограничение | Что успевает уложиться | Что обычно имеется в виду |
|---|---|---|
| n ≤ 20 | даже `O(2ⁿ)` | перебор всех подмножеств, полный перебор вариантов |
| n ≤ 500 | `O(n³)` | тройной вложенный цикл, работа с матрицей |
| n ≤ 5 000 | `O(n²)` | все пары элементов |
| n ≤ 10⁵ | `O(n log n)` | сортировка, бинарный поиск по ответу |
| n ≤ 10⁶ | `O(n)` | один-два прохода, множество или словарь |
| n ≤ 10⁹ | `O(log n)` или `O(1)` | по такому входу нельзя даже пройти один раз |

Последняя строка — самая полезная. Если в условии стоит `n ≤ 10⁹`, а вход
при этом одно число, а не список, то проход по всем значениям исключён
самим ограничением: ответ считается формулой или половинным делением.

## Задание

Для каждой ситуации запишите три строки: **какой класс сложности проходит**,
**какое решение** вы предложите и **что мешает** взять решение попроще.
Ответы — в свою заметку `lesson_03/limits.md`.

1. Список номеров заказов за сутки, `n ≤ 200 000`. Найти, есть ли среди них
   хотя бы два одинаковых.
2. Список цен на складе, `n ≤ 100 000`. Найти три самые дешёвые позиции.
3. Отсортированный архив чеков, `n ≤ 10⁷`, запросов `q ≤ 10⁵`. По каждому
   запросу сказать, есть ли такой чек.
4. Координаты курьеров, `n ≤ 3 000`. Найти два ближайших друг к другу.
5. Одно число `k ≤ 10⁹`. Сказать, сколько раз его можно разделить пополам
   до единицы.
6. Два списка накладных, `n ≤ 10⁵` и `m ≤ 10⁵`, оба отсортированы. Собрать
   из них один отсортированный список.

## На что смотрят при проверке

- класс сложности назван для **времени и для памяти**, а не только для времени;
- сказано, при каком входе решение работает дольше всего;
- если выбран более сложный подход — названо, что мешало обойтись простым;
- в ситуациях 3 и 6 в оценке две буквы, а не одна: величины растут независимо.

## Частая ошибка на этом задании

«`n ≤ 200 000`, значит нужен `O(n)`» — вывод верный, но не потому, что
двести тысяч большое число. `O(n²)` здесь означает 4·10¹⁰ операций, это
часы работы. А вот при `n ≤ 5 000` тот же `O(n²)` даёт 2,5·10⁷ операций,
а если сравниваются только пары `i < j`, то вдвое меньше — и решение проходит,
хотя алгоритм не изменился ни на строку. Класс сложности сам
по себе не хороший и не плохой — его сравнивают с ограничением.
