15.3

Разбор строки событий
и повреждённый ввод

Вторая задача КТП — разобрать строку события в словарь, а журнал из многих строк — в структурированный результат. В главе разобраны два уровня разбора, почему ключ отделяют методом partition, код с пошаговым прогоном и то, как разбор журнала переживает повреждённые строки.

§1Два уровня разбора

Строка события делится дважды. Сначала line.split(';') режет её на поля. Потом каждое поле делится на ключ и значение по знаку =. В блоке ниже видны оба шага. Кнопки подставляют повреждённые строки — те, о которых спрашивали интервьюера в главе 15.1, §4.

split(';') с аргументом сохраняет пустые куски: две точки с запятой подряд дают поле ''. Так повреждение не теряется, и его можно назвать по номеру поля. split() без аргумента пустые куски выбросил бы, но он режет по пробелам, а не по ;.

Блок проверяет каждый кусок по порядку: пустой ли он, есть ли =, не пустой ли ключ, не встречался ли ключ раньше. Код функции делает те же четыре проверки в том же порядке. Одна точка с запятой в конце строки по контракту допустима, поэтому код отрезает её до split.

§2Почему partition, а не split

Первое, что приходит в голову для поля, — key, value = field.split('='). На строке из примера это работает. Но значение может содержать =, как в последней кнопке блока: note=a=b.

изменённая версия

На втором поле split('=') даёт три куска ['note', 'a', 'b'], и разложить их в две переменные нельзя: ValueError. Сообщение об ошибке при этом про распаковку, а не про поле, и номера поля в нём нет.

field.partition('=') делит строку по первому = и всегда возвращает три части: ключ, сам разделитель и всё остальное. Если = нет, разделитель и значение — пустые строки. Проверка sep == '' находит поле без =, а знаки = в значении остаются на месте.

Python в этой строке: field.partition('=')

partition возвращает кортеж из трёх строк. split с ограничением maxsplit=1 тоже делит по первому разделителю, но возвращает список из одного или двух элементов, и его длину пришлось бы проверять отдельно.

>>> 'note=a=b'.partition('=')
('note', '=', 'a=b')
>>> 'user'.partition('=')
('user', '', '')
>>> 'note=a=b'.split('=', 1), 'user'.split('=', 1)
(['note', 'a=b'], ['user'])

§3Код и пошаговый прогон

Напишите функцию сами. Тесты проверяют строку из примера, пробелы, = в значении, пустое значение, точку с запятой в конце и четыре повреждения. У каждого повреждения проверяется номер поля в тексте ошибки.

Прогон — на строке из примера. Для каждого поля видны все четыре проверки. Если все пройдены, пара записывается в словарь.

Каждый символ строки читается по одному разу при split, partition и strip. Проверка key in event в словаре стоит O(1). Время — O(n), память — O(n) на список полей и словарь.

§4Журнал: ошибка строки не останавливает разбор

Журнал — много строк событий, по одной на строку текста. Если в нём тысяча строк и одна повреждена, остальные 999 нужны. Поэтому parse_log не даёт исключению из parse_event выйти наружу: ловит его, записывает номер строки и текст ошибки и переходит к следующей строке. После разбора проверяется, что у записи есть обязательные ключи time, user и action.

Прогон — на журнале из трёх строк, вторая повреждена: в ней две точки с запятой подряд.

Формат результата — пара списков. В events — словари верных записей по порядку, с ними можно сразу работать. В errors — пары «номер строки, текст ошибки», по ним человек находит строку в файле. Функция ничего не печатает и не решает, что делать с ошибками: показать их, записать в файл или остановить работу решает тот, кто её вызвал. Что случится, если try убрать, показано в главе 15.4.
