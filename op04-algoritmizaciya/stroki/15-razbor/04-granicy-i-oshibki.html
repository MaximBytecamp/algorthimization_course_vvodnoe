Контроль занятия по КТП — «проверка malformed input, длинных серий и корректной сложности», результат сдаётся Pull Request с тестами. В этой главе — граничные входы и ошибки, которые видны только на них, сводка ошибок по симптомам и список проверки кода.

В этой главе

  2. Сводка ошибок по симптомам
  3. Исправьте функции

§1Граничные входы

У сжатия граничные входы — пустая строка, строка из одной серии, последняя серия, серия длиннее 9 и цифра во входе. У разбора — пустое поле, поле без =, = в значении, повтор ключа и повреждённая строка посреди журнала. Цифра во входе и = в значении разобраны в главах 15.2 и 15.3. Ниже ещё три версии. Каждая запущена рядом с верной на том же входе.

Функции с изменёнными строкамипереключите вкладку

compress записан по-другому: цикл по k сравнивает символ с предыдущим, а серия записывается, когда символ сменился. Вход — 'aaabcc'.

изменённая версия

'a3b'Серия записывается, только когда символ сменился. После последней серии смены нет, и 'c2' теряется. Ошибка видна на любой непустой строке, но тест «одна серия» 'aaa' даёт самый явный ответ: пустую строку.

верная версия

'a3bc2'После цикла дописана последняя серия. Проверка if s: нужна для пустой строки: у неё нет последнего символа. В коде главы 15.2 этой развилки нет: каждая серия, включая последнюю, пишется внутри одного цикла.

В decompress цифры длины читаются через if, а не while. Вход — 'a12b'.

изменённая версия

ValueErrorПрочитана одна цифра '1', и верная запись принята за повреждённую: длины 1 в записи не бывает. Без проверки длины 1 ошибка нашлась бы на следующем шаге: цифра 2 оказалась бы на месте символа серии. На сериях короче 10 версия отвечает верно, поэтому нужен тест с длинной серией.

верная версия

'aaaaaaaaaaaab'Цикл прочитал обе цифры, длина — 12.

В parse_log нет try: исключение из parse_event выходит наружу. Вход — журнал из трёх строк, вторая повреждена.

изменённая версия

ValueErrorПервая строка разобрана, на второй разбор прерван. Третья, верная, не прочитана, а разобранная первая потеряна вместе со списком events: функция не вернула ничего. На журнале без повреждений эта версия отвечает верно.

верная версия

2 записи, 1 ошибкаОшибка второй строки записана в errors с номером 2, третья строка разобрана.

Все три ошибки на «удобных» входах не видны или видны не сразу: серии короткие, журнал чистый. Поэтому граничные тесты пишут по списку из начала раздела. Стартовый набор проверяет каждый пункт отдельным тестом, а тест test_compress_linear — ещё и сложность.

Ошибки таблицы делятся на три группы. Первая — границы прохода: последняя серия и конец строки. Вторая — формат записи: многозначная длина, цифры во входе, = в значении. Третья — повреждённый ввод: что считается ошибкой и где её ловят.

§4Проверка кода и объяснение решения

Решение занятия сдаётся Pull Request с тестами. Проверку кода соседа ведут по списку: каждый пункт — одна из групп ошибок из §2 или требование КТП.

Код принимается, если

Последняя серия записываетсяТест «одна серия» 'aaa' → 'a3' есть и проходит.
Длина серии читается и пишется всеми цифрамиЕсть тесты с сериями длиннее 9 и длиннее 99.
Результат собирается через список и joinНет среза остатка строки на каждой серии; test_compress_linear проходит.
Ключ отделяется по первому '='partition; тест с = в значении есть.
Каждое повреждение — отдельный тестПустое поле, поле без =, пустой ключ, повтор ключа; в тексте ошибки — номер поля.
Ошибка строки не останавливает журналТест с повреждённой строкой в середине: верные строки после неё разобраны.

«Иду по строке двумя индексами: i стоит на начале серии, j уходит до её конца. Пишу символ и длину, если она больше 1, и ставлю i = j. Каждый символ j проходит один раз, поэтому O(n). Цифры во входе запрещаю: иначе 'a12' получалась бы и из двенадцати a, и из самой 'a12'. Тесты: пустая строка, одна серия, серия из двенадцати символов, цифра во входе, миллион символов на время».

Что показываетПроход, сложность, почему запрещены цифры, граничные тесты.

«Строку события режу по ';', поле — по первому '=' через partition, потому что в значении может быть '='. На каждое повреждение — ValueError с номером поля. parse_log ловит эту ошибку, пишет номер строки и текст в errors и идёт дальше, так что одна плохая строка не теряет остальные. Результат — пара: верные записи и ошибки».

Что показываетДва уровня разбора, выбор partition, обработку повреждённого ввода, формат результата.
