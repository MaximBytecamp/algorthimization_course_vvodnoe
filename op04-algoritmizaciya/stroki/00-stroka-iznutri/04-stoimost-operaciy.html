§1Как строка лежит в памяти

В занятии 7 массив хранился ячейками одинакового размера, и адрес ячейки по индексу вычислялся одной формулой. Строка в Python, в реализации CPython, хранится так же. Для каждой строки выбирается ширина ячейки — 1, 2 или 4 байта — по самому большому номеру символа в ней. Строка из латиницы и цифр занимает 1 байт на символ, строка с кириллицей — 2, строка с эмодзи — 4. Ширина одна для всех символов строки.

Строка из ста латинских букв занимает 141 байт: 41 байт служебных данных и по байту на символ. Сто букв я — 258 байт, по два на символ. Последняя строка вывода показывает, что одной буквы я среди 99 латинских достаточно, чтобы вся строка перешла на ячейки по два байта. Это внутренний формат Python, он не совпадает с UTF-8 из главы 0.2: там ширина у каждого символа своя.

Из одинаковой ширины ячеек следуют две оценки. Символ по индексу s[i] вычисляется по адресу за O(1), как элемент списка. Длина хранится в объекте строки, и len(s) тоже стоит O(1).

§2Таблица стоимости операций

Строку нельзя изменить, поэтому любая операция, которая возвращает строку, создаёт новую и копирует в неё символы. Её стоимость не меньше длины результата. Операции, которые ищут или сравнивают, в худшем случае просматривают всю строку. В таблице n — длина строки s, m — длина t.

По отдельности каждая операция дешёвая. Квадратичное время появляется, когда операция стоимостью O(n) выполняется на каждом из n шагов цикла. Ниже разобраны два таких случая.

§3Сборка строки по частям

Результат задачи часто строят по символу: сжатую строку, строку без лишних пробелов, ответ из частей. Прямая запись — s = s + ch в цикле. Строку нельзя дописать, поэтому каждый шаг создаёт новую строку и копирует в неё все прежние символы. Второй способ — складывать части в список и один раз в конце соединить их методом join. В блоке ниже строка 'склад' собирается обоими способами, под каждым — сколько символов скопировано.

Для строки из 5 символов разница — 15 копирований против 5. Для строки длины n первый способ копирует 1 + 2 + … + n = n(n + 1)/2 символов, это O(n²). Второй копирует каждый символ один раз: O(n) на добавление в список и O(n) на join.

Замер показывает, что в CPython есть исключение. Если на строку указывает только одно имя, CPython дописывает символ в ту же строку без копирования прежних символов, и сборка через s += ch занимает O(n). Это оптимизация конкретной реализации. Она перестаёт работать, как только на строку указывает второе имя: строка сохранена в другой переменной, лежит в списке или передана в функцию. Во втором опыте замера в цикл добавлена одна строка prev = s.

Замер выполнен на ноутбуке автора, Python 3.12.12, процессор Apple M4. Каждое число — медиана трёх запусков скрипта, в каждом запуске — медиана семи повторов. Когда n удваивается, время join и обычного += растёт в 2–2,5 раза, время += со второй ссылкой — в 3–7 раз. При n = 320 000 эта версия работает больше секунды, join — 6 мс. Руководство по стилю Python PEP 8 по этой причине рекомендует в коде, где важна скорость, собирать строку через ''.join() и не полагаться на оптимизацию +=.

§4Метод строки внутри цикла

Второй случай квадратичного времени выглядит ещё короче. Задача занятия 13 — найти первую букву, которая встречается в строке один раз. Прямое решение для каждой буквы вызывает s.count(ch). Строка в этом коде не копируется, но count просматривает всю строку, то есть стоит O(n), и вызывается до n раз. Второе решение один раз считает частоты всех букв словарём Counter за O(n), а потом проходит строку ещё раз и берёт частоту из словаря за O(1).

Для замера взяты строки из случайных русских букв, в которых каждая буква встречается чётное число раз. Уникальной буквы нет, и оба решения проходят строку до конца — это худший случай.

16 000116,091,46

При удвоении n время первого решения растёт примерно в 4 раза, второго — в 2. При n = 16 000 разница — около 80 раз. Условия замера те же, что в §3: медиана трёх запусков по семь повторов. Из обоих опытов следует правило для задач на строки: внутри цикла по строке не вызывают операции, которые сами проходят всю строку, — count, in, find, срез, + со строкой-результатом. Нужные данные считают один раз до цикла. Дальше, в главе 0.5, — три вида задач занятий 13–15, где это правило применяется.

Проверьте себяСколько стоит такой цикл для строки длины n?
result = ''
for ch in s:
    if ch != ' ':
        result = result + ch
        history.append(result)

  • Дописывание на месте работает, только когда на строку указывает одно имя. Здесь каждая промежуточная строка сохраняется в списке history, и на каждом шаге копируется весь result.

  • Верно. Строка result лежит в списке, поэтому каждое сложение создаёт новую строку и копирует все прежние символы: 1 + 2 + … + n. Память тоже O(n²): в списке хранятся все промежуточные строки.

  • В цикле нет сортировки и деления пополам. Каждый шаг копирует строку растущей длины, сумма копирований — порядка n²/2.

  • Условие уменьшает число сложений, но цикл всё равно проходит все n символов, а в худшем случае пробелов в строке нет.
