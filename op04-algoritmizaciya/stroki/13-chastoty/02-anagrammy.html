13.2

Анаграммы: сортировка
и частотный словарь

Первая задача КТП — проверить, что две строки составлены из одних и тех же букв. В главе разобраны перебор и два быстрых способа: сортировка символов и частотный словарь. Затем нормализация из контракта, код со словарём и пошаговым прогоном, замер трёх способов и версия с множеством, которая ошибается на повторах.

§1Перебор и два способа быстрее

Прямое решение повторяет то, что делают руками с карточками букв. Для каждой буквы первой строки ищут такую же карточку во второй и откладывают её. Если карточка не нашлась, строки не анаграммы. Если в конце во второй строке не осталось лишних карточек, анаграммы. В Python это цикл по a и вызов b.remove(ch) для копии второй строки списком. Поиск в списке стоит O(m), он выполняется n раз: перебор — O(n·m).

Перебор тратит время на повторный поиск. Его убирают двумя способами. Первый — сортировка: если разложить карточки обеих строк по алфавиту, у анаграмм получатся одинаковые ряды. Сортировка двух строк стоит O(n log n), сравнение рядов — O(n). Второй — частотный словарь из главы 13.1: посчитать, сколько раз встречается каждая буква в a, затем пройти b и для каждой буквы забрать одну единицу из счётчика. Каждый символ обрабатывается один раз, время O(n + m).

В блоке ниже оба способа показаны на одной паре строк. Столбики — частоты, под ними — строки после sorted. Отметьте «Сначала привести к ключу»: заглавная А станет строчной, и частоты совпадут.

Без приведения к ключу строки не анаграммы: в «Апельсин» заглавная А, в «спаниель» — строчная, а для Python это разные символы. Правила приведения записаны в контракте из главы 13.1, их выполняет функция letters.

§2Значимые символы: функция letters

По контракту регистр, пробелы и знаки не важны, а строка может прийти в форме NFD. Все три правила выполняются до подсчёта, в отдельной функции. Она возвращает список значимых символов: подсчёт и сортировка работают с ним одинаково.

Первая строка тела выполняет NFC и убирает регистр, порядок шагов взят из главы 0.3: NFC идёт первым. Вторая строка оставляет только буквы и цифры. Буква ё не заменяется: по ответу интервьюера ё и е — разные буквы.

Python в этой строке: [ch for ch in text if ch.isalnum()]

Генератор списка строит новый список за один проход. Запись читается так: «каждый ch из text, для которого ch.isalnum() истинно». Это короткая форма цикла с append.

>>> [ch for ch in 'Ау, пала!' if ch.isalnum()]
['А', 'у', 'п', 'а', 'л', 'а']

§3Код и пошаговый прогон

Функция на частотном словаре состоит из трёх частей. Сначала обе строки приводятся к спискам значимых символов, и сравниваются длины: у анаграмм они равны. Затем первый цикл считает частоты символов a. Второй цикл идёт по b и для каждого символа забирает единицу из счётчика. Если счётчик уже 0, у символа b нет пары в a. Напишите функцию сами: тесты проверяют пять ответов интервьюера из главы 13.1 и сравнивают результат с сортировкой на трёхстах случайных парах.

Прогон ниже — на строках «Апельсин» и «спаниель». Лента — список a после letters, в таблице справа — словарь count на каждом шаге. Смотрите, как на шагах 5–20 счётчики растут, а на шагах 22–45 убывают до нуля.

Инвариант второго цикла: count[ch] — сколько символов ch из a ещё не нашли пары среди пройденных символов b. Если для символа b счётчик равен 0, в b этого символа больше, чем в a, и ответ False. Если второй цикл дошёл до конца, каждый символ b нашёл пару. Лишних символов в a тоже нет: длины равны, а пар столько же, сколько символов в b. Без проверки длин этот вывод неверен, такая версия разобрана в главе 13.4.

Память: словарь хранит по ключу на каждый разный символ, это O(k), где k — число разных символов. Для русских слов k не больше 33 плюс цифры. Списки, которые возвращает letters, добавляют O(n + m). Если хранить их не нужно, подсчёт можно вести сразу по строке, проверяя символы в том же цикле.

§4Сортировка или словарь: замер

Контроль занятия по КТП требует сравнить сортировку и частотный словарь. Оба способа и третий, с Counter, записываются через ту же функцию letters.

По оценке словарь лучше: O(n) против O(n log n). Замер проверяет, как это выглядит на деле. Строки — анаграммы из случайных русских букв, поэтому все три способа проходят их до конца.

nсловарь в цикле, мсsorted, мсCounter, мс
50 0007,711,56,0
100 00016,022,812,5
200 00031,958,426,8
400 00065,4118,355,3

Замер выполнен на ноутбуке автора, Python 3.12.12, Apple M4. Каждое число — медиана трёх запусков bench.py из стартового набора, в каждом запуске — медиана пяти повторов. Во все три времени входит letters, около 11 мс при n = 400 000.

При удвоении n все три времени растут примерно вдвое. Множитель log n у сортировки на этих длинах почти не виден: от 50 000 до 400 000 он вырастает с 15,6 до 18,6, то есть на 19 %. Разница — в постоянном множителе: sorted медленнее словаря в 1,8 раза при n = 400 000. Counter быстрее словаря в цикле, потому что подсчёт в нём выполняется кодом на C, а цикл for — интерпретатором Python. Выбор на собеседовании: словарь — O(n) по времени и O(k) по дополнительной памяти, сортировка — O(n log n) по времени и O(n) по памяти на два отсортированных списка. Сортировку берут, когда её код заметно короче, а n небольшое.

§5Версия с множеством

Короткая запись set(letters(a)) == set(letters(b)) проверяет, что в строках одни и те же буквы. Множество хранит каждый символ один раз, поэтому частоты теряются. Ниже обе версии запущены на строках «папа» и «пап».

У «папа» и «пап» множества букв равны, {'п', 'а'}, и версия с set отвечает True. Верная версия останавливается на шаге 3: длины 4 и 3 разные. Ошибку видно только на строках, где буква повторяется разное число раз. На «листок» и «слиток» обе версии отвечают верно, поэтому в тестах занятия есть пары «папа» — «пап» и «аб» — «аа».

Вторая похожая ошибка — сортировка без letters: sorted('Апельсин') == sorted('спаниель') даёт False, потому что заглавная 'А' после сортировки стоит в начале, а строчная 'а' — на её месте во второй строке. Следующая задача занятия — первая уникальная буква, глава 13.3.
