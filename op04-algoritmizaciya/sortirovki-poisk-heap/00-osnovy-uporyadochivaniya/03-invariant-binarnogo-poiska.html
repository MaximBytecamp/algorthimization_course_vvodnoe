Бинарный поиск не перебирает список по одному элементу. Он сохраняет отрезок, где искомое значение ещё может находиться, и на каждом шаге отбрасывает половину данных.

В этой главе
  1. Почему нужен отсортированный список
  2. Что сохраняет инвариант
  3. Три шага до найденного значения
  4. Как поиск заканчивается без ответа

§1Почему нужен отсортированный список

Нужно найти число 18 среди оценок в списке. Если значения стоят без порядка, после проверки 14 нельзя сказать, где искать 18 дальше. В отсортированном списке известно: все числа слева от 14 меньше 14, а все справа больше 14.

Индексы показывают место числа в списке. Первый элемент имеет индекс 0, последний — индекс 6. Бинарный поиск хранит две границы: left для левого индекса и right для правого. Между ними находится рабочий отрезок.

Отсортированный список с индексамиtarget = 18
0123456
371114182431
В начале left = 0 и right = 6: рабочий отрезок содержит весь список.

Середину рабочего отрезка вычисляют как mid = (left + right) // 2. Оператор // делит без дробной части. Для границ 0 и 6 середина равна (0 + 6) // 2 = 3. На индексе 3 стоит число 14.

§2Что сохраняет инвариант

Инвариант — утверждение, которое остаётся истинным после каждого шага алгоритма. Для поиска точного значения используем такой инвариант: если target есть в списке, он находится на отрезке индексов от left до right включительно.

Знак <= важен: отрезок из одного элемента всё ещё нужно проверить. Когда left становится больше right, в рабочем отрезке не остаётся индексов. Тогда значение не найдено.

Инвариант в каждом кадреточный поиск
target найден здесь или остаётся внутри границ left..right.
рабочий отрезокпроверяемая серединаисключённые индексы
После сравнения граница сдвигается так, чтобы исключённая половина уже не могла содержать target.

Когда scores[mid] меньше цели, все элементы слева от середины и сама середина тоже меньше цели. Их можно исключить, присвоив left = mid + 1. Когда значение в середине больше цели, симметрично сдвигают правую границу: right = mid - 1.

§3Три шага до найденного значения

Теперь выполним поиск 18. Каждый кадр показывает состояние до проверки середины. Жёлтая карточка — элемент scores[mid]. Синие карточки входят в рабочий отрезок. Серые карточки уже исключены и больше не будут проверяться.

Шаг 1left = 0, right = 6, mid = 3
0123 · mid456

scores[3] = 14. Число 14 меньше цели 18. Индексы 0–3 содержат числа не больше 14, поэтому цель там отсутствует. Новая граница: left = 3 + 1 = 4.

Шаг 2left = 4, right = 6, mid = 5
012345 · mid6
371114182431

scores[5] = 24. Число 24 больше цели 18. Индексы 5–6 содержат числа не меньше 24, поэтому цель там отсутствует. Новая граница: right = 5 - 1 = 4.

Шаг 3left = 4, right = 4, mid = 4
01234 · mid56
371114182431

scores[4] == target. Сравнение вернуло True, поэтому поиск возвращает индекс 4. Инвариант завершён найденным значением.

За три проверки найдено число среди семи элементов. Линейный поиск мог бы проверить пять значений: 3, 7, 11, 14 и 18. На коротком списке разница небольшая. На большом отсортированном списке отбрасывание половины становится заметнее.

Проверьте себяПосле первого шага для target = 18 чему равно left?

  • Граница сдвигается, потому что 14 меньше 18.

  • mid = 3. Индексы 0–3 исключены, поэтому left = mid + 1 = 4.

  • Правая граница сохраняется равной 6 после первого шага.

§4Как поиск заканчивается без ответа

Поиск должен уметь сообщать и об отсутствии значения. Возьмём цель 19. После двух первых сравнений рабочий отрезок снова состоит из одного индекса 4, где лежит 18. Значение 18 меньше 19, поэтому левая граница перейдёт за правую.

После проверки 18 для цели 19 получается left = 5 и right = 4. Условие цикла left <= right ложно. Рабочий отрезок пуст, а инвариант сообщает: если 19 был в списке, он должен был находиться внутри границ. Таких границ больше нет, значит значения в списке нет.

Состояние после неудачного поискаtarget = 19
left 5рабочего индекса нетright 4
371114182431
left > right означает пустой рабочий отрезок. Функция возвращает None.

Инвариант помогает писать бинарный поиск без пропуска индекса. До цикла он верен для всего списка. После каждого сдвига границы он остаётся верен для меньшего отрезка. В конце он объясняет результат поиска.

Проверьте себяКогда функция binary_search возвращает None?

  • В этом случае поиск сдвигает left и продолжает работу.

  • Рабочий отрезок пуст. Искомого индекса больше нет.

  • Середина может совпасть с целью или оставить рабочий отрезок для следующих шагов.
