Два равных ключа, новый список и число сравнений меняют выбор сортировки. На тех же заказах разберём, что сохраняется, что создаётся заново и почему размер данных важен.

§1Что происходит с равными ключами

В первой главе все суммы различались. В журнале могут оказаться два заказа с одинаковым временем. Если сортировка располагает заказы по времени, она должна решить, останется ли B перед D или их взаимное положение изменится.

Ключи B и D одинаковы: оба равны "12:40". После сортировки B всё ещё расположен перед D. Такое свойство называют стабильностью сортировки: записи с равными ключами сохраняют исходный взаимный порядок.

Стабильная сортировка по времениключ B = ключ D

До сортировки

B12:40 · пришёл 1-мD12:40 · пришёл 2-мA13:10 · пришёл 3-м
↓ сортируем по time

После сортировки

B12:40 · остался перед DD12:40 · остался после BA13:10
Сортировка переместила A после пары с временем 12:40. Внутри пары порядок B, D сохранился.

Стабильность полезна, когда один порядок уже содержит смысл. Например, журнал поступления уже расставлен по очереди, затем его сортируют по времени. Заказы с одинаковым временем продолжают идти в порядке поступления. Если нужен другой порядок равных записей, ключ делают составным: например, (order["time"], order["id"]).

§2Что хранит новый список sorted

Функция sorted возвращает новый список. В нём другой порядок ссылок на те же словари. Сами словари B, A и C не копируются заново для каждой позиции.

Первое сравнение показывает, что by_total и orders — разные списки. Второе показывает, что в начале by_total лежит тот же словарь A, который был на втором месте в orders. Оператор is проверяет, один ли это объект в памяти.

Поэтому изменение самого словаря видно через оба списка. Если выполнить by_total[0]["total"] = 800, сумма A изменится и в orders[1]. Новый список хранит собственный порядок, но элементы внутри него остаются прежними объектами.

§3Когда список меняет list.sort

Метод list.sort перестраивает существующий список. Его выбирают, когда исходный порядок больше не нужен. Метод возвращает None, поэтому результат не присваивают той же переменной.

Метод copy создал отдельный список для опыта. Вызов queue.sort(...) изменил порядок внутри него. Переменная result получила None, потому что готовый список уже находится в queue.

Новый список требует место для своего порядка. Сортировка на месте избегает второго списка, но её алгоритм всё равно может использовать служебную память. Размер такой памяти зависит от алгоритма и входных данных.

§4Из чего складывается цена сортировки

Цена алгоритма складывается из работы с ключами и сравнений ключей. Пусть в списке n записей. Функцию ключа Python вызывает по одному разу для каждой записи, поэтому для трёх заказов получится три значения: 1900, 700 и 1200.

Число сравнений зависит от алгоритма и от расположения данных. В модели сортировки вставками из главы 0.1 худший случай возникает, когда каждый следующий ключ меньше предыдущих. Для трёх элементов потребуется до трёх сравнений: 3 × 2 / 2 = 3.

Не нужно запоминать формулы наизусть. Достаточно видеть разницу роста: при удвоении списка перебор всех пар растёт примерно в четыре раза, а n log n — заметно медленнее. Поэтому на маленьком списке простая модель удобна для понимания, а на большом списке используют стандартную сортировку Python.

Проверьте себяЧто сохранится после by_total = sorted(orders, key=lambda order: order["total"])?

  • sorted создаёт новый список. Исходный список не перестраивается.

  • Порядок A, C, B появляется после вызова orders.sort(...). Вызов sorted(orders, ...) оставляет orders в исходном порядке.

  • Новый список хранит ссылку на уже существующий словарь A.
