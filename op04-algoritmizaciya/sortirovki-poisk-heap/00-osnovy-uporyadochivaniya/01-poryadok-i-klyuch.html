§1Порядок — это договор

В журнале доставки три заказа записаны в момент поступления. Курьеру нужен порядок по времени выезда. Номер заказа остаётся частью записи, но не определяет место в маршруте. Слово «отсортировать» требует уточнения: по номеру, времени, сумме или городу.

Здесь порядок хранения — B, затем A, затем C. Он может совпасть с временем, но это не гарантировано. Для алгоритма нужен критерий: функция, которая каждой записи сопоставляет сравнимое значение. Такой критерий называют ключом.

Одна запись — несколько возможных порядковсначала назовите ключ
по idA13:10 · 700 ₽B12:40 · 1900 ₽C14:05 · 1200 ₽
по timeB12:40 · 1900 ₽A13:10 · 700 ₽C14:05 · 1200 ₽
по totalA13:10 · 700 ₽C14:05 · 1200 ₽B12:40 · 1900 ₽
Данные одни и те же. Меняется только ответ на вопрос: «какое поле определяет место записи?»

Последовательность называют отсортированной по возрастанию, если для каждой соседней пары ключ слева не больше ключа справа. Для времён это означает 12:40 ≤ 13:10 ≤ 14:05. Не нужно сравнивать каждую запись со всеми остальными: достаточно проверить соседние пары.

У строк одинакового формата ЧЧ:ММ лексикографический порядок совпадает с порядком времени. Если формат не задан, его сначала приводят к надёжному виду — например, к числу минут. Алгоритм не должен полагаться на случайное удобство входных строк.

§2Ключ извлекает нужную часть записи

Сама запись может быть словарём, объектом или кортежем. Сравнивать целый словарь не требуется: ключ извлекает одно значение, по которому строится порядок. Для выезда курьера нужен time.

У хорошего ключа один ясный смысл. Функция не меняет заказ и не печатает результат. Она только отвечает, какое значение использовать в сравнении. Благодаря этому чтение кода разделяется на два шага: сначала выбираем ключ, затем выбираем направление — по возрастанию или убыванию.

ЗадачаКлючПервой окажется
Выдать курьерам по времениorder["time"]самая ранняя доставка
Показать дорогие заказыorder["total"], reverse=Trueсамый дорогой заказ
Собрать список по номеруorder["id"]заказ с меньшим номером

Если условие говорит «сначала срочные, а среди них — по времени», одного поля недостаточно. Для нескольких уровней порядка в Python используют кортеж ключей. В заданиях раздела этот приём задаст порядок записей с одинаковым первым ключом.

§3Как Python сортирует по key

Функция sorted создаёт новый список. Она получает исходные записи, вычисляет ключ для каждой и располагает записи по ключам. Исходный orders не меняется.

Выражение lambda order: order["total"] — короткая функция ключа. Она получает один заказ и возвращает его сумму. Список by_total содержит те же словари в другом порядке. Исходный orders сохраняет порядок B, A, C.

Схема разделяет исходный список и результат. На жёлтых карточках показаны ключи, по которым расположились заказы.

Сортировка по сумме создаёт новый списокkey=total
ordersB1900 ₽A700 ₽C1200 ₽
by_totalA700 ₽C1200 ₽B1900 ₽
В orders первым остаётся B. В by_total первым стоит A: его ключ 700 меньше 1200 и 1900.

Метод list.sort упорядочивает существующий список и возвращает None. Его выбирают, когда исходный порядок больше не понадобится. Запись orders = orders.sort(...) заменит список значением None.

Проверьте себяЧто вернёт выражение sorted(orders, key=lambda order: order["time"])[0]["id"]?

  • A — второй по времени заказ: 13:10.

  • У B время 12:40. Это наименьший ключ, поэтому после сортировки B стоит первым.

  • C имеет самое позднее время: 14:05.

Этот вызов определяет порядок трёх разных сумм. Отдельное правило потребуется, когда у нескольких записей окажется одинаковый ключ.

§4Равные ключи и следующий вопрос

Два заказа могут иметь одинаковое время. Тогда ключи равны, но записи различаются. Сортировка всё равно корректна: соседние ключи не нарушают условие ≤. Нужно отдельно решить, какой порядок равных записей ожидается.

В Python равные элементы сохраняют относительный порядок: B остаётся перед D. Такое свойство называется стабильностью. Если условие требует другой порядок равных записей, ключ времени дополняют вторым ключом.

На схеме у B и D один ключ — 12:40. Их расположение друг относительно друга не изменилось после сортировки.

Равные ключи в стабильной сортировкеtime = 12:40
до сортировкиB12:40D12:40A13:10
после сортировкиB12:40D12:40A13:10
B и D имеют равные ключи. Python сохранил их исходный порядок: B перед D.

Теперь можно формулировать задачу точно: назвать данные, ключ, направление и правило для равных ключей. Это подготовка не только к сортировке. Бинарный поиск требует уже упорядоченных ключей, а heap выбирает следующий элемент по приоритету — то есть тоже по ключу.
