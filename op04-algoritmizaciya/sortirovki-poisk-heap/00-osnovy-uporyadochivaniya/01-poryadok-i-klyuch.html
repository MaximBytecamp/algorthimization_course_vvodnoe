В журнале три заказа стоят в порядке поступления. Диспетчеру нужна очередь от меньшей суммы к большей. На этом примере разберём правило сортировки, ключ и результат sorted.

§1Из какого порядка начинаем

Заказы поступили в журнал один за другим. Поэтому B оказался первым, затем A, затем C. Этот порядок говорит только о времени поступления. Он не отвечает на вопрос, какой заказ должен быть первым в очереди по сумме.

Список хранит три полные записи. У каждой есть номер, время и сумма. Чтобы задать порядок, нужно назвать поле, по которому записи будут сравниваться. Такое поле или вычисленное значение называют ключом сортировки.

Одни записи — три разных порядкаполе задаёт правило
ключ idAномер ABномер BCномер C
ключ timeB12:40A13:10C14:05
ключ totalA700 ₽C1200 ₽B1900 ₽
Порядок меняется вместе с ключом. В этой главе ключ — total, поэтому первым нужен заказ A с суммой 700 ₽.

Для порядка по возрастанию ключ слева не больше ключа справа. В итоговой очереди это будет 700 ≤ 1200 ≤ 1900. Теперь можно показать, как из записей получить эти три числа.

§2Функция ключа и lambda

Сортировке нужна функция, которая получает одну запись и возвращает её ключ. Сначала запишем такую функцию обычным способом. Параметр — имя для значения, которое функция получает при вызове. Здесь параметр называется order и в каждом вызове хранит один словарь из списка. Оператор return завершает вызов функции и возвращает найденное значение.

При первом вызове в параметр order попадает словарь B, поэтому функция возвращает 1900. При втором вызове в него попадает словарь A, поэтому результат — 700. Сама функция не переставляет записи. Она сообщает сортировке число для сравнения.

Выражение orders[0] выбирает первую запись списка, B. Эта запись целиком становится значением параметра order. Затем выражение order["total"] читает из словаря поле total. Так же будут обработаны A и C: по одному вызову функции на каждую запись.

Как работает функция ключаодин вызов
В функцию передалиorder = {"id": "A", "total": 700}
→
Строка return взялаorder["total"]
→
Функция вернула700
Для B, A и C такая функция вернёт 1900, 700 и 1200.

Запись lambda order: order["total"] создаёт ту же функцию, только без имени. Её используют здесь один раз — прямо в аргументе key=. Часть слева от двоеточия принимает запись, часть справа возвращает её сумму.

Запись key=total_key передаёт в сортировку функцию. Скобки вызова здесь не ставят. Запись key=total_key(orders[0]) сначала запустила бы функцию для B и получила число 1900. Параметр key должен содержать функцию: сортировка применяет её к каждой записи списка.

Слово lambda не сортирует список. Оно только передаёт в sorted короткую функцию ключа. Теперь видно, какие числа получат карточки; дальше разберём, как по этим числам записи переходят в новый список.

§3Как записи переходят в новый порядок

Ниже показана модель сортировки вставками. Она держит три области: непросмотренные записи, карточку в руках и уже упорядоченную часть нового списка. На каждом шаге одна карточка исчезает из первой области и занимает место в третьей.

Шаг 1Берём B с ключом 1900

Очередь после взятия

A700
C1200

Карточка в руках

B1900

Новый список после шага

B1900

B — первая карточка, поэтому сравнивать её пока не с чем. Упорядоченная часть равна [B].

Шаг 2Берём A с ключом 700

Очередь после взятия

C1200

Карточка в руках

A700

Новый список после шага

A700
B1900

Сравнение 700 < 1900 ставит A перед B. B сдвигается на одну позицию вправо: [A, B].

Шаг 3Берём C с ключом 1200

Очередь после взятия

пусто

Карточка в руках

C1200

Новый список после шага

A700
C1200
B1900

Сначала 1200 < 1900, поэтому C проходит перед B. Затем 1200 > 700, поэтому C остаётся после A. Получается [A, C, B].

Карточка переносится целиком вместе с номером, временем и суммой. Ключ нужен только для выбора позиции.

Это понятная модель сортировки вставками. Она показывает перенос элементов по шагам. Вызов sorted возвращает тот же порядок, а точная последовательность внутренних сравнений не входит в договор языка Python.

На втором и третьем кадрах карточка показана в средней зоне до переноса. Правая зона показывает новый список после завершения шага. Это два последовательных момента. В программе запись существует в единственном экземпляре.

§4Что возвращает sorted

Функция sorted принимает исходный список и функцию ключа. Она возвращает новый список. Поэтому результат нужно сохранить в отдельную переменную.

В вызове ниже orders — данные, key= — правило получения ключа, а переменная слева от знака = получает готовый список. Обе записи вызова дают один результат. В программе выбирают одну: именованную функцию используют, когда её нужно читать или вызывать ещё раз; lambda подходит для короткого одноразового правила.

Первая строка передаёт в key функцию total_key. Вторая передаёт равную ей функцию через lambda и перезаписывает by_total тем же результатом. Следующие две строки проверяют порядок: в новом списке A, C, B, а исходный orders сохранил B, A, C.

Два списка после вызоваодни словари, разный порядок
ordersB1900 ₽A700 ₽C1200 ₽
by_totalA700 ₽C1200 ₽B1900 ₽
sorted оставил orders без изменений и вернул упорядоченный список в by_total.

Метод orders.sort(key=...) действует иначе: он перестраивает сам orders и возвращает None. Его используют, когда исходный порядок больше не нужен. Теперь осталось рассмотреть записи с одинаковыми ключами.

Проверьте себяЧто окажется первым в sorted(orders, key=lambda order: order["time"])?

  • У B время 12:40. Это наименьший ключ времени.

  • У A время 13:10. Ключ B меньше.

  • У C время 14:05. Это наибольший ключ времени.

§5Когда ключи равны

Два заказа могут иметь одну и ту же сумму или одно и то же время. Равные ключи допустимы в порядке по возрастанию: для соседей используют знак ≤. Строгий знак < запретил бы равные значения.

У B и D ключ одинаков: 12:40. Python сохранил их взаимный порядок: B остался перед D. Это свойство называют стабильностью сортировки.

Равные ключи остаются в исходном порядкеtime = 12:40
до сортировкиB12:40D12:40A13:10
после сортировкиB12:40D12:40A13:10
B и D имеют одинаковый ключ. Их взаимный порядок не изменился.

Задачу сортировки можно сформулировать точно: назвать записи, ключ, направление и правило для равных ключей. Такое описание понадобится и дальше: бинарный поиск работает с уже упорядоченными ключами, а heap выбирает запись по ключу-приоритету.
