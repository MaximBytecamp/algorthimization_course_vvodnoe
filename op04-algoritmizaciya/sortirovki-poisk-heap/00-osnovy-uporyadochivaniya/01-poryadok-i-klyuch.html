В журнале три заказа стоят в порядке поступления. Диспетчеру нужна очередь от меньшей суммы к большей. На этом примере разберём правило сортировки, ключ и результат sorted.

В этой главе
  1. Из какого порядка начинаем
  2. Ключ отвечает за место записи
  3. Что возвращает sorted
  4. Когда ключи равны

§1Из какого порядка начинаем

Заказы поступили в журнал один за другим. Поэтому B оказался первым, затем A, затем C. Этот порядок говорит только о времени поступления. Он не отвечает на вопрос, какой заказ должен быть первым в очереди по сумме.

Список хранит три полные записи. У каждой есть номер, время и сумма. Чтобы задать порядок, нужно назвать поле, по которому записи будут сравниваться. Такое поле или вычисленное значение называют ключом сортировки.

Одни записи — три разных порядкаполе задаёт правило
ключ idAномер ABномер BCномер C
ключ timeB12:40A13:10C14:05
ключ totalA700 ₽C1200 ₽B1900 ₽
Порядок меняется вместе с ключом. В этой главе ключ — total, поэтому первым нужен заказ A с суммой 700 ₽.

Для порядка по возрастанию ключ слева не больше ключа справа. В итоговой очереди это будет 700 ≤ 1200 ≤ 1900. Теперь можно показать, как из записей получить эти три числа.

§2Ключ отвечает за место записи

Запись остаётся словарём со всеми полями. Ключ извлекает из неё только сумму. Функция ключа получает один словарь order и возвращает значение order["total"].

Первое число относится к B, второе — к A, третье — к C. Словарь и список сохраняются без изменений. Ключ даёт сортировке числа, которые можно расположить по возрастанию.

Ниже показана подробная модель сортировки вставками. Она строит новую упорядоченную часть слева направо: берёт следующую запись, сравнивает её ключ с ключами уже стоящих карточек и вставляет на найденное место.

1Читаем исходный orders
Bkey = 1900первый в списке
Akey = 700второй в списке
Ckey = 1200третий в списке

↓

3Вставляем A перед B

Это модель сортировки вставками. Вызов sorted возвращает тот же порядок. Последовательность сравнений внутри реализации не входит в договор языка Python.

Модель показывает действие сортировки: записи не превращаются в числа. Числа помогают выбрать место каждой записи. Дальше этот результат зададим одной строкой Python.

§3Что возвращает sorted

Функция sorted принимает исходный список и функцию ключа. Она возвращает новый список. Поэтому результат нужно сохранить в отдельную переменную.

Первая строка создаёт by_total. В первом выводе виден новый порядок A, C, B. Во втором выводе B, A, C: исходный orders не изменился.

Два списка после вызоваодни словари, разный порядок
ordersB1900 ₽A700 ₽C1200 ₽
by_totalA700 ₽C1200 ₽B1900 ₽
sorted оставил orders без изменений и вернул упорядоченный список в by_total.

Метод orders.sort(key=...) действует иначе: он перестраивает сам orders и возвращает None. Его используют, когда исходный порядок больше не нужен. Теперь осталось рассмотреть записи с одинаковыми ключами.

Проверьте себяЧто окажется первым в sorted(orders, key=lambda order: order["time"])?

  • У B время 12:40. Это наименьший ключ времени.

  • У A время 13:10. Ключ B меньше.

  • У C время 14:05. Это наибольший ключ времени.

§4Когда ключи равны

Два заказа могут иметь одну и ту же сумму или одно и то же время. Равные ключи допустимы в порядке по возрастанию: для соседей используют знак ≤. Строгий знак < запретил бы равные значения.

У B и D ключ одинаков: 12:40. Python сохранил их взаимный порядок: B остался перед D. Это свойство называют стабильностью сортировки.

Равные ключи остаются в исходном порядкеtime = 12:40
до сортировкиB12:40D12:40A13:10
после сортировкиB12:40D12:40A13:10
B и D имеют одинаковый ключ. Их взаимный порядок не изменился.

Задачу сортировки можно сформулировать точно: назвать записи, ключ, направление и правило для равных ключей. Такое описание понадобится и дальше: бинарный поиск работает с уже упорядоченными ключами, а heap выбирает запись по ключу-приоритету.
