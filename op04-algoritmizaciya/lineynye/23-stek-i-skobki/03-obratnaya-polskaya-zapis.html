23.4

Обратная польская запись

В этой главе разобрано вычисление постфиксного выражения. Проверим порядок операндов, целочисленное деление и ошибки формы входа.

В этой главе
  1. Операция после аргументов
  2. Порядок операндов
  3. Деление без float
  4. Полная функция и проверка формы

§1Операция после аргументов

В ведомости сначала записывают два числа, затем действие над ними. Запись 2 3 + означает 2 + 3. Постфиксная, или обратная польская запись, ставит операцию после её аргументов.

Обычная записьПостфикснаяРезультат
(2 + 3) * 42 3 + 4 *20
8 - 38 3 -5
-7 / 3 с усечением-7 3 /-2

Скобки в постфиксной записи не нужны: положение операций определяет порядок. Число добавляется в стек. Операция снимает два последних значения и кладёт результат.

Вход — список строк: записи целых чисел, принимаемые int(token), и операции + - * /. Деление усекается к нулю. Ошибки формы и токенов дают ValueError; деление на ноль — ZeroDivisionError. Вход не изменяется.

Токен — отдельная строка входного списка. Знак минус в токене -7 является частью числа. Отдельный токен - обозначает бинарное вычитание, то есть действие над двумя значениями.

Теперь проследим, почему первым снимается правый аргумент.

§2Порядок операндов

На стопку положили карточку 8, затем карточку 3. Сверху лежит 3. Поэтому первое снятие даёт right, второе — left. Для вычитания требуется left - right.

Схема показывает замену двух значений одним. Перед операцией в стеке должно быть хотя бы два числа.

Пошаговый разбордно слева → вершина справа

Для 2 3 + после сложения остаётся 5. Затем добавляется 4, умножение заменяет 5 и 4 числом 20. Для 8 3 - перестановка снятых значений дала бы -5 вместо 5.

ОперацияПервый popВторой popВычисление
8 3 -right = 3left = 88 - 3 = 5
8 2 /right = 2left = 88 / 2 = 4
Разбор на примере стопки

Стопка хранит карточки с готовыми числами. Оператор снимает две верхние карточки и кладёт одну. Что есть что: первый pop — правая карточка выражения; второй pop — левая; append — результат операции.

Вычитание обнаруживает перестановку аргументов. Отрицательное деление обнаруживает другую ошибку: округление вниз вместо усечения к нулю.

§3Деление без float

Если разделить долг 7 на 3 части и отбросить дробную часть, получится -2. В Python -7 // 3 даёт -3: оператор // округляет вниз. Для контракта с усечением вычислим модуль частного и затем его знак.

leftrightМодуль частногоРезультат к нулю
-732-2
7-32-2
-7-322
1300

Условие (left < 0) != (right < 0) истинно при разных знаках. Тогда знак модуля меняется. Перевод через float не нужен: большие целые числа могут потерять точность при таком переводе.

Правило деления определено. Соберём проход с проверкой количества аргументов и итогового результата.

§4Полная функция и проверка формы

Как в ведомости, операция без двух чисел не завершает расчёт. Перед снятием проверяется длина стека. В конце должен остаться один итог: два отдельных числа не образуют выражение.

Ветка числа преобразует token через int и добавляет значение. Неверная запись даёт ValueError. Continue начинает следующий шаг цикла, поэтому числовой токен не попадает в ветку операции. После вычисления value возвращается в стек.

Инвариант: Стек содержит значения завершённых частей выражения. Операция заменяет два последних значения одним результатом: сначала снимается правый операнд.

ВходРезультатПроверка
Пустой списокValueErrorВ конце ноль значений
1 +ValueErrorДо + меньше двух значений
1 2ValueErrorВ конце два значения
5 0 /ZeroDivisionErrorНулевой правый операнд

Здесь n — количество токенов. Каждое значение добавляется один раз и снимается не более одного раза.

O(n) стековых действий и O(n) ячеек памяти. Оценка O(n) времени предполагает числа ограниченного размера.

Для произвольно больших целых нужно учитывать длину чисел. Умножение длинных чисел занимает больше постоянного времени. Стековая оценка считает число добавлений и снятий.

Проверьте себя

В стеке [8, 3] встретился токен -. Что возвращается в стек?

  • Сверьте порядок обработки и состояние вершины. Первым снимается right=3, затем left=8. Вычисляется 8 - 3.
  • Первым снимается right=3, затем left=8. Вычисляется 8 - 3.
  • Сверьте порядок обработки и состояние вершины. Первым снимается right=3, затем left=8. Вычисляется 8 - 3.

Для сравнения, повторный поиск операций и удаление токенов из середины списка может дать O(n²). Стек не сдвигает необработанный хвост. Сначала проверим ошибки на коротких входах.
