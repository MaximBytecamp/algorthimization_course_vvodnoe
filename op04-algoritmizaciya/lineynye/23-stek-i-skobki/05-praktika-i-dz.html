В этой главе собраны задания на стек, проверки и критерии сдачи. На паре решим скобки и постфиксное выражение, дома добавим отмену действий.

§1Порядок работы на паре

Как перед выполнением заказа, сначала фиксируют требования, затем проверяют результат. На каждую задачу запишите контракт, три коротких примера и инвариант. После этого реализуйте функцию и запустите тесты.

ЭтапВремяРезультат
Уточнить оба контракта5 минутВход, выход, ошибки
Скобки20 минутФункция и контрпримеры
Обратная польская запись25 минутФункция и правила деления
Проверить и объяснить15 минутТесты, инвариант, стоимость

Время — ориентир для практической части занятия. Дополнительные задания не заменяют две обязательные функции. Скачайте стартовый архив lesson_23.zip: заготовки без решений, проверки и README.

Сохраните код в solution.py. Команда python check.py запускает проверки; до реализации она завершается ошибкой NotImplementedError. Теперь выберите первую задачу.

§2Две обязательные функции

Проверка перед сдачей похожа на сверку нескольких пунктов накладной. Зелёный тест подтверждает только проверенный случай. Добавьте собственный пример к каждому пункту контракта.

ФункцияПервый примерГраница
is_balanced{[()]} → True(() → False
eval_rpn8 3 - → 51 + → ValueError

Оба столбца нужно проверить после реализации. Первый подтверждает основной проход, второй — завершающие проверки.

Скобки. Строка содержит только ()[]{}. Вернуть bool; пустая строка правильная. Вход не изменяется.

Вычислитель. Вход — список строк: записи целых чисел, принимаемые int(token), и операции + - * /. Деление усекается к нулю. Ошибки формы и токенов дают ValueError; деление на ноль — ZeroDivisionError. Вход не изменяется.

Песочница запускает Python через Pyodide после нажатия кнопки. Первая загрузка требует сети. Код хранится локально в браузере; «Вернуть заготовку» заменяет его исходным текстом. Итоговый файл сохраните отдельно.

После обязательных задач примените тот же порядок снятия к отмене действий.

§3Домашняя работа: история добавлений

Как при снятии наклеек, границей отмены является последняя наклейка целиком. Реализуйте apply_actions без повторного соединения всей строки на каждом шаге.

Список действий состоит только из ('add', строка) и ('undo',). Отмена снимает последнее неотменённое добавление целиком. При пустой истории ничего не происходит. Вернуть итоговую строку; вход не изменяется. Повтор отменённого действия не предусмотрен.

Дополнительно: максимальная глубина скобок

Для правильной последовательности из () верните максимальное число одновременно открытых скобок. Для неправильной выдайте ValueError. Примеры: пустая строка → 0, ()() → 1, (()()) → 2. В этой задаче достаточно счётчика и максимума.

ВходРезультат
пустая строка0
()()1
(()())2
)(ValueError

Дополнительную функцию depth(text) можно сохранить отдельно. Сдача обязательных задач от неё не зависит. Осталось оформить объяснение и результаты проверки.

§4Что сдавать

Проверяющий должен воспроизвести результат по сохранённым файлам. Приложите solution.py, результаты check.py и краткое объяснение трёх функций.

КритерийБаллыПодтверждение
Контракт и примеры2Пустые входы и ошибки формы
Корректность трёх функций4Все проверки и свои контрпримеры
Инварианты и порядок снятия2Устное объяснение и трассировка
Стоимость и оформление2Оценки с пояснением размера входа

Всего 10 баллов. Для apply_actions учитывается длина результата; для ОПЗ оговаривается размер чисел. Для оценки нужны код, результаты тестов и объяснение.

Разбор на примере стопки

Сдача похожа на передачу собранной вещи с инструкцией проверки. Что есть что: solution.py — работающая часть; check.py — повторяемая проверка; записка — объяснение выбора стека и его границ.

Код и объяснение готовы. В мок-интервью те же решения нужно получить из условия по этапам.
