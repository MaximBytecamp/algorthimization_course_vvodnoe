23.3

Правильная скобочная последовательность

В этой главе разобрана проверка трёх видов скобок. Построим инвариант, проверим порядок закрытия и сопоставим стек с подсчётом баланса.

В этой главе
  1. Вложенность и порядок
  2. Добавление и проверка вершины
  3. Инвариант и последняя проверка
  4. Счётчик и повторное удаление пар

§1Вложенность и порядок

Коробку внутри коробки закрывают раньше внешней. Открывающая скобка создаёт такую незавершённую пару. Закрывающая должна совпасть с последней открытой скобкой.

Строка содержит только ()[]{}. Вернуть bool; пустая строка правильная. Вход не изменяется.

ВходОтветПричина
{[()]}TrueВсе пары закрыты в обратном порядке
([)]FalseДля ) вершина равна [
(()FalseОдна открывающая осталась
Пустая строкаTrueНезавершённых пар нет

Равное число открывающих и закрывающих не доказывает правильность. В строке ([)] числа совпадают, но пары пересекаются. Нужен порядок типов незакрытых скобок. Для его хранения используем стек.

§2Добавление и проверка вершины

Как при закрытии коробок, новый открытый уровень кладётся поверх предыдущего. Словарь pairs сопоставляет закрывающий символ с нужным открывающим.

Открывающая скобка добавляется через append. Для закрывающей проверяется пустота. Выражение or вычисляется слева направо: если стек пуст, pop не вызывается. При непустом стеке снятая вершина сравнивается с pairs[char].

На схеме виден стек после каждого символа. Исходная последовательность расположена отдельно от незакрытых скобок.

Пошаговый разбордно слева → вершина справа

После {, [ и ( в стеке три элемента. Символ ) снимает (, затем ] снимает [, затем } снимает {. Для ([)] проверка останавливается при первой несовпавшей паре.

Разбор на примере стопки

Открытая коробка — открывающая скобка в стеке. Закрыть можно последнюю коробку, совпавшую по типу. Что есть что: append открывает уровень, pop снимает уровень, pairs задаёт нужную пару.

После прохода требуется ещё одна проверка: незакрытые уровни могут остаться без встреченной ошибки.

§3Инвариант и последняя проверка

После проверки всех вложенных коробок снаружи не должно остаться открытых. Поэтому функция возвращает not stack. Пустой стек даёт True, непустой — False.

Инвариант: После обработанного префикса стек содержит незакрытые открывающие скобки в порядке их появления. Верхняя закрывается первой.

Шаг доказательстваСостояние
До проходаПрефикс пуст, стек пуст
ОткрывающаяДобавляется новое незавершённое открытие
ЗакрывающаяСнимается совпавшая вершина; иначе ответ False
После проходаTrue только при отсутствии незакрытых скобок

Здесь n — длина строки. Каждый символ обрабатывается один раз. Для строки из n открывающих скобок стек хранит n элементов.

O(n) времени и O(n) дополнительной памяти в худшем случае.

Проверьте себя

Почему строка (() получает False?

  • Сверьте порядок обработки и состояние вершины. Одна ( остаётся в стеке. Функция возвращает False через not stack.
  • Одна ( остаётся в стеке. Функция возвращает False через not stack.
  • Сверьте порядок обработки и состояние вершины. Одна ( остаётся в стеке. Функция возвращает False через not stack.

Инвариант объясняет корректность. Сравним этот способ с решениями для более узкого контракта.

§4Счётчик и повторное удаление пар

Для одного вида одинаковых коробок тип хранить не нужно. Если допустимы только ( и ), хватает счётчика balance. Открывающая увеличивает его, закрывающая уменьшает; отрицательное значение означает ошибку.

МетодВремяПамятьКогда подходит
Счётчик balanceO(n)O(1)Только один вид скобок
СтекO(n)O(n)Несколько видов и вложенность
Повторно удалять (), [], {}O(n²) в худшем случаеO(n)Короткий разбор идеи, не длинный ввод

Для глубокой строки (((...))) повторное удаление соседних пар сокращает строку лишь на два символа за проход. Сумма длин просмотренных строк имеет порядок n². Стек обрабатывает каждый символ один раз.

На собеседовании объяснение состоит из контракта, инварианта, границ и стоимости. Если во вход добавляют буквы, сначала уточняют: пропускать их или считать ошибкой. Текущий код предполагает только скобки.

Теперь заменим символы в стеке числами. Порядок снятия сохранится, но вершина станет правым операндом.
