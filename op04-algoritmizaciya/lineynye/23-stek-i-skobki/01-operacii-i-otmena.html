23.2

Операции стека и отмена действий

В этой главе разобраны операции стека на list, отмена добавлений и стек вызовов. Сравним порядок LIFO с фактическими изменениями данных.

В этой главе
  1. Вершина на правом конце list
  2. Отмена целого добавления
  3. Стек вызовов

§1Вершина на правом конце list

В стопке документов добавление сверху не требует перекладывать остальные листы. В Python вершиной стека назначим правый конец списка. Добавление — append, просмотр — stack[-1], снятие — pop().

ОперацияИзменяет стекСтоимость
append(x)Добавляет x справаO(1) амортизированно
stack[-1]НетO(1)
pop()Удаляет и возвращает вершинуO(1)
not stackНетO(1)

Амортизированная оценка относится к серии добавлений. При расширении массива отдельный append может потребовать O(n) работы. Суммарная работа n добавлений остаётся O(n). Просмотр и снятие на пустом списке дают IndexError.

Разбор на примере стопки

Край стопки совпадает с концом списка. Что есть что: весь список — стопка; последний элемент — вершина; append кладёт сверху, pop снимает сверху. Перед снятием проверяют, есть ли элемент.

Операции на одном конце подходят для истории добавлений. Определим единицу отмены.

§2Отмена целого добавления

Если наклеить две подписи, последнюю можно снять целиком. Длину подписи учитывать не нужно. В нашей модели одно add добавляет строку, а undo снимает последнее неотменённое add.

Список действий состоит только из ('add', строка) и ('undo',). Отмена снимает последнее неотменённое добавление целиком. При пустой истории ничего не происходит. Вернуть итоговую строку; вход не изменяется. Повтор отменённого действия не предусмотрен.

Переменная chunks хранит фрагменты. Ветка add сохраняет строку, включая пустую. Ветка elif проверяет наличие фрагмента перед pop. Последняя строка соединяет оставшиеся фрагменты через пустой разделитель.

На схеме отменяются добавления целиком. Текущий текст получается соединением элементов стека.

Пошаговый разбордно слева → вершина справа

После добавлений «при» и «вет» стек содержит два фрагмента. Отмена снимает «вет»; остаётся «при». Пустой фрагмент тоже является отдельным добавлением и должен сниматься первым.

Инвариант: Стек chunks содержит фрагменты всех неотменённых добавлений в исходном порядке. Их соединение даёт текущий текст.

Инвариант — свойство, которое сохраняется после каждого шага. До первого действия стек пуст. Add дописывает очередной фрагмент, undo снимает последний. Поэтому после всех действий соединение стека даёт нужный текст.

Повторное соединение всей строки после каждого add увеличило бы работу. Здесь join вызывается один раз.

O(m + L) времени: m действий и L символов результата. Память — O(m + L), включая итоговую строку.

Та же последовательность «внутреннее действие завершается раньше внешнего» встречается при вызовах функций.

§3Стек вызовов

Во время разговора можно отложить вопрос, ответить на уточнение, затем вернуться к вопросу. Вызов функции тоже приостанавливает внешний вызов до возврата внутреннего. Кадр вызова хранит состояние конкретного вызова: локальные значения и место возврата.

В примере n — целое неотрицательное число. Сначала начинается countdown(2), затем countdown(1), затем countdown(0). Базовый случай — вызов с n=0. Он возвращает 0. После неё завершается вызов с n=1, затем с n=2. Схема показывает кадры от внешнего к внутреннему.

Пошаговый разбордно слева → вершина справа

У каждого вызова своё значение n. Кадр внешнего вызова остаётся, пока работает внутренний. Стеком вызовов управляет среда исполнения; список chunks из прошлой задачи создаёт наша программа.

СпособДополнительная памятьОграничение
Рекурсивный countdown(n)O(n) кадровГлубина рекурсии Python ограничена
Цикл с уменьшением nO(1)Кадры для каждого шага не создаются

Рекурсивный пример показывает порядок вызовов. Проверку скобок выполним циклом и явным стеком, чтобы глубина вложенности не зависела от предела рекурсии.
