22.2

Слияние упорядоченных списков

Объединим две упорядоченные цепочки без копирования полезных узлов. Разберём роль dummy, продвижение хвоста и присоединение оставшейся части.

В этой главе
  1. Выбирать из двух голов
  2. Собирать за хвостом
  3. Проверить связи
  4. Остатки и задача

В развороте каждый узел переносился в начало готовой части. При слиянии узлы добавляются в конец, а их порядок определяется сравнением значений.

§1Выбирать из двух голов

Два устройства записали события в порядке времени. Одна цепочка содержит 1 → 4, другая — 2 → 4. Нужно получить общий порядок 1 → 2 → 4 → 4, сохранив оба события с отметкой 4.

Слияние соединяет две уже упорядоченные последовательности в одну. В каждом исходном списке следующий элемент не меньше текущего. Поэтому самый маленький из оставшихся элементов находится у одной из двух голов. Достаточно сравнить их, взять меньший и сдвинуть только эту голову.

Функция merge(left, right) принимает две конечные цепочки, упорядоченные по неубыванию. Значения должны допускать сравнение <=. Цепочки не должны содержать общих узлов: алгоритм перестраивает их связи на месте. Он возвращает голову результата и не создаёт копии полезных узлов.

Построим две цепочки. Имена B и D различают узлы с одинаковым значением 4.

Равенство значений не делает объекты одинаковыми. При слиянии должны сохраниться и B, и D. Если значения равны, будем сначала брать узел из левой цепочки.

В таблице перечислены исходные поля. Две головы ведут к разным наборам объектов.

ОбъектvaluenextИсходная цепочка
A1BЛевая

C2DПравая
D4NoneПравая

Сравнение голов выберет A1 перед C2. После этого левой головой для выбора станет B4. Для сохранения выбранных узлов заведём отдельный хвост результата.

§2Собирать результат за хвостом

Для результата заведём служебный узел dummy, как при удалении в модуле 21. Полезные узлы будут начинаться с dummy.next. Ссылка tail отмечает последний уже выбранный узел; сначала это сам dummy.

Строка tail.next = left присоединяет выбранный узел к результату. Затем left = left.next сдвигает левую рабочую ссылку. После выбора из любой стороны tail = tail.next переводит хвост на присоединённый узел.

Условие цикла требует два непустых остатка. Когда один закончился, сравнивать больше нечего. Последняя строка присоединения берёт весь второй остаток: left, если он не равен None, иначе right. При двух пустых остатках записывается None.

Посмотрите, как хвост переходит с dummy на A, затем на C и B. Выбранный узел пока хранит прежнее next; эта связь меняется, когда к нему присоединяют следующий выбранный узел.

Слияние A1 → B4 и C2 → D4

Буквы обозначают конкретные объекты Node. Сплошные стрелки выходят из поля next, пунктирные — от переменных. Тире у переменной означает, что её присваивание ещё не выполнено.

После выбора A поле A.next ещё ведёт к B. При выборе C строка tail.next = right меняет A.next: теперь A ведёт к C. Узел B не теряется, потому что на него указывает left. Выбранная часть заканчивается у tail, а его прежнее продолжение ещё не обязано быть окончательным.

Следующая таблица отделяет выбранную часть от остатков. Она не утверждает, что поле tail.next уже очищено.

На каждой итерации выбирается минимальная из двух голов. Все элементы оставшихся частей не меньше уже выбранного хвоста. Так сохраняется порядок результата, а один из остатков сокращается на узел. Проверим порядок конкретных объектов после вызова.

§3Проверить идентичность узлов

Вызовем слияние и сравним конкретные объекты. Служебный узел в результат не входит.

Внешние имена left и right всё ещё указывают на A и C. Однако их пути уже изменились: A теперь ведёт к C, а C — к B. Поэтому после вызова исходные списки нельзя считать независимыми. Для дальнейшей работы используют result.

Сравним пути от внешних имён. Эти имена не перемещались, но поля доступных через них объектов изменились.

Внешнее имяДо mergeПосле merge
leftA1 → B4 → NoneA1 → C2 → B4 → D4 → None
rightC2 → D4 → NoneC2 → B4 → D4 → None
resultЕщё не заданоA1 → C2 → B4 → D4 → None

Пути от left и right теперь пересекаются. Повторно передавать их как независимые входы слияния нельзя: это нарушит условие отсутствия общих узлов.

Предскажите результатВ начале есть A1 → B4 и C2 → D4. Уже выбран A, затем выполнено tail.next = right для C. Что хранит A.next?

  • Раньше A.next вела к B, но присоединение C переписало это поле. Ссылка left по-прежнему сохраняет B.

  • tail указывал на A, а right — на C. Присваивание изменило поле A.next.

  • Полю next передана ссылка right. Значение узла не копируется.

Почему спискам нельзя иметь общий хвост

Пусть обе входные головы указывают на один узел 5. Из левого входа он выбирается первым. После завершения цикла правый остаток — тот же узел, а хвост результата уже у него. Присоединение остатка создаёт самоссылку.

Здесь намеренно нарушен контракт. Проверка ограничена чтением одной ссылки; обход до None завис бы. Для корректного слияния нужны независимые цепочки. Алгоритм не выполняет отдельную проверку пересечения.

Для допустимых независимых входов осталось проверить завершение одного из остатков и пустые цепочки.

§4Остатки, стоимость и задача

Проверим пустые входы, дубликаты и остаток длиннее одного узла. Вспомогательные функции собирают и читают только конечные цепочки.

Если длины равны n и m, время в худшем случае O(n + m): каждый выбор сокращает один остаток. Готовый остаток присоединяется одной записью ссылки, без повторного обхода. Дополнительная память O(1): один dummy и несколько рабочих ссылок. Полезные узлы уже существовали во входных списках.

Граничные случаи различаются тем, выполняется ли сравнение и какой остаток присоединяется после цикла.

Левый входПравый входЧто делает алгоритм
NoneNoneПрисоединяет None; возвращает None
NoneУзел 6Возвращает тот же узел 6
12 → 3 → 5Выбирает 1; присоединяет весь правый остаток
3 → 31Выбирает 1; присоединяет весь левый остаток

Пустые входы обрабатываются тем же кодом, потому что служебный узел даёт место для первого присоединения.

Задача: объединить два журнала

Напишите merge(left, right) с тем же контрактом. Для 1 → 3 → 5 и 2 → 3 → 6 получите 1 → 2 → 3 → 3 → 5 → 6. При равенстве выбирайте левый узел первым. До кода нарисуйте изменение поля у хвоста, когда после 1 выбирается 2.

Проверьте два пустых входа, один пустой, по одному узлу, дубликаты и длинный остаток. Сохраните ссылки на две тройки и через is подтвердите их порядок в результате. Циклы и общие узлы не входят в допустимый вход.

  • Сравниваются только головы непустых остатков.
  • Выбранный узел присоединяется через поле хвоста.
  • Хвост результата и головы остатков — разные роли.

В слиянии две рабочие ссылки идут по разным цепочкам. Далее две ссылки будут идти по одной цепочке, но с разной скоростью.
