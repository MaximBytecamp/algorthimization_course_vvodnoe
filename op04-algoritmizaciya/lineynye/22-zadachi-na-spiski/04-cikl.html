22.4

Как обнаружить цикл

Обнаружим замкнутую цепочку без бесконечного обхода и без хранения всех посещённых узлов. Для встречи указателей важен один объект, а не одинаковые числа.

  3. Почему они встретятся

Поиск середины останавливался у конца списка. Теперь разберём вход, на котором конца нет: ссылка next возвращает нас к уже посещённому узлу.

§1Когда обход не приходит к None

При ошибке в связывании поле next последнего созданного узла может вести к прежнему узлу цепочки. Тогда обход снова и снова посещает те же объекты. Такая замкнутая часть называется циклом. Перед запуском операций, которые ожидают конец списка, полезно проверить его наличие.

Функция has_cycle(head) возвращает True, если из головы достижим цикл, иначе False. Она только читает ссылки и не размыкает цикл. Предполагается конечное число узлов: у каждого поле next ведёт на другой узел или равно None. Пока работает проверка, другие части программы связи не меняют.

Построим A7 → B7 → C9 → B7. Две семёрки нужны специально: одинаковые значения не доказывают возвращение в тот же объект.

Из A сначала попадаем в B, затем в C, затем опять в B. Узел A не входит в цикл. До None этот путь не дойдёт. Поэтому здесь нельзя вызывать обычный to_values или печатать всю цепочку циклом «пока не None».

Таблица показывает, почему конец недостижим. У каждого из трёх объектов есть продолжение.

Объектvaluenext
A7B
B7C
C9B

После первого посещения C снова выбирается B. Для обнаружения этого повторения будем сравнивать объекты, на которые указывают две переменные.

§2Встреча медленной и быстрой ссылок

Начнём slow и fast с головы, как при поиске середины. На каждой итерации slow делает один переход, fast — два. Если после перемещения они ссылаются на один объект, обнаружен цикл. Проверять встречу до первого движения нельзя: в начале обе ссылки совпадают у любого непустого списка.

В условии встречи используется is: он сравнивает идентичность объектов. Сравнение slow.value == fast.value ошибочно: одинаковые значения могут храниться в разных узлах конечного списка. Даже slow == fast лучше не использовать: поведение == может быть переопределено в классе.

На схеме цикл замкнут сплошной стрелкой из C.next в B. Проследите два полных движения, а затем проверку встречи. Поля узлов всё время остаются прежними.

A7 → B7 → C9 → B7

Буквы обозначают конкретные объекты Node. Сплошные стрелки выходят из поля next, пунктирные — от переменных. Тире у переменной означает, что её присваивание ещё не выполнено.

После первого движения slow у B7, fast у C9: объекты различны. После второго slow у C9, fast проходит C → B → C и тоже оказывается у C9. Встреча произошла внутри цикла. Это не означает, что C — его начало: вход в цикл здесь находится у B.

Таблица фиксирует ссылки после полных движений. Проверка встречи выполняется после обоих присваиваний slow и fast.

ИтерацияslowfastПроверка
СтартA7A7Ещё не проверяем
1B7C9Разные объекты
2C9C9Один объект: True

Результат отвечает только на вопрос о наличии цикла. Поиск его входа, длины или размыкание — другие задачи; этот алгоритм их не выполняет. Далее обоснуем, почему встреча произойдёт при любой длине цикла.

§3Почему встреча неизбежна

Если цикла нет, fast доходит до None или последнего узла. Условие завершает цикл, функция возвращает False. Если цикл есть, обе ссылки рано или поздно попадут в него: за пределами цикла путь не разветвляется.

Внутри цикла fast за одну итерацию проходит на один переход больше, чем slow. Поэтому расстояние между ними по кругу каждый раз меняется на единицу. Например, в кольце из четырёх узлов отставание fast от slow проходит состояния 3, 2, 1, 0. Нулевое расстояние означает встречу.

На кольце длины k любое начальное расстояние от 0 до k − 1 за не более чем k движений дойдёт до нуля. Так обнаружение цикла не требует сохранять все посещённые узлы. Этот способ называют алгоритмом Флойда или методом медленного и быстрого указателей.

Для кольца из четырёх узлов зафиксируем пример отставания fast от slow. Расстояние измеряется по направлению next от fast до slow.

Полных движений внутри кольцаОтставание fast от slow
03 перехода
12 перехода
21 переход
30: один объект

Обе ссылки движутся, но fast сокращает это расстояние на единицу. Когда оно равно нулю, условие slow is fast даёт True.

Проверим построенный пример и намеренно создадим ложную подсказку для сравнения значений: три одинаковые семёрки, но без цикла.

Первая проверка на a вернула True и сохранила замыкание C.next → B. На обычной цепочке одинаковые значения дали равенство чисел, но ссылки различались. Правильная функция вернула False.

Предскажите результатУ A7 → B7 → C7 → None после первого полного движения slow находится у B, fast у C. Что должна сделать has_cycle?

  • Совпадение чисел не является встречей указателей. Узлы B и C разные.

  • Проверка slow is fast ложна. Следующее условие цикла обнаружит fast.next = None, и функция вернёт False.

  • Начальное совпадение есть у любой головы. Встреча проверяется только после движения.

Самоссылка и цикл после длинного начала

Самый короткий цикл состоит из одного узла, ссылающегося на себя. Он тоже обнаруживается после движения. У второго примера начало длиннее: 1 → 2 → 3 → 4 → 5 → 3. Проверки только читают ссылки.

Функция не зависит от длины начального пути и положения входа. Однако она сообщает только True или False: возвращённое значение не является ссылкой на узел встречи.

Проверка цикла обоснована. Применим её к коротким входам и сформулируем требования практикума.

§4Границы, стоимость и практикум

Проверим границы отдельно: пустой список, один обычный узел, два узла без цикла и замыкание на голову. В циклических случаях проверяем ссылки напрямую, без обхода до None.

Пусть до цикла μ узлов, а внутри него k. Время обнаружения O(μ + k): после входа обеих ссылок в цикл для встречи достаточно не более k движений. Для конечной цепочки из n узлов время O(n). Дополнительная память в обоих случаях O(1).

Задача: проверить корректность цепочки

Реализуйте has_cycle(head), не меняя поля узлов и не собирая набор посещённых объектов. До кода нарисуйте два движения для A7 → B7 → C9 → B7. Отдельно объясните, почему сравнение значений даст ложный ответ на трёх семёрках без цикла.

Проверьте пустой список, один обычный узел, самоссылку, нечётную конечную цепочку, цикл на голову и цикл после незамкнутого начала. Ожидается False только для входов, где достижимо None.
