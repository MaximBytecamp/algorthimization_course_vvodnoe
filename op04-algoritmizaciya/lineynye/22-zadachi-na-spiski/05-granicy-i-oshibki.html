22.6

Границы и ошибки

Соберём граничные тесты четырёх алгоритмов. Найдём ошибки по состоянию ссылок, исправим функции и проверим их в браузере.

§1Граничные входы

При проверке собранной цепочки одних значений недостаточно: два разных узла могут хранить одну семёрку. Контракт задаёт также объекты, связи и форму ответа.

Граничный тест — маленький допустимый вход, на котором меняется число итераций или ветка алгоритма. Сначала запишите ожидаемый ответ, затем запускайте функцию.

АлгоритмМинимальные входыЧто проверить
reverse0, 1, 2 и 5 узловТе же объекты в обратном порядке; новый хвост ведёт в None.
mergeОба пустые; один пустой; равные значения; длинный остатокКаждый исходный узел один раз, левые равные перед правыми.
middleДлины 0–6, одинаковые значенияОтвет is nodes[n // 2]; все next прежние.
has_cycleПустой; самоссылка; цикл на голову; цикл после началаБулев ответ; поля не меняются. Равные значения без цикла дают False.

Цикл допустим только для has_cycle из этих четырёх функций. Не запускайте на нём остальные функции: конечность — их предусловие, то есть требование к входу.

Два объекта различаются независимо от подписи на схеме. Поэтому сохраните ссылки на узлы до вызова и проверяйте их через is. Теперь свяжем симптомы с конкретными строками.

§2Симптом и причина

Один и тот же результат на экране может иметь разные причины. Например, короткий вывод после reverse возникает и при потере остатка, и при сохранении старой головы. Сопоставьте состояние ссылок со строкой, которая его изменила.

СимптомПричинаМинимальный контрпример
После разворота виден один узелНе сохранён результат или продолжение прочитано после смены next.A → B → None. Проверьте new_head и A.next отдельно.
merge потерял последние узлыПосле while не присоединён остаток.[1] и [2, 3]. Должны остаться все три объекта.
merge замкнул цепочкуОдин общий объект присоединён повторно; вход нарушает контракт.Обе головы указывают на один узел A. Такой вход исключён.
middle падает на одном узлеУ fast.next читается next без проверки.A → None: fast.next уже None.
Цикл найден в конечном спискеСравниваются value вместо объектов или проверяется совпадение до движения.Три семёрки без цикла должны дать False.
Проверка цикла не завершаетсяОдин из указателей не сдвигается или используется обход до None.A.next = A. Для Флойда ответ True после первого движения.

§3Исправьте функции

В каждой заготовке намеренно изменена одна часть алгоритма. До запуска назовите вход, который обнаружит ошибку. После исправления выполните тесты и объясните изменение поля или рабочей ссылки.

Песочница загружает Python с cdn.jsdelivr.net по кнопке «Запустить тесты». Первый запуск требует интернета. Код остаётся в локальном хранилище браузера; автоматической отправки преподавателю нет. Зависший запуск прерывается через пять секунд после загрузки Python.

Сравним порядок двух строк на одном входе A5 → B8 → None. Нажимайте вкладки: таблицы показывают состояние сразу после каждого присваивания.

СтрокаA.nextfollowingПуть от current
Старт: prev = None, current = ABНе заданаA → B → None
current.next = prevNoneНе заданаA → None
following = current.nextNoneNoneA → None

Поле A.next уже перезаписано. После чтения following равна None; узел B не попадёт в результат.

СтрокаA.nextfollowingПуть от current
Старт: prev = None, current = ABНе заданаA → B → None
following = current.nextBBA → B → None
current.next = prevNoneBA → None

Ссылка following сохранила B до изменения A.next. После prev = current и current = following работа продолжится с B.

Во втором варианте A.next тоже становится None, но путь к B остаётся в переменной. В каждой песочнице ниже найдите аналогичную причину ошибки и исправьте функцию.

Разворот списка

Найдите дефект в reverse(head). Полный контракт — в 22.2.

Сверка после собственной попытки

Перед проверкой while ссылка prev ведёт по уже обработанным узлам в обратном порядке. current держит начало необработанной части. Сначала сохраняем current.next, затем меняем поле, переносим prev и current.

Слияние списков

Найдите дефект в merge(left, right). Полный контракт — в 22.3.

Сверка после собственной попытки

Участок от dummy.next до tail содержит уже выбранные узлы в нужном порядке. left и right держат головы остатков. Связь после tail ещё может вести в остаток: граница готовой части задаётся именно tail.

Правая середина

Найдите дефект в middle(head). Полный контракт — в 22.4.

Сверка после собственной попытки

После t полных итераций slow находится на позиции t, fast — на позиции 2t или равен None. Перед двойным переходом проверяются fast и fast.next. Остановка даёт slow на позиции n // 2.

Наличие цикла

Найдите дефект в has_cycle(head). Полный контракт — в 22.5.

Сверка после собственной попытки

На каждой полной итерации slow делает один переход, fast — два. Встречу через is проверяем после обоих движений. В конечной цепочке fast достигает конца; внутри цикла разность позиций меняется на один шаг по кругу.

Зелёные тесты подтверждают эти случаи. Проверьте также, что исправленная строка соответствует контракту. Затем объясните завершение цикла.

§4Как объяснить решение

На проверке решения нужно восстановить путь по стрелкам и назвать причину остановки. Возьмите один пример, проговорите значения рабочих ссылок и только затем назовите оценку сложности.

АлгоритмПочему заканчиваетсяСтоимость
reverseПосле каждой итерации необработанных узлов на один меньше.O(n) времени, O(1) памяти.
mergeКаждый выбор сокращает один остаток; затем второй присоединяется целиком.O(n + m) в худшем случае, O(1) памяти.
middlefast за один шаг цикла проходит две ссылки к концу конечной цепочки.O(n) времени, O(1) памяти.
has_cyclefast достигает конца либо догоняет slow в конечном кольце.O(n) времени, O(1) памяти; n — число достижимых узлов.
Проверьте себяДля A7 → B7 → C7 → None has_cycle вернула True. Какой тест лучше отличит сравнение значений от сравнения объектов?

  • Совпали только value. Ни один объект повторно не посещается.

  • На пустом входе ошибочное сравнение может вообще не выполняться.

  • Так ошибка скроется: значения перестанут совпадать.
