22.2

Разворот списка

Развернём направления next, сохранив сами узлы. Разберём, зачем нужны три рабочие ссылки и почему результат вызова становится новой головой.

В этой главе
  1. Что разворачивается
  2. Сохранить продолжение
  3. Новая голова
  4. Границы и задача

В модуле 21 менялось одно поле при вставке или удалении. Теперь изменение повторяется для каждого узла, поэтому особенно важен порядок присваиваний.

§1Что разворачивается

Журнал хранит события цепочкой 42 → 17 → 30. Теперь их нужно читать от последнего к первому. У односвязного списка нет перехода назад. Чтобы новый обход шёл 30 → 17 → 42, нужно изменить поля next. Значения останутся в своих узлах.

Функция reverse(head) принимает голову конечной цепочки и возвращает новую голову. Она использует существующие узлы и меняет их связи. Пустой список даёт None, один узел остаётся собой. Вход с циклом не подходит: у него нет последнего узла.

Создадим три именованных объекта. После разворота эти имена позволят проверить идентичность узлов.

Здесь a и head указывают на один объект 42. Разворот не создаёт его копию. Меняется путь между теми же тремя объектами.

Таблица фиксирует исходные поля узлов. По ней можно восстановить путь от головы до None.

Объектvaluenext до разворота
A (a)42B
B (b)17C
C (c)30None

Ссылка head ведёт к A. Повернув A.next, мы изменим первый переход. Чтобы продолжить работу с B и C, потребуется отдельная ссылка на остаток.

§2Сохранить продолжение и повернуть одну связь

Разделим работу на уже развёрнутую часть и оставшуюся цепочку. Переменная prev хранит начало готовой части, current — первый ещё не обработанный узел. В начале готовой части нет, поэтому prev = None.

Перед изменением current.next сохраним прежнее продолжение в following. Затем направим current.next на готовую часть. После этого текущий узел становится её новой головой, а работа продолжается с сохранённого following.

Четыре строки тела цикла решают разные задачи: сохранить путь, повернуть стрелку, обновить готовую часть, перейти дальше. Подставим исходные узлы в пошаговый разбор. При первом повороте у A поле next становится None, но узел B доступен через following.

Разворот 42 → 17 → 30

Буквы обозначают конкретные объекты Node. Сплошные стрелки выходят из поля next, пунктирные — от переменных. Тире у переменной означает, что её присваивание ещё не выполнено.

После первой итерации готовая часть — A → None, а оставшаяся — B → C → None. После второй готовая часть начинается с B и ведёт к A. В конце current равна None, а prev указывает на C. Функция возвращает prev.

Перед каждой проверкой цикла prev ведёт по обработанным узлам в обратном порядке, а current — по необработанным в исходном. Это инвариант: утверждение, которое остаётся верным от итерации к итерации. На каждом шаге необработанных узлов становится на один меньше.

После итерацииПуть от prevПуть от current
0NoneA42 → B17 → C30 → None
1A42 → NoneB17 → C30 → None
2B17 → A42 → NoneC30 → None
3C30 → B17 → A42 → NoneNone

Таблица показывает состояние после всех четырёх присваиваний. Ссылки prev и current не обозначают одно и то же: одна держит готовую часть, другая — остаток. Теперь сохраним возвращённую голову и проверим внешние ссылки.

§3Новая голова и прежние имена

Сохраним результат отдельно и проверим объекты. Внешняя переменная head пока остаётся на A: присваивания локальной переменной функции не меняют её.

Если вызвать reverse(head) и отбросить возвращённую ссылку, внешний head останется на старом первом узле. Его next уже равен None, поэтому оттуда виден лишь один узел. Обычная запись вызова — head = reverse(head).

Сравним внешние ссылки до присваивания новой головы и после него.

Моментheadnew_headПуть от head
До вызоваAЕщё не заданаA → B → C → None
После new_head = reverse(head)ACA → None
После head = new_headCCC → B → A → None

Возвращённая ссылка даёт доступ ко всей развёрнутой цепочке. Старая голова теперь является последним узлом.

Предскажите результатФункция начала разворот A42 → B17 → C30. Выполнены только following = current.next и current.next = prev первой итерации. Где находится B?

  • following сохранила ссылку на B до изменения A.next. Строка current = following ещё не выполнялась.

  • Ни одна из выполненных строк не перемещает current.

  • Изменение A.next разрывает один путь, но following сохраняет другой.

Почему обратный порядок строк теряет остаток

В ошибочном фрагменте сначала меняют поле, а потом пытаются прочитать из него прежнее продолжение. Следующий запуск ограничен первой итерацией.

После current.next = prev поле уже хранит None. Прочитать прежнюю ссылку на узел 17 из него нельзя. Поэтому сохранение following стоит до поворота стрелки.

Порядок ссылок проверен на трёх узлах. Проверим также пустой вход и короткие цепочки.

§4Границы, стоимость и задача

Добавим функции для сборки конечной цепочки и чтения её значений. Сборка идёт с конца: каждый новый узел ставится перед уже построенной частью. Чтение двигает только локальную переменную head; связи не меняет.

Два разворота возвращают исходный порядок. Каждый из n узлов обрабатывается один раз: время O(n). Дополнительная память O(1), потому что число рабочих ссылок не зависит от длины списка. Вспомогательный to_values создаёт массив для проверки, но сам алгоритм разворота его не использует.

Для каждого граничного входа проверим форму результата и ссылки.

ВходРезультатЧто проверяем
NoneNoneЦикл пропущен
Один узел 8Тот же узел 8next остаётся None
1 → 22 → 1Новая голова — прежний второй узел
1 → 2 → 3 → 4 → 55 → 4 → 3 → 2 → 1Все узлы обработаны

Такие проверки покрывают отсутствие итераций, одну итерацию и повторение тела цикла. Примените их к самостоятельному решению.

Задача: вернуть события в обратном порядке

Реализуйте reverse(head) для конечного односвязного списка. Значения оставьте в своих узлах; меняйте только next. Верните голову результата. До кода нарисуйте первый поворот в цепочке 5 → 8 → 2 и подпишите ссылку, которая сохраняет остаток.

Проверьте пустой вход, один узел, два узла и нечётную длину. Для 5 → 8 → 2 ожидается 2 → 8 → 5. Сохраните ссылки на исходные узлы и подтвердите через is, что результат содержит эти объекты.

  • Путь к остатку сохраняется до изменения поля.
  • Каждый шаг переносит один узел в готовую часть.
  • Новая голова возвращается и сохраняется вызывающим кодом.

Разворот собирает одну цепочку из одной исходной. Следующий алгоритм собирает одну цепочку из двух, выбирая меньшую из доступных голов.
