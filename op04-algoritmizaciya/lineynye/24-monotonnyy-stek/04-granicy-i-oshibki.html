Границы и ошибки моностека

В этой главе разобраны пустой вход, равенства и остаток стека. Проверим ошибки короткими контрпримерами.

В этой главе
  1. Пустой вход и хвост
  2. Равные значения
  3. Типичные ошибки

§1Пустой вход и хвост

На пустом списке ответ должен иметь длину 0. В поиске следующего большего на возрастающем входе каждый новый элемент снимает предыдущий. На убывающем входе все индексы остаются до конца. Они сохраняют ответ -1. В гистограмме оставшиеся столбцы ещё нужно проверить на площадь.

Входnext_greaterwarmer_dayslargest_rectangle
[][][]0
[1, 2, 3][2, 3, -1][1, 1, 0]4
[3, 2, 1][-1, -1, -1][0, 0, 0]4
[2, 2][-1, -1][0, 0]4

На входе [3, 2, 1] все индексы остаются в стеке next_greater. Здесь -1 — предусмотренный ответ. Для гистограммы оставшиеся высоты всё ещё могут дать максимум. Затем проверим роль равенства.

§2Равные значения

Равные значения — место, где «строго» и «нестрого» дают разные алгоритмы. Для next greater равный элемент не подходит. Для next greater or equal подходит. В тестах нужны [5, 5], [5, 6] и [6, 5].

Условие снятияnext_greater([5, 5])Оценка
<[-1, -1]верно для строго большего
<=[5, -1]ошибка текущего контракта

Во второй строке равный элемент ошибочно считается большим. Изменять знак можно только вместе с контрактом. Условия равенства — одна из причин ошибок; проверим и остальные.

Контроль границы

Что вернёт next_greater([])?

  • Ответ должен иметь ту же длину, что и вход.
  • У пустого входа нет позиций.
  • Пустой список входит в контракт этой функции.
Почему if не заменяет while

На [3, 2, 4] текущая четвёрка должна снять 2 и 3. Один if снимет только 2. Получится [-1, 4, -1] вместо [4, 4, -1].

Контрпримеры проверяют отдельные причины ошибки. В практике для каждого теста укажите, какую строку алгоритма он проверяет.
