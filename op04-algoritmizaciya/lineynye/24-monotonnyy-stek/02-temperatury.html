24.3

Температуры и ближайший меньший

В этой главе разобраны дни ожидания и ближайший меньший элемент. Сопоставим результаты и условия снятия индексов.

В этой главе
  1. Температуры как тот же шаблон
  2. Ближайший меньший
  3. Выбор условия снятия

На календаре ожидание измеряют числом дней между двумя отметками. Даты нужны даже тогда, когда сами значения температуры уже известны.

Контракт warmer_days. Вход — список целых температур. Вернуть список расстояний до первой строго большей температуры справа. Если такого дня нет, записать 0. Пустой вход даёт []; исходный список сохраняется.

§1Температуры как тот же шаблон

В задаче о температурах формулировка меняется, но механизм тот же: для каждого дня ищем первый более тёплый день справа. Ответ — число дней ожидания. Поэтому при снятии записываем разность индексов.

Пошаговый прогон полного кода

Слева показан весь код с подсветкой текущей строки. Справа — входные данные и переменные перед её выполнением. Кнопка «шаг →» выполняет строку: её результат виден на следующем шаге. Кнопка «← шаг» возвращает предыдущий кадр, а «⏮» — начало прогона.

Пара day, temp получается из enumerate. Снятый индекс old_day обозначает день без ответа. Текущий day — первый подходящий, поэтому расстояние равно day - old_day. Индексы в стеке возрастают, температуры по ним не возрастают.

ДеньТемператураСнятые дниОтветы для снятых
073——
17401 − 0 = 1
274—равная температура не подходит
371——
47234 − 3 = 1

Дни 1, 2 и 4 остаются с нулями. Итог [1, 0, 0, 1, 0]. Сравним знак снятия с поиском меньшего.

На схеме меняются текущий индекс, стек и уже записанные ответы. Выберите вход, затем пройдите шаги вперёд и назад.

Сплошная рамка выделяет текущую позицию, пунктир — снятый индекс. Строка кода подсвечена на выполненной операции. Состояния схемы вычисляются для выбранного входа; код студента схема не запускает.

§2Ближайший меньший

Чтобы искать ближайший меньший элемент, меняется только условие снятия: снимаем вершину, если она больше текущего значения. Это полезный признак: общий каркас остаётся тем же, меняется смысл «кандидат получил ответ».

ЗадачаСнимаем, покаВ стек идут значения
Следующий большийtop < currentне возрастают
Следующий меньшийtop > currentне убывают
Не меньше или не большеусловие включает =зависит от контракта

При поиске меньшего значения стек становится неубывающим. Текущий меньший элемент снимает большие значения на вершине. Проверим это на [4, 2, 3, 1].

ЭлементСнимаемые значенияСтек после добавления
4—[4]
24 → ответ 2[2]
3—[2, 3]
13 → 1, затем 2 → 1[1]

Результат [2, 1, 1, -1]. У числа 1 справа нет меньшего. Теперь проверим равенства в обоих шаблонах.

§3Выбор условия снятия

Частая ошибка — заменить знак «на глаз». Сначала скажите, какой ответ требуется: строго больше, больше или равно, строго меньше. Затем проверьте равные значения отдельным тестом.

Проверьте себя

Для [73, 74, 74] через сколько дней наступит потепление для первого дня?

  • Первый 74 уже больше 73 и стоит через один день.
  • День с первым 74 уже подходит. Дальнейший поиск увеличил бы ожидание ошибочно.
  • Ответ 0 означает, что более тёплого дня нет.
Контрпример замене < на <=

Для температур [30, 30] правильный ответ [0, 0]. Если снимать по <=, первый день получит 1, хотя потепления не произошло.

Оба алгоритма выполняют O(n) стековых действий и используют O(n) памяти. Кроме ответа-значения и ответа-расстояния, момент снятия даёт границы прямоугольника.
