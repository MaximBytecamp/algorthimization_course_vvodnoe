§1Список Python

В списке работ записаны номера трёх задач: 42, 17 и 30. Задачи расположены в порядке выполнения. В Python такую последовательность можно сохранить в list и получить третий номер по индексу 2.

Индекс — позиция элемента, отсчитанная от нуля. У первого номера индекс 0, у третьего — 2. Чтобы обратиться к нужной позиции, список использует массив ссылок на объекты. Ссылка связывает ячейку с объектом, который в ней представлен.

В CPython, распространённой реализации Python, ячейки этого массива размещены подряд. По индексу вычисляется положение нужной ссылки. Это похоже на ряд пронумерованных почтовых ящиков: номер позволяет сразу выбрать ящик. На схеме показан массив из трёх ссылок; сами числа хранятся в отдельных объектах.

Список tasks: три ячейки со ссылкамиtasks[2] → 30
0→ 42
1→ 17
2→ 30индекс 2

Выделена ячейка с индексом 2. Первые две ссылки при обращении tasks[2] не перебираются. Поэтому доступ по известному индексу занимает O(1): число действий не растёт вместе с длиной списка. Слово «динамический» в названии массива означает, что его размер может меняться. При нехватке места CPython выделяет более крупный массив и переносит туда ссылки.

Те же три номера можно соединить ссылками между отдельными узлами. У такого хранения другой путь к третьему элементу.

§2Узел связного списка

В связном списке элементы образуют цепочку. Каждый элемент, или узел, хранит значение и ссылку на следующий узел. Это похоже на карточки с указателями: текст находится на самой карточке, а указатель ведёт к следующей.

Для узла определим класс Node. Поле value хранит номер задачи, поле next — ссылку на следующий узел. У последнего узла поле next равно None: следующего узла нет.

Вызов Node(30) создаёт узел. Метод __init__ заполняет его поля, а self обозначает создаваемый объект. Значение 30 передаётся параметру value. Параметр next_node не указан, поэтому используется значение по умолчанию None. Выражение third.next is None проверяет отсутствие следующего узла.

На схеме ниже — поля созданного объекта third. В отличие от ячейки массива, узел содержит отдельное поле для перехода.

Поля узла thirdNode(30)
value30
nextNone

Число 30 — значение задачи, а None отмечает конец цепочки. Чтобы получить список из трёх задач, нужно создать ещё два узла и связать их через next.

§3Построение цепочки

Карточки можно соединять с конца: сначала подготовить последнюю, затем указать её на предыдущей. В коде уже создан узел third. Создадим перед ним узел со значением 17, а перед тем — узел со значением 42.

При вызове Node(17, third) поле next получает ссылку на объект third. Вызов Node(42, second) связывает первый узел со вторым. Имя head хранит ссылку на первый узел — голову списка. Через неё доступна вся цепочка.

На схеме стрелка означает переход по полю next. Указатель head расположен у первого узла; крайний None — значение поля third.next.

Цепочка от head до последнего узлатри задачи
head42next → 17
second17next → 30
third30next → None

Подпись next → 17 сокращает фразу «ссылка на узел со значением 17». В поле находится ссылка на объект, а число хранится в его value. Узлы могут располагаться в разных местах памяти: цепочка сохраняется за счёт этих ссылок.

Пустой связный список записывают как head = None. В таком списке отсутствует первый узел. У непустого списка есть голова, от которой начинается обход.

§4Обход цепочки

Чтобы прочитать карточки по порядку, начинают с первой и следуют указателям. В программе для этого нужна переменная current: она хранит ссылку на текущий узел. Сначала ей присваивается head, затем на каждом шаге — current.next.

Условие current is not None проверяет наличие узла. В теле цикла печатается его значение, затем выполняется переход. После узла 30 переменная current получает None, и цикл заканчивается. Порядок чтения показан в таблице.

Шагcurrent.valueВыводКуда ведёт current.next
14242к узлу 17
21717к узлу 30
33030None, конец обхода

В каждой строке читается один узел. За полный обход цепочки из n узлов выполняется n шагов, поэтому его стоимость — O(n). Поля узлов при этом сохраняются. Меняется переменная current, а head остаётся ссылкой на узел 42. Обход можно повторить, снова присвоив current = head.

Обход читает все значения по порядку. Теперь сравним его с доступом к одной заданной позиции.

§5Доступ к элементу и стоимость операций

В пронумерованном ряду можно сразу выбрать третье место. В цепочке карточек до третьей ведут два указателя: с первой на вторую и со второй на третью. В программе эти два пути записываются как tasks[2] и head.next.next.value.

В списке нужная ячейка выбирается на первом шаге. В цепочке сначала читается голова, затем выполняются два перехода по next. Для индекса i потребуется i таких переходов. В худшем случае приходится дойти до последнего узла, поэтому доступ по позиции занимает O(n).

Изменение ссылок и поиск позиции — отдельные операции. Вставка после уже известного узла требует постоянного числа изменений и стоит O(1). Если сначала нужно найти этот узел по позиции, стоимость поиска добавляется: в худшем случае получится O(n). Выбор структуры зависит от того, какая операция выполняется чаще.

Проверьте себяКак получить значение третьего узла, если известна только ссылка head?

  • Класс Node не определяет доступ по индексу. Запись с квадратными скобками здесь вызовет TypeError.

  • Первый переход ведёт к узлу 17, второй — к узлу 30. Поле value содержит значение 30.

  • Это значение второго узла — 17. Чтобы добраться до третьего, нужен ещё один переход.

Проверьте себяПосле обхода current равно None. Что произойдёт при чтении head.value?

  • Цикл менял переменную current. Поля узлов и ссылка head при обходе сохранились.

  • На последний узел указывала переменная current перед завершением обхода. Ссылка head всё время вела к первому узлу.

  • Присваивание current = current.next меняет только current. Ссылка head остаётся прежней.
