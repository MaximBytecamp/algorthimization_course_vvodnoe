§1Две записи одной очереди

Зачем этот шаг: отделить порядок задач от способа их хранения.

В списке дел записаны три задачи: «исправить ошибку», «ответить клиенту», «проверить отчёт». Порядок важен: сначала берут первую задачу, затем вторую. Сохранить этот порядок можно двумя способами.

Первый способ — список Python. Он похож на ряд пронумерованных ячеек. Второй — цепочка карточек. На каждой карточке есть текст задачи и отметка, где лежит следующая карточка. Первая карточка доступна через имя head — голову цепочки.

Список tasks

0A1B2C

Ячейка уже имеет номер. tasks[2] сразу означает третью ячейку.

Цепочка узлов

head→A→B→C→None

Узлы не получают общий индекс. Следующий узел известен только из поля .next текущего.

Буквы на схеме — короткие подписи задач. В обеих структурах третьей будет задача C. Путь к ней разный: список использует индекс 2, а цепочка последовательно читает две ссылки .next.

По-простому: карточки с подсказкой

Карточки лежат в разных местах. На каждой есть подсказка, где искать следующую. Чтобы взять третью, сначала читают подсказку первой, затем второй.

Первая карточка→Подсказка ко второй→Подсказка к третьей

Что есть что: карточка — узел; текст — value; подсказка — next; ссылка на первую — head; «дальше нет» — None.

Теперь разберём, как номер ячейки позволяет получить элемент списка Python.

§2Список Python и индекс

Зачем этот шаг: понять, почему доступ по индексу не требует обхода списка.

В ряду пронумерованных шкафчиков можно сразу подойти к месту с нужным номером. Похожим образом устроен доступ к ячейке списка. CPython — распространённая реализация Python, на которой запускаются примеры книги.

В реализации CPython список — динамический массив ссылок на объекты. Его ячейки идут подряд, а номер ячейки позволяет вычислить, где находится нужная ссылка. Поэтому получить элемент по известному индексу — операция O(1): число действий не растёт вместе с длиной списка.

Индекс считают с нуля, поэтому у третьего элемента индекс 2. Это не адрес объекта в памяти и не значение id(). Индекс — позиция в данном списке. id(obj) — целое идентификационное значение объекта в текущем запуске Python; его не используют для обхода списка.

Слово «динамический» означает, что размер списка может меняться. При нехватке места CPython выделяет более крупный массив и переносит в него ссылки. Это объясняет название «динамический массив».

На схеме ячейки содержат ссылки. Тексты задач находятся в отдельных объектах.

Выделена ячейка с индексом 2. При таком обращении первые две ссылки не перебираются. У цепочки узлов устройство другое: переход хранится внутри каждого узла.

§3Узел, head и None

Зачем этот шаг: определить, из каких объектов состоит цепочка.

У карточки задачи два поля: текст и указатель на следующую карточку. Такой элемент цепочки называют узлом.

В связном списке каждый узел хранит два поля: value со значением и next со ссылкой на следующий узел. Последнему переходить некуда, поэтому его next равно None. Пустая цепочка тоже записывается как head = None: первого узла нет.

Здесь next_node — параметр конструктора, а .next — поле узла. В поле хранится ссылка на другой объект Node либо значение None. Ссылка не обязана быть числовым адресом, и для работы с цепочкой не нужно узнавать её через id().

Стоимость вставки

Вставить новый узел после известного узла можно за O(1): достаточно изменить несколько ссылок. Но чтобы вставить после i-го узла, сначала надо дойти до него от head. Этот поиск стоит O(n). Полная стоимость включает поиск позиции и изменение ссылок.

Ниже показаны поля последнего узла и отдельно — пустая цепочка.

У последнего узла значение есть, но ссылка next равна None. В пустой цепочке первого узла вообще нет. Теперь соединим три узла в одну последовательность.

§4Построение и обход цепочки

Зачем этот шаг: собрать цепочку и прочитать все её значения.

Карточки можно связывать с конца: сначала положить последнюю, затем подписать указатель к ней на предыдущей. Так же построим цепочку в коде. У последнего узла поле next равно None. Предыдущему передают ссылку на последний; затем создают голову. Чтобы прочитать цепочку, берут переменную current и на каждом шаге переходят к current.next.

Проверка is not None останавливает цикл до попытки прочитать поле у None. Переменная current меняется, а head остаётся ссылкой на первый узел. Цепочку можно обойти ещё раз, снова начав с head.

Оранжевым выделен текущий элемент, светлым — пройденные узлы цепочки. При первом шаге в списке выделяется C, а в цепочке — A. Затем обход цепочки выполняет два перехода по next. Для индекса i число переходов равно i; в худшем случае доступ занимает O(n), где n — длина цепочки.

Углубление: что хранит next

В Python переменная и поле объекта связываются с объектами. Когда second передают как next_node, поле head.next ссылается на тот же объект, что и имя second. Это не индекс 1 и не обещание, что объект лежит рядом в памяти. Цепочка держится на ссылках между объектами.

Получается два отдельных действия: найти узел и изменить его ссылки. Их стоимость нужно оценивать отдельно.

§5Что запомнить

  1. list в CPython — динамический массив ссылок; доступ по известному индексу занимает O(1).
  2. Связный список состоит из узлов value и next. head хранит первый узел, конец и пустая цепочка обозначаются None.
  3. Чтобы найти i-й узел, идут от head по .next; это O(n).
  4. Вставка после известного предшественника занимает O(1), но поиск предшественника может занять O(n).
