В этой главе сравниваются доступ по индексу, изменение ссылки и работа с концами. Примеры показывают выбор между list, цепочкой Node, deque, dict и set по нужной операции.

§1Сначала назвать операцию

Вопрос «какая структура быстрее?» поставлен неполно. Быстрой бывает конкретная операция. Сначала нужно сказать, что программа делает чаще: получает элемент по номеру, добавляет в конец, снимает с начала, идёт по ссылке или ищет запись по ключу.

СтруктураКогда подходитОсновные операцииЧто не является её сильной стороной
listНужен порядок и доступ по индексуitems[i] — O(1); append — амортизированно O(1); pop() — амортизированно O(1)Удаление или вставка в начале и середине сдвигает элементы: O(n)
Цепочка NodeНужны переходы по ссылкам и изменение после уже известного узлаизменить известную ссылку next — O(1)Добраться до позиции i нужно переходами от головы: O(n)
dequeЭлементы регулярно входят и выходят с концовappend, appendleft, pop, popleft — O(1)Доступ к середине по индексу не его основная задача
setНужно много раз отвечать «есть ли такой ключ?»x in seen, добавить, удалить — в среднем O(1)Нет доступа по позиции и нет связанного значения
dictПо ключу нужно найти связанное значениеdata[key], добавить, удалить ключ — в среднем O(1)Поиск значения без ключа требует перебора

Оценка O(1) не означает «мгновенно» и не говорит о точном числе наносекунд. Она означает, что число основных действий не растёт с числом элементов. При линейном обходе или сдвиге число действий растёт пропорционально длине последовательности: такую стоимость обозначают O(n).

У списка запрос tasks[1] сообщает позицию, поэтому ответ получается сразу. У множества запрос — ключ 17. У словаря по ключу 17 найдено связанное с ним состояние. Это разные задачи, хотя все примеры содержат одно и то же число.

§2Поиск и изменение ссылки — разные части работы

В связной цепочке изменение ссылки может быть простым, но сначала нужный узел часто нужно найти. Рассмотрим цепочку 42 → 17 → 30. Если уже известен узел 42, можно исключить из цепочки следующий узел 17 одной заменой поля next у предшественника 42.

После замены previous.next первый переход ведёт сразу к 30. У узла 30 поле next равно None, что подтверждает последняя часть результата. Узел 17 стал недоступен через head.

Изменение известной ссылкиузел 17 исключается из цепочки
Красная стрелка — новое значение поля next. Узел 17 стал недоступен через head; поиск самого previous в длинной цепочке был бы отдельной операцией O(n).

Если ссылка на предшественника неизвестна, программа начинает от head и проходит узлы. Этот поиск в худшем случае занимает O(n). Только после него идёт быстрая замена ссылки. Нельзя называть всю операцию O(1), если поиск входит в её условие.

§3Память и расположение данных

Помимо числа действий структуры используют память по-разному. Для всех пяти структур общий рост с числом хранимых элементов обычно описывают как O(n). Постоянные расходы различаются. Список хранит массив ссылок. Каждый узел содержит значение и ссылку next. Дек организован для работы с концами. Словарь и множество содержат служебные ячейки хеш-таблицы.

Не стоит выводить точное число байт из этой таблицы. Оно зависит от версии Python, реализации интерпретатора, разрядности, размера объектов и текущего запаса свободных ячеек. Число байт сравнивают на одинаковых данных в конкретной среде; одна оценка O(n) этого сравнения не заменяет.

ОсобенностьЧто она даётЧто учитывать
В CPython list хранит ссылки рядомПо индексу можно сразу выбрать ячейку; последовательный проход часто удобен для процессораВставка в середину требует сдвига ссылок
Узлы — отдельные объектыИзвестную ссылку можно изменить без сдвига всей последовательностиУ каждого узла есть собственные поля; при обходе переходят по ссылкам
deque рассчитан на концыДобавление и снятие слева и справа не требуют сдвига всей очередиОн не заменяет список, когда главное — произвольный индекс
dict и set — хеш-таблицыКлюч обычно находится быстроТаблица хранит служебное место для поиска; порядок не выбирают по индексу

Фраза «рядом» относится к внутреннему массиву ссылок списка, а не обязательно к самим объектам-значениям. Фраза «часто удобен для процессора» не является обещанием времени выполнения конкретной программы. Когда стоимость важна на практике, измеряют именно свой код и свою среду после выбора правильной модели.

§4Три выбора структуры

Рассмотрим три задачи. В каждом случае сначала названа повторяющаяся операция, затем выбрана структура. Это надёжнее, чем выбирать контейнер по привычке.

Выбор 1: номер задания известендоступ по позиции

В журнале есть задания [42, 17, 30]. Программа много раз получает задание с номером позиции i, например tasks[2]. Подходит list: известный индекс даёт доступ O(1). Цепочка Node здесь заставляла бы каждый раз идти от 42 через ссылки.

Не путайте позицию с ключом. Если 42 — уникальный идентификатор, а не индекс, для поиска по нему нужен dict или set.
Выбор 2: известен сосед в цепочкеизменение ссылки

Редактор уже держит ссылку на узел перед местом изменения. Нужно убрать следующий узел 17 из фрагмента 42 → 17 → 30. Подходит цепочка Node: заменить одно поле next можно за O(1). Если редактору приходится сначала искать узел 42 от головы, стоимость поиска нужно прибавить.

Здесь решает не слово «вставка», а условие «предшественник уже известен».
Выбор 3: заявки и их номераочередь плюс поиск по ключу

Заявки обслуживаются в порядке прихода, поэтому ожидающие номера лежат в deque: новая заявка добавляется через append, следующая снимается через popleft. Одновременно программа должна быстро проверять, встречался ли номер 42, и хранить его статус. Для проверки подходит set, для статуса — dict.

Одна программа может использовать несколько структур. deque отвечает за порядок очереди, set и dict — за поиск по ключу.

Итак, краткий путь выбора такой: назовите нужную операцию, проверьте её оценку, затем учтите порядок элементов и дополнительную память. Для связного списка нужно отдельно описать путь поиска и изменение полей. Это даёт основу для проверки операций на узлах.

Три разобранных условия сведены в таблицу: в каждом выбор определяется доступной информацией и нужным действием.

ИзвестноНужноВыбор
Индекс 2прочитать 30list: tasks[2]

Порядок прихода и номера заявокснять первую, проверить номер, получить статусdeque + set/dict

Совпадение чисел не делает операции одинаковыми. Индекс выбирает позицию, ссылка задаёт объект, ключ используется для поиска записи.

Проверьте себяНужно много раз получить элемент по известному индексу i. Что выбрать?

  • Верно. Доступ items[i] у списка занимает O(1).

  • До позиции i в односвязной цепочке нужно дойти переходами next, это O(n).

  • У множества нет позиции i. Оно отвечает на вопрос, есть ли ключ.

Проверьте себяВ цепочке удаление после известного узла стоит O(1). Почему удаление «элемента с номером 30» может стоить O(n)?

  • Заменить ссылку можно. Быстрая часть операции как раз состоит в этой замене.

  • Верно. Изменение известной ссылки O(1), но поиск нужного места от головы в худшем случае O(n).

  • Сдвиг характерен для массива списка. В цепочке меняют ссылки между отдельными узлами.
