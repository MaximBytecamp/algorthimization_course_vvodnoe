§1Два имени и один узел

Ссылка — это значение, которое позволяет обратиться к объекту. Имя переменной тоже хранит ссылку. Присваивание b = a не создаёт второй узел: оба имени ведут к одному объекту.

Оператор is проверяет идентичность: один ли это объект. Ответ True показывает, что a и b — две ссылки на один узел. Поэтому запись в поле через b видна и через a.

На схеме две пунктирные стрелки принадлежат именам. Они оканчиваются у одной рамки. Сплошная стрелка из поля next ведёт к None, потому что следующего узла нет.

Два имени, один объектb = a
Имена находятся вне узла. Поля value и next принадлежат самому объекту.

При работе со списком учитывают идентичность узлов. Если две ссылки ведут к одному узлу, изменение его next меняет путь для всех, кто приходит к этому узлу. Нового числа и нового хвоста при таком присваивании не появляется.

Имя похоже на ярлык на карточке: смена ярлыка оставляет карточку прежней. Замена указателя на самой карточке меняет путь к соседу. В Python различие определяется левой частью присваивания.

ЗаписьЧто меняетсяЧто сохраняется
current = head.nextссылка в переменной currentполя всех узлов
head.next = middleполе next у узла headссылка в переменной head

Поэтому при разборе строки сначала находят место записи слева от =. Затем вычисляют правую часть и записывают полученную ссылку.

§2Как поле next меняет цепочку

Поле next хранит ссылку на следующий узел. Его можно заменить. Сначала построим короткую цепочку из 42 и 30, затем подготовим отдельный узел 17.

У head поле next уже ведёт к tail. У middle пока нет продолжения. На первом рисунке стрелка из head.next ещё обходит узел 17.

До изменения next42 → 30
Узел 17 существует, но из head до него ещё нет пути.

Одно присваивание head.next = middle направило бы голову к 17, но прежняя ссылка на 30 была бы потеряна из цепочки. Поэтому вставка выполняется в другом порядке: сначала запоминают хвост в поле нового узла.

§3Вставка с сохранением хвоста

Пусть предшествующий узел уже известен: это head. Для вставки после него нужны две строки. Первая сохраняет старое продолжение, вторая заменяет ссылку предшественника.

В первой строке middle.next получает прежнюю ссылку head.next, то есть ссылку на объект tail. Голова ещё ведёт прямо к 30. Эта строка сохраняет хвост.

Строка 1: сохранить старую связьmiddle.next = head.next
Выделено изменённое поле middle.next. Теперь две стрелки приходят к одному хвосту 30.

Во второй строке меняется только поле head.next. Оно начинает вести к уже подготовленному узлу 17. Его поле next сразу продолжает путь к прежнему хвосту.

Строка 2: включить новый узелhead.next = middle
Хвост 30 остался тем же объектом: это подтверждает проверка head.next.next is tail.

После известного предшественника вставка меняет два поля и занимает O(1). Если известна только позиция, сначала нужно дойти до предшественника от головы; этот поиск может занять O(n).

Что произойдёт, если переставить строки вставки

Для отдельного опыта создадим узлы с именами bad_head, bad_middle и bad_tail. Исходная цепочка этой главы от head сохранится.

После первой записи bad_head.next уже ведёт к новому узлу 17. Поэтому вторая запись связывает узел 17 с ним самим. Таблица показывает место ошибки.

МоментПуть от bad_headГде узел 30
до вставки42 → 30 → Noneдоступен от головы и через bad_tail
после первой записи42 → 17 → Noneдоступен только через bad_tail
после второй записи42 → 17 → 17 → …доступен только через bad_tail

Правильная последовательность сначала сохраняет ссылку на 30 в новом узле. В ошибочном варианте обход застрянет у 17: каждый переход вернёт тот же узел. Такой список нельзя передавать показанному циклу обхода.

§4Исключение узла и головы

Чтобы исключить внутренний узел, предшественник должен начать ссылаться на его продолжение. Сначала сохраним исключаемый объект в переменной removed, затем изменим одно поле next.

После второй строки путь из head идёт прямо к 30. Третья строка не обязательна для самой цепочки, но отсоединяет сохранённый узел 17: его next становится None.

Исключённый узел больше не стоит на путиhead.next = removed.next
Переменная removed удерживает ссылку на объект 17. В этом примере тот же объект также доступен через middle. Исключение из цепочки сохраняет объект, пока к нему есть другие ссылки.

У головы нет предшественника. Чтобы исключить первый узел, достаточно передвинуть саму ссылку head на следующий объект.

В присваивании справа сначала читается прежнее поле head.next, затем имя head получает эту ссылку. Отдельная переменная old_head нужна только потому, что мы хотим показать отсоединённый узел.

При удалении сначала менялся путь из узла 42, затем — сама голова. Обе операции нужно проверить и на списках, где соседнего узла нет.

§5Пустая цепочка и один узел

У пустого списка нет первого объекта: head равно None. У списка из одного узла голова указывает на этот узел, а его next равно None. Эти границы проверяют до доступа к полям.

Последнее присваивание исключает единственный узел из списка: голова становится None. Читать empty.next нельзя, потому что объект None не имеет поля next.

Схема показывает состояние single до строки single = single.next. После этой строки обе переменные, empty и single, равны None.

Две границы спискаempty и single
Пустоту проверяют условием head is None. Для одного узла эта проверка ложна, но head.next is None истинно.

Операция над известной головой или известным предшественником меняет постоянное число ссылок. Главное правило остаётся тем же: прежде чем заменить единственный путь к хвосту, сохраните этот путь в новом поле или в переменной.

Проверьте себяПосле b = a выполнено b.next = tail. Куда ведёт a.next?

  • Имена a и b указывают на один объект. У него одно поле next.

  • Присваивание меняет поле общего узла. Поэтому результат виден через обе ссылки.

  • Присваивание ссылки не копирует объект tail.

Проверьте себяПочему при вставке сначала выполняют middle.next = head.next?

  • После замены head.next старая ссылка была бы недоступна через голову. Новый узел должен получить её заранее.

  • Копии не создаются: поле получает ссылку на существующий объект.

  • Голова остаётся ссылкой на узел 42. Меняется только его поле next.
