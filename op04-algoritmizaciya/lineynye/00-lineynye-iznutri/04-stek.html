Стек:
последний входит — первый выходит

В этой главе разобран стек и правило LIFO. На списке Python показаны добавление, чтение и снятие верхнего элемента, а также проверка пустоты.

В этой главе

  2. Стек в списке Python
  3. Пустой стек и узлы
  4. Стоимость операций

§1Правило LIFO

В стопку тетрадей сначала положили тетрадь 42, затем 17, затем 30. Сверху лежит 30. Чтобы добраться до 17, сначала снимают 30. Новую тетрадь также кладут сверху.

Такой порядок обработки называют стеком. У стека один рабочий конец — верх, или вершина. Добавление и снятие выполняются только с этого конца. Правило называется LIFO: last in, first out, «последним вошёл — первым вышел».

Стек из трёх номеровверх — единственный рабочий конец
Стрелка показывает направление снятия. У стека нет отдельного доступа к середине: его основная задача — работа с верхом.

В программе стек может хранить не только номера. Важен порядок: следующей обрабатывается последняя добавленная задача. Теперь запишем эту модель средствами Python.

§2Стек в списке Python

Для стека подходит list. Конец списка считают верхом стека. Метод append кладёт элемент на этот конец. Метод pop без аргумента снимает элемент с него и возвращает снятое значение. Выражение stack[-1] возвращает верхний элемент, сохраняя стек.

Ниже те же строки показаны как смена состояния. В каждой строке слева находится стек до команды, справа — после неё. Подпись «верх» всегда стоит у последнего элемента списка.

Четыре строки: до и послеappend и pop
СтрокаДо выполненияДействиеПосле выполнения
stack.append(42)[]42 входит сверху[42], верх: 42
stack.append(17)[42], верх: 4217 входит сверху[42, 17], верх: 17
stack.append(30)[42, 17], верх: 1730 входит сверху[42, 17, 30], верх: 30
stack.pop()[42, 17, 30], верх: 3030 выходит сверху[42, 17], верх: 17
Значение, которое вернул pop(), — 30. После снятия новым верхом стал 17.

Индекс -1 означает последний элемент. Поэтому stack[-1] вернул 30, но список остался прежним. После pop() элемента 30 в списке уже нет.

В REPL число 30 появилось дважды по разным причинам. Различие между чтением и снятием видно по состоянию списка.

ВыражениеРезультатСтек после действия
stack[-1]30[42, 17, 30]
stack.pop()30[42, 17]

REPL печатает результат выражения автоматически. В программе снятое значение сохраняют присваиванием item = stack.pop(). Если результат нигде не сохранить, элемент всё равно будет снят. У пустого стека снимать нечего: перед этой операцией нужна проверка.

§3Пустой стек и связь с узлами

Пустой стек записывается как []. У него нет верха. Перед снятием можно проверить стек условием if stack:: пустой список в таком условии даёт False.

Вызов pop() на пустом списке вызывает IndexError. Та же проблема будет у empty[-1]. В программе обычно выбирают одно правило: сначала проверять if stack: или сознательно обрабатывать исключение.

Стек можно построить и из узлов связного списка. Переменная top тогда указывает на верхний узел. Положить значение — создать новый узел, который ссылается на прежний верх. Снять — передвинуть top на следующий узел. Это та же модель LIFO, только вместо конца списка используются ссылки next.

Стек как цепочка узловtop указывает на верх
Для этой главы достаточно списка. Узлы показывают, что стек — правило порядка, а не единственный вид хранения.

§4Почему операции на вершине быстры

У списка конец доступен сразу. Поэтому stack[-1] выполняется за O(1). У append и pop() амортизированная оценка — O(1): для серии операций на конце стоимость постоянна в среднем на одну операцию. Обычно append добавляет в свободную ячейку на конце.

Иногда свободных ячеек нет. Тогда Python выделяет для списка более крупный массив и переносит ссылки. Одно такое добавление занимает O(n). Но расширение не происходит при каждом append: после него есть запас мест для следующих элементов. Поэтому серия добавлений имеет амортизированную стоимость O(1) на одно добавление.

Операция стека на listЧто делаетОценка
stack.append(x)кладёт x на верхамортизированно O(1)
stack.pop()снимает и возвращает верхамортизированно O(1)
stack[-1]читает верх, не снимая егоO(1)
stack.pop(0)снимает нижний элемент и сдвигает остальныеO(n), не операция стека

Амортизированная оценка не означает, что каждый отдельный append одинаково короткий. Она говорит о серии операций: редкое расширение распределяет свою стоимость на множество обычных добавлений. При удалении Python также может уменьшить внутренний массив списка. Поэтому для pop() здесь указана амортизированная оценка. Стек использует один конец, а очередь разделяет концы добавления и снятия.

Проверьте себяЧто будет напечатано?

  • Первым добавленный элемент лежит на дне. Стек снимает верхний, последний добавленный элемент.

  • Верно. После трёх append верхом стал 30, поэтому pop() вернёт 30.

  • Средний элемент не является рабочим концом стека. Сначала нужно снять 30.

Проверьте себяКак безопасно снять верхний элемент, если стек может быть пустым?

  • Верно. Непустой список истинный в условии, поэтому pop() не будет вызван на пустом стеке.

  • Эта запись не снимает элемент. На пустом списке она также вызовет IndexError.

  • На пустом списке будет та же ошибка. Кроме того, это снятие с начала, а не с верха стека.
