25.2

Обработчик очереди задач

Соберём обработчик команд add, run и close. Очередь хранит ожидающие задачи, а отдельный список — уже выполненные. Разберём порядок и закрытие без потери остатка.

В этой главе
  1. Договоримся о командах
  2. Состояние до и после команды
  3. Реализация и проверка
  4. Стоимость и другой контракт

§1Договоримся о командах

Пусть загрузчик документов получает команды. ("add", "имя") ставит задачу в очередь. ("run",) выполняет одну ожидающую задачу. Работа задачи здесь представлена её именем в списке выполненных.

Команда ("close",) прекращает приём и выполняет весь остаток в порядке FIFO. После неё любые команды ошибочны. Если поток закончился, остаток не выполняется автоматически: функция возвращает его отдельно.

СитуацияРезультатПричина
run при пустой очередиБез измененияВыполнять нечего
add с повторным именемДобавить ещё одну задачуИмена не обязаны быть уникальными
add с пустой строкойДобавить задачу с именем ""Пустое имя разрешено контрактом
Неизвестная команда или неверная формаValueErrorВход вне протокола
Команда после closeValueErrorПриём закрыт

Вход — конечный итерируемый объект с кортежами команд. Итерируемый объект выдаёт элементы по одному; это может быть список или генератор. Функция возвращает пару списков (completed, pending). Исходный список команд остаётся прежним.

С таким контрактом можно проверить содержимое очереди после каждой команды.

§2Состояние до и после команды

Проследим поток: добавить A, добавить B, выполнить, добавить C, закрыть. Начало очереди показано первым. Схема отдельно показывает ожидающие и выполненные задачи.

После run задача A исчезает из ожидающих и появляется в выполненных. Close снимает сначала B, затем C. Смена команды не переставляет оставшиеся задачи.

После командыОжидаютВыполнены
add AA—
add BA, B—
runBA
add CB, CA
close—A, B, C

Инвариант: pending содержит все добавленные, но ещё не выполненные задачи в порядке прихода. Completed содержит уже выполненные в порядке обработки. Каждая корректная команда сохраняет эти свойства.

Проверим сохранение этого порядка в реализации.

§3Реализация и проверка

Deque отвечает за быстрые операции с обоих концов. Флаг closed отделяет завершённый протокол от очереди, которая временно пуста. Это разные состояния: пустая открытая очередь ещё принимает задачи.

Пошаговый прогон полного кода

Слева показан весь код с подсветкой текущей строки. Справа — входные данные и переменные перед её выполнением. Кнопка «шаг →» выполняет строку: её результат виден на следующем шаге. Кнопка «← шаг» возвращает предыдущий кадр, а «⏮» — начало прогона.

Проследите, как popleft переносит первую задачу в completed. На close флаг closed становится True до снятия остатка. Возвращаются два списка: выполненные задачи и ожидающие.

Самопроверка: порядок строк

Соберите центральную часть обработчика: выполнение одной задачи и закрытие. Pending, completed и closed уже созданы; показанный фрагмент выполняется внутри цикла по командам.

Стрелки ↑ и ↓ меняют порядок строк с сохранением отступов. После сборки нажмите «Проверить порядок». Кнопка «Показать ответ» возвращает исходный порядок.

Сначала проверяется закрытие, затем форма кортежа. Поэтому неверная команда не успевает изменить очередь. У run снятие выполняется только после проверки if pending. В close цикл снимает весь остаток.

Прогон на живых данных: выполним функцию для того же потока. Левая часть результата — выполненные задачи, правая — ожидающие.

По-простому

Это журнал обработки заявок: запись в ожидании — ещё не выполненная работа. Забрать первую запись означает выполнить самую раннюю заявку. Закрытие — закончить очередь и больше не принимать команды.

ШагЧто происходит
Приёмappend ставит имя после уже ожидающих
Выполнениеpopleft снимает самое раннее имя
Закрытиеwhile pending завершает остаток; closed блокирует новые команды

Что есть что: очередь ожидания — pending, журнал выполнения — completed, состояние приёма — closed. Исключение означает ошибку всего вызова; частичный результат функция не возвращает.

Корректность порядка проверена на примерах. Остаётся посчитать число операций и объём памяти.

§4Стоимость и другой контракт

Пусть m — число команд, a — число add. Каждая задача добавляется один раз и снимается не более одного раза. Цикл close выполнит не больше a снятий. Время — O(m), если сравнение команд и операции со ссылками на имена считаются постоянными.

РешениеОдна операция снятияВесь поток
list.pop(0)O(q): сдвиг q − 1 ссылокДо O(m²)
deque.popleft()O(1)O(m)

Pending занимает O(q), где q — наибольшая длина ожидания. Но completed хранит результат: с ним общая память может достигать O(m). Чтение команд по одной ещё не делает весь обработчик константным по памяти.

Если close должен отменять задачи

Нужно изменить контракт и результат: отменённые задачи отделяются от выполненных. Замена цикла на clear теряет информацию о снятых задачах. Для потоковой обработки можно отправлять каждое выполненное имя потребителю, не накапливая completed.
