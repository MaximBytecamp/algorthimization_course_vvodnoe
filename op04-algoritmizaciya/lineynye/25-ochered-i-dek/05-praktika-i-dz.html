§1Маршрут работы на 90 минут

Сначала зафиксируйте вход, результат и границы. Вручную воспроизведите очередь после команд. После собственной попытки реализуйте обработчик; к максимуму окна переходите с готовой трассой кандидатов.

Скачайте стартовый архив lesson_25.zip. В нём заготовки, публичные тесты и описание контрактов; решений нет. Команда python check.py проверяет обработчик и максимум окна. До реализации ожидаются ошибки NotImplementedError.

Песочницы загружают Python через Pyodide по кнопке. Для первой загрузки нужна сеть; локальный архив работает без неё. Браузер сохраняет код локально, но для сдачи нужен отдельный файл.

Начните с функции обработки команд.

§2Базовое ядро: обработчик задач

Реализуйте process_tasks(commands). Add принимает строковое имя, run выполняет самую раннюю задачу, close выполняет остаток и запрещает последующие команды. Пустой run ничего не меняет. Возвращается пара списков: выполненные и ожидающие.

КомандыВыполненыОжидают
add A, add B, run, add CAB, C
add A, closeA—
run——

Повторяющиеся имена и пустая строка допустимы. Ошибочная форма команды даёт ValueError. Для самостоятельного теста выберите минимум две задачи: одна задача не различает FIFO и LIFO.

После проверок FIFO дополните обработку кандидатов окна.

§3Каркас: максимум каждого окна

Дополните max_window(nums, k). Вход — список целых и целая ширина 1 ≤ k ≤ n. Верните список значений максимумов; исходный список не меняйте. На неверной ширине выдайте ValueError.

ВходОтвет
[4, 1, 3, 5, 2, 5], k = 3[4, 5, 5, 5]
[3, -1, 2], k = 1[3, -1, 2]
[3, -1, 2], k = 3[3]
[5, 5, 5], k = 2[5, 5]

Покажите в трассе два повода снятия: устарел индекс и появился не меньший кандидат. Объясните, почему списки значений окна и кандидатов могут иметь разную длину. Базовый результат пары — корректная очередь; дек доводится по каркасу и проверкам.

Когда версия для массива работает, измените способ получения значений.

§4Домашняя работа: вход становится потоком

После рабочей базовой версии измените условие: значения приходят по одному, весь вход хранить нельзя. Реализуйте генератор iter_max_window(values, k). Генератор выдаёт результаты по одному через yield. Список результатов внутри функции не создаётся.

Values — конечный итерируемый объект целых. K — положительное целое; при k < 1 возникает ValueError во время начала перебора. Если поток короче k, полных окон нет: генератор не выдаёт значений. Это отличается от контракта max_window, где длина известна заранее.

МассивПотокЗачем меняется
В деке индекс iВ деке пара (i, value)Старое значение нельзя читать из полного массива
len(nums) известнаДлина заранее неизвестнаСлишком короткий поток даёт пустую выдачу
answer.append(...)yield ...Не накапливаем результат
Сборка и прогон потока · после самостоятельной попытки

Для разбора используем ту же логику удаления кандидатов. Теперь каждая запись содержит пару (индекс, значение), а полный ответ выдаётся через yield.

Пошаговый прогон полного кода

Слева показан весь код с подсветкой текущей строки. Справа — входные данные и переменные перед её выполнением. Кнопка «шаг →» выполняет строку: её результат виден на следующем шаге. Кнопка «← шаг» возвращает предыдущий кадр, а «⏮» — начало прогона.

После yield кадр возобновления показывает тот же набор локальных переменных. Дек хранит пары индекса и значения; уже прочитанные значения вне кандидатов не сохраняются.

Самопроверка: порядок строк

После самостоятельного решения соберите потоковую версию шага. В деке находятся пары, поэтому возраст проверяется через [0], а значение через [1].

Стрелки ↑ и ↓ меняют порядок строк с сохранением отступов. После сборки нажмите «Проверить порядок». Кнопка «Показать ответ» возвращает исходный порядок.

Запустите python check.py --stream. Проверка test_consumption проверяет чтение по мере запроса: для первого ответа при k = 3 должны быть прочитаны ровно три значения. Рабочая память — O(k), если потребитель тоже не накапливает все ответы.

Дополнительно: кольцевой буфер

Дополните RingQueue из архива. Проверьте ёмкость 1, None, заполнение, несколько оборотов и сохранность состояния после ошибки. Команда python check.py --extra добавляет эти проверки. Эта задача не заменяет обязательную очередь.

§5Что сдавать и как оценивать

Сохраните работу в portfolio/lesson_25/: solution.py, tests.py, complexity_note.md и результат запуска. В tests.py добавьте свой граничный сценарий. В complexity_note.md запишите инварианты, стоимость и различия контрактов массива и потока.
