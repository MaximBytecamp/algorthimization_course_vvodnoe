25.3

Кольцевой буфер: очередь в массиве

Кольцевой буфер хранит очередь в массиве фиксированной длины. Вместо сдвига элементов двигается индекс головы. Разберём переход через конец и различие пустого и полного состояния.

В этой главе
  1. Освободившееся место используется снова
  2. Две операции без сдвига
  3. Границы и стоимость

§1Освободившееся место используется снова

У обработчика может быть ограничение: одновременно ожидают не больше трёх задач. Для такой очереди выделим массив из трёх ячеек. Индекс head указывает на первую задачу, size хранит число занятых мест.

После снятия A из [A, B, C] перемещать B и C не нужно. Head станет равным 1. Следующую задачу D можно записать в освободившуюся ячейку 0.

Физический порядок [D, B, C] отличается от логического: очередь выдаст B, C, D. Чтение начинается с head, здесь это ячейка 1.

ПараметрСмыслПример
capacityЧисло ячеек3
headИндекс первого элемента1
sizeЧисло элементов3
tail = (head + size) % capacityМесто следующей записи, если очередь не полнаПри size = 2: (1 + 2) % 3 = 0

Остаток от деления возвращает индекс в диапазон массива. При ёмкости 3 после индекса 2 идёт индекс 0. Размер нужен отдельно: совпадение позиции записи с head возможно и у пустого, и у полного буфера.

Зафиксируем эти правила в двух операциях: push и pop.

§2Две операции без сдвига

Контракт класса RingQueue: capacity — положительное целое. Push принимает любое значение. При заполнении выдаёт OverflowError, не перезаписывая данные. Pop возвращает первую задачу; пустая очередь даёт IndexError.

Соберите метод pop: сначала проверка пустоты, затем сохранение значения, очистка ячейки и изменение индексов. Отступы уже заданы.

Стрелки ↑ и ↓ меняют порядок строк с сохранением отступов. После сборки нажмите «Проверить порядок». Кнопка «Показать ответ» возвращает исходный порядок.

Пошаговый прогон кода

В прогоне виден весь код и подсвечена строка, которая сейчас будет выполнена. Таблица показывает состояние перед этой строкой. Перейдите на следующий шаг, чтобы увидеть её результат. Последний кадр показывает возврат функции.

Для прогона добавлена ring_demo: она создаёт очередь ёмкости 3, добавляет A, B, C, снимает A и добавляет D. В конце снимает B, C, D. Методы класса совпадают с реализацией выше.

Переходы между __init__, push и pop показаны в одном классе. После заполнения head сдвигается, запись D использует ячейку 0. Возврат ring_demo выдаёт B, C, D.

Конструктор один раз выделяет массив. Push сначала проверяет заполнение, затем вычисляет tail и увеличивает size. Pop сначала сохраняет значение, освобождает ссылку, сдвигает head по кругу и уменьшает size.

После снятия в ячейку записывается None: ссылка на снятое значение освобождается. Само значение None тоже допустимо: заполнение определяется только size. Это позволяет не запрещать полезные данные ради внутреннего устройства.

Прогон на живых данных: после снятия A снова используем нулевую ячейку.

По-простому

В ограниченном списке ожидания освободившееся место не пропадает. Когда запись доходит до конца массива, индекс следующей записи возвращается к началу через остаток от деления. Сам массив не вращается.

ШагЧто происходит
После снятияhead сдвигается; оставшиеся элементы не копируются
При добавленииtail вычисляется через head и size
Что есть чтослот — data[i]; первая задача — data[head]; число ожидающих — size

Инвариант: 0 ≤ size ≤ capacity. Логический элемент с номером j хранится по индексу (head + j) % capacity для 0 ≤ j < size.

Сохранение этого свойства проверим на пустом и полном буфере.

§3Границы и стоимость

Для ёмкости 1 оба действия используют ячейку 0. Size отличает наличие элемента от пустоты. На полном буфере проверка должна произойти до записи: иначе потеряется самая ранняя задача.

СлучайОжиданиеЧто проверить
capacity = 0ValueErrorНет деления по модулю нуля
push в полный буферOverflowErrorСтарые данные сохраняются
pop из пустогоIndexErrorhead и size не меняются
Несколько оборотовFIFO сохраняетсяИндекс возвращается в начало
push(None), pop()NoneПустота не определяется по значению

Создание массива стоит O(capacity) времени и памяти. Каждая push и pop работает за O(1). Обход всей очереди стоил бы O(size). Буфер здесь не увеличивается автоматически.

Проверьте себя

В буфере capacity = 4, head = 3, size = 2. Куда запишется следующий элемент?

  • (3 + 2) % 4 = 1. Заняты ячейки 3 и 0; следующая свободная — 1.
  • (3 + 2) % 4 = 1. Заняты ячейки 3 и 0; следующая свободная — 1.
  • (3 + 2) % 4 = 1. Заняты ячейки 3 и 0; следующая свободная — 1.
Почему deque(maxlen=3) — другой контракт

У ограниченного deque добавление в заполненную структуру автоматически вытесняет элемент с противоположного конца. Так сохраняют последние события. Для очереди задач вытеснение означает потерю невыполненной работы. Наш RingQueue вместо вытеснения выдаёт OverflowError.

Кольцевой буфер объясняет, как избежать сдвига в массиве. Для максимума окна требуется ещё одно решение: какие старые элементы можно вообще перестать хранить.
