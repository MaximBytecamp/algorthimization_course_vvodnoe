25.4

Максимум скользящего окна

Найдём максимум каждого отрезка длины k. Вместо пересчёта храним в деке только кандидатов: старые уходят из начала, вытесненные — с конца.

В этой главе
  1. От перебора к кандидатам
  2. Индексы возрастают, значения убывают
  3. Код и прогон
  4. Почему суммарно O(n)

§1От перебора к кандидатам

Мониторинг записал шесть измерений: [4, 1, 3, 5, 2, 5]. Нужно вернуть максимум каждых трёх соседних измерений. Получатся четыре полных окна. До третьего элемента полное окно ещё не собрано.

Индексы окнаЗначенияМаксимум
0…24, 1, 34
1…31, 3, 55
2…43, 5, 25
3…55, 2, 55

Прямой способ: для каждого окна вызвать max. Это O((n − k + 1)k) времени, то есть O(nk) сверху. Но при движении окна не все старые значения способны стать ответом.

Когда приходит 3, прежнее 1 уже не пригодится. Тройка больше и уйдёт из окна позже. Во всех полных окнах, заканчивающихся сейчас или позже и содержащих эту единицу, будет и тройка. Такого кандидата можно удалить навсегда.

СравнениеОставитьПричина
Старое 1, новое 3Новое 3Больше и свежее
Старое 4, новое 3ОбаПосле ухода 4 может понадобиться 3
Старое 5, новое 5Новое 5Максимум тот же, новое уйдёт позже

Одного текущего максимума недостаточно. Когда он выйдет из окна, понадобится следующий кандидат. Монотонный дек сохраняет кандидатов в порядке убывания значений.

Остаётся совместить удаление слабых кандидатов с выходом за левую границу.

§2Индексы возрастают, значения убывают

Храним индексы, чтобы узнать возраст кандидата и получить его значение. Для позиции i окно начинается в i − k + 1. Значит, все индексы ≤ i − k уже устарели.

На шаге i = 3 индекс 0 покидает окно. Затем новое 5 снимает оставшихся слабых кандидатов с конца. На последнем шаге новое 5 заменяет равное старое 5. Ответ остаётся равным 5.

Порядок шагаОперацияСмысл
1popleft, пока первый индекс ≤ i − kУбрать всё за левой границей
2pop, пока последнее значение ≤ новоеУбрать вытесненных кандидатов
3append(i)Новый индекс становится кандидатом
4Записать значение первого, если i ≥ k − 1Выдать ответ для полного окна

Инвариант после добавления: индексы строго возрастают и принадлежат текущему окну. Их значения строго убывают. Первый кандидат даёт максимум полного окна. Слово «строго» здесь связано с выбранным сравнением ≤.

Если снимать только строго меньшие

Сравнение < тоже позволяет получить значения максимумов. Тогда равные кандидаты остаются, а значения в деке не возрастают. Нельзя смешивать две версии инварианта. Если нужны индексы максимумов, сначала уточните, предпочитать ранний или поздний равный.

Теперь обе причины удаления можно записать отдельными циклами.

§3Код и прогон

Контракт: nums — список целых, k — целое. Требуется 1 ≤ k ≤ len(nums), иначе ValueError. Функция возвращает новый список значений и не меняет nums. Пустой список при любой ширине нарушает этот контракт.

Первый while удаляет устаревшие индексы из начала. Второй while сравнивает значения, но снимает индексы с конца. В answer записывается значение nums[candidates[0]].

Прогон на живых данных: выполним пример и отдельно проверим равные и отрицательные значения.

По-простому

Дек — короткий список претендентов на максимум. Первый сейчас сильнее всех. Новый претендент вытесняет с конца тех, кто не сильнее него и старше.

ШагЧто происходит
Сначала возрастУшедшие за границу снимаются из начала
Затем полезностьСлабые старые снимаются с конца
Что есть чтопретендент — индекс; сила — nums[index]; срок — принадлежность окну

Этот разбор похож на монотонный стек из модуля 24, но есть существенное отличие: кандидаты дополнительно устаревают с противоположного конца. Удаление с обоих концов обеспечивает дек.

Два цикла while обрабатывают разное число элементов на шаге. Для стоимости посчитаем снятия по всему проходу.

§4Почему суммарно O(n)

Индекс добавляется ровно один раз. После снятия он не возвращается. Он уходит либо по возрасту из начала, либо из-за более сильного значения с конца. Суммарно снятий не больше n.

ЧастьОценкаОбоснование
Все appendnОдин на позицию
Все снятия обоих видовНе больше nОдин индекс не снимается дважды
ВремяO(n)Линейное число операций
Рабочий декO(k)Не больше ширины окна
Список результатаO(n − k + 1)По одному значению на окно

Внутренние while не означают O(n²): один шаг может снять много индексов, но следующие шаги их уже не увидят. Сравнения целых считаются O(1) при ограниченном размере чисел.

Зачем хранить индекс, а не только значение?

  • Значение не сообщает, осталось ли оно в текущем окне. По индексу проверяем левую границу.
  • Значение не сообщает, осталось ли оно в текущем окне. По индексу проверяем левую границу.

При потоковом входе полный массив недоступен. Тогда рядом с индексом хранится значение. Это сохраняет O(k) рабочей памяти без хранения всех измерений.
