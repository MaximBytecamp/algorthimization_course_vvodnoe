25.1

Как узнать задачу на очередь и дек

Стек возвращал последнее отложенное действие. Теперь порядок меняется: сначала обрабатываем того, кто ожидает дольше. Разберём, когда нужна очередь, а когда — два конца дека.

В этой главе
  1. Порядок обработки элементов
  2. Почему в задачах появляется дек
  3. Контракт до кода

§1Порядок обработки элементов

Сервис получил заявки A, B и C. Один обработчик берёт их по времени поступления. Пока выполняется A, новые заявки встают после C. Это правило FIFO: first in, first out, «первым пришёл — первым вышел».

В главе 0.5 очередь уже была представлена через deque. Здесь используем знакомые операции для решения задач. Сначала сравним, какой элемент выбирает каждая структура.

ТребованиеСледующий элементСтруктура
Заявки в порядке поступленияСамая ранняя ожидающаяОчередь
Отмена последнего измененияПоследнее неотменённоеСтек
Добавить или снять с любого концаПервый либо последнийДек
Самая срочная заявкаС наибольшим приоритетомПриоритетная очередь

Очередь FIFO сохраняет порядок прихода. Приоритетная очередь выдаёт элемент по приоритету. У deque выбор с начала и конца не заменяет поиск по произвольному приоритету.

Проверьте себя

В очередь добавили A, затем B. Сняли одну заявку, добавили C. В каком порядке выйдут оставшиеся?

  • Первой уже вышла A. Из ожидающих B поступила раньше C.
  • Первой уже вышла A. Из ожидающих B поступила раньше C.
  • Первой уже вышла A. Из ожидающих B поступила раньше C.

§2Почему в задачах появляется дек

Дек — двусторонняя очередь. В Python append добавляет в конец, popleft снимает из начала. Операции appendleft и pop используют другие концы. Каждая из этих операций работает за O(1).

Скользящее окно — последние k соседних значений: с каждым новым измерением границы сдвигаются на одну позицию. Кандидат — сохранённый элемент, который ещё может дать максимум. У максимума окна два разных повода удалить кандидата. Старый индекс выходит из начала, а бесполезный кандидат снимается с конца. Поэтому одной обычной очереди недостаточно.

Схема задачиЧто хранитьКогда удалять
Обработка по приходуОжидающие заявкиСамую раннюю при обслуживании
Максимум последних k измеренийИндексы кандидатовСтарые из начала, слабые с конца

Для FIFO храним все ожидающие заявки. Для максимума окна сохраняем кандидатов, которых ещё нельзя исключить. Инвариант — свойство состояния, которое сохраняется после каждого шага.

Выбор структуры задаёт операции. Теперь уточним допустимые данные и ошибки.

§3Контракт до кода

Порядок операций понятен, но граничное поведение нужно договорить отдельно. Например, пустая очередь может давать исключение, а неверная ширина окна — ошибку параметра.

ЗадачаДоговорённостьПроверка
Обработчик задачКоманды ('add', строка), ('run',), ('close',); ошибки — ValueErrorrun при пустой очереди ничего не делает
Максимум окнаСписок целых; 1 ≤ k ≤ n; иначе ValueErrormax_window([], 1) → ValueError
Кольцевой буферПоложительная ёмкость; полное заполнение — OverflowErrorПустое снятие → IndexError

Для окна возвращаем значения максимумов. Равные максимумы допустимы. Обработчик возвращает выполненные и оставшиеся задачи. Во всех задачах сохраняем исходные данные.

Сверить выбор структуры

Чтобы сравнить скорость, сначала сравните операции. list.pop(0) сдвигает оставшиеся ссылки и стоит O(n). У deque.popleft() такого сдвига нет. Но чтение середины дека не становится O(1).

Контракт задаёт ожидаемый результат и поведение на ошибочном входе. Для обработчика нужно также определить, какие команды меняют очередь и как завершается приём.
