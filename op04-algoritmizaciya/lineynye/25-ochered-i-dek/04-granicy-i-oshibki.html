25.5

Границы и ошибки

Проверим места, где легко нарушить порядок: пустая очередь, заполненный буфер, равные максимумы и команда после закрытия.

В этой главе
  1. Матрица границ
  2. Ошибка порядка снятия
  3. Устаревший максимум остаётся
  4. Не смешивать контракты

§1Матрица границ

Сначала запишем ожидаемое поведение. Результат на границе зависит от контракта: пустой run допустим, пустой pop ошибочен, а слишком короткий поток ещё не даёт полного окна.

СлучайОжидаетсяКакую ошибку ловит
process_tasks([])([], [])Лишний обязательный элемент
run на пустом ожидании([], [])Снятие без проверки
add A, close, add BValueErrorПриём после закрытия
RingQueue(1): push A, push BOverflowErrorТихая потеря A
max_window([2, 2, 1], 2)[2, 2]Удаление по значению без возраста
max_window([3], 1)[3]Неверный момент первого ответа
max_window([], 1)ValueErrorНет допустимого окна

Проверяйте состояние после неудачной операции буфера. OverflowError должен оставить прежнее содержимое; IndexError не должен менять head и size. Сам факт исключения ещё не доказывает корректность состояния.

Начнём с ошибки, которая видна уже на двух задачах.

§2Ошибка порядка снятия

В обработчике заменили popleft на pop. На единственной задаче различие не видно. Поэтому минимальный полезный пример содержит две заявки.

СостояниеОшибка: popНужно: popleft
Ожидали A, BВыполнена B; осталась AВыполнена A; осталась B

Исправьте только место снятия, сохранив протокол команд. Затем запустите все проверки: исправление FIFO не должно сломать пустой run и close.

В этой песочнице намеренно ошибочная реализация. Тест с двумя задачами должен её отвергнуть. Затем верните popleft в обоих местах снятия.

Для окна требуется другая проверка: момент устаревания индекса.

§3Устаревший максимум остаётся

Следующая ошибка возникает на левой границе. Удаление по условию index < i − k запаздывает на один шаг: индекс i − k уже не входит в окно.

ШагОкноВерный максимумПри ошибочной границе
i = 1, k = 2[8, 1]88
i = 2, k = 2[1, 2]28

Исправьте сравнение возраста. Повторите проверку на убывающем массиве: там старые большие значения не снимаются с конца и ошибка видна особенно хорошо.

Сравнение ≤ в первом while означает «уже вне окна». Сравнение ≤ во втором означает «не сильнее нового». Одинаковый знак используется по разным причинам.

После исправления границы проверим, какие замены структуры сохраняют контракт.

§4Не смешивать контракты

Частая попытка ограничить память — заменить deque на deque(maxlen=k). Но автоматическое вытеснение ограничивает число кандидатов без проверки возраста. В деке кандидатов может быть намного меньше k элементов.

ИзменениеПочему недостаточноЧто делать
deque(maxlen=k) вместо удаления старыхЧисло кандидатов не равно возрастуПроверять индекс начала
Хранить только значенияРавные значения теряют привязку к позицииХранить индексы или пары
На close очистить pendingЗадачи пропали без выполненияСнять остаток по FIFO
Считать None свободным местомНельзя хранить None как данныеПроверять size

На этапе отладки проверяйте инварианты после каждого шага. Для дека индексы возрастают, значения убывают, первый индекс не старше левой границы. Такая полная проверка занимает O(k) на шаг и не входит в линейную рабочую версию.

Почему тесты не доказывают O(n)

Медленный пересчёт max по каждому окну тоже даст правильные ответы. Для оценки стоимости нужно показать код и посчитать операции. Тесты проверяют результаты, а объяснение инварианта и стоимости — устройство решения.

Теперь перенесём эти проверки в самостоятельную работу. Базовая задача остаётся обработчиком очереди, а для максимума окна предоставлен каркас.
