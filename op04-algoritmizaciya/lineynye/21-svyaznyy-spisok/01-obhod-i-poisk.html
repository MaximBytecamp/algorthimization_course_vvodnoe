21.1

Обход
и поиск

В этой главе разобраны обход и поиск в связном списке. На цепочке 42 → 17 → 30 показано, как переменная current последовательно получает ссылки на узлы.

В этой главе
  1. Контракт узла и головы
  2. Обход цепочки
  3. Поиск значения
  4. Инвариант current

§1Контракт узла и головы

Договоримся о двух именах. Объект Node имеет поля value и next. Переменная head хранит ссылку на первый узел или None, если цепочка пуста. Список в этой главе заканчивается на None: циклические связи здесь не рассматриваются.

Узел third завершает цепочку: его next равно None. Переменная head не является отдельным узлом. Она только указывает на объект со значением 42.

На схеме пунктирные стрелки идут от переменных. Сплошные стрелки начинаются именно в поле next, поэтому показывают реальные связи между объектами.

Цепочка от head42 → 17 → 30

Из head доступен первый узел. Из его next доступен второй. Поэтому одной ссылки на голову достаточно, чтобы пройти всю цепочку.

§2Обход цепочки

Обход читает значения всех узлов по порядку. Переменная current начинает с head. Пока она не равна None, можно прочитать поле value и перейти по next.

Печать не меняет ссылки. Присваивание current = current.next меняет только переменную current. Голова остаётся у первого узла.

Два последовательных шага обходасначала печать, затем переход

После строки перехода current указывает на узел 17. Значение 42 уже выведено. На следующем круге цикла будет напечатано 17.

Для цепочки из n узлов тело цикла выполняется n раз. Значит, полный обход имеет стоимость O(n).

§3Поиск значения

Поиск использует тот же путь, но останавливается раньше, если найдено нужное значение. Функция возвращает сам узел. Если такого значения нет, она возвращает None.

Возвращается объект узла со значением 17. Поэтому проверка found is second даёт True: обе переменные ссылаются на один объект. При отсутствии значения функция доходит до None и возвращает его.

Поиск 17: остановка у найденного узлаreturn current

В лучшем случае искомое значение находится в голове. В худшем случае нужно проверить все узлы. Стоимость поиска — O(n).

§4Инвариант current

Инвариант цикла — утверждение, верное перед каждой проверкой его условия. Здесь current указывает на первый ещё не обработанный узел. Когда таких узлов нет, переменная равна None.

Перед циклом первым необработанным узлом является голова. После печати или проверки значения этот узел становится обработанным. Строка current = current.next переводит переменную к следующему необработанному узлу. Когда последняя ссылка ведёт к None, работа закончена.

Таблица фиксирует состояние перед проверкой while при обходе. После печати указатель ещё остаётся у обработанного узла; переход восстанавливает инвариант к началу следующей итерации.

Перед проверкойУже напечатаноcurrent
1ничегоузел 42
242узел 17
342, 17узел 30
442, 17, 30None

В последней строке необработанных узлов нет, поэтому цикл завершается. При поиске совпадение может завершить функцию раньше. Этот же путь от головы позволяет найти место для изменения ссылок.

Проверьте себяЧто должна вернуть find(head, 17)?

  • Функция возвращает current, то есть объект узла, а не его поле value.

  • Найденный узел можно сравнить с другой ссылкой через is или использовать его поля.

  • Голова указывает на узел 42. Поиск идёт дальше до совпадения.

Проверьте себяЧто меняет строка current = current.next?

  • Слева от знака равенства стоит имя переменной, а не поле объекта.

  • Узлы и ссылка head не меняются. Переменная начинает указывать на следующий узел.

  • Поле value в этой строке вообще не используется.
