§1Основа для проверок

При проверке связного списка сравнивают порядок значений и ссылки на объекты. Для этого в примерах есть функция values: она возвращает значения в порядке обхода. Она не меняет цепочку.

Функция values подходит для проверки порядка значений. При одинаковых значениях нужно дополнительно различать сами объекты. Для этого нужна проверка идентичности через is.

В таблице разобран результат values(head): поле value читается до перехода по next.

currentresult после appendСледующее current
узел 17[17]узел 30
узел 30[17, 30]None

После второго перехода возвращается список [17, 30]. Для пустой цепочки цикл пропускается полностью.

§2Пустая цепочка и один узел

У пустого списка head равна None. У списка из одного узла поле head.next равно None. Обе границы нужно обработать до чтения полей узла.

assert проверяет условие: при истинном условии выполнение продолжается, при ложном возникает AssertionError. Поэтому успешные проверки ниже не печатают вывода. Это проверки примеров при обычном запуске Python; режим -O отключает assert.

Последняя проверка подтверждает завершение поиска отсутствующего значения в одноэлементной цепочке. Успешный поиск возвращает тот же объект only, отсутствующее значение — None.

Две граничные формы спискапроверка до обращения к полям

Условие цикла current is not None делает обход безопасным в обеих ситуациях. Только внутри цикла известно, что у current можно читать value и next.

§3Фиктивная голова

Удаление первого настоящего узла отличается от удаления после предшественника: у головы предшественника нет. Фиктивная голова, или dummy, — служебный узел перед списком. Он не входит в данные. Его поле next указывает на настоящую голову.

Переменная previous хранит предшественника проверяемого узла. Удаление меняет его поле next. Оператор break завершает цикл после первого совпадения; затем выполняется return dummy.next.

Когда удаляется 17, переменная previous остаётся равной dummy. Строка изменения ссылки выполняется так же, как для узла в середине: previous.next перепрыгивает удаляемый узел. После операции функция возвращает dummy.next, а не сам dummy.

Удаление первой 17 через dummyслужебный узел не возвращается

После присваивания dummy.next ведёт сразу к 30. Узел 17 больше не достижим из результата. Возвращённая ссылка ведёт к узлу со значением 30, поэтому фиктивный узел не становится частью списка.

На цепочке 4 → 7 → 9 сравним удаление головы и середины. Кнопки выбирают удаляемое значение, а шаги показывают изменение поля у его предшественника.

Удаление с dummy: голова и серединаодна операция для обоих случаев

Шаг 0 из 3

Создан dummy. previous = dummy, dummy.next указывает на узел 4.

При удалении 4 меняется поле dummy.next, при удалении 7 — поле next узла 4. Пунктирная стрелка previous показывает этот предшественник. Сплошные стрелки показывают поля next. У исключённого узла сохраняется собственная ссылка на следующий объект, но путь от dummy.next проходит мимо него.

Фиктивная голова также работает для пустой цепочки: тогда dummy.next равно None. Единая форма уменьшает число особых случаев в коде.

Новая голова возвращается из функции. Внешнее имя first из примера продолжает указывать на исходный узел 17. Таблица показывает ссылки после удаления головы.

Имя или полеКуда ведёт после удаления
firstпрежний узел 17
dummy.next внутри функцииузел 30
new_head снаружиузел 30

Для продолжения работы с изменённым списком используют возвращённую ссылку. Когда голова хранится в переменной head, вызов записывают как head = remove_first(head, wanted).

§4Нет значения и дубликаты

Если искомого значения нет, remove_first проходит до конца и возвращает прежнюю голову. Цепочка при этом не должна измениться. Проверим результат и идентичность первой ссылки.

Два узла могут хранить одно число, но оставаться разными объектами. Функция удаляет первое совпадение: узел left. Проверка result.next is right важнее одной проверки значений: она подтверждает, что в цепочке остался второй объект 17.

Проверка is отвечает на вопрос «это тот же объект?». Проверка == для списков значений отвечает на вопрос «такой ли порядок данных?». Для работы со ссылками обычно нужны оба вида проверки.

У двух совпадающих значений разные имена узлов. Таблица показывает, какой объект должен сохраниться.

МоментПуть от головыОбъекты 17
до удаления9 → left → right → Noneleft и right
после удаления9 → right → Noneтолько right доступен от головы

Проверка значений подтверждает порядок [9, 17]. Проверка result.next is right уточняет, какой из двух объектов остался. Тот же разбор можно выполнить вручную на четырёх узлах.

§5Ручное прослеживание

Короткая задача: цепочка содержит 4 → 7 → 7 → 9. Вызов remove_first(head, 7) удаляет только первое значение 7. До раскрытия разбора запишите, на какой узел будет ссылаться head.next в результате.

Показать разбор по строкам

Сначала dummy.next ведёт к 4, а previous равно dummy. Первый узел после previous содержит 4, поэтому переменная переходит к узлу 4.

Теперь previous.next — первый узел 7. Условие совпадает. Выполняется previous.next = previous.next.next: поле next узла 4 начинает вести ко второму узлу 7. Первый узел 7 выпадает из цепочки.

Функция возвращает dummy.next, то есть прежний узел 4. Поэтому head.next в результате указывает на второй узел 7, а значения равны [4, 7, 9].

В этой задаче переход по ссылке меняется у узла 4, хотя удаляется следующий узел. Ручное прослеживание определяет, у какого предшественника нужно изменить поле. Результат проверяется запуском и сравнением ссылок.

Таблица фиксирует изменения ссылок из ручного разбора. Узлы с одинаковым значением различаются именами.

СтрокаpreviousПуть от dummy.next
previous = dummyслужебный узел4 → первая 7 → вторая 7 → 9
previous = previous.nextузел 44 → первая 7 → вторая 7 → 9
previous.next = previous.next.nextузел 44 → вторая 7 → 9

Меняется поле у узла 4. Проверка result.next is second_seven подтверждает сохранение второй семёрки, а не только числа 7.

Проверьте себяЧто возвращает remove_first(None, 5)?

  • Созданный dummy хранит next = None. Цикл не выполняется, а функция возвращает dummy.next.

  • Функция возвращает его поле next, а не объект dummy.

  • Условие previous.next is not None не позволяет читать поле у None.

Проверьте себяЗачем в тесте дубликатов используется result.next is right?

  • Оператор is не сравнивает числа и не вычисляет сумму.

  • Значения двух узлов одинаковы. Идентичность доказывает, что остался именно объект right.

  • Проверка is ничего не меняет в цепочке.
