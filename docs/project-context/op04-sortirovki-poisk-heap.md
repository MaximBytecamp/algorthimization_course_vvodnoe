# ОП.04 · Сортировка, бинарный поиск и heap

## Старт книги (26.11.2026)

- Новый раздел расположен в `op04-algoritmizaciya/sortirovki-poisk-heap/`.
  Главная страница книги — `index.html`, локальные стили — `sortirovki.css`.
- Карточка на общей странице ОП.04 ведёт в новый раздел.
- Начат модуль 0 «Упорядочивание изнутри». Первая готовая глава:
  `00-osnovy-uporyadochivaniya/01-poryadok-i-klyuch.html`.
- Глава объясняет порядок по ключу, проверку соседних ключей, `sorted(..., key=...)`,
  различие с `list.sort` и стабильность равных ключей. Примеры Python проверены.
  В §2 сначала объяснена полная функция ключа, один её вызов и эквивалентная
  краткая запись `lambda`; затем §3 показывает сортировку вставками тремя зонами
  каждого шага: очередь после взятия, карточка в руках и новый список после шага.
  B образует первую упорядоченную часть; A (700) вставляется перед B (1900); C
  (1200) встаёт между A и B. Модель явно не выдаётся за внутреннюю
  последовательность сравнений реализации Python `sorted`.
- Глава 0.2 «Стабильность, память и цена сортировки» готова:
  `00-osnovy-uporyadochivaniya/02-stabilnost-pamyat-i-cena.html`. На равных ключах
  B/D показана стабильность Python; отдельно разобраны новый список `sorted` со
  ссылками на те же словари, изменение существующего списка через `list.sort`,
  вызовы функции ключа и рост числа сравнений. Каталог и переход из 0.1 ведут в
  новую главу.
- План оставшейся части модуля 0: инвариант бинарного поиска; монотонный
  предикат; слияние отсортированных потоков; heap и priority queue. Будущие
  главы в каталоге помечены как план и не имеют несуществующих ссылок.
- КТП сверено напрямую: раздел охватывает занятия 27–36 — сортировки, пользовательский
  порядок, бинарный поиск, merge/sweep line, heap, top-k, k-way merge и мок-интервью № 3.
