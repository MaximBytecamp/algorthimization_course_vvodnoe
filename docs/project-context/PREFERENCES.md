# Постоянные правила пользователя

Обновлено: 2026-11-05. Сжато из заметок `archive/claude-memory` (подробности и причины
там же, по имени в скобках).

## Git

- Коммит — без строки `Co-Authored-By: Claude`, почта автора
  `-c user.email=bytecampmm@gmail.com` (no-claude-coauthor-trailer).
- После каждого коммита сразу `git push`, не спрашивая; в ответе — хеш и где смотреть
  результат. Отклонённый push не перезаписывать силой (always-push-after-commit).
- Архивы `*.zip.enc` и готовый код (`tools/code*`, `tools/proekt*`, `tools/proto*`) не
  отправлять в открытые репозитории; новые папки с кодом сразу в `.gitignore`; перед
  `git add` смотреть `git status` (no-ready-code-in-public-repos).

## Учебный текст

- Взрослая лекция для новичка: связное объяснение, термин вводится и сразу объясняется,
  без ссылок вперёд, сквозных загадок, вопросов «ответьте сами» и придуманных названий
  блоков. В трудном месте — аналогия и пример после термина (clear-text-for-beginners).
- Одна линия мысли на главу, без служебных блоков и повторов условия (op04-book-less-text).
- Не писать «вслух» и «устная защита решения» (avoid-vsluh-in-slide-text).
- Инструкции — прямое указание с причиной вместо запрета; повторяющееся действие —
  кадром в каждом разделе (instructions-no-prohibitions).
- Каждое действие — шаг `ol.steps` с кадром; части «Делаем» / «Разбираемся»; F5 перед
  проверкой (do-and-read-phases).
- Код разбирать подробно, по конструкциям, с примером «что пришло → что получилось»
  (code-walkthrough-detail).
- Страницы-инструкции верстать компонентами справочника по Git, не самодельными рамками
  (pages-use-book-components).
- ДЗ в колоде: зачин «не хочет, но очень хочет», мем, слайд порядка сдачи, PDF
  (homework-slide-convention).

## Тесты

- Условие: ситуация списком + отдельный блок «Что нужно сделать»; без «слева/справа»
  (test-task-clarity).
- Верный вариант не выделяется длиной и формой; разное число верных; условие не
  подсказывает ответ; «найти ошибку» — только реальная ошибка (test-options-no-giveaways).
