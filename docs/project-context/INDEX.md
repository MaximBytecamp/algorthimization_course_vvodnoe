# Память проекта

Эта папка — каноническая память репозитория. Она хранится в Git и отображается в
Obsidian как папка проекта.

## Что читать

- [CURRENT](CURRENT.md) — текущая работа и ближайший шаг. Читать в начале задачи.
- [DECISIONS](DECISIONS.md) — решения, которые влияют на будущую работу.
- [CONSTRAINTS](CONSTRAINTS.md) — постоянные границы памяти и изменений.
- [PREFERENCES](PREFERENCES.md) — постоянные правила пользователя: Git, учебный текст, тесты.
- [BACKLOG](BACKLOG.md) — только согласованные, но ещё не начатые задачи.
- [EFFICIENCY](EFFICIENCY.md) — команды и настройки для экономии контекста.
- [MODEL_EVAL](MODEL_EVAL.md) — проверка Terra, Sol и Astra на типичных задачах.
- [Карта проекта](graph/Карта%20проекта.md) — граф «проект → дисциплина → модуль»
  со связями на исходники и исторические заметки.
- [Каталог архива Claude](archive/claude-memory/MEMORY.md) — ссылки на 93 тематические
  заметки, накопленные до перехода на Codex.
- `handoffs/` — короткие точки продолжения для нового чата.

## Как экономить контекст

1. Сначала читать только `CURRENT.md`.
2. По названию задачи найти одну или несколько заметок в каталоге архива.
3. Открыть только найденные заметки и проверить их утверждения по текущим файлам.
4. Не читать весь архив и не переносить в чат полный вывод команд.

После добавления или перемещения модулей перестроить граф:

```bash
python3 docs/project-context/tools/build_graph.py
```

Для быстрого поиска по архиву:

```bash
rg -n -i 'слово|другое слово' docs/project-context/archive/claude-memory
```

## Что сохранять

Запись нужна, если без неё новый чат может повторить исследование, нарушить принятое
решение или неверно продолжить незавершённую работу. Реализация остаётся в коде,
проверки — в тестах, история — в Git.

Такой контекст записывается сразу после появления, пока известны источник и причина:

- принятые решения и причины выбора;
- проверенные факты, результаты опытов и важные ограничения инструментов;
- найденные канонические файлы, команды проверки и неочевидные зависимости;
- состояние большой незавершённой работы и ближайший шаг;
- повторяющиеся требования пользователя, влияющие на будущие задачи.

Сначала обновляется существующая заметка. Новая создаётся только для отдельной темы,
которую потребуется находить независимо. После добавления новой заметки ссылка на неё
вносится в этот индекс или тематический каталог.

Секреты, персональные данные, полные переписки, исходный код и обычный вывод команд
в память не копируются.
