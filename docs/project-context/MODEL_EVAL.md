# Проверка маршрутизации моделей

Обновлено: 2026-11-05

## Метод

Terra, Sol и Astra получили одинаковый компактный набор из пяти типичных задач:
вычитка текста о Pushgateway, план мини-урока, исправление Python retry, выбор схемы
мониторинга batch job и структура нового учебного модуля. Оценка качественная:
интерфейс подагентов не предоставил сопоставимых данных о токенах и времени.

## Результат

| Модель | Сильные стороны | Ограничения | Роль |
|---|---|---|---|
| Terra | Самый компактный ответ, корректная вычитка и ясный план | Меньше архитектурных деталей | Тексты и черновики |
| Sol | Полная техническая картина, полезные edge cases и хорошая структура | Немного подробнее Terra | Основная смешанная работа |
| Astra | Наиболее отшлифованные формулировки и сильная структура | На этом тесте прирост относительно Sol небольшой | Сложный критический аудит |

Все три модели нашли фактическую ошибку о якобы автоматическом удалении метрик
Pushgateway и исправили условие последней попытки с `attempts` на `attempts - 1`.
Sol дополнительно отметил риск уникального идентификатора запуска в grouping key;
Astra точнее подчеркнула отдельную обработку отсутствующей метрики.

## Решение

- `terra_writer` использовать для документации, учебных черновиков и перестройки текста.
- `sol_builder` оставить основным агентом для задач, совмещающих код, архитектуру и текст.
- Astra не включать автоматически: применять для высокорисковых решений, трудной
  диагностики или финального глубокого аудита.
- Повторить сравнение на реальной большой главе, если качество Terra или Sol начнёт
  заметно расходиться с требованиями `$vychitka`.
