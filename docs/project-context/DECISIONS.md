# Решения о памяти проекта

## 2026-11-05 — Двухуровневая память

Постоянно читаются только `AGENTS.md`, `INDEX.md` и `CURRENT.md`. Большие тематические
заметки подгружаются по запросу. Это уменьшает расход контекста и сохраняет подробности.

## 2026-11-05 — Канонические файлы хранятся рядом с кодом

Markdown-файлы лежат в `docs/project-context`, проходят через Git и отображаются в
Obsidian через ссылку из основного vault. Obsidian служит интерфейсом, а репозиторий —
источником истории и переносимости.

## 2026-11-05 — Память Claude сохранена архивом

94 исходные заметки скопированы без смысловой переработки в
`archive/claude-memory`. Они считаются историческими срезами: пути, состояние задач и
правила в них нужно сверять с текущим кодом и прямыми указаниями пользователя.

## 2026-11-05 — Передача между чатами выполняется через `$handoff`

Навык обновляет `CURRENT.md` и создаёт короткую запись в `handoffs/`. Полная переписка
между чатами не переносится.

## 2026-11-05 — Полезный контекст сохраняется сразу

Решения, проверенные факты, результаты исследований, неочевидные пути и состояние
длинной работы записываются в память по мере появления. `$handoff` остаётся снимком для
смены чата, но не является единственным моментом обновления Obsidian. Существующие
заметки дополняются, чтобы память не разрасталась дубликатами.

## 2026-11-05 — Граф строится по смысловым единицам

Узлами графа являются проект, дисциплины и модули или уроки. Изображения, архивы,
зависимости, кэши и каждый отдельный исходный файл не превращаются в узлы: они указаны
ссылками внутри соответствующего модуля. Граф создаётся скриптом
`docs/project-context/tools/build_graph.py` и перестраивается после изменения структуры.

## 2026-11-05 — Каталог навыков ограничен 3500 токенами

В `~/.codex/config.toml` установлено `skills.max_context_tokens = 3500`. Полные инструкции
выбранного навыка подгружаются отдельно; ограничение уменьшает стартовый каталог. Для
обслуживания памяти установлен `$context-audit`.

## 2026-11-05 — Плагин Notion удалён

Каноническая память хранится в `docs/project-context` и отображается в Obsidian. Плагин
Notion удалён, чтобы не дублировать контекст и не поддерживать две расходящиеся базы.

## 2026-11-05 — Контекст и модели маршрутизируются по нагрузке

В глобальной конфигурации Codex включено сжатие истории после ответа при заполнении
70% окна. `$router` оставляет простые действия основной модели и при достаточной выгоде
делегирует узкие подзадачи агентам `luna_fast`, `terra_writer` или `sol_builder`.
Подагент получает только необходимые пути и ограничения; Astra не используется
автоматически для обычной продолжительной работы.

## 2026-11-05 — Поиск памяти выполняется локальным FTS-индексом

Навык `$context-search` индексирует `docs/project-context` в скрытом исключённом из
Git SQLite-кэше и возвращает только несколько релевантных заметок. Архив Claude
исключён из обычного индекса и подключается только как явный fallback. Встроенная
Memories отключена, чтобы не создавать параллельную базу рядом с Obsidian.

## 2026-11-05 — Claude Code на общей памяти Obsidian

Claude Code использует ту же память `docs/project-context`, что и Codex. Встроенная
auto-memory Claude для проекта выключена, чтобы не было второй базы; навыки общие через
символические ссылки, агенты — Haiku и Sonnet, основная модель — Opus. `CLAUDE.md` не
создаётся: `AGENTS.md` загружается и так, импорт дал бы двойную загрузку.

## 2026-11-05 — Модель Claude не переключается автоматически

Основная модель — Opus, effort medium. Режим `opusplan` (Opus в планировании, Sonnet в
исполнении) не включён: учебные тексты должны писаться основной моделью. Экономия —
через `/clear` между несвязанными задачами, `/effort low` для мелких действий и
подагентов по `/router`. Строка состояния показывает заполненность контекста.

## 2026-11-05 — Архив Claude не публикуется

Репозиторий публичный, а в `archive/claude-memory` есть пароль архивов студентов, соли
кодов результатов тестов и пути к эталонам. Архив исключён из Git (`.gitignore`) и
живёт только локально и в Obsidian; ссылки на него из графа работают только локально.

## 2026-11-06 — Справочник по наблюдаемости переделывается в лекционный формат

Пользователю не нравится текущий справочник `observability/`: четыре разные книги
(модуль 1 в одной вёрстке, 2–4 в другой, семь стендов), повторы (target, scrape,
counter объясняются в нескольких модулях), главы — перечни понятий с 1–10 примерами
кода. Образец — лекционные главы справочника по Python (`python_theory_makarov/temy/46-slovari`):
один раздел — одно понятие, абзац → код → вывод → объяснение, ~30 примеров на главу;
и лекционные главы системного программирования. Сквозного проекта не нужно: каждая
лекция со своими короткими логичными примерами кода.
Пилот 06.11.2026: `observability/lekcii/2-2-counter.html` + `observability/lekcii/styles.css`
(новая палитра: графит #172026, бирюзовый #0E7C66, янтарь #F2B33D, IBM Plex Sans/Mono, тонкие рамки
со скруглением; вывод — светлый блок под кодом, ошибка — оранжевый, разбор кода — `.walk`). Примеры
прогнаны на prometheus-client 0.26.0. Вторая версия (по замечанию «чётче отделять мысли»): раздел — белая карточка `.part` с подвалом-переходом `.next`;
первая строка `.about` («о чём раздел»); определение `.def` с полями «что это / что даёт / пример»; вывод `.key`;
рисунок ситуации или схема `figure.scene` (inline SVG, классы `sc-*`) почти в каждом разделе; тёмная обложка `.cover`.
Третья версия (по просьбе «ближе к лекциям по Python»): `lekcii/styles.css` = копия `python_theory_makarov/styles.css`
(книга с корешком, сетка, рамки 3px с тенью, Pixelify/Literata/Inter/Roboto Mono) + в конце блоки лекций в том же
языке; карточки убраны, разделы разделены пунктиром. Ждёт оценки пользователя; остальные лекции — после неё.
Режим чтения (06.11.2026): `observability/lekcii/reader.js` — лекция по одному разделу `.leaf > .part`
(одна мысль на экран), кнопки «Читать по шагам» / «Продолжить» в блоке `.reader-start`, панель «Назад / Дальше»,
← → и Esc, прогресс сверху, место чтения в localStorage. Каждая цельная мысль — свой `.part`; длинную серию
шагов выносить в отдельный `.part`. Подключать `reader.js` в каждой лекции.
Спокойная подача (06.11.2026, «слишком много цвета и разных блоков»): три цвета — тёмно-синий, синий, бледно-голубой;
оранжевый только для ошибок, жёлтый убран. Тень только у кода; рисунки, определения, разборы, таблицы, глоссарий —
тонкая рамка 2px без тени; «о чём раздел», «вывод», переход и связки серий — текстом с чертой, без закрашенных плашек.
Наполнение лекции 2.2 (06.11.2026): §0 запуск примеров (venv, prometheus-client 0.26.0), счётчик и gauge рядом,

Пересборка справочника (06.11.2026): одна книга `observability/lekcii/`, карта — `observability/lekcii/PLAN.md`

## 2026-11-09 — Тесты Angular и React используют общий интерактивный движок

Тест каждого завершённого модуля содержит 15 заданий только по материалам этого модуля. Общий движок
`~/angular_react_makarov/testy/shared/` поддерживает выбор одного и нескольких ответов, порядок, группы, подстановку,
выбор строки кода и число. Настройки теста: 35 минут, одна попытка, перемешивание, фиксация ухода со вкладки,
разбор после отправки и проверяемый код результата. Границы оценок: 13–15 — «5», 10–12 — «4», 7–9 — «3».
