# Aggregation Pipeline: $group, сортировка, подсчёты, bucket и facet

#### $group: Группирует документы по указанному полю и вычисляет агрегатные значения (например, сумму, среднее, количество).

Это одна из самых мощных стадий в агрегационных пайплайнах MongoDB. Она позволяет группировать документы по указанному полю (или нескольким полям) и вычислять агрегатные значения, такие как сумма, среднее, количество и другие.

Что делает $group?

Группирует документы по указанному полю (или нескольким полям).

Вычисляет агрегатные значения для каждой группы.

Создает новый документ для каждой группы.

Синтаксис:

```python
{ "$group": { "_id": <выражение>, <field>: { <аккумулятор>: <выражение> }, ... } }
```

_id — поле или выражение, по которому группируются документы.

<field> — имя нового поля, которое будет содержать результат агрегации.

<аккумулятор> — функция агрегации (например, $sum, $avg, $max, $min, $push и т.д.).

<выражение> — выражение, которое вычисляет значение для агрегации.

Основные аккумуляторы:

$sum: Вычисляет сумму значений.

$avg: Вычисляет среднее значение.

$max: Находит максимальное значение.

$min: Находит минимальное значение.

$push: Добавляет значения в массив.

$addToSet: Добавляет уникальные значения в массив.

$first: Возвращает первое значение в группе.

$last: Возвращает последнее значение в группе.

Примеры использования $group:

Исходные данные:

```python
[
    {
        "_id": 1,
        "name": "Alice",
        "department": "HR",
        "salary": 50000
    },
    {
        "_id": 2,
        "name": "Bob",
        "department": "IT",
        "salary": 60000
    },
    {
        "_id": 3,
        "name": "Charlie",
        "department": "HR",
        "salary": 70000
    },
    {
        "_id": 4,
        "name": "David",
        "department": "IT",
        "salary": 80000
    }
]
```

Пример 1: Группировка по полю и вычисление суммы

Пайплайн:

```python
pipeline = [
    {
        "$group": {
            "_id": "$department",  # Группировка по department
            "total_salary": { "$sum": "$salary" }  # Сумма salary для каждой группы
        }
    }
]
```

Результат:

```python
[
    {
        "_id": "HR",
        "total_salary": 120000
    },
    {
        "_id": "IT",
        "total_salary": 140000
    }
]
```

Документы сгруппированы по полю department.

Для каждой группы вычислена сумма поля salary.

Когда использовать $group:

Для агрегации данных: Когда нужно вычислить сумму, среднее, количество и т.д.

Для группировки данных: Когда нужно сгруппировать документы по определенным полям.

Для создания сводных отчетов: Когда нужно подготовить данные для анализа.

Важные моменты:

Поле _id:

Обязательное поле, по которому происходит группировка.

Если нужно сгруппировать по нескольким полям, используй вложенный объект.

Аккумуляторы:

Используй аккумуляторы для вычисления агрегатных значений.

Производительность:

$group может быть ресурсоемким, особенно на больших коллекциях. Используй индексы для оптимизации.

#### $sort: Сортирует документы по указанным полям.

Это одна из самых простых, но важных стадий в агрегационных пайплайнах MongoDB. Она позволяет сортировать документы по указанным полям в порядке возрастания или убывания.

Что делает $sort?

Сортирует документы по одному или нескольким полям.

Поддерживает сортировку по возрастанию (1) или убыванию (-1).

Синтаксис:

```python
{ "$sort": { <field1>: <order>, <field2>: <order>, ... } }
```

<field> — имя поля, по которому происходит сортировка.

<order>:

1 — сортировка по возрастанию.

-1 — сортировка по убыванию.

Примеры использования $sort:

Исходные данные:

```python
[
    {
        "_id": 1,
        "name": "Alice",
        "age": 25,
        "salary": 50000
    },
    {
        "_id": 2,
        "name": "Bob",
        "age": 30,
        "salary": 60000
    },
    {
        "_id": 3,
        "name": "Charlie",
        "age": 35,
        "salary": 70000
    }
]
```

Пайплайн:

Порядок сортировки:

#### $count: Возвращает количество документов на текущем этапе пайплайна.

Что делает $count?

Возвращает количество документов на текущем этапе пайплайна.

Создает новый документ с указанным именем поля, содержащим количество документов

Синтаксис:

```python
{ "$count": <имя_поля> }
```

<имя_поля> — имя поля, в которое будет записано количество документов.

Примеры использования $count:

Исходные данные:

```python
[
    {
        "_id": 1,
        "name": "Alice",
        "age": 25,
        "department": "HR"
    },
    {
        "_id": 2,
        "name": "Bob",
        "age": 30,
        "department": "IT"
    },
    {
        "_id": 3,
        "name": "Charlie",
        "age": 35,
        "department": "HR"
    }
]
```

Пример 1: Подсчет всех документов

Пайплайн:

```python
pipeline = [
    {
        "$count": "total_employees"  # Подсчёт всех документов
    }
]
```

Результат:

```python
[
    {
        "total_employees": 3
    }
]
```

В коллекции 3 документа, поэтому результат — {"total_employees": 3}.

Пример 2: Подсчёт документов после фильтрации

Пайплайн:

```python
pipeline = [
    {
        "$match": { "department": "HR" }  # Фильтрация по department
    },
    {
        "$count": "hr_employees"  # Подсчёт документов после фильтрации
    }
]
```

Результат:

```python
[
    {
        "hr_employees": 2
    }
]
```

После фильтрации осталось 2 документа, где department равен "HR".

Пример 3: Подсчёт документов после группировки

Пайплайн:

```python
pipeline = [
    {
        "$group": {
            "_id": "$department",  # Группировка по department
            "total_salary": { "$sum": "$salary" }  # Сумма salary для каждой группы
        }
    },
    {
        "$count": "total_departments"  # Подсчёт количества групп
    }
]
```

Результат:

```python
[
    {
        "total_departments": 2
    }
]
```

После группировки по department получилось 2 группы (HR и IT).

Когда использовать $count:

Для подсчета документов:

Когда нужно узнать количество документов, соответствующих определённым критериям.

Для анализа данных:

Когда нужно получить статистику по данным (например, количество сотрудников в отделе).

Для отладки:

Когда нужно проверить, сколько документов прошло через определенные стадии пайплайна.

Важные моменты:

Результат:

$count всегда возвращает один документ с указанным именем поля и количеством документов.

Производительность:

$count не требует дополнительных вычислений, так как просто возвращает количество документов.

#### $sortByCount: Группирует документы по указанному выражению и сортирует по количеству документов в каждой группе.

Эта стадия агрегации объединяет функции $group и $sort:

Сначала группирует документы по указанному выражению.

Затем сортирует группы по количеству документов в убывающем порядке (от большего к меньшему).

Синтаксис:

```python
{ "$sortByCount": <выражение> }
```

<выражение>: Поле или выражение для группировки (например, "$department").

Примеры:

Исходные данные (employees):

```python
[
  { "name": "Alice", "department": "HR" },
  { "name": "Bob", "department": "IT" },
  { "name": "Charlie", "department": "HR" },
  { "name": "David", "department": "IT" },
  { "name": "Eve", "department": "IT" }]
```

Пример 1: Группировка по полю department

Пайплайн:

```python
pipeline = [
  { "$sortByCount": "$department" }
]
```

Результат:

```python
[
  { "_id": "IT", "count": 3 },    // В IT 3 сотрудника
  { "_id": "HR", "count": 2 }     // В HR 2 сотрудника
]
```

Документы сгруппированы по полю department.

Группы отсортированы по count (количеству документов) в порядке убывания.

Пример 2: Группировка по вычисляемому выражению

Допустим, мы хотим сгруппировать сотрудников по первой букве имени:

Пайплайн:

```python
pipeline = [
  { "$sortByCount": { "$substrCP": ["$name", 0, 1] } }  // Берём первый символ имени
]
```

Результат:

```python
[
  { "_id": "A", "count": 1 },    // Alice
  { "_id": "B", "count": 1 },    // Bob
  { "_id": "C", "count": 1 },    // Charlie
  { "_id": "D", "count": 1 },    // David
  { "_id": "E", "count": 1 }     // Eve
]
```

Пример 3: Фильтрация перед группировкой

Подсчёт отделов с зарплатой > 50K:

Пайплайн:

```python
pipeline = [
  { "$match": { "salary": { "$gt": 50000 } } },  // Сначала фильтруем
  { "$sortByCount": "$department" }
]
```

Результат (предположим, что у Alice и Charlie зарплата ≤ 50K):

```python
[
  { "_id": "IT", "count": 3 },   // Bob, David, Eve
  { "_id": "HR", "count": 0 }    // Нет подходящих документов
]
```

Когда использовать?

Анализ популярности (например, самые частые теги в блоге).

Статистика по категориям (отделы, города, статусы заказов).

Поиск аномалий (например, категории с неожиданно большим/малым количеством записей).

Важные нюансы:

Всегда сортирует по count в порядке убывания.

Эквивалентен пайплайну:

```python
[
  { "$group": { "_id": <выражение>, "count": { "$sum": 1 } } },
  { "$sort": { "count": -1 } }
]
Но $sortByCount записывается короче и работает эффективнее.
```

Пустые/отсутствующие значения тоже попадают в группу { "_id": null, "count": N }.

$sortByCount — это удобный способ быстро получить отсортированную по популярности статистику без сложных пайплайнов.

#### $bucket: Группирует документы в "корзины" на основе указанного выражения.

#### $bucketAuto: Автоматически группирует документы в "корзины" с равными интервалами.

$bucket: Ручное создание корзин

Группирует документы в заранее заданные диапазоны ("корзины") на основе указанного выражения.
Пример использования: группировка по возрасту, ценам, датам и т.д.

Синтаксис

```python
{
  "$bucket": {
    "groupBy": <expression>,  // Поле или выражение для группировки (например, "$age")
    "boundaries": [<min>, ..., <max>], // Границы корзин (числа в порядке возрастания)
    "default": <значение>,    // Корзина для значений вне boundaries (опционально)
    "output": {               // Дополнительные вычисляемые поля (опционально)
      "<field>": { <accumulator> }
    }
  }
}
```

Как это работает?

Границы корзин (boundaries):

Задаются вручную.

Формат интервалов: [левая граница включительно, правая граница исключительно).

Пример: boundaries: [0, 10, 20] → корзины [0-10), [10-20).

groupBy: Значение, по которому группируются документы.

Должно быть числом, иначе документ попадет в default (если задан) или будет проигнорирован.

default: Корзина для значений:

Выходящих за пределы boundaries (например, age: 100 при boundaries: [0, 50]).

Равных null или отсутствующих.

output: Дополнительные агрегации (например, сумма, среднее, список имён).

Пример: Группировка по возрасту

Исходные данные

```python
[
  { "name": "Alice", "age": 25 },
  { "name": "Bob", "age": 30 },
  { "name": "Charlie", "age": 35 },
  { "name": "David", "age": 40 },
  { "name": "Eve", "age": 18 }
]
```

Пайплайн

```python
pipeline = [
  {
    "$bucket": {
      "groupBy": "$age",
      "boundaries": [18, 30, 40, 50],  // Корзины: 18-30, 30-40, 40-50
      "default": "invalid_age",
      "output": {
        "count": { "$sum": 1 },
        "names": { "$push": "$name" }
      }
    }
  }
]
```

Результат

```python
[
  { "_id": 18, "count": 2, "names": ["Eve", "Alice"] },  // 18 ≤ age < 30
  { "_id": 30, "count": 2, "names": ["Bob", "Charlie"] }, // 30 ≤ age < 40
  { "_id": 40, "count": 1, "names": ["David"] },          // 40 ≤ age < 50
  { "_id": "invalid_age", "count": 0, "names": [] }       // Для age ≥50 или null
]
```

Ошибки, которых нужно избегать

Неупорядоченные границы:

boundaries: [30, 10, 50]  // Ошибка! Должно быть [10, 30, 50].

Некорректные типы данных:
Если groupBy возвращает строку, MongoDB выдаст ошибку.
Решение: преобразовать в число с помощью $toInt.

Пропущенные границы:
Если boundaries не покрывают все возможные значения, используйте default.

$bucketAuto: Автоматические корзины

Автоматически создаёт корзины с примерно равным количеством документов или равными интервалами.
	Пример использования: анализ распределения данных без заранее известных границ.

Синтаксис

```python
{
  "$bucketAuto": {
    "groupBy": <expression>,  // Поле или выражение для группировки
    "buckets": <number>,      // Желаемое количество корзин (MongoDB может изменить)
    "output": {               // Дополнительные вычисляемые поля (опционально)
      "<field>": { <accumulator> }
    },
    "granularity": <string>   // Шаблон округления границ (опционально)
  }
}
```

buckets: Приблизительное количество корзин. MongoDB может изменить его для оптимизации распределения.

granularity: Округление границ до "красивых" значений (например, 10, 50, 100).
Допустимые значения: R5, R10, R20, R40, R80, 1-2-5, E6, E12, ....

output: Аналогично $bucket.

Пример: Группировка зарплат

Исходные данные

```python
[
  { "name": "Alice", "salary": 45000 },
  { "name": "Bob", "salary": 65000 },
  { "name": "Charlie", "salary": 80000 },
  { "name": "David", "salary": 35000 },
  { "name": "Eve", "salary": 95000 }
]
```

Пайплайн

```python
pipeline = [
  {
    "$bucketAuto": {
      "groupBy": "$salary",
      "buckets": 3,
      "granularity": "R10",  // Округление до 10, 50, 100 и т.д.
      "output": {
        "count": { "$sum": 1 },
        "avgSalary": { "$avg": "$salary" }
      }
    }
  }
]
```

Результат

```python
[
  {
    "_id": { "min": 35000, "max": 50000 },
    "count": 2,
    "avgSalary": 40000  // 35000 (David) и 45000 (Alice)
  },
  {
    "_id": { "min": 50000, "max": 80000 },
    "count": 1,
    "avgSalary": 65000  // Bob
  },
  {
    "_id": { "min": 80000, "max": 100000 },
    "count": 2,
    "avgSalary": 87500  // Charlie (80000) и Eve (95000)
  }
]
```

| Критерий | $bucket | $bucketAuto |
| --- | --- | --- |
| Контроль границ | Полный (ручной ввод) | Автоматический |
| Гибкость | Для четких бизнес-правил | Для разведочного анализа |
| Производительность | Быстрее (если границы известны) | Медленнее (вычисляет границы) |
| Типы данных | Числа, даты | Числа, даты, строки |
| Использование | Возрастные группы, ценовые диапазоны | Анализ распределения данных |

Для $bucket:

Всегда проверяйте, что boundaries покрывают все возможные значения.

Используйте default, чтобы не потерять данные.

Для $bucketAuto:

Начинайте с buckets: 3-5, затем увеличивайте.

Используйте granularity для "красивых" границ.

Типичные ошибки

Путаница с границами:

// Неправильно!

```python
{ "$bucket": { "boundaries": [10, 5, 20] } }
 Границы должны быть в порядке возрастания.
```

Некорректный тип данных:

// Ошибка, если "salary" — строка.

```python
{ "$bucketAuto": { "groupBy": "$salary" } }
Решение: преобразуйте поле в число с помощью $toInt.
```

Игнорирование default:

Документы с groupBy: null или значениями вне boundaries будут потеряны, если default не задан.

Параметр granularity определяет, по какому математическому правилу округляются границы корзин в $bucketAuto. Это особенно полезно для создания "красивых" (человеко-читаемых) интервалов, например, 10–20–50–100 вместо 11.3–23.7–49.1.

Допустимые значения granularity

MongoDB поддерживает следующие стандартные шаблоны округления:

| Значение | Описание | Пример ряда |
| --- | --- | --- |
| R5 | Ряд R5 (ISO 3:2016) — удвоение через каждые 3 шага | 1, 2, 5, 10, 20, 50, 100... |
| R10 | Ряд R10 — более плавное увеличение | 1, 1.25, 1.6, 2, 2.5, 3.2, 4... |
| R20 | Ряд R20 | 1, 1.12, 1.25, 1.4, 1.6, 1.8, 2... |
| R40 | Ряд R40 | 1, 1.06, 1.12, 1.18, 1.25... |
| R80 | Ряд R80 (наиболее детализированный) | 1, 1.03, 1.06, 1.09, 1.12... |
| 1-2-5 | Популярный шаблон для гистограмм | 1, 2, 5, 10, 20, 50, 100... |
| E6 | Ряд E6 (экспоненциальный) | 1, 1.5, 2.2, 3.3, 4.7, 6.8... |
| E12 | Ряд E12 | 1, 1.2, 1.5, 1.8, 2.2, 2.7... |
| E24 | Ряд E24 | 1, 1.1, 1.2, 1.3, 1.5, 1.6... |
| E48 | Ряд E48 | 1, 1.05, 1.1, 1.15, 1.21, 1.27... |

Как работает округление?

MongoDB использует выбранный шаблон (R5, R10 и др.), чтобы привести вычисленные границы корзин к ближайшему "красивому" числу из ряда.

Пример с granularity: "R5"

Допустим, MongoDB вычислила предварительные границы:
[23, 47, 89, 130]

После применения R5 (ряд: 1, 2, 5, 10, 20, 50, 100, 200...) границы станут:
[20, 50, 100, 200]

Пример с granularity: "1-2-5"

Предварительные границы:
[17, 33, 78, 110]

После применения 1-2-5 (ряд: 1, 2, 5, 10, 20, 50, 100, 200...):
[10, 20, 50, 100, 200]

Практические примеры

Пример 1: Группировка зарплат с granularity: "R10"

Исходные данные

```python
[
  { "salary": 45000 },
  { "salary": 67000 },
  { "salary": 82000 },
  { "salary": 93000 }
]
```

Пайплайн

```python
pipeline = [
  {
    "$bucketAuto": {
      "groupBy": "$salary",
      "buckets": 3,
      "granularity": "R10",  // Округление до 10, 20, 50, 100...
      "output": { "count": { "$sum": 1 } }
    }
  }
]
```

Результат

```python
[
  { "_id": { "min": 40000, "max": 50000 }, "count": 1 },  // 45000
  { "_id": { "min": 50000, "max": 80000 }, "count": 1 },  // 67000
  { "_id": { "min": 80000, "max": 100000 }, "count": 2 }  // 82000, 93000
]
```

Пример 2: Группировка времени с granularity: "1-2-5"

Исходные данные

```python
[
  { "time_sec": 5 },
  { "time_sec": 12 },
  { "time_sec": 17 },
  { "time_sec": 23 }
]
```

Пайплайн

```python
pipeline = [
  {
    "$bucketAuto": {
      "groupBy": "$time_sec",
      "buckets": 3,
      "granularity": "1-2-5",  // Ряд: 1, 2, 5, 10, 20, 50...
      "output": { "count": { "$sum": 1 } }
    }
  }
]
```

Результат

```python
[
  { "_id": { "min": 0, "max": 5 }, "count": 1 },    // 5
  { "_id": { "min": 5, "max": 10 }, "count": 0 },   // Пусто
  { "_id": { "min": 10, "max": 20 }, "count": 3 }   // 12, 17, 23 (но 23 >20 → ошибка?)
]
```

Ошибка в пояснении: На самом деле, MongoDB скорректирует количество корзин, чтобы границы соответствовали 1-2-5.
Фактический результат:

```python
[
  { "_id": { "min": 0, "max": 5 }, "count": 1 },
  { "_id": { "min": 5, "max": 10 }, "count": 0 },
  { "_id": { "min": 10, "max": 20 }, "count": 2 },  // 12, 17
  { "_id": { "min": 20, "max": 50 }, "count": 1 }   // 23
]
```

Когда какое значение использовать?

R5, R10, 1-2-5 — для денег, времени, возраста.
Пример: цены в интервале 100–200–500 руб.

E6, E12 — для научных данных (например, сопротивление резисторов).

Без granularity — если нужны точные, но некрасивые границы.

Важные нюансы

MongoDB может изменить количество корзин (buckets), чтобы границы соответствовали выбранной granularity.

Границы всегда округляются вверх.
Например, при R10 число 23 → 50, а не 20.

Если granularity не задана, границы будут закругленными (например, 11.3–23.7).

#### $facet: Позволяет выполнять несколько независимых пайплайнов в одной стадии.

Оператор $facet — это мощный инструмент в MongoDB, который позволяет выполнять несколько независимых агрегационных пайплайнов в рамках одной стадии. Результаты всех пайплайнов объединяются в один документ с разными полями.

Синтаксис

```python
{
  "$facet": {
    "<outputField1>": [ <pipeline1> ],  // Первый пайплайн
    "<outputField2>": [ <pipeline2> ],  // Второй пайплайн
    ...
  }
}
```

<outputField> — название поля, в которое сохранится результат пайплайна.

<pipeline> — массив стадий агрегации (аналогично обычному пайплайну).

Как это работает?

Все пайплайны внутри $facet выполняются параллельно на одних и тех же входных документах.

Каждый пайплайн не зависит от других (не может использовать результаты соседних).

Итоговый документ содержит все результаты вложенных пайплайнов.

Пример 1: Анализ коллекции orders

Задача:
Для коллекции заказов (orders) получить:

Общее количество заказов.

Среднюю сумму заказа.

Топ-3 самых дорогих заказов.

Исходные данные

```python
[
  { "_id": 1, "product": "Laptop", "price": 1200 },
  { "_id": 2, "product": "Phone", "price": 800 },
  { "_id": 3, "product": "Tablet", "price": 500 },
  { "_id": 4, "product": "Monitor", "price": 300 }
]
```

Пайплайн с $facet

```python
pipeline = [
  {
    "$facet": {
      "total_orders": [  // Пайплайн 1: количество заказов
        { "$count": "count" }
      ],
      "avg_price": [    // Пайплайн 2: средняя цена
        { "$group": { "_id": null, "avg": { "$avg": "$price" } } }
      ],
      "top_expensive": [  // Пайплайн 3: топ-3 дорогих заказов
        { "$sort": { "price": -1 } },
        { "$limit": 3 },
        { "$project": { "product": 1, "price": 1 } }
      ]
    }
  }
]
```

Результат

```python
[
  {
    "total_orders": [ { "count": 4 } ],
    "avg_price": [ { "_id": null, "avg": 700 } ],
    "top_expensive": [
      { "_id": 1, "product": "Laptop", "price": 1200 },
      { "_id": 2, "product": "Phone", "price": 800 },
      { "_id": 3, "product": "Tablet", "price": 500 }
    ]
  }
]
```

Пример 2: Анализ пользователей (users)

Задача:
Для коллекции пользователей (users) получить:

Количество пользователей по странам.

Распределение по возрасту (группы: <20, 20-30, 30+).

Список самых активных пользователей (по количеству заказов).

Пайплайн

```python
pipeline = [
  {
    "$facet": {
      "by_country": [  // Группировка по странам
        { "$group": { "_id": "$country", "count": { "$sum": 1 } } }
      ],
      "by_age": [      // Распределение по возрасту
        {
          "$bucket": {
            "groupBy": "$age",
            "boundaries": [0, 20, 30, 100],
            "default": "unknown",
            "output": { "count": { "$sum": 1 } }
          }
        }
      ],
      "most_active": [  // Топ-5 активных пользователей
        { "$sort": { "orders_count": -1 } },
        { "$limit": 5 },
        { "$project": { "name": 1, "orders_count": 1 } }
      ]
    }
  }
]
```

Результат (пример)

```python
[
  {
    "by_country": [
      { "_id": "USA", "count": 10 },
      { "_id": "Germany", "count": 5 }
    ],
    "by_age": [
      { "_id": 0, "count": 3 },    // <20 лет
      { "_id": 20, "count": 12 },  // 20-30 лет
      { "_id": 30, "count": 8 }    // 30+ лет
    ],
    "most_active": [
      { "_id": 1, "name": "Alice", "orders_count": 15 },
      { "_id": 2, "name": "Bob", "orders_count": 12 }
    ]
  }
]
```

Когда использовать $facet?

Сложная аналитика — когда нужно получить несколько разных статистик за один запрос.

Оптимизация производительности — вместо нескольких отдельных запросов к базе.

Подготовка данных для отчетов — например, дашборды с разными метриками.

Ограничения

Параллельные пайплайны не обмениваются данными — каждый работает независимо.

Нет поддержки $lookup внутри $facet — нельзя делать JOIN внутри под пайплайна.

Может потреблять много памяти — если пайплайны обрабатывают большие данные.

Альтернативы

Если $facet не подходит, можно:

Выполнить несколько отдельных запросов.

Использовать $unionWith (MongoDB 4.4+) для объединения результатов.

$facet — это "мультипайплайн", который выполняет несколько агрегаций параллельно. Результаты сохраняются в разные поля итогового документа. Идеален для комплексной аналитики, но требует аккуратного использования.

Пример для коллекции products:

```python
{
  "$facet": {
    "by_category": [ { "$group": { "_id": "$category", "count": { "$sum": 1 } } } ],
    "avg_price": [ { "$group": { "_id": null, "avg": { "$avg": "$price" } } } ],
    "cheapest": [ { "$sort": { "price": 1 } }, { "$limit": 3 } ]
  }
}
```

В MongoDB агрегационном пайплайне _id: null в операции $group означает, что вы группируете все документы коллекции вместе (без разделения на группы по какому-либо полю).

Пояснение:

$group — этап агрегации для группировки документов.

_id — определяет поле, по которому происходит группировка:

Если указать _id: "$field_name", документы будут разделены на группы по уникальным значениям этого поля.

_id: null — особый случай: все документы обрабатываются как одна большая группа (т.е. агрегация выполняется по всей коллекции).

```python
{
  "$group": {
    "_id": null,  // группируем ВСЕ документы вместе
    "avg": { "$avg": "$price" }  // вычисляем среднее значение поля `price`
  }
}
```

Этот запрос вернет одно значение — среднюю цену (avg) по всем документам коллекции (аналог SELECT AVG(price) FROM collection в SQL).

Зачем это нужно?

Когда нужно вычислить общую статистику (среднее, сумму, максимум и т.д.) по всей коллекции.

Если не требуется разбивать данные на подгруппы.

Пример результата:

```python
{ "_id": null, "avg": 25.5 }  // где 25.5 — среднее значение price
```

#### $collStats: Возвращает статистику о коллекции (например, размер, количество документов).

В MongoDB оператор $collStats используется в агрегационных пайплайнах для получения статистики о коллекции. Это мощный инструмент для администрирования и анализа данных.

Основная информация:

```python
{ $collStats: { <options> } }
```

Что возвращает:

Базовая статистика:

ns — имя коллекции

size — общий размер данных в байтах

count — количество документов

storageSize — место, занимаемое на диске

totalIndexSize — размер всех индексов

Дополнительные метрики (при включении опций):

latencyStats — статистика задержек операций

storageStats — детали хранения данных

countStats — точный подсчет документов (для шардированных коллекций)

Примеры использования:

Простая статистика:

```python
db.collection.aggregate([
  { $collStats: {} }
])
```

С включением latency statistics:

```python
db.collection.aggregate([
  { $collStats: { latencyStats: { histograms: true } } }
])
```

Полная статистика хранилища:

```python
db.collection.aggregate([
  { $collStats: { storageStats: {} } }
])
```

Особенности:

Должен быть первым этапом в пайплайне

Работает только в агрегационных запросах

Требует прав администратора для некоторых опций

Для шардированных коллекций возвращает данные по каждому шарду

Практическое применение:

Мониторинг роста коллекции

Оптимизация производительности

Планирование масштабирования

Анализ использования индексов

Пример вывода:

```python
{
  "ns": "test.users",
  "size": 1048576,
  "count": 10000,
  "storageSize": 1310720,
  "totalIndexSize": 327680,
  "indexSizes": {
    "_id_": 163840,
    "email_1": 163840
  }
}
```

3. Стадии работы с массивами

Эти стадии используются для работы с массивами в документах.
