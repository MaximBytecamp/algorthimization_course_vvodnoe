# Работа с массивами и связями: $reduce, $slice и $lookup

#### $reduce: Сворачивает массив в одно значение с помощью аккумулятора.

Оператор $reduce последовательно обрабатывает элементы массива, применяя к ним заданную логику и аккумулируя результат. Это мощный инструмент для сложных агрегаций, когда нужно преобразовать массив в единое значение.

Синтаксис

```python
{
  $reduce: {
    input: <массив>,
    initialValue: <начальное значение>,
    in: <выражение>
  }
}
```

Ключевые параметры

input - массив для обработки

initialValue - начальное значение аккумулятора

in - выражение, содержащее:

$$value - текущее значение аккумулятора

$$this - текущий элемент массива

Пример 1: Суммирование с дополнительной логикой

Входные данные (transactions):

```python
{
  "_id": 1,
  "operations": [
    { "type": "income", "amount": 100 },
    { "type": "expense", "amount": 30 },
    { "type": "income", "amount": 50 }
  ]
}
```

Запрос:

```python
db.transactions.aggregate([
  {
    $project: {
      balance: {
        $reduce: {
          input: "$operations",
          initialValue: 0,
          in: {
            $cond: [
              { $eq: ["$$this.type", "income"] },
              { $add: ["$$value", "$$this.amount"] },
              { $subtract: ["$$value", "$$this.amount"] }
            ]
          }
        }
      }
    }
  }
])
```

Результат:

```python
{ "_id": 1, "balance": 120 }
```

1. Поиск максимального значения с дополнительными условиями

Входные данные (sales):

```python
{
  "month": "Январь",
  "dailyStats": [
    { "day": 1, "sales": 120, "returns": 10 },
    { "day": 2, "sales": 200, "returns": 5 },
    { "day": 3, "sales": 80, "returns": 15 }
  ]
}
```

Запрос:

```python
db.sales.aggregate([
  {
    $project: {
      month: 1,
      bestDay: {
        $reduce: {
          input: "$dailyStats",
          initialValue: { netSales: -Infinity, day: null },
          in: {
            $let: {
              vars: {
                currentNet: { $subtract: ["$$this.sales", "$$this.returns"] }
              },
              in: {
                $cond: [
                  { $gt: ["$$currentNet", "$$value.netSales"] },
                  { netSales: "$$currentNet", day: "$$this.day" },
                  "$$value"
                ]
              }
            }
          }
        }
      }
    }
  }
])
```

Результат:

```python
{
  "month": "Январь",
  "bestDay": { "netSales": 195, "day": 2 }
}
```

2. Конкатенация строк с разделителем

Входные данные (users):

```python
{
  "username": "ivan_92",
  "permissions": ["read", "write", "delete"]
}
```

Запрос:

```python
db.users.aggregate([
  {
    $project: {
      username: 1,
      permissionString: {
        $reduce: {
          input: "$permissions",
          initialValue: "",
          in: {
            $cond: [
              { $eq: ["$$value", ""] },
              "$$this",
              { $concat: ["$$value", " | ", "$$this"] }
            ]
          }
        }
      }
    }
  }
])
```

Результат:

```python
{
  "username": "ivan_92",
  "permissionString": "read | write | delete"
}
```

Особенности работы

Порядок обработки:

Элементы обрабатываются последовательно в порядке массива

Для изменения порядка сначала используйте $sortArray

Типы данных:

initialValue определяет тип результата

Можно использовать любые BSON-типы

Производительность:

Для простых операций (сумма, среднее) предпочтительнее специализированные операторы ($sum, $avg)

Оптимален для сложных многошаговых агрегаций

Лучшие практики

Всегда указывайте initialValue соответствующего типа

Для сложных условий используйте $let для временных переменных

Разбивайте сложные выражения на подвыражения

Тестируйте на больших массивах (более 10,000 элементов)

Оператор $reduce особенно полезен для:

Построения сложных агрегаций

Работы с вложенными структурами данных

Реализации нестандартной логики обработки массивов

Создания пользовательских агрегационных функций

Для типовых операций (суммирование, конкатенация) предпочтительнее использовать специализированные операторы, но когда нужна гибкость и контроль, $reduce становится незаменимым инструментом.

#### $slice: Возвращает подмассив (часть массива).

Оператор $slice возвращает подмассив (часть массива) по указанным позициям. Это полезно для:

Ограничения количества элементов в результате

Пагинации данных

Извлечения определенных элементов из массива

Синтаксис

```python
{ $slice: [ <массив>, <начало>, <количество> ] }
```

или

```python
{ $slice: [ <массив>, <количество> ] }
```

Пример 1: Базовое использование

Входные данные (articles):

```python
{
  "_id": 1,
  "title": "Новости дня",
  "comments": [

    { "user": "Ольга", "text": "Хороший материал" }
```

```python
db.articles.aggregate([
```

Запрос (последние 3 активных комментария):

```python
db.articles.aggregate([
  {
    $project: {
```

Особенности работы

Индексация:

Положительные числа - от начала массива (0-based)

Отрицательные числа - от конца массива

Граничные случаи:

Если начало > длины массива - вернет пустой массив

Если количество > доступных элементов - вернет все доступные

Ошибки:

Если первый аргумент не массив - вернет ошибку

Если параметры не числа - вернет ошибку


Избегайте вложенных $slice

Альтернативы

Агрегация + skip/limit:

```python

{ $skip: 10 },
{ $limit: 5 },
{ $group: { _id: "$_id", comments: { $push: "$comments" } } }
```

find() с projection:

```python

```

Оптимизации передачи данных

Для работы с большими наборами данных рекомендуется комбинировать $slice с другими операторами агрегации для достижения лучшей производительности.

4. Стадии соединения и объединения

Эти стадии используются для работы с несколькими коллекциями или объединения данных.

#### $lookup: Выполняет левое внешнее соединение (left outer join) с другой коллекцией.

Оператор $lookup выполняет аналог SQL LEFT JOIN между коллекциями. Разберём его на 5 практических примерах с исходными данными и результатами.

1. Базовый JOIN (один к одному)

Задача: Связать заказы (orders) с информацией о пользователях (users) по полю user_id.

Исходные данные

Коллекция orders:

```python
[
  { "_id": 1, "product": "Ноутбук", "user_id": 101 },
  { "_id": 2, "product": "Мышь",    "user_id": 102 },
  { "_id": 3, "product": "Клавиатура", "user_id": 999 } // Пользователя нет в коллекции users
]
```

Коллекция users:

```python
[
  { "_id": 101, "name": "Анна", "email": "anna@mail.com" },
  { "_id": 102, "name": "Борис", "email": "boris@mail.com" }
]
```

Пайплайн

```python
pipeline = [
  {
    "$lookup": {
      "from": "users",          // Имя коллекции для JOIN
      "localField": "user_id",  // Поле из коллекции orders
      "foreignField": "_id",    // Поле из коллекции users
      "as": "user_data"        // Куда сохранить результат
    }
  }
]
```

Пошаговое выполнение

Шаг 1: Для каждого документа в orders MongoDB ищет совпадения в users:

Берёт значение user_id из orders → ищет документы в users, где _id равен этому значению.

Шаг 2: Результаты поиска сохраняются в массив user_data:

Если совпадение найдено → добавляет документ из users в массив.

Если совпадений нет → массив остается пустым.

Процесс для каждого документа:

| Документ в orders | Поиск в users (_id = user_id) | Результат (user_data) |
| --- | --- | --- |
| { _id: 1, user_id: 101 } | Найден { _id: 101, name: "Анна" } | [{ _id: 101, name: "Анна" }] |
| { _id: 2, user_id: 102 } | Найден { _id: 102, name: "Борис" } | [{ _id: 102, name: "Борис" }] |
| { _id: 3, user_id: 999 } | Не найдено (_id: 999 отсутствует) | [] |

Итоговый результат

```python
[
  {
    "_id": 1,
    "product": "Ноутбук",
    "user_id": 101,
    "user_data": [
      { "_id": 101, "name": "Анна", "email": "anna@mail.com" } // Совпадение
    ]
  },
  {
    "_id": 2,
    "product": "Мышь",
    "user_id": 102,
    "user_data": [
      { "_id": 102, "name": "Борис", "email": "boris@mail.com" } // Совпадение
    ]
  },
  {
    "_id": 3,
    "product": "Клавиатура",
    "user_id": 999,
    "user_data": [] // Нет совпадений (LEFT JOIN)
  }
]
```

Ключевые моменты

Типы данных:

user_id (в orders) и _id (в users) должны быть одного типа (оба Number или оба String).

Если типы разные, используйте преобразование:

```python
"localField": { "$toString": "$user_id" },  // Привести к строке
"foreignField": "_id"  // _id тоже должен быть строкой
```

Индексы:

Для ускорения JOIN создайте индекс на foreignField:

db.users.createIndex({ "_id": 1 })

LEFT JOIN:

Все документы из orders сохраняются, даже если совпадений нет (user_data: []).

Разворот массива:

Если уверены, что совпадение единственное, добавьте $unwind:

```python
pipeline = [
  { "$lookup": { ... } },
  { "$unwind": "$user_data" } // Преобразует массив в объект
]
Результат:
{
  "_id": 1,
  "product": "Ноутбук",
  "user_id": 101,
  "user_data": { "_id": 101, "name": "Анна" } // Теперь это объект, а не массив
}
```

Как MongoDB оптимизирует запрос?

Сканирование orders: Читает каждый документ в коллекции orders.

Поиск в users: Для каждого user_id выполняет поиск по индексу _id в users (если индекс есть).

Сборка результата: Объединяет данные из orders с найденными документами из users.

Когда использовать?

Профили пользователей к заказам.

Комментарии к постам.

Дополнительные данные, которые хранятся в отдельных коллекциях.

3. Фильтрация при JOIN (вложенный пайплайн)

Задача: Присоединить только активные комментарии.

Исходные данные

Коллекция posts:

```python
[
  { "_id": 1, "title": "Первый пост", "content": "..." },
```

Коллекция comments:

```python

  { "_id": 3, "postId": 2, "text": "Интересно", "isActive": true },
  { "_id": 4, "postId": 2, "text": "Не согласен", "isActive": true }
]
```

Пошаговый разбор пайплайна

Этап 1: Подготовка переменных (let)

Для каждого документа в posts создаётся переменная post_id, куда сохраняется значение _id текущего поста.

Например, для поста с _id: 1 → post_id = 1.

Этап 2: Вложенный пайплайн в $lookup

MongoDB выполняет этот пайплайн для коллекции comments, используя контекст текущего документа из posts.

$match с $expr позволяет сравнивать поля между коллекциями.

Условия фильтрации:

```python
{ "$eq": ["$postId", "$$post_id"] }:
```

$postId — поле из коллекции comments.

$$post_id — переменная из let.

Условие: "комментарий принадлежит текущему посту".

```python
{ "$eq": ["$isActive", true] }:
```

Только комментарии с isActive: true.

Результат (as): Найденные комментарии сохраняются в массив active_comments.

Для поста _id: 1:

let: post_id = 1

Поиск в comments:

Условия: postId == 1 И isActive == true

Найден: { _id: 1, postId: 1, text: "Отлично!", isActive: true }

Пропущен: { _id: 2, ... } (так как isActive: false)

Результат:

```python
"active_comments": [
{ "_id": 1, "postId": 1, "text": "Отлично!", "isActive": true }]
```

Для поста _id: 2:

let: post_id = 2

Поиск в comments:

Условия: postId == 2 И isActive == true

Найдены:

```python
[
  { "_id": 3, "postId": 2, "text": "Интересно", "isActive": true },
```

```python
[
  { "_id": 1, "product": "Ноутбук", "user_id": 101 },

]
```

Коллекция users:

```python
[
  { "_id": 101, "name": "Анна", "email": "anna@mail.com" },
  { "_id": 102, "name": "Борис", "email": "boris@mail.com" }
]
```

Пайплайн

```python
pipeline = [
  {
    "$lookup": {
      "from": "users",
      "localField": "user_id",
      "foreignField": "_id",

    "$project": {
      "product": 1,
      "user_name": "$user.name",
      "user_email": "$user.email"
    }
  }
]
```

Результат

```python
[
  {
    "_id": 1,
    "product": "Ноутбук",
    "user_name": "Анна",
    "user_email": "anna@example.com"
  }
]
```

5. Несколько JOIN в одном пайплайне

Задача: Для заказа получить:

Данные пользователя

Историю платежей

Пайплайн

```python
pipeline = [
  {
    "$lookup": {
      "from": "users",
      "localField": "user_id",
      "foreignField": "_id",
      "as": "user"
    }
  },
  {
    "$lookup": {
      "from": "payments",
      "localField": "_id",
      "foreignField": "order_id",
      "as": "payments"
    }
  }
]
```

Результат

```python
[
  {
    "_id": 1,
    "product": "Ноутбук",
    "user_id": 101,
    "user": [{ "_id": 101, "name": "Анна" }],
    "payments": [
      { "_id": 1, "order_id": 1, "amount": 50000 },
      { "_id": 2, "order_id": 1, "amount": 10000 }
    ]
  }
]
```

Типичные ошибки

Разные типы полей: // Ошибка! user_id (число) ≠ _id (строка)

```python
{ "localField": "user_id", "foreignField": "_id" }
Решение: Привести к одному типу через $toString или $toInt.
```

Отсутствие индексов:

Создайте индекс на foreignField для ускорения:

db.users.createIndex({ "_id": 1 })

Большие массивы:

Если $lookup возвращает тысячи элементов, используйте $limit во вложенном пайплайне.

$lookup — это мощный инструмент для объединения данных.Базовый синтаксис прост, но поддерживает сложные сценарии через вложенные пайплайны. Всегда проверяйте типы данных и индексы для производительности.
