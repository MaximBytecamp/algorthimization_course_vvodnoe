03

Определение · инструмент

Что такое MongoDB

MongoDB — документная система управления базами данных. Она хранит записи не строками в таблицах с заранее объявленными столбцами, а документами: самостоятельными объектами из пар «поле — значение», у каждого из которых своя структура. Документы группируются в коллекции, коллекции — в базы данных. Обращения к данным идут не на SQL, а через методы драйвера или оболочки: find, insertOne, updateOne, deleteOne.

«MongoDB is a document database designed for ease of application development and scaling. MongoDB stores data records as BSON documents. BSON is a binary representation of JSON documents, though it contains more data types than JSON.»

MongoDB Manual · Documents / What is MongoDB
чем не является Не замена реляционной базе

В нашей платформе источником истины остаётся PostgreSQL. MongoDB берёт на себя тот участок, где данные читаются и меняются целым объектом.

без схемы? Схема есть, просто она не в базе

Сервер не требует объявлять поля заранее, поэтому в одной коллекции спокойно лежат документы разной формы. Схема при этом никуда не девается — она переезжает в код приложения. На занятии 3 мы вернём часть проверок в базу.

чем управляем сегодня Сервер, оболочка и GUI

mongod — сам сервер, mongosh — консольная оболочка, Compass — графический клиент. Сегодня работаем через Compass, потому что в нём видно и данные, и типы, и результат запроса сразу.

Определение · документ

Документ: пары «поле — значение», где значением может быть другой документ

«A document is the basic unit of data in MongoDB. MongoDB documents are composed of field-and-value pairs… The value of a field can be any of the BSON data types, including other documents, arrays, and arrays of documents.»

MongoDB Manual · Documents · Document Structure
структура документаиз документации
{
   field1: value1,
   field2: value2,
   ...
   fieldN: valueN
}

Три следствия, которые видно уже на нашем резюме.

  • 1
    Значение — объектeducation хранит внутри себя level, place и year. Отдельная таблица для этого не нужна.
  • 2
    Значение — массивskills — это список строк прямо в документе, а не пять строк в таблице связи.
  • 3
    Значение — массив объектовexperience — список мест работы, у каждого свои поля и свой вложенный stack. Вложенность в вложенности здесь обычное дело.

Имена полей — строки. Имя _id зарезервировано под первичный ключ: оно уникально в пределах коллекции и не меняется.

06

Определение · формат хранения

BSON: не текст, а двоичная запись документа

На экране Compass документ выглядит как JSON, но на диске и в сети он лежит по-другому. BSON (Binary JSON) — двоичный формат представления документов. Каждое значение в нём записано с явным указанием типа и длины, поэтому серверу не нужно разбирать текст, чтобы понять, где заканчивается одно поле и начинается следующее.

«BSON is a binary serialization format used to store documents and make remote procedure calls in MongoDB. The BSON specification is located at bsonspec.org. BSON is a binary representation of JSON documents, though it contains more data types than JSON.»

MongoDB Manual · BSON Types
зачем двоичный Читается без разбора текста

Длина документа записана в первых четырёх байтах, длина каждой строки — перед самой строкой. Чтобы пропустить поле, достаточно прибавить число к смещению.

зачем типы Числа остаются числами

В JSON 65000 и "65000" различаются, а 2026-09-01 вообще не отличить от строки. В BSON есть отдельные типы для 32-битного целого, 64-битного целого, даты и двоичных данных.

чем платим Размер больше, чем у текста

Служебные байты длины и типа тоже занимают место. Наш первый документ — 183 байта, развёрнутое резюме Дроздовой — 697 байт. Числа получены запросом $bsonSize на нашем же стенде.

07

Разовый приём · документ по байтам

Один документ { n: "Пётр" } — 21 байт

15000000 02 6E00 09000000 D09FD191D182D18000 00
4 байта · длинаВесь документ занимает 0x15 = 21 байт. Число записано младшим байтом вперёд.
1 байт · тип0x02 — строка. У каждого типа свой номер: 1 — double, 2 — string, 8 — bool, 9 — date, 16 — int32.
2 байта · имя поля6E — латинская n, затем нулевой байт как признак конца имени.
13 байт · значениеСначала длина строки вместе с нулём — 9, затем «Пётр» в UTF-8: каждая кириллическая буква занимает два байта.
1 байт · конецНулевой байт закрывает документ. По нему сервер понимает, что полей больше нет.
docker exec -it hh-mongo mongosh hh
hh> db.aggregate([
     { $documents: [ { n: "Пётр" }, { a: 1 } ] },
     { $project: { doc: "$$ROOT",
                  size: { $bsonSize: "$$ROOT" } } }
   ])

[ { doc: { n: 'Пётр' }, size: 21 },
  { doc: { a: 1 },      size: 12 } ]

Пересчитайте сами: 4 + 1 + 2 + 4 + 9 + 1 = 21. Столько же вернул и сервер — вывод слева снят на нашем стенде, а не переписан из документации.

У документа { a: 1 } получается 12 байт: имя поля на байт короче, тип другой — 0x10, целое число, и значение занимает 4 байта вместо девяти.

Оператор $bsonSize считает размер документа в байтах и работает в конвейере агрегации. $$ROOT — это весь документ целиком; $documents позволяет посчитать то, чего в базе ещё нет. Тем же запросом по коллекции получаются 183 байта у резюме Беловой и 697 у Дроздовой — самое короткое и самое длинное из девяти.

Типы BSON: номер, псевдоним и где мы его увидим

Тип№Где в нашей коллекции
String2fio, city, position — текст в двойных кавычках
Object3education, contacts — вложенный документ
Array4skills, experience — список значений или объектов
ObjectId7_id — идентификатор, который база ставит сама

09

Определение · первичный ключ

Поле _id и 12 байт ObjectId

Мы не писали _id, когда вставляли первый документ, а он появился. Так и задумано: если поле не передали, драйвер или сервер подставляет значение типа ObjectId. Это 12 байт, у которых есть внутренняя структура — и по ним можно узнать, когда документ создан.

6a9e467a 4831d3c4cf a42092
4 байта · времяСекунды с 1 января 1970 года. 0x6a9e467a = 1 788 757 626, то есть 7 сентября 2026 года, 05:07:06 UTC — момент, когда мы вставили резюме Беловой.
5 байт · процессСлучайное значение, одно на процесс клиента. Оно разное на разных машинах, поэтому два клиента не столкнутся идентификаторами.
3 байта · счётчикУвеличивается на каждый новый ObjectId внутри процесса. Он и разводит документы, созданные в одну и ту же секунду.

«The 12-byte ObjectId consists of: a 4-byte timestamp, representing the ObjectId's creation, measured in seconds since the Unix epoch; a 5-byte random value generated once per client-side process; a 3-byte incrementing counter, initialized to a random value.»

MongoDB Manual · mongosh Methods · ObjectId()
docker exec -it hh-mongo mongosh hh
hh> const d = db.resumes.findOne({ fio: "Анна Белова" })
hh> d._id.toString()
'6a9e467a4831d3c4cfa42092'
hh> d._id.getTimestamp()
ISODate('2026-09-07T05:07:06.000Z')

Первые четыре байта идентификатора и дата в выводе — одно и то же число, записанное двумя способами. Отсюда полезное следствие: сортировка по _id почти совпадает с сортировкой по времени создания. Но полагаться на это как на точное время не стоит — секунды ставит клиент, а не сервер, и часы на машине студента могут отставать.

Заход · что именно мы ставим

Сервер и клиент — это две разные программы

Здесь чаще всего и путаются: «скачал MongoDB» может означать и то, и другое. Сервер хранит данные и отвечает на запросы, клиент — рисует окно и эти запросы отправляет. Без сервера клиенту не к чему подключаться, а сервер прекрасно работает и без всякого окна.

сервер · mongod Держит данные и слушает порт 27017

Мы поднимаем его образом mongo:7 в Docker Compose. Так у всей группы одна и та же версия, а полный сброс делается одной командой — это пригодится, когда мы будем ломать стенд намеренно.

ставится один раз на весь раздел
клиент · MongoDB Compass Показывает данные, типы и результат запроса

Отдельное приложение с сайта mongodb.com. Оно ничего не хранит: закроете Compass — данные останутся на сервере. Кроме него есть консольная оболочка mongosh, к ней мы придём на занятии 2.

Поднимаем MongoDB в Docker Compose

services:
  mongo:
    image: mongo:7          # одна версия у всей группы
    container_name: hh-mongo
    ports:
      - "27017:27017"    # порт наружу = порт внутри
    volumes:

Шаг 3 из 6 · подключение

Открываем Compass и подключаемся строкой mongodb://localhost:27017

Строка подключения разбирается на четыре части, и каждая отвечает за своё.

  • 1
    mongodb://Схема: по ней клиент понимает, каким протоколом говорить. У облачного Atlas схема другая — mongodb+srv://.
  • 2
    localhostАдрес сервера. Контейнер пробросил порт на нашу же машину, поэтому адрес локальный.
  • 3
    27017Порт MongoDB по умолчанию. Если он занят другим стендом, в docker-compose.yml меняется левое число, и здесь пишется оно же.
  • 4
    NameИмя соединения — только для нас, на сервер оно не уходит. Пишем «Стенд занятия», чтобы через месяц не гадать, что это за адрес.

Логина и пароля в строке нет: сервер поднят без проверки подлинности. Для учебного стенда на своей машине это допустимо, и мы к этому вернёмся в разделе о защите — там пустой пароль станет отдельной темой разговора.

Отказ · читаем сообщение целиком

Compass пишет ECONNREFUSED — и это хорошая новость

что означает Адрес есть, слушать некому

Соединение отклонено на уровне операционной системы: по адресу 127.0.0.1:27017 никто не отвечает. То есть Compass дошёл до нужной машины, но программы на порту нет.

что делать Проверить сервер, а не строку

Смотрим docker compose ps: если контейнера нет или он Exited — поднимаем заново. У нас на паре так и вышло: контейнер остановился, пока мы читали теорию.

чем отличается от других Три сообщения — три разные причины

ECONNREFUSED — сервер не запущен. Server selection timed out — адрес недоступен, чаще всего опечатка в имени хоста. Authentication failed — сервер есть, но не пускает: неверные логин или пароль.

Шаг 5 из 6 · база и коллекция

База hh и коллекция resumes создаются одним окном

Compass не даёт создать базу без коллекции — и это не каприз интерфейса, а свойство сервера.

«If a collection does not exist, MongoDB creates the collection when you first store data for that collection.»

MongoDB Manual · Databases and Collections

То есть база живёт ровно до тех пор, пока в ней что-то лежит. Пустая база, из которой удалили последнюю коллекцию, исчезает из списка сама.

Определение · запрос

Фильтр — это тоже документ

В SQL запрос написан на отдельном языке: SELECT … WHERE city = 'Ярославль'. В MongoDB запрос — это такой же объект из пар «поле — значение», что и данные. Мы описываем документом, каким должен быть искомый документ, и сервер возвращает все, которые под описание подходят.

форма { поле: значение }

Простейший фильтр: найти всё, где поле равно значению. Пустой фильтр {} означает «без условий» — вернутся все документы коллекции.

оператор { поле: { $оператор: значение } }

Когда нужно не равенство, значение заменяется вложенным документом с оператором: $gt — больше, $lt — меньше, $in — входит в список, $exists — поле есть.

несколько условий { поле1: …, поле2: … }

Два поля в одном фильтре соединяются по «и». Отдельный $and для этого не нужен — он пригодится только там, где условия относятся к одному и тому же полю.

Где это набирать: строка запроса на вкладке Documents. Кнопка Find выполняет фильтр, Reset очищает, Options открывает сортировку, проекцию и ограничение количества.

Запрос 1 из 5 · точное совпадение

{ city: "Ярославль" } — 5 документов из 9

Самая частая форма запроса и самая частая причина пустого результата.

  • 1
    Значение сравнивается целиком«Ярославль» не найдёт «г. Ярославль» и не найдёт «ярославль». Поиск по части строки — это отдельный оператор $regex, и он работает медленнее.
  • 2
    Тип тоже сравнивается{ salary: 65000 } не найдёт документ, где зарплата сохранена строкой "65000". Число и строка — разные значения.
  • 3
    Кавычки обязательныСтрока пишется в кавычках, число — без. Через два экрана мы посмотрим, что будет, если про это забыть.
25

Запросы 2 и 3 из 5 · вглубь документа

Точка идёт внутрь объекта, а массив ищется по элементу

вложенное поле Путь через точку, всё вместе в кавычках

Запись "education.level" означает «поле level внутри объекта education». Кавычки нужны, потому что точка внутри имени иначе читается как обращение к свойству. Глубина не ограничена: "experience.0.stack" добирается до стека первого места работы.

массив Условие проверяется для каждого элемента

{ skills: "MongoDB" } читается не как «массив равен строке», а как «среди элементов массива есть такой». Ни $in, ни индекс элемента для этого не нужны — и это, пожалуй, самое неожиданное правило для того, кто пришёл из SQL.

26

Запрос 4 из 5 · сравнение, сортировка, проекция

Кто просит больше 100 000 — по убыванию и только два поля

  • 1
    Filter: { salary: { $gt: 100000 } }Оператор $gt — строго больше. Есть и $gte, $lt, $lte, $ne.
  • 2
    Project: { fio: 1, salary: 1, _id: 0 }Единица — «показать поле», ноль — «убрать». Поле _id возвращается всегда, если его не выключить явно.
  • 3
    Sort: { salary: -1 }Минус единица — по убыванию, единица — по возрастанию. Самойлов со 150 000 оказывается первым.

Проекция — это не украшение. Она уменьшает то, что сервер собирает и передаёт по сети, и на больших документах разница заметна. Когда мы дойдём до производительности, это будет первым, что мы проверяем в медленном запросе.

27

Запрос 5 из 5 · есть ли поле

{ portfolio: { $exists: true } } — вопрос, которого нет в SQL

В таблице столбец есть у всех строк, вопрос стоит иначе: пустое значение или нет. В коллекции поле может просто отсутствовать, и это третье состояние.

поля нет { portfolio: { $exists: false } }

Семь резюме, где ссылки на портфолио никто не заполнял.

поле есть, значение пустое { portfolio: null }

Осторожно: этот фильтр находит и документы, где поля нет вовсе. Чтобы разделить два случая, условия придётся соединить.

$exists — рабочий инструмент, когда коллекция копилась годами и форма документов менялась. Он же первым показывает, что схема в коде и схема в базе разошлись.

Отказ · разбор ошибки

Строка без кавычек: кнопка Find гаснет

что произошло Запрос даже не ушёл на сервер

Compass разбирает фильтр у себя, и Ярославль без кавычек для него — имя переменной, а не строка. Разбор не удался, поэтому кнопка отключилась, а список документов остался прежним.

чем это отличается от пустого результата Ноль документов — тоже ответ

Если фильтр разобрался, но ничего не нашёл, счётчик покажет 0 – 0 of 0, а рамка останется обычной. Красная рамка означает ошибку записи, пустой список — ошибку в данных или в условии.

привычка Смотреть на счётчик, а не на экран

Строка 1 – 5 of 5 — единственное честное подтверждение, что запрос выполнен и вернул именно столько. Скриншот со счётчиком мы и просим приложить к работе.

Две вкладки, которые пригодятся дальше

Что Compass знает о коллекции без нашего описания

Schema Схема, восстановленная по данным

Compass берёт выборку документов и показывает, какие поля встречаются, каких типов и как распределены значения. У city сразу видно, что Ярославль занимает большую часть, а у courses — что поле есть далеко не везде. Это отчёт по факту, а не описание схемы: сервер такой схемы не хранит.

Indexes Единственный индекс создан не нами

Индекс _id_ сервер создаёт вместе с коллекцией, и удалить его нельзя. Все наши сегодняшние запросы шли без индексов — на девяти документах это незаметно. На занятии 4 мы посмотрим тот же запрос на выборке побольше и научимся читать план его выполнения.
