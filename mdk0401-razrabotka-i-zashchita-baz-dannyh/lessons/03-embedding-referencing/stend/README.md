# Стенд занятия 2 · две формы одной связи

Тот же одиночный MongoDB 7, что и на занятии 1. Новое здесь — данные: одна и та же
связь «резюме → компания» собрана двумя способами, и обе формы лежат в базе рядом,
чтобы их можно было сравнить не на словах, а запросом.

## Запуск

```bash
docker compose up -d      # поднять сервер
docker compose ps         # статус должен стать healthy
```

Строка подключения для Compass — `mongodb://localhost:27017`, база `hh`.
Если Docker не встаёт, три способа поднять сервер разобраны в
[`../../02-mongodb-pervyy-dokument/stend/SETUP.md`](../../02-mongodb-pervyy-dokument/stend/SETUP.md).

## Загрузка данных

```bash
for f in companies resumes_embed resumes_ref interviews; do
  docker exec -i hh-mongo mongoimport --quiet --db hh --collection $f --drop --jsonArray < seed/$f.json
done
```

В Compass то же самое делается через **ADD DATA → Import JSON or CSV file** по одному файлу.

| Коллекция | Документов | Что внутри |
|---|---|---|
| `companies` | 8 | справочник компаний, ключ `_id` задан руками: `"c-ozon"`, `"c-tensor"` |
| `resumes_embed` | 150 | компания вложена в каждый элемент `experience` целиком |
| `resumes_ref` | 150 | те же резюме, но в `experience` только `company_id` |
| `interviews` | 60 | приглашения на собеседование; здесь та же компания продублирована второй раз |

Резюме в обеих коллекциях одни и те же и лежат под одинаковыми `_id` — иначе
сравнивать формы было бы нечестно.

## Скрипты

| Файл | Что делает | Сколько идёт |
|---|---|---|
| `queries.mongodb.js` | три счёта занятия: чтение карточки, отчёт по отрасли, заявка CR-014; плюс размер и кардинальность | ~5 секунд |
| `grow.mongodb.js` | доводит встроенный массив до предела документа: рост по шагам, отказ на вставке и отказ на дописывании | ~30 секунд |
| `scale.mongodb.js` | собирает большую базу (20 000 резюме, 5 000 компаний) и повторяет замеры на ней | ~40 секунд |

Запуск любого:

```bash
docker exec -i hh-mongo mongosh hh --quiet --file /dev/stdin < queries.mongodb.js
mongosh hh --quiet --file queries.mongodb.js        # если сервер стоит в системе
```

Ключ `--file` обязателен: без него `mongosh` читает поток как ввод в оболочку
и рвёт запросы, записанные в несколько строк.

**`queries.mongodb.js` меняет данные:** он выполняет заявку CR-014 и переименовывает
компанию. Чтобы вернуть базу в исходное состояние, перезалейте `seed/` командой выше —
она идёт с ключом `--drop`.

## Числа, которые должны получиться

| Что | Значение |
|---|---|
| копий названия «Ozon Tech» | 49 в резюме + 5 в приглашениях + 1 в справочнике |
| правка в вложенной форме | `modifiedCount: 49` |
| правка в ссылочной форме | `modifiedCount: 1` |
| объём | 129 914 байт против 94 018 + 1 176 |
| предел документа | остановка на 86 000 откликов, 16 694 908 байт |

Миллисекунды у вас будут свои — они зависят от машины. Число документов и число
байт должны совпасть: если нет, данные загрузились не полностью или дважды.
