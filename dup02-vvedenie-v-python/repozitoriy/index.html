Работа с репозиторием курса

Все работы по дисциплине хранятся в одном репозитории на GitHub. Его создаёт каждый студент из шаблона преподавателя. Здесь по шагам разобрано всё, что с ним делается: как создать, как работать за компьютером колледжа и дома, как сдать работу и как получить новые задания.

Где лежат файлы

Работа идёт с тремя копиями. Шаблон ведёт преподаватель. Ваш репозиторий на GitHub — копия шаблона, в которую вы сдаёте работы. Папка на компьютере — копия вашего репозитория, в ней вы пишете код.

Из этого следуют два правила. Работа считается сданной, когда она есть в вашем репозитории на GitHub. Файлы, которые лежат только в папке на компьютере, преподаватель не видит. Новые задания сначала приходят на GitHub, а на компьютере появляются после Sync Changes.

1Первый раз: создать репозиторий

Делается один раз в начале курса, удобнее всего в браузере. Если аккаунт на GitHub уже есть, начните с шага 2.

  1. Зарегистрируйтесь на GitHub

    Откройте github.com/signup, введите почту, пароль и имя пользователя (логин). Подтвердите почту кодом из письма.

    Логин будет в адресе каждого вашего репозитория, его увидит работодатель. Берите латиницу по имени и фамилии: ivan-petrov, ipetrov-dev. Не подходят krutoy2009, user123456.

    справа вверху на github.com стоит ваш аватар, в меню под ним — ваш логин.
  2. Скопируйте почту для коммитов

    Git подписывает каждое сохранение (коммит) почтой. Репозиторий открытый, поэтому настоящую почту увидит любой. GitHub выдаёт для этого служебный адрес.

    • Аватар справа вверху → Settings → слева Emails.
    • Отметьте Keep my email addresses private.
    • Под этим пунктом написан адрес вида 12345678+ivan-petrov@users.noreply.github.com. Скопируйте его в заметки: он понадобится в разделах 2 и 3.
    Коммиты с другой почтой не появятся на графике активности в профиле. Если указать настоящую почту при включённом пункте Keep private, GitHub не примет отправку с ошибкой GH007.
  3. Откройте шаблон курса

    github.com/MaximBytecamp/python-start-template. Справа вверху над списком файлов нажмите Use this template → Create a new repository.

    Кнопку Fork не нажимайте. Форк остаётся привязан к шаблону, и GitHub не засчитывает коммиты в форке в активность профиля.
  4. Заполните форму
    ПолеЧто выбрать
    Include all branchesне отмечать
    Ownerваш логин
    Repository namepython-start
    DescriptionМои работы по Python: домашние, практические, задачник
    видимостьPublic: репозиторий должны открыть преподаватель и работодатель

    Нажмите Create repository.

    под именем репозитория написано generated from MaximBytecamp/python-start-template. Без этой строки обновления материалов приходить не будут: удалите репозиторий и создайте заново по шагу 3.
  5. Впишите себя в README

    На странице репозитория откройте файл README.md → значок карандаша ✎ справа вверху. Замените Имя Фамилия на свои, впишите группу. Нажмите Commit changes… → в окне оставьте Commit directly to the main branch → Commit changes.

    Этот файл первым видит любой, кто открывает репозиторий. Позже в таблицу «Лучшие работы» добавьте 2–3 работы, которые стоит открыть первыми.

  6. Добавьте темы репозитория

    Справа на странице репозитория, блок About → шестерёнка ⚙. В поле Topics введите через пробел python python3 learning → Save changes. По темам репозиторий находится в поиске GitHub.

  7. Отправьте ссылку преподавателю

    Скопируйте адрес из строки браузера: https://github.com/ваш-логин/python-start.

2Начало пары за компьютером колледжа

За этим компьютером до вас работали другие студенты. Их аккаунт может остаться в трёх местах: в браузере, в VS Code и в хранилище паролей Windows. Пока там чужой вход, ваши коммиты уйдут от чужого имени или GitHub не примет отправку. Проверка занимает пару минут, её делают в начале каждой пары.

  1. Браузер: войдите в свой GitHub

    Откройте github.com. Если справа вверху чужой аватар: аватар → Sign out → на странице подтверждения снова Sign out (если вошли несколько аккаунтов — Sign out from all accounts). Затем Sign in и войдите в свой аккаунт.

    аватар → в меню ваш логин.
  2. VS Code: выйдите из чужого аккаунта

    Значок человечка внизу левой панели. Если там чужое имя: имя → Sign Out.

  3. Удалите сохранённый пароль GitHub

    Git запоминает вход отдельно от VS Code, в хранилище паролей системы. После выхода из VS Code запись прошлого студента остаётся, и Git отправит ваши файлы от его имени.

    Windows

    1. Пуск → наберите Диспетчер учётных данных → откройте.
    2. Вкладка Учётные данные Windows.
    3. В списке «Общие учётные данные» найдите записи со словом github, например git:https://github.com.
    4. Каждую раскройте стрелкой → Удалить → Да.

    То же одной командой в терминале: cmdkey /delete:git:https://github.com

    macOS

    1. Cmd + Пробел → наберите Связка ключей (Keychain Access) → откройте.
    2. В поиске справа вверху введите github.com.
    3. Записи вида «пароль интернета»: правая кнопка → Удалить.
    в списке нет записей со словом github. Если записей не было с самого начала, шаг пропускается.
  4. Склонируйте свой репозиторий

    VS Code → значок Source Control слева (Ctrl + Shift + G) → Clone Repository → Clone from GitHub.

    VS Code попросит войти: Allow → откроется браузер → Continue или Authorize Visual-Studio-Code → вернитесь в VS Code. Если окно предлагает войти от чужого имени, значит, в браузере не выполнен шаг 1.

    В списке выберите ваш-логин/python-start. Папку для копии укажите Документы: не «Загрузки» и не рабочий стол. На вопрос Would you like to open the cloned repository? нажмите Open.

    слева в проводнике VS Code видны папки homework, practice, problems, exams; в строке состояния внизу слева написано main.
  5. Укажите Git своё имя и почту

    Откройте терминал: Terminal → New Terminal (Ctrl + `). Терминал откроется в папке репозитория. Выполните три команды, подставив своё имя и почту из шага 2 раздела 1:

    git config user.name "Иван Петров"
git config user.email "12345678+ivan-petrov@users.noreply.github.com"
git config pull.rebase false

    Команды без --global пишут настройку только в эту папку. Следующий студент за этим компьютером её не получит. Настройка папки важнее общей настройки компьютера, поэтому имя прошлого студента в ваши коммиты не попадёт. Третья команда говорит Git, как объединять ваши коммиты с новыми материалами, пришедшими на GitHub.

    команда git config user.email печатает вашу почту.
Если папка уже склонирована вами на прошлой пареОткройте её через File → Open Folder… и нажмите Sync Changes, чтобы забрать новое с GitHub. Шаги 1–3 выполняются всё равно: на компьютере мог работать кто-то после вас. Если папки нет или сомневаетесь, чья она, склонируйте заново: всё сданное лежит на GitHub.

3Свой компьютер дома

Настройка делается один раз. Python и VS Code ставятся по главе 0 справочника.

  1. Установите Git

    Windows

    Скачайте установщик с git-scm.com/downloads/win и установите, на всех экранах нажимая Next. Перезапустите VS Code.

    macOS

    В терминале выполните git --version. Если Git не установлен, система предложит поставить инструменты разработчика: нажмите Установить.

    в терминале VS Code команда git --version печатает номер версии.
  2. Укажите Git имя и почту для всего компьютера

    Дома компьютер ваш, поэтому настройка ставится с --global один раз для всех папок:

    git config --global user.name "Иван Петров"
git config --global user.email "12345678+ivan-petrov@users.noreply.github.com"
git config --global pull.rebase false
  3. Войдите в GitHub и склонируйте репозиторий

    Как в шагах 4 раздела 2: Clone Repository → Clone from GitHub → ваш python-start → папка Документы → Open.

  4. Дальше — каждый раз

    VS Code при запуске открывает последнюю папку. Перед работой нажмите Sync Changes или значок ⟳ внизу в строке состояния. Клонировать заново не нужно.

4Сдать работу из VS Code

Порядок одинаковый для домашних, практических работ, задачника и контрольных. Все работы загружаются в ветку main: отдельные ветки и Pull Request не создаются.

  1. Заберите новое с GitHub

    Source Control → Sync Changes (или ⟳ в строке состояния). Так на компьютер придут новые задания и правки, сделанные через сайт.

  2. Узнайте, куда класть работу

  3. Создайте папку и файлы

    В проводнике VS Code наведите на папку homework → значок New Folder… → введите имя, например 01-variables. Затем на новой папке → New File… → task_01.py.

    Кнопка ▷ справа вверху или в терминале python homework/01-variables/task_01.py (на macOS — python3). Сверьте вывод с примерами задания.

  5. Сделайте коммит

    Source Control → в поле Message напишите, что сдаёте. Первое слово — папка, затем номер и что сделано: homework 01: задачи 1–3. Нажмите ✓ Commit.

  6. Отправьте на GitHub

    После коммита на месте кнопки появится Sync Changes 1↑: один коммит ждёт отправки. Нажмите её. Если VS Code спросит про отправку и получение коммитов, нажмите OK.

  7. Проверьте на сайте

    Откройте свой репозиторий на github.com. Над списком файлов — ваше сообщение коммита и ваш логин, в папке homework — новая папка.

    коммит на GitHub подписан вашим логином. Если там чужое имя или серый значок без аватара — раздел 8, строки 2 и 3.

5Сдать работу через сайт GitHub

Подходит, когда файлы готовы, а VS Code под рукой нет: на чужом компьютере, с телефона. Если вы работаете и в VS Code, перед следующей работой в нём нажмите Sync Changes, чтобы забрать загруженное через сайт.

Загрузить готовые файлы в новую папку

  1. Откройте папку вида работы

    Свой репозиторий на github.com → папка homework (или practice, problems, exams).

  2. Создайте папку работы

    GitHub не создаёт пустые папки, поэтому папка появляется вместе с первым файлом. Нажмите Add file → Create new file. В поле имени наберите 01-variables/README.md: знак / превращает 01-variables в папку. В тексте файла напишите задание. Нажмите Commit changes…, в сообщении — homework 01: README, оставьте Commit directly to the main branch → Commit changes.

  3. Загрузите файлы решений

    Вы оказались в новой папке. Add file → Upload files → перетащите файлы task_01.py, task_02.py. Внизу в сообщении напишите homework 01: задачи 1–2 → Commit changes.

    Пункт Create a new branch for this commit не выбирайте: работа уйдёт в отдельную ветку, и в main её не будет видно.

Исправить файл, который уже лежит в репозитории

Откройте файл → карандаш ✎ → исправьте → Commit changes… → сообщение homework 01: исправлена задача 2 → Commit changes.

6Получить новые задания

Преподаватель дополняет шаблон: новые задания, конспекты, заготовки задач. Создавать репозиторий заново не нужно.

Как это устроено

В репозитории лежит файл .github/workflows/update-materials.yml. Каждый день в 06:00 по Москве GitHub по этому файлу сравнивает ваш репозиторий с шаблоном и переносит новое. В истории это коммит materials: обновление из шаблона курса от github-actions[bot].

ЧтоЧто происходит
lectures/, materials/, docs/заменяются версией преподавателя
README.md в папках homework/, practice/, problems/, exams/заменяются: в них таблицы выданных работ
новые папки заданий и заготовкидобавляются, если их у вас нет
ваши решения, ваши README.md в папках работ, README.md в корнене меняются

Отсюда правило: файлы из первых двух строк не редактируйте, правка пропадёт при следующем обновлении. Свои решения пишите в своих файлах.

Забрать обновление сразу

  1. Запустите обновление на GitHub

    Свой репозиторий → вкладка Actions → слева Обновление материалов курса → справа Run workflow → зелёная Run workflow.

  2. Дождитесь зелёной галочки

    Через полминуты в списке появится запуск. Зелёная галочка — обновление прошло. Внутри запуска, в разделе Обновление материалов курса, перечислены добавленные и обновлённые файлы.

    Красный крестик и текст шаблон не найден означают, что репозиторий создан не кнопкой Use this template. Создайте его заново по разделу 1 и перенесите свои файлы.
  3. Заберите на компьютер

    VS Code → Sync Changes. Новые папки появятся в проводнике.

7Конец пары за компьютером колледжа

Следующий студент не должен получить доступ к вашему GitHub. Шаги обратные разделу 2.

  1. Отправьте всё на GitHub

    Source Control: в списке Changes пусто, на кнопке нет счётчика ↑. Если есть изменения — коммит и Sync Changes по разделу 4.

  2. Выйдите из VS Code

    Значок человечка → ваше имя → Sign Out.

  3. Удалите сохранённый пароль

    Как в шаге 3 раздела 2: Диспетчер учётных данных Windows или Связка ключей macOS, записи со словом github.

  4. Выйдите из GitHub в браузере

    Аватар → Sign out → на странице подтверждения снова Sign out.

  5. Удалите папку репозитория

    Закройте папку в VS Code (File → Close Folder) и удалите Документы/python-start. Всё отправленное хранится на GitHub, на следующей паре склонируете заново.

8Ошибки и что с ними делать

Полный текст ошибки VS Code показывает по кнопке Show Command Output или Open Git Log. Ищите строку из первого столбца.
