1Зачем и на что опирается

§1Что даёт стандарт

В библиотеке книги расставлены по одной системе. Читатель находит нужную полку в любом зале, библиотекарь проверяет фонд по одному списку. Стандарт репозитория делает то же для работ студентов: одинаковые папки и имена во всех дисциплинах.

КтоЧто получает
СтудентПапки, имена и порядок сдачи одинаковые на всех курсах. Разбираться заново в каждой дисциплине не нужно.
ПреподавательПроверяет работы по одному пути: homework/03-lists/task_02.py лежит там же у каждого студента.
РаботодательЗа полминуты понимает, чей репозиторий, что в нём и как запустить код.
ВсеНовые задания переносятся в репозиторий студента каждый день, пересоздавать его не нужно.

Открытый репозиторий студента — часть его портфолио. Поэтому правила начинаются с того, что смотрят при найме.

§2Что смотрит работодатель

Выводы из статей о найме начинающих разработчиков и из документации GitHub. У каждого вывода — источник и правило стандарта, которое из него следует.

ВыводИсточникПравило стандарта
На репозиторий кандидата тратят 30–60 секунд. По коду проект не изучают: что это за проект, должно быть видно из README.Хабр, 2024README в корне с одинаковыми разделами
README отвечает на три вопроса: что это, на чём написано, как запустить.DOUраздел «Как запустить» в README, проверка в README работы

Лучше 2–3 актуальных работающих репозитория, закреплённых в профиле, чем десяток брошенных.Хабр, 2025раздел «Лучшие работы» в README и закреплённые репозитории
Коммит попадает в график активности, если почта привязана к аккаунту, репозиторий не форк и коммит сделан в ветку по умолчанию.GitHub DocsUse this template вместо форка, все работы в main, служебная почта
График активности показывает регулярность. Совет — не меньше пяти дней с коммитами в неделю.BloomTechкоммит после каждой работы, все работы в одном аккаунте

Эти выводы говорят, что смотрят. Как это оформить, видно по репозиториям, которые собирают задачи и решения так же, как студенческий репозиторий собирает работы.

2Как устроен репозиторий

§4Структура репозитория

Набор папок одинаковый во всех дисциплинах. Папки, которых в дисциплине нет, в шаблоне не создаются: в курсе без задачника нет problems/.

Репозиторий студента на примере ДУП.02

python-start/имя: тема дисциплины латиницей через дефис
├── README.mdвизитка студента: автор, лучшие работы, как запустить
├── homework/домашние задания
│   ├── README.mdтаблица выданных ДЗ
│   └── 01-variables/README.md, task_01.py, task_02.py
├── practice/практические работы на занятиях
├── problems/задачник: chapter-1-3/task_07.py
├── exams/тесты quiz-NN и контрольные exam-NN
├── project/курсовой или сквозной проект, если он есть
├── lectures/конспекты занятий
├── materials/файлы, розданные на занятиях
├── docs/SUBMIT.md и UPDATES.md: правила сдачи и переноса
└── .github/workflow и скрипт переноса заданий

Подсвечены папки работ студента. Остальное ведёт преподаватель.

Каждый файл в репозитории принадлежит одному владельцу:

ПутьВладелецПри переносе из шаблона
README.md в корнестудентне меняется
папки работ и файлы в нихстудентновые папки и заготовки добавляются, существующие файлы не меняются
README.md папок первого уровняпреподавательзаменяется: в нём таблица выданных работ
lectures/, materials/, docs/, .github/scripts/, .gitignore, .gitattributesпреподавательзаменяются

Разделение по владельцу — основа стандарта. Студент и преподаватель не правят один и тот же файл, поэтому перенос из шаблона проходит без конфликтов. Чтобы преподаватель и студент одинаково называли папки и файлы, нужны правила имён.

§5Имена папок и файлов

Имя файла работает как подпись на корешке папки в архиве: по нему находят нужное без открытия. Поэтому имя называет содержимое и строится по одной схеме.

Было в шаблоне до 22.10.2026dz/dz-01-peremennye/zadacha_1.py
→

только a–z, 0–9, -, _task_01.pyзадача 1.pyкириллица и пробелы ломают адреса и команды терминала

Имя папки для новой работы задаёт преподаватель в таблице README.md папки вида работ. Студент копирует имя оттуда и не переводит тему на английский самостоятельно. Имена описывают папки, а первое, что видит гость репозитория, — README в корне.

§6README в корне

README в корне — обложка репозитория. Разделы и их порядок одинаковые у всех студентов. Файл принадлежит студенту, перенос из шаблона его не меняет.

Разделы README.md в корне

таблица «Автор»имя, группа, курс, язык, редактор
## Лучшие работы2–3 ссылки на работы, которые стоит открыть первыми
## Структурадерево папок с пояснениями

Описание репозитория на GitHub (блок About) повторяет первую фразу README. В Topics — язык и область: python, learning.

README в корне описывает весь репозиторий. Каждая работа внутри описывается своим README.

§8Сообщения коммитов

Сообщение коммита — строка в журнале изменений. По журналу видно, какая работа и когда менялась, если строки составлены по одной формуле: <папка> <номер>: <что сделано>.

ДЗ 1homework 01: задачи 1–3
исправление в ДЗ 1homework 01: исправлен вывод в задаче 2
задачникproblems 1.3: задачи 1–5
контрольнаяexam 01: вариант 2, задачи 1–10
перенос из шаблонаmaterials: обновление из шаблона курса (коммит бота)

Все работы — в ветке main. Ветки и Pull Request используются только в дисциплинах, где их проходят; такая дисциплина пишет об этом в своём docs/SUBMIT.md. Последняя строка таблицы — коммит, который делает GitHub при переносе заданий. Он появляется в истории каждого студента без его участия.

3Перенос заданий и профиль

§9Новые задания без пересоздания

Репозиторий, созданный кнопкой Use this template, не связан с шаблоном общей историей: GitHub копирует файлы одним коммитом. Поэтому кнопки «забрать изменения шаблона» у такого репозитория нет. Способов добавить перенос четыре:

СпособКак работаетПодходит
Форк и кнопка Sync forkфорк помнит исходный репозиторий, GitHub забирает изменения одной кнопкойнет: коммиты в форке не попадают в график активности
git merge --allow-unrelated-historiesстудент добавляет адрес шаблона и сливает его ветку со своейнет: первое слияние даёт конфликт в каждом файле, который преподаватель изменил после создания копии
Действие actions-template-syncпо расписанию открывает Pull Request с изменениями шаблонанет: каждому студенту нужно включить разрешение в настройках и сливать запросы; конфликты решаются в пользу шаблона и могут затереть решение
Свой workflow с правилом владельцараз в сутки скачивает шаблон, заменяет файлы преподавателя, добавляет недостающие, делает коммит в mainда: от студента действий не требуется, конфликтов нет, решения не перезаписываются

Выбран последний способ. Он работает в четыре шага:

Перенос заданий из шаблона, каждый день в 06:00 по Москве

1 · Запускфайл .github/workflows/update-materials.yml скопирован студенту вместе с шаблономпо расписанию или Run workflow
2 · Шаблонимя берётся из поля template_repositoryодин файл на все дисциплины
3 · Переносскрипт update_materials.py из свежей копии шаблона применяет правило владельцаничего не удаляется
4 · Коммитmaterials: обновление из шаблона курса от github-actions[bot]студент забирает Sync Changes

В самом шаблоне workflow завершается без изменений. Права workflow — contents: write: этого достаточно для коммита в свой репозиторий. Проверено 22.10.2026 на закрытом репозитории из python-start-template. Изменённый студентом конспект заменён версией шаблона, удалённый homework/README.md возвращён, решение в exams/exam-01/task_01.py сохранено.

На полях: ограничение токена

Токен GitHub Actions не может менять файлы в .github/workflows/. Если изменится сам файл workflow, студенты, создавшие репозиторий раньше, получат новую версию только вручную. Поэтому логика переноса вынесена в скрипт, а workflow оставлен минимальным.

Репозиторий наполняется работами и заданиями. Чтобы его увидели при найме, нужно оформить профиль.

4Для преподавателя

§11Для преподавателя

Шаблон дополняется после каждого занятия. Новая работа выдаётся в четыре шага:

  1. В homework/README.md (или practice/, exams/) дописать строку: папка, задание, срок.
  2. Если нужна заготовка — папка homework/NN-тема/ с README.md и пустыми task_NN.py. Студент получит её, если у него ещё нет такой папки.
  3. Конспект в lectures/ и файлы в materials/ — по shared/REPO_TEMPLATES.md.
  4. Коммит и push в шаблон. На следующее утро материалы будут у всех студентов.

Чего не делать с выданными файлами

Не переименовывать и не удалятьУ студентов старые файлы останутся, новые добавятся рядом.
Не менять заготовки после выдачиУ студента, который уже начал, они не обновятся. Исправление пишется в README.md папки вида работ или в docs/.
Не класть решения и ответыШаблон открытый.
