# Шаблоны репозиториев студентов

Правила для репозиториев-шаблонов дисциплин: что в них лежит, что дополняется
после каждого занятия и что проверяется перед публикацией. Студент создаёт
из шаблона личную копию кнопкой **Use this template** и ведёт в ней все работы
по дисциплине.

## Где лежат шаблоны

Исходник каждого шаблона — отдельный git-репозиторий внутри папки дисциплины
(в `.gitignore` курса). Публикация — `push` в `main` репозитория на GitHub.

| Дисциплина | Исходник в курсе | Репозиторий на GitHub |
|---|---|---|
| ОП.03 Информационные технологии | `op03-informacionnye-tehnologii/funnel-starter/` | `MaximBytecamp/funnel-project-template` |
| ОП.03, сайт для практики | `op03-informacionnye-tehnologii/ga4-analytics-lab/` | `MaximBytecamp/ga4-analytics-lab` |
| ОП.04 Алгоритмизация | `op04-algoritmizaciya/starter-pack/` | `MaximBytecamp/algo-portfolio-template` |
| ОП.05 Операционные системы | `op05-operacionnye-sistemy-i-sredy/os-starter/` | `MaximBytecamp/os-environments-template` |
| МДК.01.01 Разработка модулей | `mdk0101-razrabotka-modulei/backend-starter/` | `MaximBytecamp/backend-starter-template` |
| МДК.04.01 Базы данных | `mdk0401-razrabotka-i-zashchita-baz-dannyh/data-platform-starter/` (вторая копия — `~/data-platform-template`) | `MaximBytecamp/data-platform-template` |
| Стандартизация | `standartizaciya-sertifikaciya-i-dokumentovedenie/api-standard-template/` | `MaximBytecamp/api-standard-template` |

Коммиты в шаблоны — с почтой `bytecampmm@gmail.com` и без трейлера
`Co-Authored-By`.

Перед работой выполнить `git fetch` и сравнить с `origin/main`: шаблон мог
измениться из другой копии. Если локальная копия отстаёт, сначала
`git pull --ff-only`.

`api-standard-template` — эталонный проект API, работы по занятиям в него
не сдаются. Папки `lectures/` и `materials/` в него не добавляются, ветка `main`
защищена, правки идут через pull request. `ga4-analytics-lab` — код сайта
для практик ОП.03; конспекты к нему лежат в `funnel-project-template`.

## Состав шаблона

| Путь | Что внутри |
|---|---|
| `README.md` | назначение репозитория, как создать копию, таблица заданий, порядок сдачи, ссылки на `lectures/` и `materials/` |
| `lesson_NN/` | задание: `README.md` с условием, бланк `homework_NN.md`, `screens/README.md` с именами кадров |
| `lectures/` | конспект каждой проведённой темы и `README.md` с оглавлением |
| `materials/tema-NN-…/` | файлы, которые раздавались на занятии, и `README.md` с описанием каждого файла |
| `docs/SUBMIT.md` | таблица заданий, сроки, требования к скриншотам, чек-лист |
| `docs/git/` | разбор работы с Git в VS Code по кадрам |
| `.github/pull_request_template.md` | шаблон описания запроса на слияние |

Образец полного состава — `funnel-starter` (ОП.03).

## После каждого занятия

Шаблон дополняется в тот же день, когда занятие проведено. Добавляются три
вещи: задание, конспект темы и файлы занятия.

### 1. Задание

Папка `lesson_NN` по образцу предыдущих заданий этой дисциплины. Новая строка
дописывается в таблицу заданий главного `README.md` и в `docs/SUBMIT.md`.

### 2. Конспект темы в `lectures/`

Файл `lectures/tema-NN-<имя>.md`. Разделы одинаковые во всех темах:

| Раздел | Что пишется |
|---|---|
| ссылки в шапке | презентация, страница материалов на сайте курса, папка в `materials/`, задание `lesson_NN` |
| Содержание лекции | что разбирали: определения, устройство, примеры из презентации, ограничения сервиса |
| Термины | таблица «термин → значение» для новых понятий темы |
| Что делали на занятии | нумерованные шаги практики, которую выполнили на паре |
| Что вошло в проект | что после занятия появилось у студента: сайт, таблица, настройка сервиса, файл; в каких следующих темах это используется |
| Документация | ссылки на официальные источники из окна источников презентации |

Новая строка дописывается в таблицу тем `lectures/README.md`. Если у дисциплины
есть сквозной проект, в таблицу «что есть в проекте после темы» добавляется
строка с результатом занятия.

Источники для конспекта: текст колоды (`index.html`), `LESSON.md` или
`LESSON_PLAN.md`, `PRACTICE.md`, памятки и шпаргалки занятия, README
раздаточного комплекта. Факты, числа и названия кнопок берутся оттуда.
Своих фактов в конспект не добавлять. Перечни («шесть признаков», «пять
фильтров»), инварианты и шаги практики сверять с текстом колоды: план урока
называет их короче, чем они разобраны на экранах.

Конспект пишется только по пройденному. Если в группе тема пройдена частично
или есть решение не упоминать инструмент (например, МДК.01.01: из темы 4
пройдены главы 4.1–4.2, Pylance и mypy в текстах для студентов не называются),
конспект ограничивается пройденными главами.

### 3. Файлы занятия в `materials/`

Папка `materials/tema-NN-<имя>/` с копиями того, что раздавалось на паре:
стенды, код для вставки, CSV, шаблоны отчётов, чек-листы, тексты для
копирования. В `README.md` папки — ссылки на презентацию и конспект и таблица
«файл → что это». Если у темы нет своих файлов, в папке остаётся только
`README.md` со ссылками.

При копировании:

- архивы `.zip` не копировать, файлы кладутся распакованными; исключение —
  архив, в котором лишние файлы являются частью задания (`.env`, `.DS_Store`,
  `.pyc`): `.gitignore` шаблона их отбросит, поэтому такой комплект остаётся
  архивом;
- папки сравнить с архивом на сайте (`diff -rq`): в шаблон попадает то же,
  что скачивает студент;
- служебные файлы преподавателя не копировать: `SCREENSHOTS.md`, `QA.md`,
  `SOURCE.md`, `build.mjs`, `manifest.json`, `shots/`;
- в скопированных текстах заменить ссылки на эти файлы ссылкой на задание
  `lesson_NN` или на таблицу кадров на странице материалов;
- относительные ссылки на картинки (`shots/…`) заменить полными адресами
  на сайте курса;
- проверить, что команды запуска ссылаются на существующие файлы;
- не копировать README и скрипты, которые рассчитаны на структуру другого
  репозитория (`../stend/load.sh`, `work/`, `etalon/`): вместо копии дать
  ссылку на папку этого репозитория;
- сверить место сдачи в комплекте с шаблоном: папка, ветка и номер задания
  в `homework_NN.md` комплекта должны совпадать с `lesson_NN` шаблона;
- файлы, которые `.gitignore` шаблона исключает, но проекту нужны
  (`.vscode/settings.json`), добавлять через `git add -f`;
- в `.md` из генератора заменить `&amp;`, `&lt;`, `&gt;` на сами символы;
- скриптам `.sh` вернуть право запуска (`chmod +x`): при распаковке через
  Python оно теряется;
- тесты комплекта запустить: заготовки должны собираться и падать только
  на `NotImplementedError`;
- не копировать файлы с ID своих таблиц, токенами и адресами развёртываний
  (например, `deployment/Code.gs`); в коде для студентов остаются заглушки
  `G-XXXXXXXXXX` и «ID своей таблицы»;
- в данных только вымышленные имена и почта на `example.com`.

## Проверка перед публикацией

### Главный README.md

- Описание в начале говорит, что лежит в репозитории сейчас: задания,
  лекции, материалы.
- Таблица заданий совпадает с папками `lesson_NN` и с `docs/SUBMIT.md`.
- Нет устаревших чисел («три домашние работы» при семи заданиях).
- Нет противоречий с новым содержимым: например, «сюда попадают только бланки»
  после добавления `lectures/` и `materials/`.
- Все относительные ссылки открываются.

### Описание репозитория на GitHub

```bash
gh repo view MaximBytecamp/<имя> --json description,homepageUrl,repositoryTopics,isTemplate
```

- `description` перечисляет актуальное содержимое и числа;
- `homepageUrl` ведёт на страницу дисциплины на сайте курса;
- `repositoryTopics` заполнены;
- `isTemplate` равно `true`.

Обновление:

```bash
gh repo edit MaximBytecamp/<имя> --description "…" --homepage "…" --add-topic …
```

Карточка шаблона на странице дисциплины (`index.html` курса) описывает
то же содержимое, что и `description`.

### Текст

Проверяется весь текст шаблона, а не только добавленный: главный README,
`docs/SUBMIT.md`, README и бланки заданий, конспекты, описания файлов. Он проверяется
по [`TEXT_REVIEW.md`](TEXT_REVIEW.md) и [`EDITORIAL_REWRITE.md`](EDITORIAL_REWRITE.md).
Сначала грепы, затем сплошная вычитка: грепы находят известные обороты,
остальное находится только чтением.

Греп по новым файлам шаблона:

```bash
python3 - <<'EOF'
import re,glob
F=[f for f in glob.glob('**/*.md',recursive=True) if not f.startswith('docs/git/')]
P=r'это не просто|погрузим|в современном мире|мощн\w+ инструмент|играет важную роль|позволяет эффективно|представьте|давайте|именно|не просто|вовсе|и есть |не случайно|это нормально|так и должно быть|ровно|главн|самое|учебн|вслух|, а не |— не |\bне \w+, а |живёт|ловит|знает|умеет|переживёт|вырастет|честн|причес|руга[ею]тся|вста[ёе]т|не встал|всё готово|действительно|на самом деле|важно |просто |сам[аио]? '
for f in F:
    for i,l in enumerate(open(f,encoding='utf-8'),1):
        if re.search(P,l,re.I): print(f'{f}:{i}',l.strip()[:140])
EOF
```

Что искать при вычитке:

| Что | Пример | Как исправить |
|---|---|---|
| одушевление программы или сайта | «сайт не знает о Measurement ID», «код живёт», «`.gitignore` ловит» | «на сайте не стоит код с Measurement ID», «код хранится», «исключает из коммитов» |
| мутное общее слово | «сдаются проверяемые результаты», «доступны базовые автоматизации» | назвать конкретно: «сдаются работы», «практика выполняется на тарифе Free» |
| разговорное вместо точного | «чтобы события куда-то приходили», «ломают разбор полностью» | «чтобы принимать события», «метку аналитика не читает» |
| антитеза «X, а не Y», «это не Z» | «это не доля сеансов» | прямое утверждение: «долей сеансов его называть нельзя» |
| оценочная подводка | «Правило простое:», «основа для всех следующих тем» | «Правило сдачи:», что именно используется дальше |
| утверждение шире источника | «каждый шаг выполняется автоматически», хотя комментарий пишет человек | сузить до того, что делает сервис |
| неточный факт | «браузер не сообщает источник» при существующем `Referer` | «передаёт ненадёжно: заголовка часто нет» |
| слово «учебный» | «учебный стенд» | «стенд», «тестовая заявка» |
| морализаторство, призыв вместо правила | «раздел про ИИ заполнять нужно честно», «важно показать рабочий результат» | что написать и что проверяется: «напишите, для чего ИИ использовался, или „не использовал“» |
| разговорные слова | «причесать формулировки», «команда ругается», «если Docker не встаёт», «всё готово» | «поправить формулировки», «команда выдаёт ошибку», «не устанавливается», «окружение готово» |
| метафора и одушевление | «отсюда вырастет сервис», «том переживёт перезапуск», «таблица ловит ошибки» | «в нём будет собран сервис», «том сохранится после перезапуска», «таблица отмечает ошибки» |
| лозунг с тире | «Репозиторий не переписывается — он дописывается» | «Новые хранилища добавляются в этот же репозиторий» |
| утешение и усилители | «так и должно быть», «ровно такими», «действительно», «что именно» | убрать слово, оставить факт |

### Ссылки

```bash
python3 - <<'EOF'
import re,os,glob
for f in glob.glob('**/*.md',recursive=True):
    for m in re.finditer(r'\]\(([^)#]+)',open(f,encoding='utf-8').read()):
        u=m.group(1)
        if u.startswith('http') or u.startswith(('screens/', 'screenshots/')):
            continue  # кадры в бланках студент добавляет сам
        if not os.path.exists(os.path.join(os.path.dirname(f),u)):
            print('BROKEN',f,u)
EOF
```

Внешние адреса сайта курса проверяются запросом `curl -s -o /dev/null -w '%{http_code}'`.

Все адреса почты — на `example.com`, ID таблиц и токенов нет.

Скопированные конспекты, практики и стенды остаются копиями файлов курса:
стилистику в них правят в исходнике (`lessons/…`) и копируют заново,
чтобы текст в шаблоне и на сайте совпадал.
