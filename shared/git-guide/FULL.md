В файле появится примерно такое:
<<<<<<< HEAD
role: frontend developer
=======
role: backend developer

**>>>>>>> conflict-01-role-backend**

![Шаг 106](img-full/106.png)

HEAD — это текущая ветка, то есть main.
incoming / нижняя часть — это изменения из ветки, которую мы вливаем.
Git не понимает, какую строку оставить, потому что обе ветки изменили одно и то же место.
можно разрешить конфликт:

**Кнопки решения конфликта над строками**

![Шаг 107](img-full/107.png)

Accept Current Change
Оставить текущую версию из ветки, в которой ты сейчас находишься.
Accept Incoming Change
Оставить входящую версию из ветки, которую ты вливаешь.
Accept Both Changes
Оставить обе строки.
Получится так:

```
name: Student
role: frontend developer
role: backend developer
status: active
```

**Итог после Accept Both Changes**

.gitignore, .gitkeep и .md-файлы
В Git-проектах часто встречаются служебные файлы, которые помогают правильно хранить проект, не отправлять лишнее на GitHub и красиво оформлять описание репозитория.
.gitignore
.gitignore — это файл, в котором указывают, какие файлы и папки Git должен игнорировать.
Он нужен, чтобы в репозиторий не попадали:
временные файлы;
кэш;
виртуальные окружения;
системные файлы;
файлы с паролями и токенами;
папки сборки;
зависимости, которые можно установить заново.
Пример .gitignore для Python-проекта:
venv/
.venv/
__pycache__/
*.pyc
.env
*.log
.vscode/
.idea/
.DS_Store
Пример .gitignore для JavaScript-проекта:
node_modules/
.env
dist/
build/
*.log
.vscode/
.idea/
Главная идея:
.gitignore защищает репозиторий от мусора и секретных данных.
Важно помнить: если файл уже был добавлен в Git, то простое добавление его в .gitignore не остановит отслеживание. Нужно дополнительно убрать файл из индекса Git.
Например:
git rm --cached .env
.gitkeep
Git не сохраняет пустые папки.
Если в проекте есть пустая папка, Git её просто не увидит и не отправит на GitHub.
Например, нужна структура:
project/
├── src/
├── logs/
├── uploads/
└── README.md
Но папки logs/ и uploads/ пока пустые. Чтобы Git сохранил эти папки, внутрь кладут специальный пустой файл:
.gitkeep
Пример:
project/
├── logs/
│   └── .gitkeep
├── uploads/
│   └── .gitkeep
└── README.md
.gitkeep — это не встроенная команда Git, а обычное соглашение между разработчиками.
Главная идея:
.gitkeep нужен, чтобы сохранить пустую папку в репозитории.
.md-файлы
.md — это Markdown-файлы.
Markdown — это простой формат разметки текста. Он позволяет красиво оформлять документацию: заголовки, списки, таблицы, ссылки, изображения и блоки кода.

README.md
GitHub автоматически показывает README.md на главной странице репозитория.
Обычно в README.md пишут:
название проекта;
краткое описание;
возможности проекта;
используемые технологии;
инструкцию по запуску;
автора;
скриншоты проекта.

Краткое описание проекта.

- Удаление задач

## 11. Служебные файлы: .gitignore, .gitkeep, README

### .gitignore

Список того, что git не должен отслеживать. Нужен, чтобы в репозиторий
не попадали временные файлы, виртуальные окружения, кэш и — главное —
**пароли и токены**.

```gitignore
\# Python
.venv/
__pycache__/
*.pyc
.env

\# системное и редакторы
.DS_Store
.vscode/
.idea/
```

Важно: если файл **уже** попал в git, добавить его в `.gitignore` мало —
git продолжит его отслеживать. Нужно убрать его из индекса:

```bash
git rm --cached .env
```

### .gitkeep

Git хранит файлы, а не папки: пустую папку он просто не заметит. Если
структура важна (например, нужна папка `logs/`), внутрь кладут пустой файл
`.gitkeep`. Это не команда git, а договорённость между разработчиками —
имя может быть любым, просто это прижилось.

### README.md

Файл, который GitHub показывает на главной странице репозитория. Обычно
в нём: название проекта, короткое описание, как запустить, что умеет
и кто автор. Пишется на Markdown — том же формате, что и этот документ.

```markdown
\# Название проекта

Краткое описание.

\## Запуск

    python main.py
```

| Файл | Зачем |
|---|---|
| `.gitignore` | не пускает в репозиторий мусор и секреты |
| `.gitkeep` | сохраняет пустую папку |
| `README.md` | описывает проект на GitHub |
