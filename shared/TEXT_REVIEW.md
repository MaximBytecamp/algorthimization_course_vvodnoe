# Редакторский аудит текста в колодах

Промпт, по которому проверяется весь текст, который видит студент. Применять дословно,
а не пересказом. Ниже — сам промпт, дальше — команды проверки и список того, что этот
аудит регулярно вылавливает помимо стилистики.

---

## Промпт

Проведи полный редакторский аудит текста в готовой веб-презентации и сразу внеси необходимые исправления в файлы проекта.

Структуру презентации, порядок экранов, дизайн, вёрстку, анимации, интерактивные элементы и функциональность не изменяй. Новые разделы и экраны не добавляй. Работай только с текстом.

Проверь весь текст, который видит студент:

* заголовки и подзаголовки;
* объяснения;
* определения;
* подписи;
* примеры;
* задания;
* кнопки;
* подсказки;
* сообщения интерфейса;
* вопросы и варианты ответов.

Исправляй только те места, где текст действительно можно улучшить. Удачные формулировки оставляй без изменений.

Текст должен звучать как объяснение хорошего преподавателя-практика: понятно, спокойно, точно и по-человечески. Аудитория — студенты СПО и первых курсов вузов, которые только изучают тему. Не разговаривай с ними как с детьми и не заменяй профессиональный термин бытовой метафорой: сначала назови понятие точно, затем объясни механизм и покажи его значение для программы.

Убери:

* глупые или неестественные формулировки;
* фразеологизмы и художественные метафоры;
* канцелярский язык;
* рекламные фразы;
* мотивационные лозунги;
* искусственно эмоциональные выражения;
* псевдофилософские вступления;
* натужный молодёжный сленг;
* риторические вопросы без учебной пользы;
* повторение одной мысли разными словами;
* слова, которые звучат умно, но ничего не объясняют;
* характерные нейросетевые конструкции вроде «это не просто X, а Y».

Не используй выражения наподобие:

* «давайте погрузимся»;
* «откроем для себя»;
* «в современном мире»;
* «сердце системы»;
* «магия программирования»;
* «краеугольный камень»;
* «мощный инструмент»;
* «широкие возможности»;
* «ключ к успеху»;
* «выводит работу на новый уровень»;
* «становится незаменимым помощником»;
* «играет важную роль»;
* «позволяет эффективно решать задачи».

Вместо общих слов объясняй конкретно: что это, что делает, как работает, где используется и какой результат получает человек.

Не упрощай текст до потери технического смысла. Профессиональные термины сохраняй. Если термин может быть непонятен студенту, кратко объясни его обычными словами.

Не придумывай новые факты, функции, команды, результаты или возможности технологий. Сохраняй исходный смысл каждого фрагмента.

Следи, чтобы новый текст помещался в существующую композицию. По возможности сохраняй близкую длину. Не превращай короткие экраны в большие конспекты и не сокращай полезные объяснения до сухих тезисов.

Дополнительно исправь:

* орфографию;
* пунктуацию;
* грамматику;
* неудачный порядок слов;
* неоправданные повторы;
* несогласованные формулировки;
* разные варианты написания одного термина.

В конце кратко перечисли, какие типичные проблемы были исправлены. Не переписывай в отчёте весь текст презентации.

## Команды проверки

Целостность после правок — структуру менять нельзя, поэтому число экранов и разметка
должны остаться прежними:

```bash
cd lessons
for d in 0*/; do echo "$d $(grep -c '<section class=\"slide' $d/index.html)"; done
python3 -c "import html.parser,io,sys; html.parser.HTMLParser().feed(io.open(sys.argv[1],encoding='utf-8').read())" 0X-.../index.html
```

Запрещённые обороты одним прогоном по всем колодам:

```bash
grep -rniE 'это не просто |погрузим|откроем для себя|в современном мире|сердце систем|краеугольн|мощн(ый|ое|ая) инструмент|широкие возможност|ключ к успеху|новый уровень|незаменим|играет важную роль|позволяет эффективно' lessons/*/index.html
grep -rniE 'согласитесь|как вы думаете|представьте себе|давайте|как известно|не секрет' lessons/*/index.html
grep -rniE 'осуществля|данный (файл|код|метод)|в случае если|следует отметить|в связи с тем' lessons/*/index.html
```

Повторы между занятиями — заголовки не должны совпадать дословно, навигационные рубрики
(`ПИШЕТЕ САМИ`, `ШПАРГАЛКА`, `ИТОГ ЗАНЯТИЯ`, `ПРИЁМКА · ЧУЖИЕ ДАННЫЕ`) намеренно одинаковы:

```bash
python3 - <<'EOF'
import re,io,glob,collections
h=collections.defaultdict(set)
for d in sorted(glob.glob('lessons/0*')):
    s=io.open(f'{d}/index.html',encoding='utf-8').read()
    for m in re.finditer(r'<h2>(.*?)</h2>',s,re.S):
        h[re.sub(r'<[^>]+>','',m.group(1)).strip()].add(d[-2:])
for t,v in h.items():
    if len(v)>=3: print(len(v), sorted(v), t[:60])
EOF
```

Снисходительный тон — то, чего не видят предыдущие грепы. Промпт требует «не разговаривать
как с детьми» и «не упрощать до потери технического смысла», но нарушения этого пункта
выглядят как обычный человеческий текст, и глазами их пропускают. Маркеры, по которым
они ловятся:

```bash
grep -rniE 'ответ «?да»?|не станет ложью|переезжает (внутрь|наверх)|угадыв|читает как|должен себя вести|стало ясно|просто (наступ|берёт|делает)|там ведь|хватит .{0,12}опечат' lessons/*/index.html
grep -rniE 'готовый ответ|это как|можно сказать|как бы|проще говоря|грубо говоря|на самом деле всё просто' lessons/*/index.html
```

Отдельная проверка — **термин, объяснённый ниже уровня группы**. Если конструкция уже введена
в прошлых занятиях, объяснять её «на пальцах» нельзя: это читается как недоверие к аудитории.
Перед правкой полезно посмотреть, каким языком о ней говорили раньше:

```bash
grep -rn 'bool\|True\|итерац' lessons/0*/index.html | head -40
```

Связность колоды и правдивость утверждений — то, чего не видит ни один греп по формулировкам.
Порядок проверки описан в `AUTHORING.md`, раздел 9.2; здесь — две команды, с которых она начинается.

Все упоминания конструкции подряд: если два экрана определяют одно и то же по-разному,
один из них неточен.

```bash
python3 - <<'EOF' lessons/12-break-continue-menu/index.html break continue "while True" for
import re,io,html,sys
s=io.open(sys.argv[1],encoding='utf-8').read()
body=s[s.index('<main'):s.index('</main>')]
for term in sys.argv[2:]:
    print(f"\n───── {term}")
    for n,sec in enumerate(re.split(r'(?=<section class="slide)',body)[1:],1):
        t=html.unescape(re.sub(r'<[^>]+>',' ',re.sub(r'<pre.*?</pre>','',sec,flags=re.S)))
        for sent in re.split(r'(?<=[.!?])\s+',re.sub(r'\s+',' ',t)):
            if term in sent and len(sent)>30:
                print(f"  {n:>3}  {sent.strip()[:108]}")
EOF
```

Все модальные утверждения — каждое проверяется контрпримером: сделать наоборот и запустить.

```bash
grep -ohE '[^.<>]{0,55}(должн|нельзя|обязательн|всегда|никогда|единственн|стоит перв)[^.<>]{0,55}' lessons/*/index.html
```

## Что этот аудит вылавливает кроме стилистики

Каждый прогон, помимо формулировок, вскрывает содержательные дефекты — их надо править
отдельно и обязательно называть в отчёте:

- подсказка к заданию говорит про другой объект, чем само задание, или называет неверное число;
- фрагмент кода на экране не разбирается Python'ом (русское «и» вместо `and` там, где это не показ ошибки);
- два соседних предложения или два соседних экрана противоречат друг другу либо повторяют одну мысль;
- выдуманная точность в цифрах («тысячу раз в секунду»);
- термин введён без расшифровки (`traceback`, `ТЗ`, `валидация`);
- имя файла в шапке окна кода не совпадает с именем на кнопке «Показать файл»;
- один и тот же термин пишется по-разному в разных занятиях;
- уже пройденная конструкция объясняется «на пальцах», как незнакомая: `True` через «ответ да»
  вместо значения типа `bool`, хотя тип введён на занятии про сравнения.
- два экрана колоды определяют одну конструкцию по-разному («`for` заканчивать нечем» против
  «`break` обрывает перебор»);
- на экране стоит правило, которого нет: контрпример даёт тот же результат, значит это
  соглашение, и писать его надо соглашением с причиной;
- в практике наборы прогонов из критериев не совпадают с блоком «ожидаемый вывод», а вопрос
  «назовите ответ до запуска» указывает на прогон, которого на экране нет;
- след незавершённого переименования: слово осталось в другом регистре или внутри `print()`,
  то есть в том, что студент видит в терминале.
