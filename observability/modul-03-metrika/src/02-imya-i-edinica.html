§1Части имени

Сравнение из жизни
Строка в накладной

«Молоко, литры — 40»: название говорит, что за товар, единица — как читать число.

Имя метрики

process_resident_memory_bytes 47058944: память процесса, в байтах.

Поля для единицы и описания у отсчёта нет, поэтому всё о числе записывают в имя. Имя — слова через подчёркивание от общего к частному: префикс (к чему относится), что измеряется, единица, у счётчика ещё _total.

§2Базовые единицы

Сравнение из жизни
Рецепт в граммах

Муку в граммах и сахар в стаканах не сложить без перевода.

Метрики в секундах

Миллисекунды и секунды на одном графике не сравнить. Время везде в секундах — и перевод не нужен.

Prometheus единицы не переводит: _seconds и _milliseconds для него — разные имена. Поэтому документация вводит базовые единицы: одна единица на величину, без «милли» и «кило».

ВеличинаБазовая единицаПример значенияВместо
Время, длительностьseconds0.12 — 120 мсmilliseconds, minutes
Объём данных, памятьbytes67108864 — 64 МБmegabytes, bits
Доля, процентratio0.73 — 73 %percent
Температураcelsius61.5fahrenheit
Длинаmeters0.25 — 25 смcentimeters

В базовых единицах значение часто дробное: 120 мс — это 0.12 с. float64 хранит его без потерь, а в миллисекунды переводят при выводе: Grafana покажет «120 ms». Доля пишется от 0 до 1 с окончанием _ratio.

В коде длительность сразу получается в секундах: time.perf_counter() считает в них.

§3Окончания _total, _bucket, _info

После единицы в имени может стоять окончание. Оно показывает тип метрики, а значит, как обращаться с числом.

ОкончаниеГде ставитсяПример в сервисе заказов
_totalСчётчик, counterorders_created_total
_bucket, _sum, _countТри вида строк гистограммы, histogramhttp_request_duration_seconds_bucket
_infoСведения в метках, значение всегда 1python_info

Окончания _total, _bucket, _sum и _count библиотека prometheus-client дописывает сама. Единицу можно передать параметром unit.

Повторно _total не добавляется, поэтому оба способа дают одно имя. Смысл имени библиотека не проверяет: Gauge("x_ms", …, unit="seconds") без ошибки превратился в x_ms_seconds.

§4Проверка имён командой promtool

Раз библиотека смысл имени не проверяет, договорённости проверяют отдельно — подкомандой promtool check metrics из поставки Prometheus. Она читает текст метрик со стандартного ввода. Ответ сервиса заказов проходит чисто:

Файл с семью неудачными именами даёт замечания и код завершения 3 — по нему можно остановить сборку перед выпуском.

Замечания promtool и исправленные именаPrometheus 3.5.0
Единица не базовая
cache_size_megabytes → cache_size_bytesМегабайты переводятся в байты: 64 → 67108864.
report_build_milliseconds → report_build_secondsМиллисекунды переводятся в секунды: 520 → 0.52.
Окончание не соответствует типу
orders_created → orders_created_totalСчётчик без _total.
orders_total_count → orders_totalОкончание _count принадлежит гистограмме, у счётчика в конце стоит _total.
queue_length_total → queue_lengthДлина очереди — gauge, у него нет _total.
Запись имени
requestTime → request_duration_secondsСлова пишутся строчными через подчёркивание; заодно добавлена единица.

Проверка неполная: восьмое имя в файле, disk_usage_percent 73, прошло без замечаний, хотя по договорённости это disk_usage_ratio 0.73. Чистый вывод promtool не заменяет чтения имён человеком.

§5Что записать в имя, а что в метки

Сравнение из жизни
Картотека

Покупатели лежат в одном ящике с закладками по буквам. Тридцать ящиков по буквам пришлось бы открывать все.

Имя и метки

Запросы лежат под одним именем и разделены метками. Все запросы — сумма рядов одного имени.

Величину записывают в имя, её части — в метки. Если вынести метод в имя, для общего числа запросов придётся перечислять все имена, а новый метод добавит новое имя.

Метод в метке и метод в имениряды сервиса заказов
Метод в метке
http_requests_total method="GET" 11
http_requests_total method="POST" 1
Одно имя. Сумма рядов этого имени — все запросы, 12.
Метод в имени
http_requests_get_total 11
http_requests_post_total 1
Два имени. Для суммы их нужно перечислить вручную.

В коде метод — значение метки, и новый метод не требует нового имени:

Обратная ошибка — разные величины под одним именем: orders_queue{kind="length"} 3 и orders_queue{kind="capacity"} 100. Сумма 103 ничего не значит. Правило из документации: сумма или среднее по всем рядам одного имени должны иметь смысл. Если нет — нужны разные имена: orders_queue_length и orders_queue_capacity.

§6Проверьте себя

Вопрос 1Сервис записывает время ответа базы данных в миллисекундах. Какое имя и значение подходят для 250 мс?

  • Миллисекунды — не базовая единица. promtool ответит: use base unit "seconds" instead of "milliseconds".

  • Верно. Время записывается в секундах, и значение может быть дробным.

  • Без единицы в имени нельзя понять, как читать 250.

Вопрос 2В коде написано Counter("payments_failed", "…"). Какое имя будет в ответе /metrics?

  • Для счётчика библиотека дописывает окончание _total.

  • Верно. В §3 orders_created вышел в ответ как orders_created_total.

  • Окончание _count бывает у гистограммы.

Вопрос 3promtool не вывел ни одного замечания для cpu_load_percent 87. Значит ли это, что имя записано по договорённостям?

  • promtool проверяет часть правил: disk_usage_percent тоже прошёл без замечаний.

  • Верно: cpu_load_ratio 0.87.

  • _total ставится только у счётчика.

Вопрос 4Нужно считать отправленные письма отдельно по типам: регистрация, сброс пароля, рассылка. Как это записать?

  • Верно. Сумма рядов — все отправленные письма, и она имеет смысл.

  • Для общего числа писем пришлось бы перечислять имена.

  • Эта метка делит письма по результату отправки.
