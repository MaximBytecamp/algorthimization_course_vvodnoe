§1Число рядов из меток

Сравнение из жизни
Ячейки склада

5 цветов × 6 размеров = 30 ячеек. Добавить имя покупателя — ячеек станет 30 на каждого покупателя.

Ряды метрики

3 адреса × 2 метода × 3 кода = 18 рядов. Добавить номер клиента — 18 на каждого клиента.

Кардинальностьcardinality · число рядов

Число разных рядов метрики, то есть сочетаний значений её меток. Наибольшее — произведение числа значений всех меток; настоящее меньше, потому что ряд появляется, только когда сочетание встретилось.

Наибольшее число рядов метрикипроизведение значений меток

3 × 2 × 3 × 1 = 18 рядов.

С полным путём вместо шаблона — до 6 000 рядов, с номером клиента — до 1,8 миллиона на одну метрику и один target. Метка с неограниченным числом значений умножает всё остальное.

§2Опыт: полный путь и номер клиента в метках

С переменной BAD_LABELS=1 сервис ведёт второй счётчик — http_requests_by_path_total с метками path (полный путь) и customer_id (из заголовка X-Customer-Id).

Три шага: 20 запросов к заказам 1–20; 980 запросов к заказам 21–1000 со случайными клиентами 1–300; ещё 1000 запросов к заказам 1–1000 с новыми клиентами.

§4Страница TSDB status

Виновника ищут на странице Status → TSDB status (TSDB — база временных рядов Prometheus). Снимок после третьего шага:

Нужны три таблицы. TSDB Head Status — всего рядов: 2047. Top 10 label names with value count — метки с наибольшим числом значений: path — 1001, customer_id — 300 (у route — 2). Top 10 series count by metric names — метрики с наибольшим числом рядов: http_requests_by_path_total — 2001.

По второй таблице находят метку, по третьей — метрику, затем в коде — место, где метрика получает значение метки.

§5Какие значения записывать в метки

Сравнение из жизни
Отчёт поликлиники

В отчёт пишут число приёмов по отделениям, а фамилии остаются в картах.

Метрики и логи

В метки — значения из короткого списка. Номера заказов и клиентов — в лог и трассу.

Значение метки берётся из небольшого заранее известного набора. Документация советует держать кардинальность большинства метрик ниже 10.

§6Предел sample_limit

Сравнение из жизни
Предохранитель

При перегрузке он отключает всю линию: свет гаснет, проводка остаётся целой.

sample_limit

Если отсчётов в ответе больше предела, опрос отклоняется целиком: метрик target нет, но и база не растёт.

С этим файлом (PROM_CONFIG=prometheus-limit.yml BAD_LABELS=1 docker compose up -d prometheus) и ответом из 2 042 отсчётов target ушёл в DOWN:

Вместе с лишними рядами пропали и нужные. Поэтому предел ставят с запасом над обычным числом отсчётов (на стенде 61 против 500), а после срабатывания исправляют метки в приложении.

§7Проверьте себя

Вопрос 1У метрики метки route (5 значений), method (2) и status (4). Сколько рядов может быть у неё на одном target в наибольшем случае?

  • Числа значений перемножают.

  • Верно: 5 × 2 × 4.

  • 3 — число меток.

Вопрос 2Что из этого подходит для значения метки?

  • Сколько пользователей, столько значений. Почту хранят в логе.

  • Верно. Так устроена метка payment на стенде.

  • Почти каждое значение новое. Длительность пишут в гистограмму.

Вопрос 3На странице TSDB status в таблице Top 10 label names with value count первой стоит метка request_id с числом 48 000. Что это значит?

  • Верно. Дальше — найти метрику в Top 10 series count by metric names.

  • Это число разных значений метки. Число запросов показывает счётчик.

  • Таблица считает значения меток в базе.

Вопрос 4У задания sample_limit: 1000, ответ target содержит 1 200 отсчётов. Что сохранит Prometheus?

  • Ответ отклоняется целиком.

  • На стенде target перешёл в DOWN.

  • Верно. Ошибка — sample limit exceeded.
