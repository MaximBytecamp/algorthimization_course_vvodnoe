§1Зачем пределы

Сравнение из жизни
Лифт с перегрузом

Если вес больше допустимого, лифт не едет вовсе — ни с кем из пассажиров.

Предел опроса

Если ответ нарушил предел, Prometheus отклоняет опрос целиком: up = 0, ни одного отсчёта.

Одна ошибка в программе — номер заказа в метке, огромный ответ, зависшая страница — может нагрузить Prometheus так, что пострадают все задания. Пределы останавливают такой target на входе. Все они работают одинаково с sample_limit: опрос отклоняется целиком, причина записывается в ошибку target.

§2Пределы в настройках

Пределы задают в задании. В опыте у каждого предела своё задание и заведомо маленькое значение, чтобы он сработал:

scrape_timeout — сколько ждать ответа. body_size_limit — наибольший размер ответа. label_limit — сколько меток может быть у одного ряда, label_value_length_limit — какой длины значение метки. target_limit — сколько target может быть у задания после relabeling. Значение 0 у любого из них, кроме таймаута, означает «без предела», и так стоит по умолчанию.

§3Что показал опыт

Склад на время опыта «заморожен» командой docker compose pause sklad: его exporter ждёт ответа 2 секунды. Скрипт берёт из API Prometheus все target в состоянии DOWN и выводит причину:

Все пять заданий в DOWN. Полный текст ошибок объясняет, где именно нарушен предел:

  • body-size. Ответ node_exporter — 111 057 байт при пределе 1 КБ.
  • label-count. Первым сработал ряд python_info: number of labels: 8, limit: 4. Считаются все метки ряда — __name__, job, instance и пять своих.
  • label-length. Сработало имя метрики: label name: __name__, value: "python_gc_objects_collected_total", length: 33. Имя хранится как метка __name__ (глава 3.3) и тоже проверяется.
  • target-count. Обе копии в DOWN с длительностью 0: при превышении предела не опрашивается ни один target задания.

Чтение ответа останавливается на первом нарушении. У label-length scrape_samples_scraped равен 1, у label-count — 10: столько строк Prometheus прочитал, прежде чем встретил неподходящую.

§4Таймаут обрывает опрос

Последняя строка вывода — таймаут. Prometheus ждал 1 секунду и оборвал опрос. Тот же адрес, открытый вручную, ответил через 2,03 с:

Exporter знал причину и сообщил бы её строкой sklad_up 0. Но Prometheus не дождался, и в базе осталось только up 0 с текстом «context deadline exceeded». Это и есть правило из главы 4.1: таймаут exporter должен быть меньше scrape_timeout задания.

§5Как выбрать значения

Предел — предохранитель, он не должен срабатывать в обычной работе. Поэтому сначала измеряют обычные значения target, затем ставят предел с запасом:

  • размер ответа — curl -s …/metrics | wc -c; у node_exporter было 111 КБ, значит, предел в несколько мегабайт;
  • число рядов — scrape_samples_scraped (глава 3.7);
  • длина значений — не меньше самого длинного имени метрики: имя тоже проверяется;
  • таймаут — больше обычной длительности опроса scrape_duration_seconds и не больше scrape_interval (глава 2.4).

Если предел сработал, чинят программу: пока ошибка есть, предел отклоняет и все нужные ряды target.

§6Проверьте себя

Вопрос 1Ответ target нарушил label_limit в одном ряду из 300. Что сохранит Prometheus?

  • Пределы отклоняют опрос целиком.

  • Верно. Как и sample_limit в главе 3.7.

  • Метки не обрезаются, опрос отклоняется.

Вопрос 2label_value_length_limit: 20, самая длинная метка в коде — 12 символов. Может ли предел сработать?

  • Верно. Имя — метка __name__, в опыте сработало имя из 33 символов.

  • В опыте ошибка указала label name: __name__.

Вопрос 3У задания target_limit: 10, после relabeling нашлось 11 target. Сколько из них опрашивается?

  • В опыте обе копии были в DOWN с длительностью 0.

  • Верно. Все target задания получают ошибку target_limit exceeded.

Вопрос 4Exporter отвечает 2 секунды, scrape_timeout — 1 секунда. Что будет в базе?

  • Опрос оборван, ответа нет.

  • Верно. Даже если exporter знал причину, она не дошла до базы.

  • Эту строку Prometheus так и не получил.
