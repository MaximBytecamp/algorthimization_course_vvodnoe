1.9

Практика: от жалобы к проверяемому выводу

Запускаем учебный сервис на своём компьютере, проводим эксперимент из двадцати запросов, считаем показатели по сохранённым данным и оформляем отчёт. Для обязательной части нужен только Python 3.12.

§1Что в архиве

Практика выполняется на том же сервисе, что и все главы темы. Скачайте архив и распакуйте его в отдельную папку, путь к которой не содержит пробелов и русских букв.

Скачать telemetry-lab.zip ↓

Файл или папкаНазначение

console.htmlСтраница стенда, которую отдаёт адрес /lab

Если окружения Python и установка зависимостей пока непривычны, сначала прочитайте материал о структуре Python-проекта. Для практики важно одно: сервер работает в одном терминале, а скрипт эксперимента запускается во втором.

§2Запуск сервиса

Откройте терминал в папке, куда распаковали архив. Выберите свою операционную систему и выполните команды по одной.

Разберём команды для macOS и Linux.

  • cd telemetry-lab — перейти в папку проекта.
  • python3 -m venv .venv — создать виртуальное окружение в папке .venv. Библиотеки проекта будут установлены туда, а не в системный Python.
  • source .venv/bin/activate — активировать окружение. После этого команда python указывает на Python из .venv.
  • python -m pip install -r requirements.txt — установить зависимости из файла.
  • python -m uvicorn app:app --host 127.0.0.1 --port 8015 — запустить сервер. app:app означает «объект app из файла app.py».

В PowerShell окружение не активируют, а обращаются к его Python по полному пути .\.venv\Scripts\python.exe. Так команды работают, даже если политика выполнения скриптов запрещает Activate.ps1.

Последняя строка означает, что сервер готов. Номер процесса в квадратных скобках на вашем компьютере будет другим. Терминал оставьте открытым: закрыв его, вы остановите сервер. Остановить сервер штатно можно сочетанием Ctrl+C.

§3Знакомство с API через Swagger

Откройте в браузере http://127.0.0.1:8015/docs. FastAPI строит эту страницу автоматически по коду обработчиков.

Разберём раскрытый раздел. В таблице Parameters один параметр scenario типа string, передаётся в строке запроса — отметка (query). Строка Available values: fast, slow, error взята из аннотации Literal["fast", "slow", "error"] в коде, Default value: fast — из значения по умолчанию.

В разделе Responses два кода. 200 Successful Response — обычный ответ. Пример "string" не информативен, потому что обработчик возвращает объект Response напрямую и FastAPI не знает его структуру. 422 Validation Error FastAPI добавляет сам: такой ответ придёт, если передать недопустимое значение, например scenario=medium.

Кнопка Try it out позволяет выбрать значение и выполнить настоящий запрос прямо со страницы. Адрес /metrics в документации отсутствует: в коде для него указано include_in_schema=False.

§4Этап A. Три ручных запроса

Откройте http://127.0.0.1:8015/lab. Нажмите по очереди «Быстрый 200», «Медленный 200» и «Ошибка 500». После каждого нажатия перенесите данные в таблицу.

СценарийHTTPКлиент, мсОбработчик, мсСамый долгий этапПервые 8 символов request_id
fast
slow
error

Затем откройте http://127.0.0.1:8015/health и запишите ответ. Объясните в отчёте, почему он успешен, хотя последний запрос к /products завершился ошибкой.

Теперь попробуйте по трём ручным запросам ответить на вопросы из жалобы: сколько запросов было за последний час, какая их доля медленная, стал ли сервис медленнее, чем вчера. Ответов нет: три запроса описывают только три опыта, а истории стенд не хранит. Запишите это в отчёт как ограничение. В расследовании отсутствие данных фиксируют явно, а не заменяют предположением.

§5Этап B. Эксперимент из двадцати запросов

Откройте второй терминал в той же папке telemetry-lab. Сервер в первом терминале должен продолжать работать. Запустите скрипт тем же Python из окружения.

Скрипт последовательно отправляет двадцать запросов. Сценарии заданы в коде: запросы 7 и 17 медленные, запрос 13 — с ошибкой. Ответ 500 не прерывает эксперимент: скрипт перехватывает HTTPError и записывает его как обычный результат.

Коды ответов и порядок сценариев у вас совпадут с авторским прогоном. Миллисекунды будут отличаться: на длительность влияют скорость компьютера, другие программы и планировщик операционной системы. Сравнивайте закономерность, а не точные числа.

ФайлСодержимое
results/requests.csvДвадцать строк: номер, сценарий, код, client_ms, handler_ms, request_id
results/summary.jsonИтог: количества, среднее и p95 методом ближайшего ранга
results/events.jsonЗаписи о событиях этих двадцати запросов с этапами и traceback

Скрипт берёт события из /events и оставляет только те, чей request_id есть в CSV. Поэтому ручные запросы из этапа A в файл не попадут, хотя сервер их тоже запомнил.

§6Задания по данным

Все ответы записывайте в отчёт с указанием, из какого файла взяты данные и как посчитан результат.

  1. Откройте requests.csv. Проверьте, что строк двадцать, медленные запросы — седьмой и семнадцатый, ошибочный — тринадцатый.
  2. Посчитайте долю ответов 500 и долю запросов дольше 1000 мс. Для каждой доли укажите числитель и знаменатель.
  3. Сравните среднее и p95 из summary.json. Объясните, почему среднее не похоже ни на один запрос прогона.
  4. Посчитайте медиану времени клиента программой или вручную по отсортированному столбцу.
  5. Для каждой строки вычислите разность client_ms − handler_ms. Объясните, из чего она складывается.
  6. Найдите в events.json запись медленного запроса по его request_id. Выпишите этапы и проверьте, что их сумма близка к duration_ms.
  7. Найдите запись ошибочного запроса. Прочитайте traceback снизу вверх и укажите тип исключения, файл и строку.
Что можно утверждать по этим данным

Все выводы относятся к одному процессу, двадцати последовательным запросам и смоделированной зависимости. Эти ограничения нужно назвать в отчёте. Фраза «сервис медленный» по такому опыту неверна, а фраза «в этом прогоне 2 из 20 запросов длились больше 3 секунд из-за этапа dependency.wait» верна.

§7Этап C. Изменение одной величины

Хороший опыт меняет одну величину за раз. Иначе нельзя сказать, какое изменение вызвало результат.

Откройте experiment.py и найдите строку scenarios[6] = scenarios[16] = "slow". Индексы в Python начинаются с нуля, поэтому scenarios[6] — седьмой запрос. Замените строку на scenarios[6] = "slow": медленным останется только седьмой.

До запуска запишите в отчёт прогноз: как изменятся доля медленных запросов, среднее, медиана и p95. Затем запустите скрипт и сравните прогноз с новым summary.json.

Перед повторным запуском переименуйте папку results, например в results-run1. Скрипт перезаписывает файлы, и без этого первый прогон пропадёт. Метод расчёта, число запросов и длительность медленного сценария не меняйте.

§8Дополнительно: тот же сервис в Prometheus и Grafana

Эта часть нужна, чтобы своими глазами увидеть путь метрики из главы 1.8. Для неё нужен установленный Docker Desktop или Docker Engine с Compose.

  1. Остановите сервер в первом терминале (Ctrl+C) и запустите его снова с адресом --host 0.0.0.0, чтобы контейнер Prometheus мог к нему обратиться.
  2. Во втором терминале выполните docker compose up -d в папке telemetry-lab.
  3. Откройте http://127.0.0.1:9095/targets и дождитесь состояния UP у цели telemetry-lab.
  4. Запустите experiment.py два-три раза подряд.
  5. Откройте http://127.0.0.1:3015/d/telemetry-intro и сравните число на панели «Завершённые запросы» с суммой рядов запроса lab_http_requests_total в Prometheus.
  6. Остановите стенд командой docker compose down.

Число на панели будет больше, чем строк во всех ваших CSV. Счётчик приложения учитывает все запросы к /products: и из эксперимента, и из страницы стенда, и из Swagger. CSV описывает только один прогон скрипта. Это разные области учёта, а не ошибка сбора.

§12Проверьте себя

Почему experiment.py запускают во втором терминале?

В первом терминале работает сервер Uvicorn и занимает его до остановки. Скрипт — отдельная программа-клиент, которой нужен свой терминал.

Как изменятся доля медленных запросов и p95, если медленным оставить только седьмой запрос?

Доля медленных станет 1 из 20 = 5%. p95 — это 19-е значение из 20; единственный медленный запрос окажется 20-м, поэтому p95 станет длительностью самого долгого быстрого запроса, около 90 мс.

В CSV двадцать запросов, а панель Grafana показывает 45. Где ошибка?

Ошибки нет. Счётчик приложения учитывает все запросы к /products с момента запуска, включая страницу стенда и Swagger. CSV содержит только один прогон скрипта.

Что означает отметка (query) у параметра scenario в Swagger?

Параметр передаётся в строке запроса после знака вопроса: /products?scenario=slow.

§13Шпаргалка

  • Сервер: python -m uvicorn app:app --host 127.0.0.1 --port 8015 в первом терминале.
  • Эксперимент: .venv/bin/python experiment.py во втором терминале.
  • Результаты: results/requests.csv, summary.json, events.json.
  • Сравнивают коды и закономерности, а не точные миллисекунды.
  • Перед повторным прогоном сохранить папку results под другим именем.
  • Одна изменённая величина и прогноз до запуска.
  • Для Prometheus API запускают с --host 0.0.0.0.
  • В отчёте обязательно названы ограничения опыта.
