§1От регулярного наблюдения к действию

Мониторинг — организованный процесс получения и анализа данных о работе системы. Мы выбираем показатели, регулярно собираем наблюдения, сохраняем историю и задаём условия, при которых требуется внимание.

Например, каждую минуту проверяем длительность пользовательской операции. На графике видна динамика; правило обнаруживает устойчивое ухудшение; уведомление приходит человеку, который может вмешаться. Каждый участок нужен для своей работы. Красивый график без сохранённых данных не позволит вернуться к вчерашнему инциденту.

  1. ИзмеритьЧто произошло в программе
  2. СохранитьЗначение и время
  3. СопоставитьОкно, группа, базовый уровень
  4. ПоказатьГрафик или таблица
  5. ОтреагироватьПравило и действие

Мониторинг может использовать метрики, журналы событий, внешние пробы и другие данные. Его нельзя отождествить с одной программой: Grafana показывает результаты запросов к источникам, а сами измерения возникают в приложениях и инфраструктуре.

§2У одного числа может быть разная история

Значение «CPU = 80%» без дополнительных сведений трудно оценить. Возможно, нагрузка держится на этом уровне в течение часа и сервис соблюдает требования. Возможно, за минуту она выросла с 20% вместе с задержками. В обоих случаях последнее число одинаковое.

CPU · два учебных временных ряда

78 → 80 → 82 → 79 → 81 → 80%. Последнее значение: 80%.

Учебные данные для сравнения формы графика; это не измерения CPU стенда.

Временной ряд объединяет наблюдения одной величины, упорядоченные по времени. Важно сохранить смысл серии: CPU какого процесса или узла, как вычислен процент, какова частота измерений. Нельзя склеить данные разных объектов и продолжать читать линию как один процесс.

§3Четыре области наблюдения

ОбластьПоказателиВопрос
ПриложениеЗапросы, ошибки, длительности, активные запросыУхудшилось ли обслуживание пользователей?
Фоновые заданияВремя ожидания, выполнения, повторы, отказыПочему документ ещё не готов после HTTP 202?
ЗависимостиЗанятые соединения, ожидание пула, длительность обращенияНа каком внешнем ресурсе ждёт приложение?
ИнфраструктураCPU, память, диск, сетьЕсть ли ограничение ресурсов или неисправность среды?

Наблюдать только сервер недостаточно: очередь может расти при свободном CPU, если обработчики ждут внешнее API. Наблюдать только длительность HTTP тоже недостаточно: пользователь получил 202, а задание осталось в очереди. Область измерения должна соответствовать обещанной операции.

§4Окно времени меняет смысл ответа

«Ошибок пять» — неполное описание. Пять за секунду при десяти запросах и пять за сутки при миллионе — разные ситуации. Для доли ошибок числитель и знаменатель должны относиться к одним маршрутам, одному интервалу и одной системе классификации.

Если запросов не было, знаменатель равен нулю. Это отсутствие наблюдений о пользовательских запросах, а не доказательство нулевой доли ошибок. В дашборде нужно различать «0 ошибок из 100» и «нет запросов / нет данных».

Разберите самостоятельно

Две реплики API

Первая обработала 10 запросов, из них 5 ошибочных. Вторая — 990 запросов без ошибок. Чему равна общая доля ошибок?

Проверить рассуждение

5 / 1000 = 0,5%. Среднее между процентами 50% и 0% дало бы 25%, что неверно: группы имеют разный размер. Сначала складываем совместимые количества, затем делим.

§5Внешняя проба и внутренние показатели

Black-box monitoring проверяет поведение через внешний интерфейс: доступна ли страница, проходит ли операция, сколько она занимает. White-box monitoring использует сведения изнутри системы: состояние очереди, число соединений, время этапов обработчика.

Внешняя проба полезна тем, что проходит часть того же пути, что пользователь: DNS, сеть, TLS и балансировщик. Внутренний показатель может точнее локализовать задержку, но не заметить проблему на пути до приложения. Для диагностики нужны оба взгляда.

Проверяйте именно то, что обещает probe

Проверка /health не равна проверке оформления заказа. Внешняя проба может выполнять бизнес-сценарий, а внутренний health endpoint — проверять зависимости. Различие определяется точкой наблюдения и содержанием проверки, а не названием URL.

Сначала сформулируйте ответ своими словами и укажите, на какие данные опираетесь.

Проверить рассуждение

Он описывает ресурс процесса. Для ответа нужен критерий завершения бизнес-операции и наблюдение, подтверждающее этот результат.

  • У любого показателя есть объект, единица измерения, интервал и способ расчёта.
  • Для общей доли складываем количества до деления.
  • Нет данных и нулевое значение требуют разных объяснений.
