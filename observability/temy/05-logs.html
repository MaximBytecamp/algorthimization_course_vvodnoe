Логи: событие, контекст и исключение

Учимся читать структурированную запись, связывать события одного запроса и отличать стек исключения от распределённой трассы.

§1Одна запись отвечает за одно событие

Счётчик ошибок сообщает масштаб, но не сохраняет описание каждой ошибки. Лог — запись о произошедшем событии. В минимальном полезном варианте в ней есть время и содержание; в рабочем сервисе также нужны компонент, уровень и контекст.

Фраза Request processed показывает, что выполнение дошло до строки логирования. Без статуса, маршрута, времени и идентификатора мы не знаем, какой запрос обработан и каков его результат. Поэтому сначала определяем, какие вопросы должна закрывать запись, затем выбираем поля.

Структурированный лог по полям
{"service":"products-api","event":"request_completed",
 "status":500,"request_id":"f81c…","duration_ms":80.6}

Выберите поле: увидите, на какой вопрос оно отвечает и чего не гарантирует.

§2Структура упрощает поиск

В свободной строке «ошибка базы у запроса ...» контекст приходится извлекать из текста. В JSON можно отобрать event = request_completed и status = 500, затем сгруппировать по сервису. Это не делает JSON автоматически хорошим логом: значения и названия полей должны быть последовательными.

logger.info записывает сообщение через систему логирования Python; json.dumps превращает словарь в строку JSON. Здесь показан смысл полей. Полная программа дополнительно ставит временную отметку, сохраняет события для лаборатории и обрабатывает исключение.

Единицы фиксируем в имени или схеме: duration_ms измеряется в миллисекундах. Число 80 без единицы допускает слишком много трактовок. Время события в стенде записывается с часовым поясом UTC; браузер и Grafana могут показывать локальное время.

§3Читаем настоящий traceback

Traceback в Python показывает стек вызовов, приведший к исключению. Читать удобно от последней строки: там тип исключения и сообщение. Затем выше смотрим файл и строку, в которой ошибка возникла. Предыдущие кадры объясняют, как выполнение дошло до этого места.

logger.exception добавляет сведения о текущем исключении, поэтому его вызывают при обработке ошибки. Клиенту можно вернуть краткий результат, а подробности сохранить для диагностики. Возвращать весь внутренний стек пользователю для работы телеметрии не требуется.

Traceback и trace

Стек исключения описывает цепочку вызовов в месте ошибки. Распределённая трасса связывает этапы операции и их интервалы времени, в том числе между сервисами. В успешной медленной операции traceback может вообще отсутствовать, а трасса всё равно полезна.

§4Можно ли посчитать метрики из логов

Да: если каждая нужная операция записана ровно один раз и содержит достаточные поля, из журнала можно посчитать количество, долю ошибок и распределение длительностей. Неверно утверждать, что логи принципиально не подходят для численных вопросов. Цена и ограничения зависят от объёма и системы запросов.

Проблемы появляются, когда один запрос создаёт несколько строк, записи дублируются при доставке, часть событий потеряна или длительность отсутствует. Тогда «количество строк с ERROR» не равно «количество неуспешных запросов». Для расчёта нужно определить событие учёта и обработку дубликатов.

Разберите самостоятельно

Почему grep ERROR недостаточно

Один запрос сделал три повтора и завершился успешно. Каждый повтор записал ошибку. Второй запрос упал без повторов. В журнале четыре ERROR. Сколько неуспешных запросов?

Проверить рассуждение

По условию один. Количество ошибочных попыток — четыре, количество неуспешных запросов — одно. Для разных вопросов нужны разные события и явная связь попытки с запросом.

§5Сохраняем нужные подробности

Лог полезен, когда из него понятно, что случилось, где и к какой операции относится запись. Полный текст пользовательского документа или заголовок Authorization обычно не помогают ответить на этот вопрос. Для учебных материалов используются только синтетические данные; в рабочем сервисе состав полей согласуют с требованиями хранения и доступа.

Уровень ERROR не определяет масштаб. Один и тот же тип ошибки может возникнуть один раз за месяц или на каждом запросе. Поэтому контекст отдельной записи сопоставляют с количеством операций за интервал.

✓Самопроверка и памятка

Разберите самостоятельно

Как найти лог выбранного запроса среди сотни одновременных?

Сначала сформулируйте ответ своими словами и укажите, на какие данные опираетесь.

Проверить рассуждение

По его request_id или trace_id при условии, что идентификатор записан в нужных событиях. Одного совпадения времени недостаточно.

  • Полезное событие содержит время, компонент, действие и контекст.
  • Число строк с ERROR может отличаться от числа ошибочных операций.
  • Traceback локализует исключение в коде; для пути операции нужны дополнительные данные.
