# Telemetry Lab · первая тема

Учебный проект справочника «Метрики и наблюдаемость».
Автор материала — Макаров Максим Николаевич.

## Что воспроизводится

Один FastAPI-процесс обслуживает `/products` и три управляемых сценария:

- `fast`: ожидание около 80 мс в сумме;
- `slow`: около 3 секунд на моделируемой зависимости;
- `error`: настоящее исключение TimeoutError, преобразуемое в HTTP 500.

PostgreSQL здесь не подключена. Ожидание создано `asyncio.sleep`, поэтому опыт
показывает различие сигналов, а не производительность базы или процессора.
Spans измеряются вручную в одном процессе; это не экспорт OpenTelemetry.

## Подготовка · Python 3.12

Распакуйте архив, перейдите в `telemetry-lab`.

macOS / Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8015
```

Windows PowerShell — активация окружения не требуется:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8015
```

Терминал оставить открытым. Открыть в браузере:

- http://127.0.0.1:8015/lab — консоль: HTTP-ответ, событие, измеренные этапы;
- http://127.0.0.1:8015/docs — настоящий Swagger;
- http://127.0.0.1:8015/health — проверка только процесса;
- http://127.0.0.1:8015/events — последние 2000 событий в памяти;
- http://127.0.0.1:8015/metrics — упрощённый endpoint для демонстрации Prometheus.

Для остановки сервера — Ctrl+C в его терминале.

## Эксперимент из 20 запросов

Во втором терминале из той же папки:

```sh
# macOS / Linux
.venv/bin/python experiment.py
```

```powershell
# Windows
.\.venv\Scripts\python.exe experiment.py
```

Порядок: 17 fast, slow на позициях 7 и 17, error на позиции 13.
Скрипт сохранит:

- `results/requests.csv` — client_ms, handler_ms, status, request_id;
- `results/summary.json` — количества, среднее и p95 (nearest rank);
- `results/events.json` — только события этого прогона по request_id.

Числа времени будут отличаться на разных машинах. Ожидается 20 запросов,
один HTTP 500 и две внесённые медленные операции. Порог медленности 1000 мс
использован для опыта; он не является универсальной нормой для сервисов.
Если ваша машина сильно нагружена, быстрые сценарии тоже могут превысить порог.

Сохранённые авторские результаты находятся в `reference-results/`.
Они не перезаписываются запуском experiment.py.

## Как устроен код

`perf_counter()` измеряет интервалы внутри процесса. UTC-время задаёт положение
события в истории. Один request_id связывает HTTP-ответ и событие.
Обработчик `products` создаёт три spans: validate, dependency.wait, serialize;
в error последний этап не выполняется.
В журнале сохраняются последние 2000 событий. После перезапуска история в памяти
исчезает; данные CSV и JSON на диске остаются.

Counter и histogram в `/metrics` сформированы минимальным кодом для обзора пути
данных. Для рабочего приложения используйте клиентскую библиотеку и правильную
модель запуска. Учебный код работает в одном процессе, без `--workers` и без
`--reload`: отдельные процессы имели бы независимые счётчики.
Не включайте режим нескольких workers для этого опыта.

## Дополнительная демонстрация Prometheus / Grafana

Не нужна для обязательной практики первой темы. Это готовый стенд для просмотра
ролей инструментов; подробное устройство конфигурации изучается далее.
Проверено: Prometheus 3.5.0, Grafana 12.1.1, Docker Desktop 29.7.2 (macOS).
Образы закреплены по версии; это не утверждение о последних версиях продуктов.

Для связи с Docker API запускается на `0.0.0.0`:

```sh
python -m uvicorn app:app --host 0.0.0.0 --port 8015
```

На Windows используйте `.\.venv\Scripts\python.exe` вместо `python`.
Такой адрес делает API доступным на интерфейсах компьютера. Запускайте учебную
демонстрацию в доверенной локальной сети; для обычной практики достаточно 127.0.0.1.

Из папки стенда:

```sh
docker compose up -d
```

- Prometheus: http://127.0.0.1:9095
- Grafana: http://127.0.0.1:3015/d/telemetry-intro
- API не входит в Compose: он работает в отдельном Python-процессе.
- Prometheus использует `host.docker.internal:8015`, а Grafana — `http://prometheus:9090`.
- Порты Grafana/Prometheus привязаны только к localhost.
- Для Grafana включён анонимный просмотр Viewer; это локальная учебная настройка.

Сначала откройте Targets в Prometheus: цель telemetry-lab должна быть UP.
Если она DOWN, проверьте адрес и порт API, firewall и разрешение имени
host.docker.internal. В Compose предусмотрен host-gateway для Linux.

Выполните эксперимент один или несколько раз, подождите не менее двух scrape
(в стенде интервал 5 с). На графиках скорости окно равно одной минуте, поэтому
полезно отправлять запросы в течение минуты. Верхние панели показывают счётчики
с запуска — туда входят и ручные запросы из браузера.

Остановка только этого стенда из его папки:

```sh
docker compose down
```

Сторонние Compose-проекты не затрагиваются. Учебные данные Grafana/Prometheus
не закреплены отдельными именованными томами и не предназначены для длительного хранения.
