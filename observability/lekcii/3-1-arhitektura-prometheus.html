§1Два процесса и один путь данных

Почему приложение и Prometheus запускаются как разные программы.

На складе есть касса и журнал. Касса знает, сколько заказов обработано. Журналист приходит через равные промежутки, переписывает показания и уносит журнал в архив. Касса и журналист выполняют разные работы.

В системе наблюдаемости касса — сервис telemetry-lab. Он отдаёт метрики по адресу /metrics. Журналист — Prometheus. Он обращается к адресу, разбирает текст и сохраняет отсчёты.

На схеме показан путь ответа: сервис отдаёт текст, Prometheus принимает его и передаёт отсчёты во внутреннее хранилище. Сам запрос отправляет Prometheus к endpoint. Число 5 секунд — интервал из конфигурации этой лекции. Дальше разберём, какие два процесса и контейнера нужно запустить.

§2Что запускается

Состав первого опыта: приложение, Prometheus и Docker Compose.

Сначала сервис должен уже отдавать данные. В стенде он запускается отдельной командой Uvicorn на порту 8015. Затем Compose запускает контейнер Prometheus и подставляет ему файл конфигурации.

КомпонентГде работаетЗадача
telemetry-labPython-процессотдаёт HTTP-ответ /metrics
prometheusDocker-контейнеропрашивает target и хранит отсчёты
prometheus.ymlфайл стендаописывает интервал и адрес target
порт 9095локальный компьютероткрывает веб-интерфейс Prometheus

Контейнеру нужен адрес компьютера, на котором работает API. В конфигурации стенда это host.docker.internal:8015. Сам Prometheus доступен с компьютера по адресу http://127.0.0.1:9095.

Таблица разделяет роли. API поставляет числа, а Prometheus собирает и хранит их. Теперь опишем этот маршрут в YAML.

§3Конфигурация prometheus.yml

Три настройки, с которых начинается первый scrape.

Файл конфигурации — это инструкция запуска Prometheus. В первом опыте в нём достаточно интервала и одного задания сбора. Термин scrape означает один опрос target и разбор полученного ответа.

global.scrape_intervalПауза между плановыми опросами. Здесь Prometheus создаёт новый scrape каждые 5 секунд.
job_nameИмя задания. Оно попадёт в метку job у собранных рядов.
static_configs.targetsСписок адресов, заданный прямо в файле. В первом опыте адрес один.
Targetцель опроса
Что это
Адрес программы, у которого Prometheus запрашивает метрики.
Пример
host.docker.internal:8015 — имя компьютера из контейнера и порт API.
Что не входит
Target — это адрес, а не имя задания и не отдельная метрика.

В YAML адрес находится внутри задания telemetry-lab. Поэтому после запуска один адрес станет одним target, а собранные ряды получат метку job="telemetry-lab". Следующий шаг — передать этот файл контейнеру.

§4Первый запуск через Docker Compose

Как конфигурация попадает внутрь контейнера.

Compose описывает контейнер Prometheus и подключает файл с компьютера внутрь контейнера. Подключённый файл называют томом: контейнер читает его как /etc/prometheus/prometheus.yml, а исходник остаётся в папке проекта.

Левая часть записи порта — адрес компьютера, правая — порт внутри контейнера. Поэтому браузер открывает 9095, а Prometheus внутри слушает 9090. Флаг :ro подключает файл только для чтения.

Первый запрос проверяет источник, второй — готовность Prometheus принимать работу. Строки HELP и TYPE принадлежат ответу API, а сообщение Prometheus Server is Ready. — его служебному endpoint.

Оба процесса запущены. Теперь посмотрим, как Prometheus показывает найденный адрес.

§5Target и job

Как адрес из YAML превращается в объект сбора.

В почтовом отделении адрес получателя и название маршрута — разные поля. Адрес указывает, куда ехать, а маршрут объединяет похожие отправления. В Prometheus target — адрес, а job — имя группы, к которой этот адрес относится.

Сейчас в задании один target. Если позже в список добавить второй адрес, оба target будут относиться к job telemetry-lab. Это разделение пригодится в запросах: по job можно выбрать группу, а по instance — конкретный адрес.

Связь с target видно в веб-интерфейсе. Откроем страницу Targets.

§6Страница Targets

Где проверить, что Prometheus нашёл цель и опросил её.

Откройте http://127.0.0.1:9095/targets. В разделе задания telemetry-lab появится одна строка. Её состояние зависит от последнего опроса.

Поле в TargetsЗначение в первом опыте
Jobtelemetry-lab
Endpointhost.docker.internal:8015
StateUP
Last scrapeвремя последнего успешного опроса

В строке видны четыре связанных значения: job telemetry-lab, endpoint с адресом API, состояние UP и время последнего scrape. Состояние UP означает, что последний опрос endpoint завершился успешно. Оно не означает, что каждый маршрут приложения исправен.

ПолеЧто показывает
Endpointадрес, который опрашивается
Stateрезультат последнего scrape
Last scrapeкогда закончился последний опрос
Scrape durationсколько длился последний опрос

Targets отвечает на вопрос о связи Prometheus с endpoint. Для поиска результата в базе нужен язык запросов PromQL. Начнём с самого короткого ряда — up.

§7Ряд up

Число, которое Prometheus создаёт для каждого target.

Индикатор на панели связи показывает результат последней попытки дозвониться. Значение 1 означает «ответ получен», значение 0 — «опрос завершился ошибкой». В Prometheus таким индикатором служит ряд up.

upслужебный ряд target
1
Последний scrape target завершился успешно.
0
Prometheus не получил корректный ответ от target.
Метки
job — имя задания, instance — адрес конкретного target.

up описывает доступность опрашиваемого endpoint. Он не проверяет содержание всех метрик и не сообщает, что бизнес-операция завершилась правильно. Эти вопросы потребуют других рядов.

Ряд up появился автоматически. Посмотрим, где лежат остальные отсчёты.

§8Что записывает Prometheus

Как ответ /metrics превращается в ряды с метками.

Endpoint возвращает текст. Prometheus разбирает в нём имя метрики, метки и число, добавляет служебные метки job и instance, затем записывает отсчёт со временем. Один ответ может дать много рядов.

Запрос к Prometheus показывает сохранённые отсчёты. Дальше разберём, как устроен сам цикл scrape.

§9Если target недоступен

Что меняется, когда последний опрос не получил ответ.

Если касса закрыта, журналист записывает результат попытки в отдельную колонку. Старое число продаж не превращается в новое число. Так Prometheus разделяет значение метрики и состояние связи с target.

При остановленном API запрос к up{job="telemetry-lab"} после неудачного scrape даст 0. Запрос к прикладной метрике не создаст новое значение. Разбор пропусков и устаревших рядов будет отдельной темой после знакомства с циклом scrape.

Первый запуск закончен: Prometheus нашёл target, получил ответ и записал служебный ряд. Закрепим действия в короткой практике.

§10Практика

Проверка первого запуска без изменения конфигурации.

Задача 1. Найдите target

Запустите API и Prometheus из папки observability/lab. Откройте Targets и выпишите job, endpoint и состояние строки.

Что нужно получить

Одна строка задания telemetry-lab, endpoint host.docker.internal:8015 и состояние UP.

Проверка

Откройте http://127.0.0.1:9095/targets. Если состояние DOWN, сначала проверьте, что API запущен на 8015 и контейнер может обратиться к host.docker.internal.

Задача 2. Проверьте ряд

В поле запроса Prometheus выполните up{job="telemetry-lab"}. Затем выполните up без фильтра и сравните результат.

Что нужно получить

Первый запрос возвращает target задания telemetry-lab со значением 1. Второй может показать несколько служебных рядов, если Prometheus собирает собственные метрики или дополнительные задания.

Проверка

У первого ряда должны быть метки job="telemetry-lab" и instance="host.docker.internal:8015". Число 1 означает успешный последний scrape.

§11Проверьте себя

Вопросы по первому запуску. Ответ раскрывается щелчком.

Чем target отличается от job?

Target — конкретный адрес, который опрашивается. Job — имя группы, в которую этот адрес включён. Один job может содержать несколько target.

Что означает up = 1?

Последний scrape target завершился успешно. Это не проверка каждой бизнес-операции и не гарантия правильности всех прикладных метрик.

Почему браузер открывает 9095, если Prometheus внутри слушает 9090?

Compose публикует порт контейнера: запись 127.0.0.1:9095:9090 связывает локальный 9095 с портом 9090 внутри контейнера.

Что произойдёт, если API остановить?

После неудачного scrape ряд up{job="telemetry-lab"} примет значение 0. Прикладные ряды перестанут получать новые отсчёты.
