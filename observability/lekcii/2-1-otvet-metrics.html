§1Что отдаёт /metrics

Какой текст приложение отдаёт по адресу /metrics и кто его читает.

На вокзале висит табло. Оно никому ничего не отправляет: на нём написаны текущие сведения о поездах, и каждый, кто подошёл, читает одни и те же строки. Адрес /metrics устроен так же. Приложение держит там текущие значения своих метрик, а Prometheus, браузер или curl приходят и читают их.

Адрес /metricsmetrics endpoint
Что это
Адрес внутри приложения, на который оно отвечает текстом с текущими значениями своих метрик.
Кто читает
Prometheus — по расписанию; человек — браузером или curl, чтобы проверить.
Пример
http://localhost:8000/metrics у программы из этого раздела.

Получим такой ответ от настоящей библиотеки. Программа ниже заводит счётчик HTTP-запросов и открывает адрес /metrics на порту 8000. Затем она записывает в счётчик 125 успешных запросов, 3 запроса к несуществующей странице и 1 запрос неразрешённым методом:

Слева код прибавляет к счётчикам. Числа лежат в памяти процесса — в реестре, общем списке метрик. Когда приходит запрос GET /metrics, библиотека проходит по реестру и собирает из него текст. Готового текста между запросами нет: каждый читатель получает его свежим. Остальная лекция разбирает этот текст строка за строкой, а затем — сам реестр.

Вывод

Адрес /metrics отдаёт текущие значения метрик обычным текстом. Текст собирается из реестра в момент запроса.

Начнём со строки значения — в ответе её больше всего.

§2Строка значения

Из каких частей состоит строка значения и по каким правилам каждая записывается.

Строка складской ведомости: «коробки · цвет синий · склад № 2 · 125 штук». Сначала — что считают, потом уточнения, в конце — количество. Строка значения в /metrics построена так же:

Имя и метки вместе называют ряд, о котором идёт речь, значение говорит, сколько в нём сейчас. Для каждой части есть правила записи:

ЧастьПравилоПример
имя метрикилатинские буквы, цифры и _; первый символ — не цифраhttp_requests_total
имя метките же символы; имена с __ в начале заняты служебными метками Prometheusstatus
значение меткивсегда текст в двойных кавычках, даже если похоже на числоstatus="200"
порядок метокне важен: тот же набор в другом порядке — тот же ряд{status="200",method="GET"}
значениечисло через точку; допустимы 125, 125.0, 1.25e2, а также NaN, +Inf, -Inf125.0

Проверим эти правила программой. В библиотеке есть разборщик формата — функция, которая читает текст /metrics так же, как его читает получатель, и возвращает отдельные значения. Дадим ей три строки, записанные по-разному:

text_string_to_metric_families(text)Разбирает текст и возвращает метрики по одной. Метрику вместе со всеми её рядами библиотека называет семейством (family).
family.name, family.type, family.documentationИмя семейства, тип из строки TYPE и текст из строки HELP.
family.samplesОтдельные значения: имя строки, метки словарём, число.
Строка текстаЧто получилось на прогоне
…{method="GET",status="200"} 125метки {'method': 'GET', 'status': '200'}, значение 125
…{status="404",method="GET"} 1.25e2метки в другом порядке прочитаны так же; 1.25e2 → 125.0
…{method="POST",status="405"} 1.0значение 1.0
строки HELP и TYPEтип counter, описание Total HTTP requests; имя семейства — http_requests, без _total

Все три записи числа прочитаны как числа, порядок меток не помешал. Имя семейства разборщик записал без окончания _total: у счётчика окончание относится к строке значения, а сама метрика называется короче.

Вывод

Строка значения — имя, метки в фигурных скобках и число через пробел. Значения меток — всегда в кавычках, число — всегда через точку.

Над строками значений стоят строки с решёткой. Разберём, что они сообщают.

§3Строки HELP и TYPE

Что сообщают строки описания и что будет без них.

Строка, которая начинается с #, — комментарий. Из комментариев читают только два вида:

СтрокаЧто сообщаетИз ответа §1
# HELP имя текстпояснение для человека# HELP http_requests_total HTTP requests
# TYPE имя типтип метрики: counter, gauge, histogram, summary или untyped# TYPE http_requests_total counter

На то, как хранится число, тип не влияет: в базе это такое же число. Тип подсказывает человеку и запросам, как с числом обращаться. Например, скорость роста имеет смысл считать только у счётчика. Что будет, если строк описания нет? Дадим разборщику три строки без HELP и TYPE, заодно с особыми значениями:

queue_length 7Строка без меток: фигурные скобки не нужны.
temperature{room="kitchen"} NaNNaN — «не число», например когда значение не удалось измерить.
limit_bytes +Inf+Inf — бесконечность, например «ограничения нет».

Все три строки приняты. Тип у всех — unknown, «не указан»: без строки TYPE нельзя сказать, счётчик это или что-то другое. Значения NaN и +Inf прочитаны как особые числа Python — nan и inf. Поэтому библиотека всегда пишет HELP и TYPE сама: так у каждой метрики есть описание и тип.

Вывод

HELP — пояснение для человека, TYPE — тип метрики. Без TYPE строки читаются, но тип остаётся неизвестным.

Строки без описания приняты. Посмотрим, какие ошибки записи не принимаются.

§4Ошибки записи

Какие ошибки делают текст непригодным для чтения.

Бланк заявления с неправильно записанной датой возвращают целиком: остальные девять полей отдельно не принимают. С ответом /metrics так же. Если Prometheus не может прочитать хотя бы одну строку, опрос считается неудачным, и не сохраняется ни одно значение из ответа. Проверим, какие ошибки разборщик библиотеки не принимает:

broken = {…}Словарь: название ошибки → текст с этой ошибкой.
list(text_string_to_metric_families(text))Разбор идёт по мере чтения, поэтому list(...) заставляет прочитать весь текст.
except Exception as errorПерехватывает ошибку разбора и печатает её тип и текст.

Все пять текстов отклонены с ValueError. Сведём ошибки и их исправления в таблицу:

ОшибкаТекст ошибкиКак правильно
{method=GET}Invalid labels: method=GET{method="GET"}
61,5could not convert string to float: '61,5'61.5
# TYPE h countrInvalid metric type: countrcounter
{a="1",a="2"}Invalid labels: a="1",a="2"каждая метка один раз
нет значенияcould not convert string to float: ''число в конце строки

Все пять — ошибки, при которых строку нельзя прочитать как «имя, метки, число» или тип непонятен. Пока ответ собирает библиотека, такие ошибки почти не встречаются: она сама ставит кавычки, точку и правильный тип. Они появляются, когда текст /metrics пишут вручную, как у стенда products-api из части 1, или собирают склейкой строк. Проверка своих строк разборщиком перед выпуском ловит их заранее.

Вывод

Значение метки без кавычек, запятая в числе, неизвестный тип, повтор метки, строка без числа — ошибки записи. Одна такая строка делает непригодным весь ответ.

Формат разобран. Теперь — откуда берётся этот текст: реестр.

§5Реестр по умолчанию

Что лежит в реестре библиотеки, когда своих метрик ещё нет.

У консьержа в доме есть список жильцов. Когда спрашивают «кто живёт в доме», он читает список, и обходить квартиры не нужно. Реестр библиотеки — такой список метрик процесса. Каждая созданная метрика записывается в него, а ответ /metrics собирается из этого списка.

Реестрregistry
Что это
Список метрик процесса, из которого собирается ответ /metrics.
Реестр по умолчанию
Общий реестр библиотеки — REGISTRY. Метрика попадает в него, если при создании не указан другой.
Пример
Счётчик http_requests из §1 записан в REGISTRY.

Посмотрим, что лежит в общем реестре сразу после импорта библиотеки, когда своих метрик нет:

REGISTRY.collect()Обходит реестр и возвращает семейства метрик с их текущими значениями — то же, из чего строится текст.
len(family.samples)Сколько строк значений у семейства.

Своих метрик нет, а в реестре четыре семейства. Их добавляют сборщики (collector) — объекты, которые при каждом обходе реестра сами вычисляют значения. Посмотрим, какие сборщики записаны в реестре:

СборщикЧто отдаётНа прогоне
GCCollectorработа сборщика мусора Pythonтри семейства python_gc_*
PlatformCollectorверсия и реализация Pythonpython_info
ProcessCollectorпамять, процессор, открытые файлы процесса: process_*ничего: данные берутся из /proc, а он есть только в Linux; прогон шёл на macOS

_collector_to_names — внутреннее поле реестра; в рабочем коде к нему не обращаются, здесь оно нужно, чтобы заглянуть внутрь. На Linux, например в контейнере Docker, в ответе появятся ещё строки process_cpu_seconds_total, process_resident_memory_bytes и другие: их отдаёт тот же ProcessCollector.

Вывод

Общий реестр REGISTRY с самого начала содержит метрики Python и процесса. Метрики приложения добавляются к ним.

Иногда эти служебные метрики мешают. Для этого заводят свой реестр.

§6Свой реестр

Когда заводят отдельный реестр и чем он отличается от общего.

В коротком примере или в тесте служебные метрики мешают: свой счётчик теряется среди строк python_gc_*. Тогда создают отдельный реестр и передают его метрике аргументом registry:

CollectorRegistry()Новый пустой реестр. Сборщиков в нём нет.
Counter(…, registry=registry)Счётчик записан в свой реестр; в общем его нет.
generate_latest(registry)Собирает текст из указанного реестра. Возвращает байты, .decode() превращает их в строку.
СтрокаЧто получилось на прогоне
generate_latest(REGISTRY)18 строк: только служебные метрики — счётчик в общий реестр не попал
generate_latest(registry)6 строк: только orders
orders.inc(3)orders_total 3.0

В своём реестре — только наш счётчик: две строки описания и значение orders_total 3.0. Ниже ещё три строки orders_created — время создания счётчика в Unix-секундах; библиотека добавляет их к каждому счётчику. Общий реестр нашего счётчика не содержит, потому что счётчик записан в другой реестр.

В сервисе используют общий реестр: служебные метрики там полезны — по ним видно память и процессор процесса. Свой реестр нужен, когда нужен короткий предсказуемый ответ: в примерах и тестах. Дальше в части 2 примеры идут со своим реестром — так их вывод помещается на экран.

Вывод

Метрика попадает в тот реестр, который ей передали, а без аргумента — в общий. Ответ /metrics показывает только метрики своего реестра.

Посмотрим, как реестр превращает метрики в текст.

§7Как реестр собирает ответ

Что возвращает обход реестра и как из этого получаются строки текста.

generate_latest не хранит готовый текст. Он обходит реестр методом collect() и записывает каждое семейство строками. Посмотрим, что даёт обход, без превращения в текст:

registry.collect()Возвращает семейства. У нас одно — http_requests.
family.samplesОтсчёты семейства: для каждого ряда — строка _total со значением и строка _created со временем создания.

Одна метрика с двумя рядами дала одно семейство и четыре отсчёта. Схема показывает, как они становятся текстом:

Слева — данные: тип и отсчёты. Справа — те же данные строками: для каждого имени строки описания, затем значения. Из-за того, что текст собирается при каждом запросе, Prometheus всегда получает текущие числа.

Вывод

Реестр хранит метрики, collect() отдаёт их семействами с отсчётами, generate_latest записывает семейства строками текста.

Остался заголовок Content-Type из §1: он говорит, каким из форматов записан текст.

§8Content-Type и OpenMetrics

Почему один и тот же адрес может отдать текст в двух форматах.

У текста /metrics два варианта. Классический текстовый формат Prometheus — тот, что мы читали. И OpenMetrics — его стандартизированное продолжение, которое понимают и другие системы. Какой вариант отдать, сервер выбирает по заголовку запроса Accept: в нём клиент перечисляет форматы, которые умеет читать. Prometheus при опросе такой заголовок отправляет. Запросим тот же адрес с тремя разными Accept:

curl -si без -Hcurl не просит ничего особого — сервер отдаёт классический текст version=0.0.4.
-H 'Accept: text/plain; version=1.0.0'Тот же текстовый формат, версия 1.0.0.
-H 'Accept: application/openmetrics-text …'Формат OpenMetrics.

В OpenMetrics три отличия, видные в выводе. Строки описания называют метрику без _total: http_requests. Строки _total и _created одного ряда стоят рядом, в одном семействе. Последняя строка — # EOF, «конец файла»: по ней видно, что ответ пришёл целиком. Числа те же самые — 125, 3 и 1.

Вывод

Формат ответа выбирается по заголовку Accept запроса. Content-Type ответа говорит, какой формат отдан. Числа в обоих форматах одинаковые.

§10Практика

Три задачи. Решение спрятано под задачей.

Задача 1. Найдите ошибки

Ситуация: коллега написал текст /metrics вручную:

Что нужно сделать

Найти строки, которые не будут прочитаны, и проверить ответ разборщиком из §4.

Решение

Не читаются две строки: у channel=mobile нет кавычек, в 3,5 запятая. Исправленные варианты — {channel="mobile"} и 3.5. Пока в ответе есть хотя бы одна из этих строк, Prometheus не сохранит ни одного значения.

Задача 2. Сколько строк в ответе

Ситуация: в своём реестре один счётчик orders с меткой channel, к нему прибавили для web и для mobile.

Что нужно сделать

Предсказать, сколько строк будет в ответе, и проверить запуском.

Решение

Восемь строк: HELP и TYPE для orders_total, два значения, затем HELP, TYPE и два значения для orders_created. Служебных метрик нет — реестр свой.

Задача 3. Формат по заголовку

Ситуация: программа из §1 запущена.

Что нужно сделать

Запросить /metrics в формате OpenMetrics и назвать три отличия от обычного текста.

Решение

Команда — третья из §8. Отличия: имя в HELP и TYPE без _total; строки _total и _created одного ряда стоят рядом; в конце строка # EOF. Content-Type — application/openmetrics-text.

§11Проверьте себя

Вопросы по лекции. Ответ раскрывается щелчком.

Хранит ли приложение готовый текст /metrics между запросами?

Нет. Текст собирается из реестра при каждом запросе, поэтому всегда содержит текущие значения.

{status="200",method="GET"} и {method="GET",status="200"} — один ряд или два?

Один: порядок меток не важен.

Почему status="200" пишут в кавычках, хотя это число?

Значение метки — всегда текст. Без кавычек строка не читается.

Что будет с ответом из двухсот строк, если в одной стоит 61,5?

Опрос неудачен целиком: не сохранится ни одно значение.

Откуда в ответе python_gc_*, если мы их не создавали?

Их добавляет сборщик GCCollector, записанный в общий реестр при импорте библиотеки.

Чем отличается ответ OpenMetrics?

Имя в описании без _total, строки одного ряда рядом, в конце # EOF. Числа те же.

§13Глоссарий

Термины лекции, включая понятия части 1: формулировка, пример и рисунок.

Метрикаmetric

Число, которое описывает много событий сразу и хранится как временной ряд.

Примерhttp_requests_total{method="GET",status="200"} 125.0.

Гделекция 1.4, §2

Временной рядtime series

Значения одной величины у одного объекта по времени. В /metrics ряд задают имя и метки.

Примерhttp_requests_total{method="GET",status="404"}.

Гделекция 1.2, §3

Адрес /metricsmetrics endpoint

Адрес приложения, который отдаёт текущие значения метрик текстом. Текст собирается в момент запроса.

Примерhttp://localhost:8000/metrics.

Гделекция 2.1, §1

Строка значенияsample line

Имя метрики, метки в фигурных скобках и число через пробел. Значения меток в кавычках, число через точку.

Примерqueue_length 7 — строка без меток.

Гделекция 2.1, §2

HELP и TYPE

Строки описания метрики: пояснение для человека и тип. Без TYPE тип неизвестен.

Пример# TYPE http_requests_total counter.

Гделекция 2.1, §3

Семейство метрикиmetric family

Метрика вместе со всеми её рядами и строками описания. Так её возвращают разборщик и collect().

Примерсемейство http_requests: тип counter, четыре отсчёта.

Гделекция 2.1, §2, §7

Реестрregistry

Список метрик процесса, из которого собирается ответ /metrics. Общий — REGISTRY, свой — CollectorRegistry().

Примерв своём реестре — 6 строк, в общем — 18 строк служебных метрик.

Гделекция 2.1, §5–§6

Сборщикcollector

Объект в реестре, который при каждом обходе сам вычисляет значения своих метрик.

ПримерGCCollector отдаёт python_gc_*, ProcessCollector — process_* в Linux.

Гделекция 2.1, §5

OpenMetrics

Стандартизированный вариант текстового формата. Отдаётся по заголовку Accept: application/openmetrics-text, заканчивается # EOF.

ПримерContent-Type: application/openmetrics-text; version=1.0.0.

Гделекция 2.1, §8

Итог лекции

Адрес /metrics отдаёт текущие значения метрик текстом, и этот текст собирается из реестра при каждом запросе. Строка значения — имя, метки в фигурных скобках и число; значения меток всегда в кавычках, число через точку. Над строками значений стоят HELP и TYPE. Значение метки без кавычек, запятая в числе, неизвестный тип и повтор метки делают непригодным весь ответ — это видно, если проверить текст разборщиком библиотеки. Общий реестр REGISTRY уже содержит служебные метрики Python и процесса; свой реестр CollectorRegistry() содержит только переданные ему метрики. Формат ответа сервер выбирает по заголовку Accept: классический текст или OpenMetrics.
