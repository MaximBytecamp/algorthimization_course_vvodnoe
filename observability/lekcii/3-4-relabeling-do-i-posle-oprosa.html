§1Два момента для меток

Почему одинаковое слово relabeling означает две разные операции.

В этот момент в конфигурации уже записаны адреса и служебные метки обнаруженной цели. После ответа /metrics появляются имена метрик, их значения и прикладные метки. Поэтому правила разделены на два поля конфигурации.

Текст endpoint формирует приложение. Relabeling меняет данные, с которыми дальше работает Prometheus: цель для запроса или образец для сохранения.

§2Relabeling target

Что можно сделать до обращения к endpoint.

relabel_configs выполняется после обнаружения target и до scrape. Правило читает метки target, может изменить адрес, путь или схему запроса, добавить обычную метку либо исключить цель. В этот момент строк из /metrics ещё нет.

__address__Внутренняя метка с адресом, к которому Prometheus обратится.
__metrics_path__Внутренняя метка с путём HTTP-запроса; обычно /metrics.
__meta_…Временные метки, которые приносит service discovery.
job, instanceОбычные метки, которые войдут в собранные ряды.

Метки с двойным подчёркиванием — служебные для настройки target. После target relabeling такие временные метки не становятся метками временного ряда. Чтобы сохранить выбранную информацию, правило записывает её в обычную метку.

§3Relabeling метрик

Что можно сделать, когда ответ endpoint уже получен.

metric_relabel_configs выполняется для каждого образца после scrape и перед сохранением в TSDB. Здесь доступны имя метрики через __name__, прикладные метки endpoint и добавленные job, instance. Правило может удалить ненужный образец или изменить его метки.

Отброшенный здесь образец не появится в запросах и не повлияет на хранилище. Но HTTP-запрос уже состоялся: metric relabeling не уменьшает число target и не исправляет их адреса.

§4Из каких частей состоит правило

Как правило берёт значение и записывает результат.

Чаще всего правило читает несколько меток, объединяет их разделителем, проверяет регулярным выражением и выполняет действие. Для понятного изменения имени метки нужны только источник, получатель и замена.

ПолеРольВ примере
source_labelsОткуда прочитать исходное значениеjob
target_labelКуда записать результатservice

У replace действие можно не писать: это значение по умолчанию. В примере действие указано, чтобы правило читалось как последовательность «взять → записать → заменить».

§5Безопасный пример до scrape

Добавляем одну понятную метку, не меняя адрес и не исключая цели.

Ниже — самостоятельный фрагмент для отдельного эксперимента. Он показывает target relabeling: из уже известного job создаётся метка service. Этот фрагмент не добавлен в observability/lab/prometheus.yml; результат на основном стенде не запускался и не заявляется.

Если такой отдельный конфиг применить и проверять в Prometheus, у успешно собранных рядов этого job появится service="telemetry-lab". Адрес target и ответ API остаются прежними: правило добавляет контекст к данным Prometheus.

Почему это безопаснее, чем пример с drop?

Правило не исключает цель, не меняет __address__ и не удаляет образцы. Его эффект легко найти в списке меток ряда и отменить удалением одного блока.

§6Пример после scrape

Ограничиваем сохранение по имени уже полученной метрики.

Следующий самостоятельный фрагмент отбрасывает образцы, имя которых начинается с go_. Условие использует __name__: эта метка появляется только у полученной метрики. Фрагмент предназначен для отдельного прогона; он не входит в конфигурацию действующего стенда.

После проверки конфигурации нужно сравнить два наблюдения: endpoint всё ещё отдаёт строки go_…, а Prometheus их не сохраняет. Такое различие подтверждает выполнение правила после scrape.

Не путайте

drop в metric_relabel_configs не отключает scrape. Prometheus всё равно обращается к endpoint, а затем не сохраняет совпавшие образцы.

§7Границы двух правил

Как не выбрать механизм, который физически не может решить задачу.

ЗадачаГде правилоПочему
Не опрашивать обнаруженный targetrelabel_configsTarget можно исключить до HTTP-запроса.
Изменить адрес или путь запросаrelabel_configsАдрес и путь нужны до scrape.
Добавить контекст всем рядам targetrelabel_configsОбычная метка target перейдёт в собранные ряды.
Не сохранять отдельные имена метрикmetric_relabel_configsИмя метрики появляется только в ответе endpoint.
Убрать метку из уже полученных образцовmetric_relabel_configsПрикладные метки известны после scrape.

Отдельная точка write_relabel_configs находится перед remote_write. Она не выбирает target и не определяет локальное хранение, поэтому здесь рассматриваются только первые два случая.

§8Практика чтения конфигурации

Сначала определяем момент данных, затем — ожидаемое наблюдение.

Задача 1. Выберите блок

Нужно не сохранять метрики с именами python_gc_…, но продолжать опрашивать target. В какой блок попадёт правило?

Проверка

В metric_relabel_configs: имя метрики известно после ответа /metrics, а target должен остаться опрашиваемым.

Задача 2. Назовите проверку

Вы добавили отдельный пример из §5. Какие два места нужно сравнить, чтобы подтвердить смысл правила?

Проверка

В статусе target — что он остаётся доступным, и в запросе к собранному ряду — что появилась метка service. Не нужно ожидать изменения текста /metrics: приложение его не меняло.

Задача 3. Найдите ошибку точки

Студент пытается изменить __address__ в metric_relabel_configs. Почему это не решит задачу?

Проверка

Адрес используется до HTTP-запроса. При metric relabeling scrape уже завершён и меняются только образцы ответа.

§9Проверьте себя

Ответы раскрываются щелчком.

Когда выполняется relabel_configs?

После обнаружения target и до scrape. В этот момент доступны адрес и служебные метки target, но ещё нет метрик endpoint.

Когда выполняется metric_relabel_configs?

После получения ответа /metrics и до сохранения образца в локальную TSDB.

Удалит ли metric relabeling строку из ответа приложения?

Нет. Ответ формирует endpoint. Правило задаёт, какой уже полученный образец Prometheus записывает в TSDB.

Что проверять после изменения relabeling?

Сначала валидность конфигурации, затем статус target и конкретные ряды или метки, которых касается правило. Проверка зависит от точки применения.
