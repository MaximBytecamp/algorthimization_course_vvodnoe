§1Метки и ряды

Как один счётчик делится на части по признаку события.

Заказы бывают оплаченные и отменённые. Если считать их одним числом, рост отмен затеряется среди оплат. На почте письма раскладывают по ящикам по адресу. Счётчик раскладывает события по меткам.

Меткаlabel
Что это
Имя и значение признака события: status="paid".
Что даёт
Один счётчик делится на части, и их можно сравнивать: сколько заказов оплачено, сколько отменено.
Пример
status, method, reason — признаки с несколькими повторяющимися значениями.
Рядseries
Что это
Метрика с конкретными значениями меток и её число. Одна строка вывода — один ряд.
Что даёт
Prometheus хранит историю каждого ряда отдельно, поэтому оплаты и отмены видны на графике разными линиями.
Пример
orders_total{status="paid"} 2.0

Имена меток перечисляют третьим аргументом. Значение выбирают методом labels():

На рисунке — путь трёх заказов из кода выше. Слева заказы с их статусом, в центре вызов labels(), справа ряды счётчика.

Два заказа со статусом paid идут по верхней стрелке в один ряд, поэтому у него 2.0. Отменённый заказ попадает в нижний ряд со значением 1.0. Над рядами стоит общее имя orders_total: метрика одна, рядов два. Эти две строки и напечатал вывод выше.

Если ряда с таким значением ещё нет, labels() создаёт его. Значения меток должны повторяться. Метка status с тремя значениями даёт три ряда. Если записать в метку номер заказа, рядов станет столько же, сколько заказов. Prometheus будет тратить память на миллионы рядов, каждый из которых вырос один раз.

С метками появляются ошибки вызова, которых у счётчика без меток не было.

§2Ошибки при работе с метками

Какие вызовы библиотека отклоняет, если у счётчика объявлены метки.

Набор меток задаётся один раз, при создании счётчика. Каждый вызов обязан назвать эти метки — иначе неизвестно, к какому ряду прибавлять.

Вызов у счётчика с меткой statusРезультат
orders.labels(status="paid").inc()ряд status="paid" растёт на 1
orders.inc()ValueError: не указано значение метки
orders.labels(state="paid").inc()ValueError: такой метки нет

На схеме — как библиотека проверяет вызов. Объявленные метки — это набор ячеек, и каждый вызов должен заполнить их все:

Первый вызов называет метку status: ячейка заполнена, ряд найден. Второй вызов обращается к счётчику без labels(): ячейка осталась пустой, и непонятно, к какому ряду прибавлять. Третий вызов называет state, а такой ячейки у счётчика нет. Второй и третий случаи дают ошибки — вот они в коде:

Обе ошибки возникают в момент вызова. Их ловит первый же запуск кода, который прибавляет к счётчику.

Есть и особенность меток без ошибки: ряд создаётся только при вызове labels().

§3Ряд с нулём

Почему ряды для известных значений меток заводят при запуске программы.

Пока ошибок оплаты не было, в ответе есть только описание метрики, без единого ряда:

Вызов labels() без inc() создаёт ряд со значением 0:

На рисунке — как выглядит график ошибок в обоих случаях:

Слева — график по первому выводу: рядов нет, рисовать нечего, на графике пусто. Справа — график после вызовов labels(): оба ряда есть и равны нулю, поэтому видна линия на нуле. Пустой график оставляет вопрос: ошибок нет или метрика не работает. Линия на нуле отвечает на него: метрика работает, ошибок не было.

Вывод

Известные значения меток заводят при запуске вызовом labels(). Тогда отсутствие событий отличается от неработающей метрики.

Все примеры до сих пор печатали ответ в терминал. Prometheus забирает его по сети.

§5Практика

Задача на то, что разобрано в лекции. Решение спрятано под задачей.

Задача 1. Неудачные входы

Ситуация:

  • в сервисе есть функция login(password, locked=False);
  • вход не удаётся по двум причинам: неверный пароль или заблокированная учётная запись;
  • на графике должна быть линия на нуле для каждой причины, даже если таких ошибок ещё не было.
Что нужно сделать

Создать счётчик login_failures с меткой reason и значениями wrong_password и locked. Завести оба ряда при запуске. Прибавлять к нужному ряду в login. Вызвать login("123"), login("qwerty"), login("secret") и напечатать ответ.

Решение

Два неверных пароля дали 2.0. Ряд locked заведён циклом при запуске и стоит на нуле. Вход с паролем secret счётчик не трогает.

§6Проверьте себя

Вопросы по лекции. Ответ раскрывается щелчком.

Зачем вызывать labels(reason="timeout") без inc()?

Вызов создаёт ряд со значением 0. График показывает линию на нуле, и отсутствие ошибок отличается от неработающей метрики.

У счётчика две метки: status с тремя значениями и method с двумя. Сколько рядов может быть?

До шести: ряд — это одно сочетание значений меток. Рядов столько, сколько сочетаний встретилось в вызовах labels().

Что произойдёт при orders.labels(state="paid").inc(), если объявлена метка status?

ValueError: Incorrect label names. Новая метка не создаётся: набор меток задан при создании счётчика.

§8Глоссарий

Термины лекции, включая введённые раньше: формулировка, пример и рисунок.

Метрикаmetric

Именованное число, которое программа сообщает о себе. Значение меняется со временем, и по его истории видно, как работает программа.

Примерorders_total — сколько заказов принято с момента запуска.

Гделекция 2.1

Ответ /metrics

Текст, который программа отдаёт по адресу /metrics. Для каждой метрики в нём описание (# HELP), тип (# TYPE) и строки «имя значение».

Примерorders_total 3.0 — последняя строка ответа из §2.

Гделекция 2.2, §2; лекция 2.4, §1

Счётчикcounter

Метрика, значение которой с момента запуска программы только растёт. Каждое событие прибавляет к ней число.

Примерпринятые заказы, ошибки оплаты, отправленные байты.

Гделекция 2.2, §1–§4

Меткаlabel

Пара «имя = значение», которая уточняет, к чему относится число. Метрика с разными значениями метки делится на разные ряды.

Примерstatus="paid" и status="cancelled" делят счётчик заказов на два ряда.

Гделекция 2.3, §1–§3

Рядtime series

Все отсчёты одной метрики с одним набором значений меток, выстроенные по времени. Одна строка ответа /metrics даёт при каждом опросе один отсчёт своего ряда.

Примерorders_total{status="paid"} — один ряд, {status="cancelled"} — другой.

Гделекция 2.3, §1

РеестрCollectorRegistry

Список метрик программы. Из него строится текст ответа /metrics: в ответ попадают все метрики реестра.

Примерregistry = CollectorRegistry(); Counter(..., registry=registry).

Гделекция 2.2, §2; лекция 2.6, §2

Итог лекции

Метки делят счётчик на ряды: каждый набор значений меток — отдельный ряд со своим числом. Набор меток задаётся при создании счётчика, и каждый вызов labels() называет ровно эти метки. Значения меток должны повторяться, а ряды для известных значений заводят при запуске, чтобы на графике была линия на нуле.
