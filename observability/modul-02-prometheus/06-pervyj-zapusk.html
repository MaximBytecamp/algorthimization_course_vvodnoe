§2Приложение app.py

Приложение стенда делает две вещи: отдаёт товар по номеру и считает собственные запросы. Счёт ведётся в одном месте, через которое проходят все запросы, и сначала показано, как это место устроено.

Сравнение из жизни
Турникет на входе

Каждый посетитель проходит через турникет. Турникет считает проходы. На то, куда посетитель идёт дальше, он не влияет.

Middleware в приложении

Каждый запрос проходит через одну общую функцию. Она увеличивает счётчик и не меняет ответ приложения. Такая функция называется middleware — промежуточный обработчик.

Путь одного запроса через приложениеstand/app.py
1 · запросGET /items/7Запрос пришёл в приложение.
2 · middlewarecount_requestsПередаёт запрос дальше и ждёт ответа.
3 · обработчикget_itemГотовит ответ с кодом 200.
4 · middleware.inc()Код ответа известен. Счётчик GET, 200 увеличен на 1.

Счётчик увеличивается после шага 3: код ответа становится известен после того, как обработчик закончил работу.

Счётчик увеличивается на четвёртом шаге, потому что код ответа становится известен только после работы обработчика. Ниже код, в котором эти четыре шага записаны.

Python в этой строке: @app.middleware("http") и await call_next(request)

Декоратор @app.middleware("http") сообщает FastAPI, что функцию нужно вызывать для каждого запроса. FastAPI передаёт в неё call_next — функцию, которая запускает обычный обработчик адреса.

Код до строки await call_next(request) выполняется раньше обработчика. Код после неё выполняется, когда ответ готов. Счётчик увеличивается после этой строки, потому что только там доступен response.status_code.

Python в этой строке: HTTP_REQUESTS.labels("GET", "200").inc()

labels() возвращает счётчик для одного сочетания меток. При первом вызове с новым сочетанием он этот счётчик создаёт. inc() увеличивает счётчик на 1, inc(5) — на 5. Уменьшить counter нельзя: библиотека сообщит об ошибке.

>>> from prometheus_client import Counter, CollectorRegistry, generate_latest
>>> r = CollectorRegistry()
>>> c = Counter("demo_total", "Demo", ["method"], registry=r)
>>> c.labels("GET").inc(); c.labels("GET").inc()
>>> print(generate_latest(r).decode())
# HELP demo_total Demo
# TYPE demo_total counter
demo_total{method="GET"} 2.0
# HELP demo_created Demo
# TYPE demo_created gauge
demo_created{method="GET"} 1.790692138359471e+09

>>> c.labels("GET").inc(-1)
Traceback (most recent call last):
  ...
ValueError: Counters can only be incremented by non-negative amounts.

Приложение считает числа и отдаёт их по запросу. Теперь нужен тот, кто будет запрашивать, и это описывают два файла настроек.

§3Конфигурация и Compose

На стенде два файла настроек. Файл prometheus.yml разобран в главе 2.2: одно задание api, target api:8000, интервал 15 секунд, timeout 10 секунд.

Файл compose.yaml описывает, какие контейнеры запустить. Docker Compose — программа, которая запускает несколько контейнеров одной командой и объединяет их в сеть.

СтрокаСмысл
build: .Образ приложения собирается из Dockerfile в этой папке
127.0.0.1:8020:8000Порт 8000 контейнера открыт на компьютере как localhost:8020. Prometheus этим портом не пользуется. Он обращается к api:8000 внутри сети

Все три выделенных файла разобраны. Остальное делается командами.

§4Запуск

Файлы разобраны, и стенд можно запускать. Запуск состоит из пяти шагов: запустить контейнеры, проверить их, отправить запросы к приложению, открыть страницу /metrics и открыть Prometheus. Команды выполняются в папке prometheus-start. Переключатель системы вверху страницы показывает команды для вашей операционной системы. В macOS и Linux команды одинаковые.

  1. Собрать образ приложения и запустить оба контейнера. При первом запуске Docker скачивает образы Python и Prometheus. Это занимает от одной до нескольких минут.
  2. Проверить, что контейнеры работают.
  3. Отправить запросы к приложению. До первого запроса у счётчика нет ни одного ряда (глава 2.3, §5). Команды отправляют 20 запросов к товарам и один запрос к несуществующему товару.
  4. Посмотреть страницу /metrics. В Windows пишут curl.exe: в PowerShell слово curl обозначает другую команду.
  5. Открыть Prometheus: http://localhost:9092, меню Status → Target health.
На полях: название пункта меню

В Prometheus 2 страница называлась Status → Targets. В Prometheus 3 она называется Status → Target health. Адрес страницы прежний: /targets. В инструкциях в интернете часто встречается старое название.

Пятый шаг открывает страницу, по которой проверяют результат запуска. Она разобрана в следующем разделе.

На этой странице Prometheus показывает все target и результат последнего scrape каждого. Ниже — страница стенда и разбор её элементов.

Элемент страницыЗначение на снимкеЧто означает

Endpointhttp://api:8000/metricsПолный адрес запроса (глава 2.2, §2). В браузере на компьютере эта ссылка не откроется: имя api известно только внутри сети Compose

В колонке State бывает три значения. Сразу после запуска там стоит UNKNOWN: target уже в списке, но первого scrape ещё не было, и ждать его приходится до 15 секунд. После успешного scrape состояние становится UP, и ряд up равен 1. После неуспешного — DOWN: ряд up равен 0, а рядом записан текст ошибки.

Target в состоянии UP означает, что числа попадают в базу. Следующий шаг — получить их оттуда запросом.

§6Первые запросы

Запросы пишут на вкладке Query. В этой главе достаточно одного вида запроса — имени метрики. Такой запрос возвращает все ряды с этим именем.

Результат показывается двумя способами. Вкладка Table показывает последнее значение каждого ряда. Вкладка Graph показывает, как значения менялись.

Пять запросов для начала

ЗапросЧто показывает
upДоступность всех target: 1 или 0
http_requests_totalВсе ряды счётчика запросов
http_requests_total{status="404"}Только ряды с меткой status="404". В фигурных скобках записывают условие отбора по меткам
scrape_duration_secondsСколько длился последний scrape каждого target
up[2m]Все значения up за 2 минуты вместе с временем. Работает только на вкладке Table

Почему число обновляется не сразу

Prometheus показывает значения последнего scrape. Если отправить 10 запросов и сразу нажать Execute, число может остаться прежним. Новое значение появится после следующего scrape, не позже чем через 15 секунд.

Пока всё работало без сбоев. Следующий опыт показывает, что видно в Prometheus, когда приложение останавливается.

§7Остановка приложения

Опыт повторяет главу 2.4, §8 на вашем компьютере. В нём приложение останавливается и запускается снова, а Prometheus продолжает работать.

  1. Остановить приложение: docker compose stop api.
  2. Через 15–30 секунд обновить страницу Target health. Состояние стало DOWN, под target записан текст ошибки. На стенде в Docker Desktop это был текст EOF, затем context deadline exceeded. В другом окружении текст может отличаться.
  3. На вкладке Query выполнить запрос up: значение 0. Затем запрос http_requests_total: пустой результат.
  4. Запустить приложение: docker compose start api. После следующего scrape состояние станет UP. Запрос http_requests_total возвращает пустой результат до первого запроса к приложению: счётчик после запуска начинается заново.
  5. На вкладке Graph выполнить запрос up за 5 минут. На графике значение опускается до 0 на время остановки.

Опыт подтверждает четыре наблюдения из главы 2.4: ряд up записывается и во время остановки, ряд приложения прерывается сразу, а счётчик после запуска начинается заново.

Остановка была намеренной. Следующий раздел помогает, когда target не работает без видимой причины.

Проверка файла настроек

Файл настроек проверяет программа promtool. Она входит в образ Prometheus. Проверку выполняют до перезагрузки настроек.

Все случаи выше относятся к запуску в Docker. Если Docker недоступен, стенд запускается иначе.

§9Вариант без Docker

Когда Docker недоступен, приложение и Prometheus запускают как обычные программы. Вариант проверен в macOS с архивом prometheus-3.5.0.darwin-arm64: target localhost:8020 получил состояние UP.

  1. Скачать архив Prometheus 3.5.0 для своей системы со страницы prometheus.io/download и распаковать. В архиве — программы prometheus и promtool.
  2. В папке стенда создать окружение Python и установить зависимости: python -m venv .venv, затем .venv/bin/pip install -r requirements.txt (в Windows — .venv\Scripts\pip).
  3. Запустить приложение: .venv/bin/uvicorn app:app --port 8020.
  4. Во втором окне терминала запустить Prometheus с файлом настроек стенда: ./prometheus --config.file=prometheus-local.yml. Веб-интерфейс откроется по адресу http://localhost:9090. Данные сохраняются в папке data рядом с программой.

В файле prometheus-local.yml записан target localhost:8020. Обе программы работают на одном компьютере, и localhost у них общий.

Стенд запущен одним из двух способов. Осталось проверить результат и поработать с ним самостоятельно.

§10Задания и проверка

Сначала проверьте результат запуска по четырём признакам.

Готово, если

TargetНа Status → Target health задание api: 1 / 1 up, состояние UP.
Запрос upВозвращает один ряд со значением 1 и метками instance="api:8000", job="api".
Запрос счётчикаhttp_requests_total возвращает не меньше двух рядов, значения совпадают с /metrics.
ОтказПосле остановки приложения up = 0 и состояние DOWN; после запуска — снова UP.

Задания

В каждом задании меняется одна настройка. Результат проверяется в веб-интерфейсе Prometheus.

  1. Интервал. Установите в prometheus.yml scrape_interval: 5s, перезагрузите конфигурацию и выполните up[1m]. Сколько значений стало за минуту и какой scrape_timeout показывает страница Status → Configuration?
  2. Метка target. Добавьте target метку env: dev (глава 2.2, §5). На каких рядах она появилась?
  3. Ошибка пути. Добавьте в задание metrics_path: /stats. Запишите текст ошибки и найдите, что изменилось в ответе /metrics приложения через минуту.
  4. Вторая метрика. Добавьте в app.py gauge items_in_progress, который увеличивается в начале обработки /items/{id} и уменьшается в конце. Пересоберите образ (docker compose up -d --build) и найдите метрику в Query.

Порядок работы с итоговым стендом записан в файле PROHOD.md. Первые четыре шага повторяют запуск из этой главы. На пятом шаге проверяется вторая метрика: пять долгих запросов поднимают значение gauge до 5, затем оно возвращается к 0. Шестой шаг — остановка приложения. Шаги с седьмого по девятый — опыты с настройками: интервал 5 секунд, неверный путь и шесть заданий с ошибками. Основной и итоговый стенды занимают порты 8020 и 9092, поэтому перед запуском одного остановите другой командой docker compose down.

Шпаргалка

Запуск и остановкаdocker compose up -d --build docker compose ps docker compose stop api docker compose start api docker compose down

down -v удаляет также данные Prometheus.

Конфигурацияpromtool check config prometheus.yml curl -X POST localhost:9092/-/reload

Для reload нужен флаг --web.enable-lifecycle.

Адреса стендаlocalhost:8020/metrics localhost:9092/targets localhost:9092/query

Внутри сети Compose приложение — api:8000.

Первые запросыup http_requests_total http_requests_total{status="404"} scrape_duration_seconds

Значения обновляются раз в scrape_interval.

Проверьте себя

Вопрос 1Ссылка http://api:8000/metrics в колонке Endpoint не открывается в браузере. Что это значит?

  • UP означает, что Prometheus получил метрики. Он обращается к приложению изнутри сети Compose.

  • Верно. Адрес target записан для сети, в которой работает Prometheus. Браузер работает на компьютере.

  • Этот флаг разрешает перезагрузку настроек. На адреса target он не влияет.

Вопрос 2Отправили 10 запросов и сразу выполнили http_requests_total. Значение не изменилось. Почему?

  • Верно. Prometheus показывает значения последнего scrape. Новое значение появится не позже чем через scrape_interval.

  • Счётчик увеличивается сразу после ответа. Страница /metrics показывает новое значение без задержки.

  • Не считаются только запросы к адресам /metrics….
