§1Ответ приложения стенда

/metrics — обычный HTTP-путь приложения. На запрос GET он возвращает текст с текущими значениями всех метрик процесса. Имя пути — соглашение: Prometheus обращается к /metrics, если в задании не указан другой metrics_path. Ответ можно получить командой curl, браузером или самим Prometheus — это один и тот же запрос.

Перед запросом на стенд отправлено 125 запросов GET /items/…, три запроса к несуществующим товарам и один POST. Ключ -i показывает заголовки ответа.

Ответ состоит из двух строк описания и трёх строк со значениями. Каждая строка со значением — один временной ряд из главы 2.1. Меток job и instance в ответе нет: их Prometheus добавляет при сборе. Отметок времени тоже нет: время ставит Prometheus.

§2Строка по частям

Ниже три строки ответа, относящиеся к ряду GET 200. Нажмите на любую часть, чтобы увидеть её роль и правила записи.

http_requests_total{method="GET",status="200"} 125разбор строки

Части строки выделены цветом: имя — оранжевым, метки — голубым, значение — зелёным.

# HELP http_requests_total Total HTTP requests # TYPE http_requests_total counter http_requests_total{method="GET",status="200"} 125
Строка HELP · описание

Комментарий со словом HELP, затем имя метрики, затем произвольный текст описания. Prometheus сохраняет его как метаданные и показывает в подсказках интерфейса. Строка необязательна; для одного имени допускается одна. Обратная косая черта и перевод строки внутри описания записываются как \\ и \n.

Строка TYPE · тип

Комментарий со словом TYPE, именем и одним из типов: counter, gauge, histogram, summary, untyped. Должна стоять до первой строки со значением этой метрики. Если её нет, тип — untyped.

Тип не меняет того, как хранится отсчёт: в TSDB это то же число. Тип нужен людям и функциям запросов, чтобы понимать, можно ли считать скорость роста.

Имя метрики

Начинается с буквы, _ или :, дальше — буквы, цифры, _, :. Двоеточие по соглашению оставлено для правил записи (recording rules), в коде приложения его не используют.

Соглашения об именах: единица измерения в конце (_seconds, _bytes), у счётчика — суффикс _total, единицы базовые: секунды, байты, метры. Префикс обычно называет подсистему: http_, process_.

Имя метки

Буквы, цифры и _, первая — не цифра. Имена, начинающиеся с __, зарезервированы для внутренних меток Prometheus, как __address__ из главы 2.2.

Внутри фигурных скобок метки разделяются запятыми; запятая после последней метки допустима. Порядок меток значения не имеет: {status="200",method="GET"} — тот же ряд.

Значение метки

Всегда строка в двойных кавычках, даже если выглядит как число: status="200". Внутри допустим любой текст UTF-8; обратная косая черта, кавычка и перевод строки экранируются как \\, \", \n.

Метка с пустым значением method="" для Prometheus равна отсутствию метки.

Набор меток и идентичность ряда

Имя вместе со всем набором меток определяет ряд. {method="GET",status="200"} и {method="GET",status="404"} — два ряда одной метрики. В одном ответе каждое сочетание имени и меток должно встречаться один раз.

Значение

Число с плавающей точкой в записи, которую понимает функция ParseFloat языка Go: 125, 125.0, 1.25e2. Допустимы NaN, +Inf, -Inf. Библиотека Python пишет 125.0; для Prometheus это то же значение 125.

После значения через пробел может стоять отметка времени — целое число миллисекунд с 1970 года. Библиотеки её не ставят, и Prometheus записывает время начала сбора.

§3Правила текстового формата

Формат описан в документации Prometheus в разделе Exposition formats. Он появился в апреле 2014 года и с тех пор меняется только расширениями. Ниже — правила спецификации. Как их применяет сам Prometheus, показано после списка.

Текстовый формат Prometheus

СтрокиКодировка UTF-8, строки разделены символом \n. Последняя строка тоже заканчивается \n. Пустые строки пропускаются. Пробелы и табуляции между частями допустимы в любом количестве.
КомментарииСтрока, начинающаяся с #, — комментарий. Разбирается, только если следующее слово HELP или TYPE; остальные комментарии пропускаются.
HELPНе больше одной строки на имя. В тексте экранируются \\ и \n.
TYPEРовно два слова после TYPE: имя и тип. Не больше одной строки на имя, до первого значения. Без неё тип untyped.
Строка значенияимя{метки} значение [отметка_времени]. Метки необязательны; фигурные скобки без меток допустимы.
ГруппировкаВсе строки одной метрики идут одной группой, HELP и TYPE — в её начале. Нельзя вывести часть рядов, затем другую метрику, затем остальные ряды первой.
УникальностьКаждое сочетание имени и меток встречается один раз. При повторе поведение по спецификации не определено. Имя метки внутри одной строки не повторяется.
Имена UTF-8Имена вне обычного набора символов (например, с точками) записываются в кавычках внутри скобок: {"my.dotted.metric", "error.message"="Not Found"}. Prometheus 3 такие имена принимает.

Разборщик Prometheus проверяет правила не одинаково строго. Чтобы это выяснить, на стенде был запущен сервер, отдающий по разным путям ответы с одним нарушением каждый, и Prometheus 3.5.0 собирал их все.

Нарушение в ответеРезультат сбораЧто сохранено
Значение метки без кавычек: {method=GET}DOWN expected label value, got "G" ("INVALID")Ничего
Запятая в числе: c 61,5DOWN strconv.ParseFloat: parsing "61,5": invalid syntaxНичего
Неизвестный тип: # TYPE h countrDOWN invalid metric type "countr"Ничего
Метка дважды: g{a="1",a="2"}DOWN label name "a" is not unique: invalid sampleНичего
Один ряд дважды с разными значениямиUP, в журнале Error on ingesting samples with different value but same timestampПервое значение, второе отброшено
TYPE после значений; разорванная группа; два TYPE; два HELPUPВсе значения; из двух HELP — последний
Нет перевода строки в конце ответаUPВсе значения
Последовательность \D в значении меткиUPЗначение C:\DIR как есть

Итог опыта: синтаксическая ошибка в любой строке прерывает разбор, и Prometheus отклоняет ответ целиком — ни одно значение не сохраняется, сбор считается неуспешным. Нарушения порядка и уникальности Prometheus 3.5 пропускает. На них нельзя полагаться: разборщик OpenMetrics и другие программы, читающие /metrics, проверяют эти правила строго, а при повторе ряда часть данных теряется без ошибки в интерфейсе.

§4Типы метрик в тексте

Четыре типа по-разному выглядят в ответе. Counter и gauge — одна строка на ряд. Histogram и summary описывают распределение и занимают несколько строк с суффиксами. Пример из документации Prometheus:

ТипЧто означает значениеСтроки в ответе
counterСколько событий произошло с запуска процесса; только растёт, при перезапуске — с нуляОдна на ряд, имя с _total
gaugeТекущая величина: очередь, память, температураОдна на ряд
histogramСколько наблюдений попало в корзины «не больше le», их сумма и число_bucket на каждую корзину, _sum, _count; корзина +Inf обязательна и равна _count
summaryКвантили, посчитанные в самом приложении, сумма и числоСтроки с меткой quantile, _sum, _count
untypedТип неизвестенОдна на ряд

Корзины гистограммы накопительные: в корзину le="0.1" входят и наблюдения из le="0.05". Поэтому значения корзин не убывают сверху вниз. Как из корзин получают перцентили, разбирается вместе с запросами PromQL.

§5Как ответ готовит prometheus-client

Текст можно собрать и вручную, но обычно его готовит клиентская библиотека. В приложении стенда метрика объявлена так:

Первый аргумент Counter — имя, второй — текст строки HELP, третий — имена меток. generate_latest превращает все метрики реестра в текст, CONTENT_TYPE_LATEST — заголовок Content-Type. Счётчик увеличивается в middleware — функции, через которую проходит каждый запрос к приложению (полный код — в главе 2.6).

У библиотеки есть поведение, которое заметно только в ответе. Все примеры ниже получены запуском prometheus-client 0.26.0.

Ряд появляется после первого событияСчётчик с метками не знает заранее, какие сочетания меток будут. Пока не было ни одного .inc(), в ответе только HELP и TYPE.

Что видно в PrometheusПосле перезапуска приложения на стенде up был равен 1, а запрос http_requests_total возвращал пустой результат, пока не пришёл первый запрос. Отсутствие ряда и значение 0 — разные состояния. Если нулевые ряды нужны сразу, их создают вызовом HTTP_REQUESTS.labels("GET", "500") без .inc(). Gauge без меток появляется сразу со значением 0.0.

Ряд _createdБез настройки у каждого ряда счётчика появляется второй ряд — время его создания:

Вывод библиотекиhttp_requests_created{method="GET",status="200"} 1.790686414305862e+09
В тексте Prometheus это отдельный gauge, и он удваивает число рядов счётчиков. В стенде ряд отключён вызовом disable_created_metrics(); то же делает переменная окружения PROMETHEUS_DISABLE_CREATED_SERIES=True.

Стандартные сборщикиЕсли не создавать свой CollectorRegistry, метрики попадают в глобальный реестр вместе с метриками самого Python.

Что добавляетсяpython_gc_objects_collected_total, python_gc_collections_total, python_info; в Linux ещё process_cpu_seconds_total, process_resident_memory_bytes и другие process_*. В macOS группы process_* нет: сборщик читает файлы /proc, которые есть только в Linux. В рабочем сервисе эти метрики полезны; в стенде свой реестр оставляет в ответе одну метрику.

На полях: имя с _total и без

В prometheus-client имя счётчика можно передать с суффиксом _total или без него — в тексте Prometheus строка значения всё равно получит _total. Разница видна в формате OpenMetrics (§6): там имя семейства в HELP и TYPE пишется без суффикса.

§6Content-Type и выбор формата

Текстовый формат Prometheus — один из нескольких. Какой формат нужен, Prometheus сообщает в заголовке Accept каждого запроса, а приложение отвечает заголовком Content-Type. Запрос Prometheus 3.5.0 был записан на стенде отдельным сервером, который печатает входящие заголовки:

Строка Accept на стенде одна; здесь она перенесена для чтения. Числа q — предпочтения: OpenMetrics 1.0 (0,6) выше, чем текст Prometheus (0,4 и 0,3). Порядок задаёт параметр scrape_protocols; по умолчанию в нём четыре текстовых формата. Двоичный формат protobuf добавляется в список, когда включены нативные гистограммы. Accept-Encoding: gzip разрешает сжатый ответ, а X-Prometheus-Scrape-Timeout-Seconds сообщает приложению, сколько Prometheus будет ждать.

§7Проверка своих строк

В поле ниже — ответ стенда. Измените его или выберите пример и нажмите «проверить» (или Ctrl+Enter). Проверка выполняет правила из §3 построчно и делит замечания на два уровня: ошибки — то, на чём Prometheus 3.5 отклоняет ответ, и нарушения спецификации — то, что он пропускает. Уровни взяты из опыта в §3. Имена в кавычках проверка не разбирает.

Проверка текстового форматаправила Prometheus 0.0.4

    В примере «повтор и запятая» два замечания разного уровня. Ряд queue_length{queue="emails"} встречается дважды — это нарушение спецификации: Prometheus сохранит 3 и отбросит 4. Значение 61,5 записано с запятой — это ошибка: дробная часть отделяется только точкой, и весь ответ будет отклонён.

    §8Проверьте себя

    Вопрос 1Почему в ответе /metrics нет меток job и instance?

    • Верно. Приложение не знает, под каким заданием и адресом его собирают. Если оно всё же отдаст job, метка станет exported_job.

    • Ответ одинаков для любого клиента: Prometheus, curl и браузер получают один и тот же текст.

    • В строке TYPE только имя и тип метрики.

    Вопрос 2В ответе 200 строк, одна из них — queue_length{queue=emails} 3. Что сохранит Prometheus?

    • Разборщик не пропускает строки: ошибка в любой строке прерывает разбор всего ответа.

    • Верно. Значение метки без кавычек — синтаксическая ошибка; up станет 0, и ни одно значение из ответа не попадёт в TSDB.

    • Значение метки должно быть в двойных кавычках; Prometheus не угадывает его.

    Вопрос 3Приложение только что перезапущено, запросов ещё не было. Что вернёт Prometheus на запрос http_requests_total?

    • Счётчик с метками не создаёт рядов до первого события: сочетания меток ещё неизвестны.

    • Верно, так было на стенде. В ответе /metrics только HELP и TYPE. Нулевые ряды создают заранее вызовом .labels(...).

    • Старые ряды после неуспешного сбора помечены устаревшими, а новый процесс отдаёт только свои значения.

    Вопрос 4Приложение отдаёт правильный текст с заголовком Content-Type: text/html. Что произойдёт в Prometheus 3.5?

    • Так вёл себя Prometheus 2. С версии 3.0 для этого нужен параметр fallback_scrape_protocol.

    • Верно, это сообщение получено на стенде для пути /metrics/html.

    • Повторного запроса нет: следующая попытка будет только в следующем интервале сбора.
