§1Ответ приложения стенда

Сравнение из жизни
Табло на вокзале

На табло написаны текущие сведения о поездах. Табло никому ничего не отправляет. Каждый, кто подошёл, читает одни и те же строки.

Страница /metrics

На странице написаны текущие значения метрик. Приложение никому их не отправляет. Prometheus, браузер и команда curl получают один и тот же текст.

/metrics — адрес внутри приложения. На запрос GET по этому адресу приложение отвечает текстом. Слово endpoint означает адрес, по которому программа принимает запросы.

Имя /metrics — общепринятое. Prometheus обращается по этому пути, если в задании не указан другой metrics_path.

Настоящий ответ

Перед запросом на стенд отправлено 125 запросов к товарам, три запроса к несуществующим товарам и один запрос POST. Ключ -i у команды curl показывает заголовки ответа.

Из чего состоит ответтри части
строки 1–4Заголовки HTTPКод 200 OK и content-type — в каком формате записан текст.
строки с #Описание метрикиHELP — пояснение для человека. TYPE — вид метрики.
три последние строкиЗначенияОдна строка — один временной ряд из главы 2.1.

В ответе нет меток job и instance и нет времени. Метки и время добавляет Prometheus, когда получает ответ.

§2Строка по частям

Сравнение из жизни
Строка складской ведомости

«Коробки · цвет: синий · склад: № 2 · 125 штук». Сначала что считают, затем уточняющие признаки, в конце количество.

Строка /metrics

http_requests_total{method="GET",status="200"} 125. Сначала имя метрики, затем метки в фигурных скобках, в конце значение.

Три части строки значенияответ стенда

Ниже та же строка вместе с двумя строками описания. Нажмите на любую часть, чтобы увидеть её назначение и правила записи.

http_requests_total{method="GET",status="200"} 125разбор строки

Части строки выделены цветом: имя — оранжевым, метки — голубым, значение — зелёным.

# HELP http_requests_total Total HTTP requests # TYPE http_requests_total counter http_requests_total{method="GET",status="200"} 125
Строка HELP · описание

Пояснение для человека: слово HELP, имя метрики и произвольный текст. Prometheus показывает этот текст в подсказках интерфейса.

Строка необязательна. Для одного имени допускается одна строка HELP.

Строка TYPE · тип

Слово TYPE, имя метрики и её тип: counter, gauge, histogram, summary или untyped. Строка стоит до первого значения этой метрики. Если её нет, тип считается untyped — «не указан».

На хранение тип не влияет: в базе это такое же число. Тип подсказывает человеку и запросам, как с числом работать. Например, скорость роста считают только для counter.

Имя метрики

Состоит из латинских букв, цифр и знака _. Первый символ — буква или _.

Принятые правила: в конце имени пишут единицу измерения (_seconds, _bytes), у счётчика — окончание _total. В начале обычно стоит название части системы: http_, process_.

Имя метки

Состоит из латинских букв, цифр и знака _, первый символ — не цифра. Имена с двумя подчёркиваниями в начале заняты служебными метками Prometheus, например __address__ из главы 2.2.

Метки разделяются запятыми. Порядок меток значения не имеет: {status="200",method="GET"} — тот же ряд.

Значение метки

Всегда текст в двойных кавычках, даже когда он похож на число: status="200".

Если внутри значения нужна кавычка или обратная косая черта, перед ней ставят обратную косую черту: \", \\. Перевод строки записывают как \n.

Набор меток

Имя вместе со всеми метками определяет ряд. {method="GET",status="200"} и {method="GET",status="404"} — два разных ряда одной метрики.

В одном ответе каждое сочетание имени и меток записывают один раз.

Значение

Число. Допустимы записи 125, 125.0 и 1.25e2. Дробная часть отделяется точкой. Библиотека Python пишет 125.0; для Prometheus это то же значение 125.

Есть три особых значения: NaN (не число), +Inf и -Inf (бесконечность).

§3Правила текстового формата

Сравнение из жизни
Бланк заявления

В заявлении десять полей. Если в одном поле дата записана неправильно, заявление возвращают целиком. Девять правильных полей не принимаются отдельно.

Ответ /metrics

В ответе двести строк. Если в одной строке ошибка записи, Prometheus отклоняет ответ целиком. Остальные строки не сохраняются.

Правила записи описаны в документации Prometheus, раздел Exposition formats. Основные правила перечислены ниже.

Основные правила текстового формата

По одной строке на значениеСтроки разделены переводом строки. Последняя строка тоже им заканчивается. Пустые строки пропускаются.
Строка значенияСначала имя, затем метки в фигурных скобках, затем через пробел значение. Меток может не быть.
КомментарииСтрока, которая начинается с #, — комментарий. Prometheus читает из комментариев только HELP и TYPE.
HELP и TYPEДля одного имени — одна строка HELP и одна строка TYPE. TYPE стоит до первого значения.
Строки одной метрики стоят вместеНельзя записать часть рядов метрики, затем другую метрику, затем остальные ряды первой.
Без повторовКаждое сочетание имени и меток встречается один раз.

Что будет при нарушении

Prometheus проверяет правила с разной строгостью. Для проверки на стенде был запущен сервер, который отдаёт ответы с одним нарушением каждый. Prometheus 3.5.0 опрашивал их все.

На правую колонку полагаться не следует. Другие программы, которые читают /metrics, проверяют эти правила строго. При повторе ряда часть данных теряется, и в интерфейсе об этом нет сообщения.

Подробнее: тексты ошибок и редкие правила

Формат появился в апреле 2014 года. Текст записывается в кодировке UTF-8. Между частями строки допустимо любое число пробелов.

После значения через пробел может стоять отметка времени в миллисекундах. Библиотеки её не пишут, и Prometheus ставит время начала опроса.

Prometheus 3 принимает имена с другими символами, например с точками. Такие имена записывают в кавычках внутри скобок: {"my.dotted.metric", "error.message"="Not Found"}.

§4Типы метрик в тексте

В строке TYPE указан тип метрики. Основных типов четыре. Два из них записываются одной строкой на ряд, два — несколькими строками.

Четыре типа метриксравнение из жизни и запись
одометр автомобиляcounterСколько событий произошло с запуска программы. Только растёт. После перезапуска начинается с нуля. Одна строка на ряд, имя заканчивается на _total.
указатель топливаgaugeТекущая величина: длина очереди, занятая память. Растёт и уменьшается. Одна строка на ряд.
ящики для посылок по весуhistogramСколько измерений попало в каждую корзину «не больше стольки-то». Несколько строк на ряд.
готовая сводкаsummaryПриложение считает, в какое время уложилась заданная доля запросов. Несколько строк на ряд.

Как устроена гистограмма

Сравнение из жизни
Учёт посылок на почте

Почта ведёт три счёта: посылки «до 1 кг», «до 5 кг» и «любого веса». Посылку весом 800 граммов засчитывают во все три счёта: она легче 1 кг, легче 5 кг и входит в общее число.

Гистограмма длительности запросов

Приложение ведёт счёт запросов «не дольше 0,05 с», «не дольше 0,1 с» и так далее. Быстрый запрос засчитывается во все корзины, границы которых он не превысил.

Пример гистограммы взят из документации Prometheus. Метка le — сокращение от less or equal, «меньше или равно». В ней записана верхняя граница корзины в секундах.

§5Как ответ готовит prometheus-client

Сравнение из жизни
Счётчик посетителей у входа

Сотрудник нажимает кнопку ручного счётчика на каждого вошедшего. Когда спрашивают, сколько людей пришло, он смотрит на счётчик и называет число.

Библиотека в приложении

Приложение вызывает .inc() на каждый запрос. Когда приходит запрос /metrics, библиотека записывает все числа в виде текста.

Текст ответа можно собрать вручную. Обычно это делает клиентская библиотека. В приложении стенда используется prometheus-client для Python.

Что в коде и что в ответеstand/app.py
В кодеВ ответе /metrics
"http_requests_total"→имя метрики в каждой строке
"Total HTTP requests"→# HELP … Total HTTP requests
Counter→# TYPE … counter
["method", "status"]→{method="…",status="…"}
generate_latest(registry)→весь текст ответа
CONTENT_TYPE_LATEST→заголовок content-type

registry — реестр, список метрик приложения. Счётчик увеличивается в отдельной функции, через которую проходит каждый запрос. Полный код разобран в главе 2.6.

Три особенности библиотеки

Эти особенности видны только в ответе. Все примеры получены запуском prometheus-client 0.26.0.

1. Ряд появляется после первого событияПока не было ни одного вызова .inc(), в ответе только строки HELP и TYPE.

Почему такЗначения меток заранее в библиотеку не записаны: она получает их при первом событии. После перезапуска приложения на стенде запрос http_requests_total возвращал пустой результат до первого запроса к приложению. Пустой результат и значение 0 — разные состояния. Чтобы ряд с нулём появился сразу, его создают вызовом HTTP_REQUESTS.labels("GET", "500") без .inc().

2. Ряд _createdБез дополнительной настройки у каждого ряда счётчика появляется второй ряд со временем его создания.

Как выглядитhttp_requests_created{method="GET",status="200"} 1.790686414305862e+09
Число рядов счётчиков удваивается. На стенде этот ряд отключён вызовом disable_created_metrics().

3. Метрики самого PythonЕсли не создавать свой реестр CollectorRegistry, метрики попадают в общий реестр библиотеки.

Что добавляетсяВ ответе появляются метрики интерпретатора: python_gc_objects_collected_total, python_info и другие. В Linux добавляются метрики процесса process_*: время процессора, память. В рабочем сервисе их оставляют. На стенде свой реестр оставляет в ответе одну метрику.

Подробнее: имя счётчика, gauge без меток, process_* в macOS

Имя счётчика можно передать библиотеке с окончанием _total или без него. В обоих случаях строка значения в тексте Prometheus получит _total.

Gauge без меток появляется в ответе сразу со значением 0.0: у него один ряд, и он создаётся вместе с метрикой.

В macOS метрик process_* нет. Библиотека читает их из папки /proc, которая есть только в Linux. Ряд _created отключает также переменная окружения PROMETHEUS_DISABLE_CREATED_SERIES=True.

§6Content-Type и выбор формата

Сравнение из жизни
Меню в кафе

Гость говорит: «Лучше меню на русском, можно на английском». Официант приносит меню и называет, на каком оно языке. Если он принесёт меню на незнакомом гостю языке, гость не сможет его прочитать.

Два заголовка HTTP

Prometheus в заголовке Accept перечисляет форматы, которые он принимает. Приложение в заголовке Content-Type называет формат своего ответа. Ответ в незнакомом формате Prometheus не разбирает.

Обмен заголовками при одном опросестенд модуля
запрос · PrometheusAccept«Понимаю OpenMetrics и текст Prometheus».
ответ · приложениеContent-Typetext/plain; version=1.0.0 — «отвечаю текстом Prometheus».
результатОтвет разобранФормат есть в списке Prometheus.

Какие бывают форматы

ФорматContent-TypeЧем отличается
Текст Prometheustext/plain; version=0.0.4 или version=1.0.0Формат из §3. Его отдаёт стенд
OpenMetricsapplication/openmetrics-textСтандарт на основе текста Prometheus. В конце обязательна строка # EOF
Protobufapplication/vnd.google.protobufДвоичный формат. Человек его прочитать не может

Неправильный Content-Type

Начиная с Prometheus 3.0 правильный Content-Type обязателен. Опыт на стенде: адрес /metrics/html отдаёт те же правильные строки с заголовком text/html.

Опыт: ответ с заголовком text/htmlPrometheus 3.5.0
ответ приложенияContent-Type: text/htmlСтроки метрик записаны без ошибок.
результатDOWNreceived unsupported Content-Type "text/html; charset=utf-8" and no fallback_scrape_protocol specified for target

Prometheus 2 в этом случае разбирал ответ как текст. Для программ, код которых исправить нельзя, в задании указывают fallback_scrape_protocol: PrometheusText0.0.4. Этот параметр называет формат, которым разбирать ответ с неправильным заголовком.

Подробнее: настоящий запрос Prometheus и та же метрика в OpenMetrics

Запрос Prometheus 3.5.0 записан на стенде сервером, который печатает входящие заголовки. Строка Accept на стенде одна, здесь она перенесена для чтения.

Числа q показывают предпочтения: чем больше число, тем желательнее формат. OpenMetrics 1.0 (0,6) стоит выше текста Prometheus (0,4 и 0,3). Порядок задаёт параметр scrape_protocols. Заголовок Accept-Encoding: gzip разрешает сжатый ответ. Заголовок X-Prometheus-Scrape-Timeout-Seconds сообщает приложению, сколько секунд Prometheus будет ждать.

Приложение стенда отвечает текстом Prometheus на любой Accept: функция generate_latest заголовок запроса не читает. Формат по заголовку выбирает готовый обработчик библиотеки make_asgi_app().

В поле ниже записан ответ стенда. Измените его или выберите готовый пример и нажмите «проверить» (или Ctrl+Enter). Проверка применяет правила из §3 к каждой строке.

Замечания делятся на два уровня, как в опыте из §3. Ошибка — Prometheus 3.5 отклоняет такой ответ. Нарушение — Prometheus 3.5 такой ответ принимает. Имена в кавычках проверка не разбирает.

    §8Проверьте себя

    Вопрос 1Почему в ответе /metrics нет меток job и instance?

    • Верно. В приложении нет сведений о задании и адресе, под которыми его опрашивают. Если приложение отдаст свою метку job, она сохранится как exported_job.

    • Ответ одинаков для любого клиента: Prometheus, curl и браузер получают один и тот же текст.

    • В строке TYPE только имя и тип метрики.

    Вопрос 2В ответе 200 строк, одна из них — queue_length{queue=emails} 3. Что сохранит Prometheus?

    • Prometheus строки не пропускает: ошибка в любой строке останавливает разбор всего ответа.

    • Верно. Значение метки без кавычек — ошибка записи. Ряд up станет равен 0, и ни одно значение из ответа не будет сохранено.

    • Значение метки должно стоять в двойных кавычках. Без кавычек Prometheus его не читает.

    Вопрос 3Приложение только что перезапущено, запросов ещё не было. Что вернёт Prometheus на запрос http_requests_total?

    • Счётчик с метками не создаёт рядов до первого события: значения меток появляются вместе с событием.

    • Верно, так было на стенде. В ответе /metrics только HELP и TYPE. Ряды с нулём создают заранее вызовом .labels(...).

    • Новая программа отдаёт только свои значения. Старые ряды после неудачного опроса перестают показываться (глава 2.4).

    Вопрос 4Приложение отдаёт правильный текст с заголовком Content-Type: text/html. Что произойдёт в Prometheus 3.5?

    • Так работал Prometheus 2. Начиная с версии 3.0 для этого нужен параметр fallback_scrape_protocol.

    • Верно, это сообщение получено на стенде для адреса /metrics/html.

    • Повторного запроса нет. Следующая попытка будет через интервал опроса.
