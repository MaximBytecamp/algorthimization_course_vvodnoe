# Практика 7 · Продолжаем существующий сайт

Сайт преподавателя: https://ga4-analytics-lab-ivanov.vercel.app. Репозиторий: https://github.com/MaximBytecamp/ga4-analytics-lab-ivanov. Студенты работают в своих копиях с занятий 5–6. Новый сайт, репозиторий и поток GA4 не создаём.

1. Сохраните текущую рабочую версию проекта коммитом. Проверьте lead-form, Google Tag и js/metrics.js.
2. Создайте учебную таблицу «GA4 Analytics Lab — Leads», лист leads, A1:I1: request_id, created_at, name, email, direction, utm_source, utm_medium, utm_campaign, status. Закрепите строку 1.
3. Добавьте dropdown I2:I: new, in_progress, done, rejected; неверный ввод отклоняется. Добавьте правила пустых обязательных полей и дублей со слайдов 193–194.
4. Extensions → Apps Script. Вставьте files/Code.gs целиком. Укажите ID таблицы. Сохраните и опубликуйте Web App от своего имени с доступом для посетителей учебной формы. Используйте URL /exec.
5. В существующем contacts.html замените только форму фрагментом files/form.html, подставьте action. Сохраните Google Tag, общий CSS, навигацию и подключение metrics.js. Старое сообщение «данные не отправляются» удалите; новый текст говорит только о попытке POST.
6. Замените прежний submit-обработчик блоком files/lead-form.js. Не добавляйте второй. Для точно такой же версии сайта преподавателя можно использовать files/script.js: CTA из текущего сайта уже сохранён. Если у вас были свои правки, переносите только обработчик формы.
7. Save → Commit «Add Google Sheets lead collection» → Push. В существующем Vercel-проекте дождитесь Ready нужного commit. Новый проект не импортируйте.
8. Откройте contacts.html без UTM. Отправьте только тестовые данные student@example.com. Найдите ID из сообщения формы в Sheets. Ожидайте direct / none / not_set и new.
9. Нажмите «Новая заявка» либо откройте новую страницу contacts.html?utm_source=telegram&utm_medium=social&utm_campaign=lesson07. Отправьте тестовую заявку. Сверьте три UTM-поля в новой строке.
10. Проверьте generate_lead в GA4. Событие и строка — два независимых результата; в этой реализации событие отражает попытку submit.
11. Проверьте пустое имя: HTML не отправляет форму. Серверную проверку тестируйте отдельным POST с пропущенным именем: строка не появляется.
12. Повторите отправку с тем же ID без reset: число строк не меняется. Для просмотра JSON временно используйте target="_blank" и затем верните submission-frame.
13. Отдельно скопируйте тестовую строку внутри Sheets: подсветка выявит дубль. После кадра удалите именно созданную копию.
14. Проверьте отказ ручного ввода finished. Переведите одну заявку new → in_progress → done через dropdown.

## Если не работает

- POST не уходит: остался старый preventDefault, некорректный action, поля не прошли required, код содержит ошибку.
- Строки нет: проверьте /exec, доступ Web App, ID таблицы, точное имя leads, порядок заголовков; откройте Executions в Apps Script.
- Код исправлен, поведение прежнее: сохранения мало; обновите версию развёртывания Apps Script.
- UTM нет: ссылка должна вести сразу на contacts.html с метками. Этот пример не сохраняет их между страницами.
- GA4 молчит, но строка появилась: проверьте тег, блокировщик и выбранный учебный поток. Не повторяйте запись только ради события.

## Результат для отчёта

Сохраните ссылки на собственный сайт, репозиторий и закрытую учебную таблицу; предоставляйте доступ только преподавателю. Приложите 14 доказательств со слайда 260. Объясните различие события и заявки, границы доверия к клиенту и назначение ID. Реальных персональных данных в отчёте быть не должно.
