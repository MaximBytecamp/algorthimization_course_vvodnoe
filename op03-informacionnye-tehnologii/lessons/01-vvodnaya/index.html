КР

Раздел 1 · станции 1–5 · 10 часов · 5 пар

Цифровая воронка и веб-аналитика

#UTM-метки

Собрать набор ссылок для учебных каналов, открыть их на сайте и проверить, что utm_source, utm_medium и utm_campaign сохраняются вместе с заявкой.

источник перехода
▸Google Tag Manager

Настроить отслеживание нажатия кнопки и отправки формы без переписывания сайта. Проверить срабатывание через Preview.

переменная → триггер → тег
≋GA4 и воронка

Проверить поступление событий в DebugView, отметить ключевое действие и построить воронку «просмотр → кнопка → форма → заявка», найти этап с наибольшей потерей.

событие · drop-off

Небольшие темы вроде правил именования UTM и параметров события разбираем внутри этих задач, а не отдельными лекциями.

Р1

Раздел 2 · станции 5–6 · 6 часов · 3 пары

Сбор и подготовка данных

▤Форма и таблица

Настроить форму так, чтобы у каждой заявки были ID, дата, источник, статус и минимально нужные поля. Добавить проверки на пустые значения и дубли.

одна строка — одна заявка
↻Power Query: очистка

Импортировать намеренно грязный файл и получить чистую таблицу без ручного копирования. После замены исходника — один Refresh.

воспроизводимые шаги
⋈Power Query: объединение

Склеить несколько файлов заявок, присоединить справочник источников и вынести строки без соответствия и дубли ключа в отдельный отчёт.

merge · unmatched rows

Разница между «красивой таблицей» и «источником данных для автоматизации» — тема этого раздела: стабильные имена столбцов важнее оформления.

Р2

Раздел 3 · станции 7–8 · 20 часов · 10 пар · ядро курса

API, webhook и первый workflow в n8n

⇄API и webhook

Через Bruno или Postman отправить тестовый запрос в учебный API, затем отправить JSON в webhook и увидеть полученный payload. Разобрать позитивный и ошибочный ответ.

HTTP · JSON · 2xx / 4xx
◱Первый workflow в n8n

Собрать цепочку Webhook → преобразование → таблица. Запустить вручную на нескольких payload и посмотреть историю выполнения. Экспортировать workflow без секретов.

trigger · node · execution
⋔Expressions, IF и Switch

Привести входящую заявку к единой структуре: переименовать поля, преобразовать дату. Развести заявки на три маршрута: обработка, ручная проверка, отказ.

mapping · ветвление
Р3

Раздел 3 · продолжение

Довести автоматизацию до устойчивой: CRM, уведомления, сбои

▦CRM и уведомления

При новой заявке создать запись в учебной CRM, при повторной — найти её и обновить статус. После успешной заявки отправить короткое сообщение в Telegram или на почту.

create vs update
⟲Сбои, дубли, retry

Намеренно сломать шаг, найти проблему по истории выполнения, добавить понятный error route, исключить повторную обработку одной заявки и разрешить ограниченный retry только для временной ошибки.

idempotency · bounded retry
⌁Автоворонка, внешний API, ИИ

Собрать ветку с Wait, проверкой статуса и условием остановки. Обогатить заявку данными из внешнего API. Добавить необязательный этап классификации обращения с проверкой результата.

follow-up · enrichment
Р3

Раздел 4 · станции 9–10 · 4 часа · 2 пары

Сверка данных и отчётность

=Сверка трёх источников

Взять выгрузки из GA4, таблицы заявок и CRM. Сопоставить их по времени, ID и источнику и найти потерянные, отклонённые и продублированные записи.

reconciliation table
▮Дашборд в Looker Studio

Подключить источник и собрать живой дашборд: каналы, события, заявки, статусы, конверсия, проблемные записи. Добавить фильтры по источнику и периоду.

scorecard · funnel
✓Проверка чужими руками

Другой студент меняет фильтр на дашборде и по нему находит заданную проблему. Если находит — дашборд читается, а не просто нарисован.

dashboard v1
Р4

Раздел 5 · финал маршрута · 6 часов · 3 пары

Безопасность, интеграция и защита

⚿Security review

Провести аудит готового workflow: перенести секреты в credentials, убрать лишние персональные поля из логов и уведомлений, подготовить чистый экспорт. Найти 4–6 намеренных нарушений в чужом workflow.

least privilege
⛭Integration Sprint и Bug Bash

Собрать маршрут UTM → сайт → GTM → GA4 → форма → webhook → n8n → CRM → уведомление → отчёт. Передать другой команде инструкцию, по которой она воспроизводит запуск и находит минимум один дефект.

handover report
★Защита v1.0

Развернуть проект с нуля, запустить тестового пользователя через размеченную ссылку, показать событие и заявку, провести её через workflow, намеренно вызвать сбой, найти и починить его, обновить дашборд.
