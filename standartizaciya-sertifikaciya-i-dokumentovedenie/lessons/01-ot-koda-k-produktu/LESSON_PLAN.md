# Первая пара: от работающего кода к готовому программному продукту

4 курс · 90 минут · 36 слайдов. Последовательность исходного сценария сохранена.
Полный сценарий — `SOURCE_SCENARIO.md`. Главная мысль: работающий код сам по себе
не доказывает готовность к передаче; нужны требования, правила, документация и проверка.

## Проведение

| Время | Слайды | Работа группы |
|---|---|---|
| 0–10 | 1–6 | Выбрать позицию о готовности; открыть восемь фактов по одному; обсудить комплект продукта |
| 10–30 | 7–15 | Уточнить пожелания; открыть определения после обсуждения; сформулировать четыре проверяемых требования; проверить границу 500 мс |
| 30–45 | 16–19 | Обсудить документы команды; вывести единые правила; найти пример в OpenAPI |
| 45–60 | 20–24 | Связать документы с читателями; найти расхождение версий; обсудить документацию в Git |
| 60–70 | 25–29 | Выделить свойства качества; рассмотреть ISO/IEC 25010:2023; собрать общую схему |
| 70–85 | 30–34 | Изучить PRACTICE_CASE.md, скопировать шаблон, заполнить docs/handoff_audit.md; после работы раскрыть пример итога |
| 85–90 | 35–36 | Назвать четыре понятия по вопросам; защитить решение об аудите |

## Порядок раскрытия

Проблема → вопрос → обсуждение → термин → применение. Кнопки голосования
фиксируют позицию, но не показывают автоматический «правильный ответ».
Ответы в блоках раскрываются преподавателем после реплик группы.
Слайд 3 открывает один из восьми фактов за нажатие; итоговый вопрос появляется после восьмого.
На слайде 13 четыре задания показываются по одному; черновики сохраняются локально,
если браузер разрешает хранилище. На слайде 15 ползунок сравнивает учебное значение с 500 мс.
Шаблон на слайде 32 разделён на пять вкладок; копируется и скачивается целиком.
Пример итогового аудита на слайде 34 скрыт до обсуждения.

## Точность примеров

- Числа на слайдах 14–15 — учебные данные, не результаты запуска сервиса.
- Среднее 420 мс не доказывает требование «каждый запрос ≤ 500 мс», если максимум 610 мс.
- Пример «нормальной авторизации» сохранён; отдельно пояснено, что вход относится
  к аутентификации, а права на действия — к авторизации.
- Национальный и международный уровни не показаны как юридическое подчинение.
  ГОСТ может обозначать межгосударственный стандарт; применимость уточняют отдельно.
- Слайд 27 показывает только часть характеристик ISO/IEC 25010:2023.
- Сертификация не является обязательным продолжением любой приёмки и не заменяется учебным аудитом.
- Практика — аудит предоставленного кейса, а не запуск отсутствующего backend.

## Навигация и показ

Откройте `index.html` напрямую или через любой статический HTTP-сервер.
Сборка и установка зависимостей не нужны. Содержание и примеры доступны без сети;
внешние источники требуют подключения.

- Стрелки ← →, PageUp / PageDown, пробел — переход между слайдами.
- Home / End — первый / последний слайд.
- F — полный экран; M — содержание; S — источники.
- Escape — закрыть диалог. Из полей ввода и вкладок клавиши не листают презентацию.
- На сенсорном экране — горизонтальный свайп вне элементов управления.
- Ссылка `index.html#32` открывает шаблон напрямую.
- Клик по макету или загруженному кадру увеличивает его.
- «Источники → Печать» выводит все слайды, раскрытия и части шаблона.

Слайды прокручиваются при нехватке высоты; навигация остаётся видимой.
На проекторе предпочтителен полноэкранный режим. Не уменьшайте шрифт ради длинного Markdown:
переключайте вкладки шаблона.

## Критерии практической работы

В файле заполнены все пять разделов. Замечания конкретны: endpoint, отсутствующий
документ, неуточнённый параметр или критерий. Предложения не выдаются за согласованные
требования. Непроведённые проверки помечены как «не проверено». Итог содержит один статус
и аргументы, связанные с требованиями, документами и доказательствами.
