# Слайд 18. Стандарт — это не обязательно ГОСТ

## Заголовок

Правила существуют на разных уровнях

## Схема

```text
МЕЖДУНАРОДНЫЙ УРОВЕНЬ
ISO / IEC и другие организации

        ↓

НАЦИОНАЛЬНЫЙ УРОВЕНЬ
ГОСТ / национальные стандарты

        ↓

ОРГАНИЗАЦИЯ
внутренние стандарты компании

        ↓

КОМАНДА / ПРОЕКТ
свои conventions и правила
```

## Важно

Стандарт сам по себе не во всех ситуациях автоматически становится обязательным.

Обязательность зависит от законодательства, договора, регламентов и условий конкретной работы.

# Слайд 28. А где здесь сертификация?

## Заголовок

Не каждую программу нужно нести «за сертификатом»

## Текст

Есть широкий процесс:

**оценка соответствия**

Мы проверяем, соответствует ли объект установленным требованиям.

А сертификация — уже один из формальных вариантов подтверждения соответствия в тех случаях, где она применяется.

## Схема

```text
ТРЕБОВАНИЯ
↓
ПРОВЕРКА
↓
ОЦЕНКА СООТВЕТСТВИЯ
↓
при необходимости
ФОРМАЛЬНОЕ ПОДТВЕРЖДЕНИЕ
```

## Подпись

Эту часть подробно разберём отдельно.

# Поведение веб-презентации

Не показывать все определения сразу.

Использовать последовательное раскрытие:

**СИТУАЦИЯ → ВОПРОС → ОТВЕТ → ТЕРМИН**

Например:

сначала показать плохое требование;

затем спросить, можно ли его проверить;

после ответа показать улучшенную формулировку;

и только затем дать термин «проверяемое требование».

На слайдах с кейсами использовать интерактивные кнопки.

На практических слайдах предоставить:

* кнопку копирования шаблона;
* возможность скачать `handoff_audit.md`;
* большие читаемые примеры Markdown;
* минимум декоративных изображений;
* схемы, документы, репозитории, таблицы и интерфейсные элементы вместо стоковых картинок.

Главный визуальный паттерн:

**ПРОБЛЕМА → ПРАВИЛО → ДОКУМЕНТ → ПРОВЕРКА**
