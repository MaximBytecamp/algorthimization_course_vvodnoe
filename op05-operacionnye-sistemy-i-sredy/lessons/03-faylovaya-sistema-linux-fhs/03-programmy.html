Программы не меняются во время работы, поэтому лежат в /usr. Но, чтобы запустить Python, никто не набирает /usr/bin/python3. Достаточно ввести python3.

Значит, оболочка сама ищет файл по короткому имени. В этом слое разберём, где и в каком порядке она ищет.

−3.1

3.1 Порядок поиска команды

PATH(7)ОпределениеPATH(7)
Имя
PATH — переменная окружения
Что это
Список каталогов, в которых оболочка ищет программу по имени. Каталоги в списке разделены двоеточием.
Как работает
Когда вы вводите имя без косой черты, Bash сначала проверяет, не встроенная ли это команда. Если нет, он по очереди заглядывает в каталоги из PATH, слева направо. Первый найденный файл запускается, дальше поиск не идёт.
Зачем
Программу можно запустить из любого каталога и не помнить, где она установлена.
Не путать
Текущего каталога в PATH обычно нет. Поэтому программу из текущего каталога запускают так: ./app. Косая черта в имени говорит оболочке, что это путь и искать не нужно.

Есть ещё псевдонимы — короткие имена для команд. Например, в Ubuntu ls на самом деле выполняется как ls --color=auto. Псевдоним оболочка подставляет раньше всего остального. Выберите команду в модели и посмотрите, как идёт поиск.

В терминале · 3.1Спрашиваем оболочку о командах
  1. command -v python3# где файл программы python3
  2. type cd# что такое cd
  3. type ls# что такое ls
  4. printf "%s\n" "$PATH" | tr : "\n"# вывести PATH, по каталогу в строке

Что должно получиться

python3 найден в /usr/bin, cd — встроенная команда (shell builtin).

На вашей машине

Если python3 в системе нет, выполните те же команды для bash: command -v bash и /usr/bin/bash --version.

?Почему программу app из текущего каталога запускают как ./app, а не просто app?Сначала ответьте сами
Текущего каталога нет в PATH, поэтому по имени app оболочка файл не найдёт. В ./app есть косая черта: это путь, и оболочка сразу запускает файл по нему. У файла ещё должно быть право на запуск.

3.2 Каталог /usr и ссылка /bin

КаталогЧто в нём лежитКто туда устанавливает
/usr/binкоманды для всех пользователейменеджер пакетов
/usr/sbinпрограммы для администратора и службы, например cupsdменеджер пакетов
/usr/libбиблиотеки и служебные файлы программменеджер пакетов
/usr/shareсправка, переводы и другие общие файлыменеджер пакетов
/usr/local/…программы, установленные вручнуюадминистратор
/opt/имясторонняя программа целиком в одном каталогепоставщик программы
USRMERGE(7)ОпределениеUSRMERGE(7)
Имя
usrmerge — объединение каталогов в /usr
Что это
Устройство современной Ubuntu, при котором /bin, /sbin и /lib — не отдельные каталоги, а ссылки на каталоги внутри /usr.
Как работает
Раньше часть программ лежала в /bin, часть — в /usr/bin. Сейчас все программы перенесли в /usr, а старые пути оставили ссылками. /bin/ls и /usr/bin/ls — один и тот же файл.
Зачем
Старые скрипты, где написано /bin/bash, продолжают работать.
Не путать
Ссылка /bin — не лишняя копия. Если её удалить, перестанут работать программы и скрипты, которые обращаются по старому пути.
В терминале · 3.2Куда ведут старые пути
  1. ls -ld /bin /sbin /lib# сведения о самих ссылках
  2. readlink /bin# что записано в ссылке
  3. readlink -f /bin# полный путь, куда она ведёт
  4. ls /usr
  5. ls /usr/local# программы, установленные вручную
Что должно получиться

все три строки начинаются с буквы l и ведут в usr.

?Можно ли удалить /bin, раз всё то же самое есть в /usr/bin?Сначала ответьте сами
Нет. Через эту ссылку к программам обращаются многие скрипты, например с первой строкой #!/bin/bash. Без ссылки они перестанут запускаться.

Итог слоя 03

01Все файлы Linux лежат в одном дереве каталогов, и путь к любому файлу начинается с корня /. 02Каталог для файла выбирают по тому, что в нём хранится: программа, настройки или данные. 03Программы лежат в /usr, а оболочка находит их по списку каталогов из переменной PATH.

Программы лежат в /usr. Когда мы вводим короткое имя, оболочка ищет файл по каталогам из PATH. Службы, такие как cupsd, запускаются по полному пути.
