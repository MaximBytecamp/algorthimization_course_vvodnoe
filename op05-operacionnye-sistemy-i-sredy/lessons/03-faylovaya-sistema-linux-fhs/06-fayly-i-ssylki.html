Имя, тип и содержимое файла

Тип объекта не определяется расширением

Первый символ подробного вывода ls обозначает тип объекта: - — обычный файл, d — каталог, l — символическая ссылка, c — символьное устройство, b — блочное. Ещё существуют p для именованного канала и s для сокета.

file анализирует объект и, для обычного файла, признаки его содержимого. Поэтому текстовый файл может не иметь расширения, а переименование в .png не превращает текст в изображение. Это другой уровень описания: и текст, и ELF-программа являются обычными файлами с разным форматом байтов.

Python в /usr/bin нередко представлен ссылкой на конкретную версию. По умолчанию file описывает ссылку; file -L следует к цели. Архитектура ELF в вашей VM зависит от платформы: на снимке ARM aarch64, на обычном ПК возможна x86-64.

В чём разница между «обычный файл» и «текстовый файл»?

Первое — тип объекта файловой системы, второе — характеристика содержимого. Исполняемая ELF-программа тоже может быть обычным файлом, хотя не является текстом.

Символическая ссылка хранит путь

Создадим info-link.txt, указывающую на data/info.txt. ln -s создаёт отдельный объект со строкой пути. Чтение через ссылку обычно следует к цели, поэтому cat покажет тот же текст.

Относительная цель разрешается от каталога самой ссылки, а не от текущего каталога читающей программы. У нашей ссылки родитель — linux-fhs-lab, поэтому data/info.txt находится правильно. Если перенести ссылку в другую папку без цели, она может стать «битой».

Если ln сообщает File exists, ссылка уже создана. Сначала проверьте ls -l info-link.txt и продолжайте с существующей ссылкой. Для повторения опыта можно выбрать новое имя; принудительное замещение здесь не нужно.

Если удалить целевой файл, сохранит ли символическая ссылка его текст?

Нет. Она хранит путь, а не копию данных. Сама ссылка останется, но чтение через неё не найдёт удалённую цель.

inode и второе имя того же файла

В типичной Unix-файловой системе запись каталога связывает имя с номером inode. Inode содержит метаданные: тип, права, владельца, размер, временные отметки и сведения о размещении данных. Имя хранится в каталоге, поэтому у одного inode может быть несколько имён.

stat показывает метаданные. Modify — изменение содержимого; Change — изменение состояния inode, например прав или числа ссылок. Это не обязательно время создания. Номер inode имеет смысл в пределах конкретной файловой системы.

ln без -s создаёт жёсткую ссылку: второе имя того же inode. У info.txt и info-hard.txt совпадут inode и содержимое, а число Links станет 2. Такая ссылка на обычный файл должна находиться в той же файловой системе. Символическая ссылка может указывать и за её пределы.

Почему удаление одного имени жёсткой ссылки не обязательно удаляет данные?

Другие имена продолжают ссылаться на тот же inode. Освобождение данных возможно после удаления последней жёсткой ссылки и закрытия оставшихся открытых ссылок процессов на файл.
