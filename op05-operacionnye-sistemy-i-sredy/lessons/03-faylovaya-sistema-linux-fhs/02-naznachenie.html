Главная мысль · что уже известно

01Все файлы Linux лежат в одном дереве каталогов, и путь к любому файлу начинается с корня /. 02…это предложение появится в конце страницы

Мы умеем читать путь. Теперь вернёмся к вопросу с обложки: почему файлы одной программы лежат в разных каталогах?

В Linux файлы раскладывают не по программам, а по тому, что в них хранится. Программа идёт в один каталог, её настройки — в другой, журналы — в третий. Это правило записано в стандарте FHS.

−2.1

2.1 Файловая система и стандарт FHS

Два понятия этого слоя легко перепутать, поэтому разберём их по очереди.

ФАЙЛОВАЯ СИСТЕМА(7)ОпределениеФАЙЛОВАЯ СИСТЕМА(7)
Имя
файловая система — ext4, btrfs, tmpfs, proc
Что это
Способ хранения файлов: как записываются имена, сведения о файлах и их содержимое.
Как работает
ext4 хранит файлы на диске, tmpfs — в оперативной памяти, а proc вообще ничего не хранит: содержимое её файлов выдаёт ядро при чтении. Для программ все они выглядят одинаково — как каталоги и файлы.
Зачем
К одному дереву каталогов можно подключить несколько файловых систем сразу.
Не путать
Файловая система отвечает на вопрос «как хранить файлы». В какой каталог класть настройки, она не решает.
FHS(7)ОпределениеFHS(7)
Имя
FHS — Filesystem Hierarchy Standard
Что это
Стандарт, который описывает, для чего нужен каждый основной каталог Linux.
Как работает
По FHS в /etc лежат настройки, в /usr — программы, в /var — данные, которые меняются во время работы. Текущая версия стандарта — FHS 3.0. Дистрибутивы следуют ему с небольшими отличиями.
Зачем
Зная стандарт, администратор найдёт журнал или настройки даже незнакомой программы.
Не путать
FHS отвечает на вопрос «где хранить файлы». Как именно они записаны на диск, стандарт не описывает.
В терминале · 2.1Проверяем каталоги из стандарта
  1. ls -d /boot /etc /home /opt /srv /usr /var /mnt /media# -d показывает сами каталоги, а не их содержимое
  2. ls -ld /root
  3. ls -la /opt /srv# что лежит внутри /opt и /srv
Что должно получиться

все каталоги существуют. /opt и /srv пустые — это нормально.

Краткое описание каталогов есть в самой Ubuntu. Команда man hier открывает справку, выход — клавиша q.

?/home — это каталог. Может ли в нём быть подключён отдельный диск?Сначала ответьте сами
Да. К любому каталогу можно подключить файловую систему с другого диска. Путь останется /home, а файлы будут лежать на подключённом диске. Как это проверить, разберём в слое 7.
−2.2

2.2 Два вопроса, по которым выбирают каталог

Чтобы понять, куда положить файл, FHS задаёт два вопроса.

Первый: меняется ли файл, пока программа работает? Сама программа после установки не меняется. Журнал, наоборот, пополняется каждую минуту.

Второй: можно ли использовать этот файл на другом компьютере? Программа одной версии одинакова на всех компьютерах. А настройки сети подходят только к этому.

СТАТИЧЕСКИЕ И ИЗМЕНЯЕМЫЕ ДАННЫЕ(7)ОпределениеСТАТИЧЕСКИЕ И ИЗМЕНЯЕМЫЕ ДАННЫЕ(7)
Имя
статические и изменяемые данные — static и variable
Что это
Статические данные не меняются сами: программы, библиотеки, справка. Изменяемые меняются во время работы: журналы, очереди, базы данных.
Как работает
Статические данные можно хранить в каталоге, куда запрещена запись. Изменяемым нужен каталог, куда программа может писать.
Зачем
Когда они разделены, программу можно обновить и не задеть данные, а резервную копию делать только для того, что меняется.
Не путать
Настройки в /etc считаются статическими, хотя администратор их правит: сама программа во время работы их не меняет.
Модель · классификация FHS 3.0, раздел 2Нажмите на каталог
подходят любому компьютеру → только для этого компьютеране меняются → меняются
Не меняются · подходят любому компьютеру
Не меняются · только для этого компьютера
Меняются · подходят любому компьютеру
Меняются · только для этого компьютера

Нажмите на каталог, чтобы узнать, почему он в этой клетке.

Эта таблица взята из стандарта FHS 3.0. Журналов и кэша в ней нет, но правило к ним применяется так же: они меняются во время работы и относятся к этому компьютеру. Поэтому они лежат в /var.

?В какую клетку таблицы попадёт файл /etc/hostname с именем компьютера?Сначала ответьте сами
В клетку «не меняются, только для этого компьютера». Программы этот файл не меняют, а имя относится только к этому компьютеру.
−2.3

2.3 Настройки: каталог /etc

КОНФИГУРАЦИОННЫЙ ФАЙЛ(7)ОпределениеКОНФИГУРАЦИОННЫЙ ФАЙЛ(7)
Имя
конфигурационный файл — хранится в /etc
Что это
Текстовый файл, в котором записаны настройки системы или программы.
Как работает
Программа читает этот файл при запуске. В /etc лежат только настройки, самих программ там нет.
Зачем
При обновлении программы её файлы в /usr заменяются. Изменённый файл настроек менеджер пакетов не перезапишет, а спросит, что с ним делать.
Не путать
/etc/os-release описывает дистрибутив. Версию ядра показывает другая команда — uname -r.
В терминале · 2.2Читаем три файла настроек
  1. cat /etc/os-release# какой дистрибутив и какая версия
  2. cat /etc/hostname# имя компьютера
  3. cat /etc/hosts# адреса, которые компьютер знает без интернета
Что должно получиться

в os-release есть NAME, VERSION и ID, в hosts есть строка localhost.

?Можно ли по файлу /etc/os-release узнать, сколько свободного места на диске?Сначала ответьте сами
Нет. В этом файле только сведения о системе. Свободное место показывает команда df, её разберём в слое 7.
−2.4

2.4 Учётная запись пользователя

Сведения о пользователях — тоже настройки, поэтому они хранятся в /etc/passwd. Команда getent passwd выводит эти сведения. Запись $(id -un) оболочка заменяет на ваше имя пользователя.

В терминале · 2.3Своя учётная запись и содержимое /etc
  1. getent passwd "$(id -un)"# строка с вашей учётной записью
  2. find /etc -maxdepth 1 -type f | head -8# первые восемь файлов в /etc
  3. find /etc -mindepth 1 -maxdepth 1 -type d | head -8# первые восемь каталогов в /etc
Что должно получиться

в строке учётной записи видны номер пользователя, домашний каталог и оболочка.

Поле Live session user,,, — описание для людей. Система его не использует.

?Попадёт ли символическая ссылка в результат команды find /etc -type f?Сначала ответьте сами
Нет. Ключ -type f выбирает только обычные файлы, а у ссылки свой тип — l.
−2.5

2.5 Раскладываем файлы CUPS

Теперь можно ответить на вопрос с обложки. Менеджер пакетов dpkg помнит, какие файлы установил каждый пакет. dpkg -S показывает, какому пакету принадлежит файл, dpkg -L — список файлов пакета. Из длинного списка мы отобрали шесть главных строк.

В терминале · 2.4Где лежит служба печати
  1. dpkg -S /usr/sbin/cupsd# из какого пакета программа cupsd
  2. dpkg -L cups-daemon | grep --color=never -xE '/(etc/cups|usr/sbin/cupsd|var/(log|spool|cache)/cups|lib/systemd/system/cups.service)'# шесть главных строк из списка файлов пакета
  3. ls -ld /run/cups# этот каталог создаёт сама служба при запуске
  4. systemctl is-active cups# проверить, что служба работает
Что должно получиться

файлы одного пакета cups-daemon лежат в /etc, /usr, /var и /run.

Модель · один пакет cups-daemon
/cups/ — одна папка программывоображаемая схема
/usrпрограмма
/etcнастройки

  • /usr/sbin/cupsdпрограмма службы печатипрограмма → /usr
  • /lib/systemd/system/cups.serviceописание службы, пришло с пакетомчасть программы → /usr/lib
  • /etc/cupsнастройки печатинастройки → /etc
  • /var/spool/cupsзадания, которые ждут печатиочередь → /var/spool
  • /var/log/cupsжурналыжурнал → /var/log
  • /var/cache/cupsкэш, программа может создать его зановокэш → /var/cache
  • /run/cupsфайлы работающей службынужны до перезагрузки → /run

Левая схема воображаемая: так выглядела бы установка, если бы файлы собирали в папку программы. Правая — настоящие адреса из кадра выше.

?Почему файл cups.service лежит в /lib/systemd/system, а не в /etc/systemd/system?Сначала ответьте сами
Этот файл пришёл вместе с пакетом, то есть он часть программы. Такие файлы лежат в /lib, а в Ubuntu это на самом деле /usr/lib. Каталог /etc/systemd/system оставлен администратору для его собственных настроек.

Итог слоя 02

01Все файлы Linux лежат в одном дереве каталогов, и путь к любому файлу начинается с корня /. 02Каталог для файла выбирают по тому, что в нём хранится: программа, настройки или данные.

Каждый файл CUPS лежит там, где хранят данные его вида: программа — в /usr, настройки — в /etc, то, что меняется во время работы, — в /var. Дальше разберём, как система находит программу по имени.
