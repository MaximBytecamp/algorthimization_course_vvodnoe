2.1 Стандарт FHS

Расположение файлов в Linux не случайно. Оно описано стандартом FHS (Filesystem Hierarchy Standard), который поддерживает Linux Foundation. Стандарт определяет, для каких данных предназначен каждый основной каталог. Благодаря ему администратор знает, где искать настройки, журналы или исполняемые файлы любой установленной программы.

Основной принцип FHS: файлы распределяются не по программам, а по типу данных. У одной программы исполняемый файл, настройки и журналы окажутся в разных каталогах. Такое разделение позволяет обновлять программы, не затрагивая настройки, и делать резервные копии только тех данных, которые меняются.

Для сравнения: в квартире вещи раскладывают не по тому, кто их купил, а по назначению — продукты на кухне, одежда в шкафу, инструменты в кладовке. Поэтому даже в чужой квартире понятно, где искать чашку. Так же и в Linux: настройки любой программы администратор ищет в /etc, а её журналы — в /var/log.

Назначение каталогов можно проверить прямо в системе, без интернета. В Linux есть встроенная справка — команда man (от английского manual, «руководство»). Для каждой команды и многих понятий в ней есть отдельная страница. Страница hier (от hierarchy, «иерархия») описывает те же каталоги, что и таблица выше: слева указан каталог, справа — его назначение.

Справка написана на английском языке. Перелистывать её можно стрелками, выйти — клавишей q.

2.2 Каталог настроек /etc

В /etc находятся конфигурационные файлы — текстовые файлы, в которых задаются параметры системы и служб. Программы читают их при запуске. Исполняемых файлов в /etc нет. Когда пакет обновляется, менеджер пакетов заменяет файлы программы, но не перезаписывает изменённые администратором настройки.

Пример. Чтобы изменить имя компьютера, администратор правит одну строку в файле /etc/hostname. Чтобы настроить службу, он открывает файл в её подкаталоге внутри /etc. Переустанавливать программу для этого не нужно.

Для примера рассмотрим три файла. /etc/os-release содержит название и версию дистрибутива, /etc/hostname — имя компьютера, /etc/hosts — таблицу соответствия имён и IP-адресов, которую система использует до обращения к DNS.

Конфигурационные файлы обычно устроены просто. Каждая строка задаёт один параметр в виде параметр=значение, а строки, которые начинаются с #, — комментарии: программа их пропускает. Например, в /etc/os-release строка NAME="Ubuntu" означает, что параметр NAME имеет значение Ubuntu. У некоторых программ формат другой, но принцип тот же: это текст, который можно открыть и изменить в любом редакторе.

2.3 Учётные записи пользователей

Сведения о пользователях тоже относятся к настройкам системы, поэтому хранятся в /etc — в файле /etc/passwd. Каждая строка этого файла описывает одну учётную запись. Строка состоит из семи полей, разделённых двоеточием. Сами пароли в этом файле не хранятся: они записаны в зашифрованном виде в отдельном файле /etc/shadow, прочитать который может только администратор.

Выполним три команды. Первая выводит строку учётной записи текущего пользователя. Команда id -un печатает имя пользователя, а конструкция $( ) подставляет результат одной команды внутрь другой. Команда getent passwd ищет в базе учётных записей строку с этим именем.

Вторая и третья команды показывают, что лежит в самом каталоге /etc. Команда find ищет объекты в указанном каталоге. Ключ -maxdepth 1 ограничивает поиск только каталогом /etc, без вложенных каталогов. Ключ -type f отбирает обычные файлы, -type d — каталоги. Ключ -mindepth 1 убирает из результата сам /etc. Знак | передаёт вывод команде head -8, которая оставляет первые восемь строк, иначе список занял бы несколько экранов.

2.4 Пример: файлы службы печати CUPS

Посмотрим, как правила FHS выполняются для настоящей программы. Возьмём CUPS — службу печати, которая по умолчанию установлена в Ubuntu. Когда в любой программе вы нажимаете «Печать», документ отправляется в CUPS. Служба ставит задание в очередь, передаёт его принтеру и записывает результат в журнал. Принтер для этого примера не нужен: нас интересует только, где лежат файлы службы.

CUPS удобна как пример, потому что у неё есть всё, что бывает у типичной службы: программа, настройки, журналы, очередь заданий и кэш. Программы в Ubuntu устанавливаются пакетами, и менеджер пакетов dpkg хранит список файлов каждого пакета. Команда dpkg -S показывает, какому пакету принадлежит файл, а dpkg -L выводит все файлы пакета. Из длинного списка отобраны основные строки.

Итоги части 2

  • Стандарт FHS определяет назначение основных каталогов Linux.
  • Файлы распределяются по типу данных: настройки — /etc, программы — /usr, изменяемые данные — /var.
  • Конфигурационные файлы — текстовые, программы читают их при запуске.
  • Учётные записи описаны в /etc/passwd, пароли хранятся в /etc/shadow.
