6.1 Типы объектов файловой системы

Каталоги, устройства и ссылки в Linux тоже являются объектами файловой системы, но разных типов. Тип обозначается первым символом строки в выводе ls -l.

СимволТип объекта
-обычный файл
dкаталог
lсимволическая ссылка
c, bсимвольное и блочное устройство
sсокет — файл для обмена данными между программами

Тип объекта не говорит о содержимом обычного файла: и текстовый документ, и исполняемая программа имеют тип -. Содержимое определяет команда file, которая анализирует сами данные. Расширение имени в Linux на тип и содержимое файла не влияет.

В терминалеТипы объектов
  1. cd ~/linux-fhs-lab
  2. file data/info.txt /usr/bin/python3 /dev/null# анализ содержимого
  3. file -L /usr/bin/python3# содержимое файла, на который указывает ссылка
  4. ls -ld data data/info.txt /bin /dev/null# четыре объекта разных типов
Результат

строки ls начинаются с d, -, l и c.

6.2 inode и жёсткие ссылки

Сведения о файле и его имя хранятся в разных местах. Тип, права доступа, владелец, размер, время изменения и расположение данных на диске записаны в структуре, которая называется inode. У каждого inode есть номер. Имени в inode нет: имена хранятся в каталогах. Каталог — это список соответствий «имя — номер inode».

Определение

inode

Структура файловой системы, в которой хранятся сведения о файле: тип, права, владелец, размер, время изменения и расположение данных. Имя файла в inode не хранится.

Поскольку имя отделено от inode, на один inode могут указывать несколько имён. Дополнительное имя называется жёсткой ссылкой и создаётся командой ln. Все имена равноправны. В inode хранится счётчик ссылок; данные файла удаляются, только когда удалено последнее имя.

Схема · имена, inode и ссылки
Каталог linux-fhs-lab
    Каталог data
      inode
      В терминалеСоздание жёсткой ссылки
      1. cd ~/linux-fhs-lab
      2. stat data/info.txt# сведения из inode
      3. ls -li data/info.txt# номер inode и число ссылок
      4. ln data/info.txt data/info-hard.txt# создать второе имя
      5. ls -li data/info*# сравнить два имени
      Результат
      у обоих имён одинаковый номер inode, число ссылок равно 2.
      Примечание
      Номера inode в вашей системе будут другими.
      6.3 Символические ссылки
      Символическая ссылка устроена иначе. Это отдельный объект со своим inode, в котором записан путь к другому файлу. При обращении к ссылке система переходит по записанному пути. Символическая ссылка может указывать на каталог или на файл в другой файловой системе, например /bin указывает на /usr/bin. Если файл по записанному пути удалить, ссылка перестанет работать.
      В терминалеСоздание символической ссылки
      1. cd ~/linux-fhs-lab
      2. ln -s data/info.txt info-link.txt# создать ссылку
      3. ls -l info-link.txt
      4. cat info-link.txt# чтение через ссылку
      5. readlink info-link.txt# путь, записанный в ссылке
      6. readlink -f info-link.txt# полный путь цели
      Результат
      ls показывает info-link.txt -> data/info.txt, cat выводит текст файла.
      Разница между двумя видами ссылок видна, если удалить исходное имя data/info.txt. Жёсткая ссылка указывает на тот же inode, поэтому данные остаются доступны. Символическая ссылка хранит путь к удалённому имени и перестаёт работать. После повторного создания имени командой ln она снова работает.
      В терминалеУдаление исходного имени
      1. cd ~/linux-fhs-lab
      2. ls -li data/info.txt data/info-hard.txt info-link.txt# исходное состояние
      3. rm data/info.txt# удалить одно имя
      4. ls -li data/info-hard.txt info-link.txt# после удаления имени
      5. cat info-link.txt# чтение через символическую ссылку
      6. cat data/info-hard.txt# чтение через жёсткую ссылку
      7. ln data/info-hard.txt data/info.txt# вернуть имя
      8. cat info-link.txt
      9. ls -li data/info.txt data/info-hard.txt# имён снова два
      Результат
      через жёсткую ссылку текст читается, через символическую — ошибка No such file or directory.
      Итоги части 6
      • Тип объекта обозначается первым символом в ls -l; содержимое определяет file.
      • Сведения о файле хранятся в inode, имя — в каталоге.
      • Жёсткая ссылка — дополнительное имя того же inode; данные удаляются вместе с последним именем.
      • Символическая ссылка хранит путь и перестаёт работать, если по этому пути нет файла.
      В отчётСнимки ls -li с одинаковыми номерами inode и опыта с удалением имени.
