Главная мысль · что уже известно

01Все файлы Linux лежат в одном дереве каталогов, и путь к любому файлу начинается с корня /. 02Каталог для файла выбирают по тому, что в нём хранится: программа, настройки или данные. 03Программы лежат в /usr, а оболочка находит их по списку каталогов из переменной PATH. 04Данные, которые меняются во время работы, раскладывают по сроку хранения: /var, /tmp и /run. 05Не каждый путь ведёт к файлу на диске: содержимое /proc, /sys и /dev выдаёт ядро. 06…это предложение появится в конце страницы

Кажется, что имя — часть файла. На самом деле имя хранится в каталоге, а сведения о файле — в отдельной записи, которая называется inode.

Из-за этого у одного файла может быть несколько имён, и удаление одного имени не всегда удаляет данные. В этом слое проверим это на опыте.

−6.1

6.1 Тип файла

Команда ls -l начинает каждую строку с буквы. Буква показывает тип объекта.

БукваТипГде встречали
-обычный файл: текст, программа, картинкаdata/info.txt
dкаталогdata
lсимволическая ссылка/bin
c и bсимвольное и блочное устройство/dev/null, /dev/sda
sсокет — файл для связи программ/run/cups/cups.sock

Что внутри обычного файла, буква не говорит: и текст, и программа отмечены знаком -. Содержимое определяет команда file. Она смотрит на сами данные, а не на расширение: если переименовать текстовый файл в .png, он останется текстовым.

В терминале · 6.1Тип и содержимое файлов
  1. cd ~/linux-fhs-lab
  2. file data/info.txt /usr/bin/python3 /dev/null# что это за файлы
  3. file -L /usr/bin/python3# -L: посмотреть на файл, куда ведёт ссылка
  4. ls -ld data data/info.txt /bin /dev/null# буквы типа в начале строк
Что должно получиться

в выводе ls есть буквы d, -, l и c.

?Чем «обычный файл» отличается от «текстового файла»?Сначала ответьте сами
«Обычный файл» — это тип объекта, его показывает буква -. «Текстовый» — это описание содержимого. Программа тоже обычный файл, но не текстовый.
−6.2

6.2 inode и второе имя файла

INODE(7)ОпределениеINODE(7)
Имя
inode — индексный дескриптор
Что это
Запись, в которой файловая система хранит сведения о файле: тип, права, владельца, размер, время изменения и место данных на диске. Имени файла в inode нет.
Как работает
Каталог — это список пар «имя — номер inode». Чтобы открыть data/info.txt, система находит в каталоге data имя info.txt, берёт номер inode и по нему находит данные.
Зачем
Поэтому у одного файла может быть несколько имён, а переименование не трогает сами данные.
Не путать
Поле Links в выводе stat показывает, сколько имён указывает на этот inode.
ЖЁСТКАЯ ССЫЛКА(7)ОпределениеЖЁСТКАЯ ССЫЛКА(7)
Имя
жёсткая ссылка — ln файл новое_имя
Что это
Второе имя в каталоге, которое указывает на тот же inode.
Как работает
Оба имени равноправны, ни одно не главное. Каждое новое имя увеличивает счётчик Links на 1. Данные удаляются, когда удалено последнее имя.
Зачем
Если удалить одно имя, файл останется доступен по другому.
Не путать
Жёсткая ссылка работает только внутри одной файловой системы.

      В терминале · 6.2Даём файлу второе имя
      1. cd ~/linux-fhs-lab
      2. stat data/info.txt# сведения из inode
      3. ls -li data/info.txt# -i добавляет номер inode
      4. ln data/info.txt data/info-hard.txt# создать второе имя
      5. ls -li data/info*# сравнить два имени
      Что должно получиться
      у двух имён одинаковый номер inode, счётчик ссылок — 2.
      На вашей машине
      Номера inode у вас будут другими. Важно, чтобы у двух имён они совпадали.
      ?Почему после удаления одного из двух имён данные остаются?Сначала ответьте сами
      Второе имя указывает на тот же inode. Данные удаляются, только когда не останется ни одного имени.
      −6.3
      6.3 Символическая ссылка
      СИМВОЛИЧЕСКАЯ ССЫЛКА(7)ОпределениеСИМВОЛИЧЕСКАЯ ССЫЛКА(7)
      Имя
      символическая ссылка — ln -s цель ссылка
      Что это
      Отдельный файл, в котором записан путь к другому файлу.
      Как работает
      Когда программа открывает ссылку, система читает записанный путь и открывает файл по нему. Если по этому пути файла нет, ссылка перестаёт работать — такую ссылку называют битой.
      Зачем
      Ссылка может вести на каталог или на файл на другом диске. Так устроены ссылки /bin → usr/bin.
      Не путать
      Размер ссылки в выводе ls — это длина записанного пути, а не размер файла, на который она ведёт.
      В терминале · 6.3Создаём ссылку
      1. cd ~/linux-fhs-lab
      2. ln -s data/info.txt info-link.txt# создать ссылку на data/info.txt
      3. ls -l info-link.txt
      4. cat info-link.txt# прочитать файл через ссылку
      5. readlink info-link.txt# какой путь записан в ссылке
      6. readlink -f info-link.txt# полный путь
      Что должно получиться
      ls показывает info-link.txt -> data/info.txt, cat выводит Linux filesystem.
      Теперь опыт, который показывает разницу между двумя видами ссылок. Удалим имя data/info.txt. Жёсткая ссылка info-hard.txt указывает на тот же inode, поэтому данные останутся. Символическая ссылка хранит путь к удалённому имени, поэтому она перестанет работать. В конце вернём имя командой ln.
      В терминале · 6.4Удаляем имя и возвращаем его
      1. ls -li data/info.txt data/info-hard.txt info-link.txt# как было
      2. rm data/info.txt# удалить одно имя
      3. ls -li data/info-hard.txt info-link.txt# как стало
      4. cat info-link.txt# прочитать через символическую ссылку
      5. cat data/info-hard.txt# прочитать через жёсткую ссылку
      6. ln data/info-hard.txt data/info.txt# вернуть имя
      7. cat info-link.txt# снова прочитать через символическую ссылку
      Что должно получиться
      после rm команда cat info-link.txt выдаёт ошибку No such file or directory, после ln снова выводит Linux filesystem.
      ?Если удалить файл, на который ведёт символическая ссылка, сохранится ли его текст в ссылке?Сначала ответьте сами
      Нет. В ссылке записан только путь. Сама ссылка останется, но открыть через неё ничего не получится — это мы и увидели после rm.

      Имя файла записано в каталоге и указывает на inode. Жёсткая ссылка — ещё одно имя того же inode. Символическая ссылка — отдельный файл, в котором записан путь.
