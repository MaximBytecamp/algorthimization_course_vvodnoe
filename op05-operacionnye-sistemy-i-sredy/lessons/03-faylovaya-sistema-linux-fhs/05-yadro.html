Главная мысль · что уже известно

01Все файлы Linux лежат в одном дереве каталогов, и путь к любому файлу начинается с корня /. 02Каталог для файла выбирают по тому, что в нём хранится: программа, настройки или данные. 03Программы лежат в /usr, а оболочка находит их по списку каталогов из переменной PATH. 04Данные, которые меняются во время работы, раскладывают по сроку хранения: /var, /tmp и /run. 05…это предложение появится в конце страницы

До сих пор за каждым путём стоял файл с содержимым на диске. Но в Linux есть каталоги, где содержимое файлов выдаёт ядро в момент чтения.

Зачем так сделано? Чтобы узнать состояние системы или обратиться к устройству, программе хватает обычных команд для работы с файлами: cat, ls, записи в файл.

−5.1

5.1 /dev: устройства

ФАЙЛ УСТРОЙСТВА(7)ОпределениеФАЙЛ УСТРОЙСТВА(7)
Имя
файл устройства — c — символьное, b — блочное
Что это
Специальный файл в /dev, через который программа обращается к устройству.
Как работает
Когда программа читает или пишет такой файл, ядро передаёт данные драйверу устройства. Символьные устройства принимают и отдают данные потоком, блочные — блоками, как диски.
Зачем
Для работы с устройством не нужна отдельная программа: достаточно открыть его файл.
Не путать
/dev/sda — это весь диск целиком. Запись в него уничтожит данные, поэтому в уроке мы пишем только в /dev/null.

/dev/null принимает любые данные и сразу их выбрасывает. Поэтому после записи в него на экране ничего не появляется. Узнать, успешно ли выполнилась команда, можно по коду завершения. Его хранит переменная $?: 0 означает успех, другое число — ошибку.

В терминале · 5.1Пишем в /dev/null и проверяем результат
  1. ls -l /dev/null /dev/zero# первая буква c — символьное устройство
  2. file /dev/null# что это за файл
  3. printf "test\n" > /dev/null# отправить текст в /dev/null
  4. printf "exit status: %s\n" "$?"# код завершения предыдущей команды
  5. lsblk -o NAME,TYPE,SIZE,MOUNTPOINTS# диски и разделы
Что должно получиться

file выводит character special, код завершения — 0.

?После записи в /dev/null на экране пусто. Значит, команда не сработала?Сначала ответьте сами
Нет. Данные и должны были исчезнуть. Успех проверяют кодом завершения $? сразу после команды.
−5.2

5.2 /proc: сведения о системе от ядра

ПСЕВДОФАЙЛОВАЯ СИСТЕМА(7)ОпределениеПСЕВДОФАЙЛОВАЯ СИСТЕМА(7)
Имя
псевдофайловая система — proc и sysfs
Что это
Файловая система, которая ничего не хранит. Её файлы и их содержимое создаёт ядро.
Как работает
Когда программа читает /proc/meminfo, ядро в этот момент собирает сведения о памяти и выдаёт их как текст. Поэтому команда ls показывает у таких файлов размер 0, а при каждом чтении содержимое новое.
Зачем
Состояние системы можно узнать обычной командой cat.
Не путать
Если скопировать файл из /proc, копия будет обычным файлом с данными на момент копирования. Обновляться она не будет.
В терминале · 5.2Память и текущая оболочка
  1. head -8 /proc/meminfo# первые восемь строк сведений о памяти
  2. echo $$# номер процесса нашей оболочки
  3. readlink /proc/$$/cwd# в каком каталоге сейчас оболочка
  4. readlink /proc/$$/exe# какая программа запущена
  5. findmnt -T /proc/meminfo -o TARGET,SOURCE,FSTYPE# тип файловой системы
Что должно получиться

тип файловой системы — proc, каталог оболочки совпадает с тем, что показывает pwd.

Лучше всего это видно на файле /proc/uptime. Первое число в нём — сколько секунд прошло с загрузки системы. Прочитаем файл, сделаем копию, подождём пять секунд и сравним.

Модель · откуда берётся содержимое файла
catпрограмма читает файл
ядросмотрит, на какой файловой системе файл
overlay / ext4читает данные с диска
procсчитает время с загрузки в момент чтения
ответ—

Числа — из кадра proc-uptime: первое чтение, чтение через пять секунд и копия, сделанная между ними.

В терминале · 5.3Файл из /proc и его копия
  1. rm -f saved-uptime.txt# удалить копию, если она осталась с прошлого раза
  2. ls -l /proc/uptime# размер файла
  3. cat /proc/uptime
  4. cp /proc/uptime saved-uptime.txt# сделать копию
  5. sleep 5# подождать пять секунд
  6. cat /proc/uptime# прочитать ещё раз
  7. cat saved-uptime.txt# прочитать копию
  8. findmnt -n -o TARGET,FSTYPE -T saved-uptime.txt | cat# где лежит копия
Что должно получиться

число в /proc/uptime выросло, а в копии осталось прежним.

?Почему копия /proc/meminfo в домашнем каталоге не обновляется?Сначала ответьте сами
При копировании сохранился текст на тот момент. Копия — обычный файл на диске, ядро её не меняет.
−5.3

5.3 /sys: устройства и их параметры

/sys — ещё одна файловая система, которую создаёт ядро. Через /proc мы читали сведения о памяти и процессах. В /sys лежат сведения об устройствах: каждый файл содержит одно значение. Например, в /sys/class/net перечислены сетевые подключения компьютера.

В терминале · 5.4Сетевые подключения
  1. ls /sys# разделы /sys
  2. ls /sys/class/net# сетевые подключения
  3. cat /sys/class/net/lo/operstate# состояние подключения lo
  4. findmnt -T /sys -o TARGET,SOURCE,FSTYPE
Что должно получиться

есть подключение lo, тип файловой системы — sysfs.

На вашей машине

Запись в некоторые файлы /sys меняет настройки ядра. В уроке мы их только читаем.

?Чем /proc отличается от /sys в наших опытах?Сначала ответьте сами
Из /proc мы читали сведения о памяти и процессах, из /sys — сведения об устройствах. Оба каталога создаёт ядро.

Итог слоя 05

01Все файлы Linux лежат в одном дереве каталогов, и путь к любому файлу начинается с корня /. 02Каталог для файла выбирают по тому, что в нём хранится: программа, настройки или данные. 03Программы лежат в /usr, а оболочка находит их по списку каталогов из переменной PATH. 04Данные, которые меняются во время работы, раскладывают по сроку хранения: /var, /tmp и /run. 05Не каждый путь ведёт к файлу на диске: содержимое /proc, /sys и /dev выдаёт ядро.

За путём не всегда стоит файл на диске. За /home — данные на диске, а за /proc, /sys и /dev — ядро, которое отвечает в момент обращения.
